# 缺节点包诊断（deps）

> **范围**：`comfyui(action="deps", ...)` 的用法——三种输入形态、三态结果的下一步动作。
> **何时读**：校验/提交报 `unknown_type`、用户问"这图缺什么包"、拿到别的机器传来的工作流时。
> **前置条件**：ComfyUI 服务在线（对照该实例 `/object_info` 与本机已装包清单）；查询不安装、不重启。

## 用法

- `workflow` 三形态：本机文件路径 / 工作流 JSON 对象（API 或 UI 格式）/ `{"template":"名称"}`；或 `classes`（类名数组）。二者互斥。
- **都不给时默认取当前画布**的类名集合（子图内部类名收不进来，要全量请显式传 workflow）。
- 返回正文是三段式中文摘要；`details.comfyui` 有完整结构化结果（summary 三段 + 每个类名的 resolutions 候选）。每段正文最多列 5 条，超出以「…另有 N 条省略」提示，**完整清单读 `details.comfyui`**。

## 三态结果与下一步动作

| 状态 | 含义 | 下一步 |
|---|---|---|
| 没装（notInstalled） | 有候选仓库但本机没装 | 去装：给用户仓库名/标题，建议装后重启服务再验 |
| 装了但没加载（installedNotLoaded） | 包在 custom_nodes 目录里，但类没出现在 object_info | 看启动日志或查依赖：多半是依赖没装 / 启动报错 / 被禁用，别急着重装 |
| 查不到来源（unresolved） | 内置映射表里没有该类名 | 手写节点或改名：可能是手写类名、拼错，或纯前端扩展包 |

## 两个常见疑问

- **为什么一个类名对应多个包**：不同作者常实现同名节点（如多个 "Load Image" 增强版），映射表会把所有候选全列出来并标注"这类名对应多个包"——**不替你挑**，结合工作流来源/上下文判断，或让用户选。装错了包类名也不会出现，还得回头排查。
- **「没装」行尾巴上的「另有已装候选」怎么读**：同一个类名有几个候选仓库、其中一部分已装、一部分没装时，正文的【没装】行会补一句`（另有已装候选：<repo>，若装了仍缺类请查它是否加载失败）`。意思是：你打算装的那个仓库不是唯一来源，本机已经装着另一个能提供该类名的包，但类没加载出来（`details.comfyui.summary.notInstalled[].alsoInstalled` 里是这些已装候选，带 `repo` / `dir`）。此时先查这个已装包的启动日志 / 是否被禁用、是否需要重启，再看要不要另装新包——否则装完 `repoY` 可能仍然缺类。两个桶依然互斥：已装候选只出现在 `alsoInstalled`，不会重复进 `installedNotLoaded`。
- **为什么纯前端扩展包查不到**：映射表基于节点类名反查 Python 侧插件仓库；纯前端扩展（只注册 JS 扩展、不产生后端节点的包）没有类名可反查，天然落不进候选，遇到时报"查不到来源"属正常，不是诊断失灵。

## 使用建议

- 先 `validate` 拿 `unknown_type` 清单，再 `deps` 定位缺包，两者配合用。
- `classes` 形态适合快速抽查个别类名（如只差一个节点时）。
- 诊断完不自动安装：装什么、从哪装由用户拍板（涉及下载与重启服务，需先说再动）。
