## 0. 一句话结论

**切到聊天页 = 宿主卸载承载 App UI 的组件 + release 掉加载承租 → iframe 作废；切回来时宿主重建。** 宿主**没有**"切走不卸载"的口子（v1.1.0→1.1.7 均未开放）。因此：**保不住，但可做到"秒恢复"**。

## 1. 实测证据（探针数据）`[实测]`

数据源：`~\.hanako\app-data\comfyui-hana\keepalive-probe\hui-page-pulse.jsonl`（每 10s 一拍，`{t, n, vis}`，`n` 为**页面内自增**计数）。

### 1.1 判定尺子

| 现象 | 含义 |
|---|---|
| 记录**变稀**（间隔变大），`n` 继续增 | 页面还在，timer 被降频（节流） |
| 记录**归零**（断档后 `n` 从 1 重来） | JS 上下文重建 = **页面被销毁后重建** |

### 1.2 全量分类（`n` 归零 vs 变稀）

- **归零型断档：73 次**
- 变稀型断档：4 次

→ **压倒性：不是节流，是销毁重建。**

### 1.3 单次受控实验（01:09–01:15）

```
01:09:38  n=1  …连续 23 拍，零断档…  01:13:18  n=23
   ... 断档 104.9s ...
01:15:03  n=1  …恢复…
```

- 断档期间**完全无记录**（不是变稀）→ 页面不存在
- `n` 归零（23 → 1）→ iframe 销毁后重建
- 断档 104.9s，重建发生在**切回时刻**

### 1.4 边界（诚实标注）

- 73 次归零里，**有一部分是当晚调试期反复重载页面造成的**（换桥版本、验收截图等），不能全算"用户切走"。比例方向不受影响，绝对数需打折。
- "切回来自愈"为**侧证**（多次 n 归零后又从 1 涨起，均为切回触发），**未做主动重建的受控实测**。

## 2. 机制（代码链）`[代码推断]`

### 2.1 App UI 靠短命承租加载

- 宿主以 `WebContentsView`（`app.asar` @11326486）承载 App 宿主视图，`partition: app-host-view:<viewId>`。
- App UI 的 iframe 靠 **iframe ticket / appSurfaceSession** 加载：`server bundle` 有 `/api/apps/iframe-ticket`、`/api/apps/:appId/ui-sessions/release`、常量 `Zj="X-Hana-App-Surface-Session"`、`skr=720*60*1e3`(≈12h)、`ikr=60*1e3`(60s)。

### 2.2 切走 → 卸载 → release（renderer，`ChatTranscript-*.js`）

React `useEffect` **清理函数**（组件卸载时执行）：

```js
return () => {
  C.cancelled = true;
  C.attempt?.controller.abort();
  lo(C.session?.held ?? null);   // ← 释放 App UI 承租
  C.session = null;
};
```

`lo()` 的实现（同文件，@739274）：

```js
function lo(e){ if(!e||e.returned) return; e.returned=true;
  const {owner:t,token:n}=e;
  fetch(.../ui-sessions/release, {method:"POST", body:JSON.stringify({token:n})})
    .catch(()=>console.error("[use-plugin-surface-url] Static App UI cleanup failed; the Host will expire the unused access"));
}
```

→ **组件卸载即 release 承租**；承租一失效，iframe URL 作废。

### 2.3 宿主未提供保活（三份普查一致）

- `contributes.cards[]` 白名单（server `index.js` @5648489）：`id/title/route/.../realization/pageOf/closable/siteNavEntry/fpFullPanel/functionPanel/detached/detachedDefaultSize/face/pageIcon/formFactors` —— **无任何保活字段**。
- `ctx.cards`/`hana.cards`/`keepAlive`/`stayMounted`/`mountPolicy`/`unloadPolicy` 全部 **0 命中**。
- 卡片契约原文（server `index.js:102135-102145`）：**"A card whose virtual row leaves the window is unloaded and its document is destroyed… There is no formal visibility or freeze bridge API to call."**
- 主进程：`backgroundThrottling:!1` **仅**用于主窗口（`app.asar` @12073701）与 browser-viewer（@12079279）；**App 宿主视图（WebContentsView @11326486）无此项**。

### 2.4 surface role：唯一"不参与卸载"的通道

- `home`/`studio`/`page` → `role:"persistent"`；`detached` → `role:"floating"`（renderer `index-DbjRpadG.js`）。
- 桌面端页宿主渲染所有 page，非活动页 `data-parked`（**保留 DOM**）；手机端 `me()` 只渲染 active + persistent/floating。
- **App 改不了**自己 surface 的 role（无 `setSurfaceRole`/`updateSurfaceRole`）。
- 唯一"切走不卸载"通道 = `card.detach` 成 `kind:"detached", role:"floating"` 的**独立窗口**。
- ⚠️ 但 `detached` 窗口**同样未设** `backgroundThrottling:!1`（`WebContentsView` @11326486），且是否躲过"组件卸载"未实测。John 判断这条路"显然是死的"。

## 3. 结论与出路

### 3.1 准确表述

**不是"App 没办法"，是"宿主没给这个开关"**（权限够不着，非技术不可行）。宿主自身对主窗口/browser-viewer 已关节流，说明**它懂得怎么做**，只是未开放给 App 视图。

### 3.2 可做的两条（B 方案）

| 步 | 内容 | 现成基础 |
|---|---|---|
| 看门 | 常驻侧（App 主进程/中继）定期探壳页腿 + 扩展腿 | `LEG_TIMEOUT_MS`、`SHELL_ALIVE_MS`、`keepalive-probe` |
| 判定 | 连续 N 次不可达 → 判掉线 | 壳页存活窗口 |
| 恢复 | 按需调 `window` op 重建壳页（不打扰用户） | `window op=open/open-host` |
| 就绪 | 等 ComfyUI 装载 + 桥重连才报"活" | `service op=wait` |

**John 拍板（2026-10-16）**：按需（ondemand）+ 静默（silent）+ 先实测（test_first）。

### 3.3 治本只有一条

向宿主递「App 视图切走不卸载 / 免节流」需求（旧文档 §七 窗口保活草案可更新到 1.1.7 语境）。宿主每版都在变，**1.1.7 没开 ≠ 下版不开**。

### 3.4 重要前提（降低焦虑）

掉的是**显示层**，不是**执行层**：ComfyUI 服务独立进程、生成任务不中断、工作流状态在服务端。所以"快速恢复"完全够用。
