## 一句话结论

推荐「Viggle turbo edit」（`Qwen-Image-2.1-viggle-turbo-edit.json`）作为专用的独立编辑工作流——6 步、无 CFG、自带 QwenImage21Cache、与本机已装节点及 LoRA 同源、单文件可下；质量优先场景（复杂编辑/保身份/文字）搭配官方 edit 模板（bf16、euler/simple、25→40-50 步、cfg=1）出片。

## 二、机制结论逐条

### 1) QwenImage21Cache —— 做什么、参数、是否必须
- 做什么（〔官方模板 note〕+〔实测〕本机源码 `comfy_extras/nodes_qwen.py`）：为编辑序列的 KV cache 设置存放设备与量化；编辑时"参考图+文本前缀"缓存一次、每步复用不重算。Viggle note 原文："stores the reference part of the sequence once instead of recomputing it every step. At dtype = default it is lossless."
- 参数（源码 tooltip）：device = auto/gpu/cpu/off（off = 每步重算前缀，更慢，唯一排除缓存作用的方法）；dtype = default/int8/int4（default 无损；int8 减半、≈bf16 精度；int4 再减半、每步误差约翻倍）。默认 auto/default。
- 是否 edit 必须：非强制（不接即无缓存/等价 off），但官方模板与 Viggle edit 均默认内置启用（dtype=default 无损），属编辑链路默认优化项。12GB 卡上它的意义在于省重复前向，不改采样逻辑。

### 3) EasyCache / Viggle turbo LoRA 能否用于 edit 加速
- Viggle turbo LoRA：即官方 edit 工作流的默认加速器（6 步替代 40 步、无 CFG），编辑链路原生支持。〔官方 Viggle edit 工作流〕
- EasyCache：未找到"用于 2.1 edit"的官方或社区直接说法。官方 edit 模板不含 EasyCache（用 QwenImage21Cache）；Viggle edit 亦不含（两文件实查）。〔官方模板 + Viggle JSON〕
- 本机经验（t2i，实测）：EasyCache 0.9 阈值在 12–20 步下有效（30s→20s），0.2 过激伤质量；6 步 turbo 下可跳步有限且可能伤蒸馏质量（建议旁路对比）。〔实测〕
- 机制上二者不冲突（EasyCache=跳采样步；QwenImage21Cache=复用前缀 KV），但 turbo 的 6 步 schedule 是蒸馏设计值，跳步需自行验证。〔推断，已标注〕

### 4) negative_prompt 在 cfg=1 时无效 —— 确认（三源）
- 官方模板 note 原文：negative_prompt: unused while cfg is 1.〔官方〕
- 本机源码 comfy/samplers.py:610：if math.isclose(cond_scale, 1.0) …: uncond_ = None —— cfg=1 时无条件分支被整体跳过。〔实测〕
- 社区技术文档同结论（ComfyUI 规格：cfg=1.0 不算负面分支）。〔社区〕

### 5) 其他选型要点
- 版本时点：Viggle 最新为 v0.3（2026-09-29）；与 v0.2.1 相比颗粒更少、更干净、细纹略柔，"不是严格升级"；官方称 6 步已接近容量上限，再提升须加步数（v0.3 的 9-step=7+2 模式仅 diffusers/Demo Space，ComfyUI 工作流里没有）。〔官方 README〕
- 编辑质量边界（官方已知限制）：复杂编辑（多参考、换脸、保身份）可能不如基础模型（重复/幽灵人影、身份漂移）；小字/长文更易花；颜色饱和度略低；2K/RGBA/mask/超 3 参考无标准评测。〔官方 README〕
- 社区列表定位 turbo："以保真换速度；适合迭代与批量；多参考组合与保身份编辑弱于 40 步"。〔社区〕
- 社区其他 turbo 线（不可互换）：Alibaba PAI Fun-Acc 4Step（官方 4 步、含编辑）；Pruna 8/5-step（各自 sigma 表）；UltraFast 8-step（编辑向、非标准加载器）；6NFE Distill（第三方全量蒸馏）。〔社区〕
- 编辑相关社区 LoRA 举例：Edit-consistency（防编辑漂移 24.3px→1.6px）、Outpaint v2、BFS Head Swap、Object Remover turbo（4 步兼容）、FG extract v4（基于 Viggle turbo，4 步）。〔社区〕
- 注意生态断层：大量 "Qwen Edit" 社区资源（含 800+ star 的 QwenEditUtils）面向更早的 Qwen-Image-Edit-2509/2511 谱系，与 2.1 基础不同、不可直接套用。〔社区，按创建时间判断，标注推断〕

## 三、推荐方案与理由

主推 A（Viggle turbo edit），理由：①编辑专用（参考槽 + 编辑 PE 可选，非 t2i 改造）；②速度（6 步，≈5× 于 40 步）；③与本机匹配度最高（节点已装、LoRA 已有 v0.2.1、模型三件套同源）；④获取最简单（单文件 ~96KB，URL 已确认）；⑤自带 QwenImage21Cache（无损默认）。明确边界：复杂编辑弱于多步基础模型 → 出片用 B。

搭配 B（官方模板 = 质量优先路径）的工作流建议：
1. 用 A 快速迭代构图/指令（6 步草稿，换 seed 试参考顺序：要保留的画幅放 image_1）；
2. 定稿后用 B 同提示词出片：bf16 + euler/simple + cfg=1 + 25→40-50 步（模板 resolution=0 保持 image_1 原尺寸；需要统一尺寸开 custom_size，且尺寸须接近 image_1 否则 edit 会偏移）；
3. 提速可选：B 上叠 EasyCache（阈值 ≈0.9 起步、6 步链路勿叠），或直接用 A 的 merged/gguf 变体；
4. 本机注意：bf16 在 12GB 卡走 offload（历史 25 步 1024px ≈40s）；int8 在本机历史反而更慢（仅本机结论）。A 默认配置峰值 ~26GB VRAM（官方 README），12GB 会走 offload，实测速度请以本机为准。

Viggle edit 工作流下载（文件已实测存在于镜像，可直接下，主脑已 HEAD 复核 200）：

- 镜像（当前网络实测可读）：https://hf-mirror.com/Viggle/Qwen-Image-2.1-viggle-turbo/resolve/main/comfyui/Qwen-Image-2.1-viggle-turbo-edit.json
