# 调研：画布提交历史 · 画布叠加层（点块弹出工具栏）实现方案

> 调研范围：ComfyUI 前端（`comfyui_frontend_package` 静态包）+ 已装插件 `rgthree-comfy` / `ComfyUI-Custom-Scripts` / `hana_bridge`。
> 标 `[实测/代码确证]` = 已从源码查证；`[推断]` = 基于先例的合理推断，待实现时验证。

## 结论（推荐做法）

挂一个**绝对/固定定位的小弹层**到 `#graph-canvas-container`（画布容器），**不要**用全屏遮罩（除非要锁操作）。
弹层位置用官方坐标 API 算：`app.canvas.convertOffsetToCanvas([x,y])`（画布逻辑坐标→相对画布像素），再加画布 `getBoundingClientRect()` 的偏移得到视口坐标；**用 `position:fixed`** 最稳（官方 dom-widgets 即如此，避免容器定位/滚动错位）。
同步用 **`app.canvas.ds.onChanged(scale, offset)`** 回调（每次缩放/平移都触发）重算位置；同时挂 `app.canvas.onDrawForeground` 兜底防丢帧——这正是 rgthree 与官方 DomWidgets 的做法。
交互用 **`pointer-events:auto`** 让弹层吃自己的点击（容器默认 `pointer-events:none` 或交给 canvas，弹层要显式吃）。裁剪问题：画布容器本身**不裁剪**（`overflow` 未设 hidden，实测 `.litecontextmenu` 等浮层可溢出），但为保险弹层用 `fixed` 并自行 `visible_area` 做离屏隐藏。

## 证据 1 · 可挂载的 DOM 容器

- `[代码确证]` 画布容器是 `id="graph-canvas-container"`（ComfyUI 主模板渲染它，并往里 `mount` 浮层）。前端多处用它做 portal 目标：
  - `GraphView-CDjciZjE.js:23:240204` 主模板 `y('div',{id:'graph-canvas-container',...})` 包住 canvas。
  - `GraphView-CDjciZjE.js:10:12330` 与 `:12456` 用 `w(Se,{to:'#graph-canvas-container'},...)` 把缩放控件、侧栏面板挂进去。
  - `app.canvasContainer = $el('div.graph-canvas-container')`（`GraphView-CDjciZjE.js:23...` 中 `this.canvasContainer`）。
- `[代码确证]` 本项目 hana_bridge 已用同容器挂载浮层（`hana-bridge-09205624.js:451`）：
  ```js
  const container = document.getElementById("graph-canvas-container") ||
                    (app && app.canvasContainer) || null;
  container.appendChild(film); // film: position:absolute; inset:0; z-index:9999
  ```
- `[推断]` 选 `#graph-canvas-container` 而非 `document.body`/`canvas` 父级：它与画布同尺寸、同生命周期，重绘不会被清（canvas 的 2D 重绘只清 `<canvas>` 位图，不动兄弟 DOM）。

## 证据 2 · 坐标换算（确切 API）

- `[代码确证]` `DragAndScale`（即 `app.canvas.ds`）提供双向换算（`settingStore-X9ZV_dAu.js:2:41737`）：
  ```js
  // 画布坐标(canvas units) → 相对<canvas>像素
  convertOffsetToCanvas(e){ return [ (e[0]+this.offset[0])*this.scale,
                                      (e[1]+this.offset[1])*this.scale ]; }
  // 相对<canvas>像素 → 画布坐标
  convertCanvasToOffset(e,t){ t=t||[0,0]; t[0]=e[0]/this.scale-this.offset[0];
                                          t[1]=e[1]/this.scale-this.offset[1]; return t; }
  ```
- `[代码确证]` `LGraphCanvas` 透传了这两个方法（`settingStore-X9ZV_dAu.js:2:404150`）：
  `convertOffsetToCanvas(e,t){return this.ds.convertOffsetToCanvas(e)}`、`convertCanvasToOffset(...)`、`convertEventToCanvasOffset(e){ let t=this.canvas.getBoundingClientRect(); return this.convertCanvasToOffset([e.clientX-t.left, e.clientY-t.top]); }`。
- `[代码确证]` `ds.offset` 是**平移量（画布单位）**，`ds.scale` 是**缩放因子**。符号验证（`bookmark.js:88`）：`canvas.ds.offset[0] = -this.pos[0] + 16` ⇒ `屏幕x = (pos + offset)*scale = 16*scale` ⇒ offset 为正=内容右移，公式与源码一致。
- `[实测公式]` 弹层（fixed）左上角视口坐标：
  ```
  rect = app.canvas.canvas.getBoundingClientRect();
  [sx, sy] = app.canvas.convertOffsetToCanvas([group.pos[0], group.pos[1]]);
  left = rect.left + sx;  top = rect.top + sy;   // 乘以 DPR 视 CSS px 而定
  ```
- `[代码确证]` `visible_area` 是**当前视口在画布坐标下的矩形** `[x, y, w, h]`（`settingStore-X9ZV_dAu.js:2:40560`，`getCanvasCenter` 用 `[e,t,n,r]=visible_area → [e+n/2, t+r/2]`）。用于判断弹层是否在视口内、离屏则隐藏。

## 证据 3 · 缩放/平移同步

- `[代码确证]` **现成事件**：`DragAndScale` 在状态变化时会调 `onChanged`（`settingStore-X9ZV_dAu.js:2:41071`）：
  ```js
  computeVisibleArea(e){ ... this._stateHasChanged() && (this.onChanged?.(t,n), copyState(...)); ... }
  ```
  ⇒ 订阅 `app.canvas.ds.onChanged = (scale, offset) => repositionPopup()` 即可在每次缩放/平移后重算——最稳、零轮询。
- `[代码确证]` **兜底/每帧**：官方 DomWidgets 把位置更新挂进 `onDrawForeground`（`GraphView-CDjciZjE.js:5:26022`）：
  ```js
  e.onDrawForeground = Ss(e.onDrawForeground, updateWidgets); // updateWidgets 每帧读 ds.offset/scale
  // updateWidgets 内：s=e.ds.offset[0], c=e.ds.offset[1], l=e.ds.scale; 与上次比较后重设 i.pos
  ```
- `[代码确证]` rgthree 同类做法：`fast_groups_service.js:52` 用 `requestAnimationFrame(() => this.run())`（调度动画帧），rgthree `reroute.js:323`/`node_mode_relay.js:61`/`dynamic_context_switch.js:106` 均用 `onDrawForeground(ctx, canvas)` 做叠加绘制。
- `[推断]` 推荐组合：`ds.onChanged` 为主（事件驱动、省 CPU），`onDrawForeground` 为兜底；无需独立 `setInterval`。若弹层是纯 DOM（非 canvas 绘制），`onChanged` 足够，`requestAnimationFrame` 仅用于合并连续帧。

## 证据 4 · 交互不冲突

- `[代码确证]` **不穿透**：hana_bridge 锁膜用 `pointer-events:auto` 让浮层吃指针（`hana-bridge-09205624.js:443`）：
  ```js
  film.style.cssText = "position:absolute; inset:0; z-index:9999; ...; pointer-events:auto; cursor:progress;";
  ```
  ⇒ 弹层自身设 `pointer-events:auto`（容器/canvas 默认把事件交给画布），点击/滚动只作用于弹层，不穿透到画布。注意：那是全屏遮罩；本需求是**小工具条**，所以只给工具条本体 `pointer-events:auto`，**不要**铺 inset:0，否则会吞掉画布交互。
- `[代码确证]` **裁剪**：`#graph-canvas-container` 的 CSS 未见 `overflow:hidden`；官网浮层（`.litecontextmenu` `position:fixed`、DomWidgets `position:fixed`）均自由溢出不被裁。
- `[推断]` 弹层用 `position:fixed`（DomWidgets 同款）可彻底避开容器 `overflow`/定位问题；若用 `absolute` 挂在容器内，需确认容器 `position:relative`（app 模板结构与 hana 锁膜 absolute 实践支持此假设）。超出视口时用 `visible_area` 隐藏而非依赖溢出。

## 未决项
1. **DPR 处理**：`convertOffsetToCanvas` 给出的是 CSS 像素还是 device 像素待实测（前端多按 CSS px 走，但需确认 `rect` 与结果单位一致）。
2. **弹层数据源**：历史提交缩略图来自哪里（workflow 快照/图片节点输出）本调研未涉及，需另行确认。
3. **触发点命中**：group 标题栏 vs 块角落的命中区域，需在前端测 `convertEventToCanvasOffset` 反算点击落在哪个 group（参考 `onGroupAdd` 用 `convertEventToCanvasOffset` 定位）。
4. **多 subgraph**：`fast_groups_service` 表明 group 存在于 root graph 与各 subgraph，弹层需跟随 `app.canvas.getCurrentGraph()` 切换（`bookmark.js` 有 `openSubgraph` 先例）。
