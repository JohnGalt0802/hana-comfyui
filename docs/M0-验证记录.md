### 2.2 `--smoke`（可选）— 后端通过 / UI 半场受阻（已定位）

**执行过程**

1. 直接 `--smoke`（无 Electron）：
   `SMOKE_RUNTIME_EXCEPTION: UI smoke requires an Electron runtime. Set HANA_APP_ELECTRON to the Electron binary installed for App development; the packaged Hana desktop executable is not a script runner.`
2. 提供 Electron：本机 `C:\Users\John Galt\AppData\Local\electron\Cache\electron-v42.3.3-win32-x64.zip`（系统缓存）解包至 `_build\electron\`，`HANA_APP_ELECTRON=<...>\electron.exe` 重跑：
   - **后端半场通过**：`"backend": {"status": "loaded", "error": null}`（临时 AppHost 成功 import 并执行 `app/index.js` 的 apply）。
   - **UI 半场失败**：每个 UI 路由报 `SMOKE_UI_ELECTRON_FAILED: Electron exited 4294967295`（进程即刻退出、无任何输出）。
3. 根因探针（最小复现，剥离 app 无关）：官方 runner 以
   `spawn(electron, [driver.mjs, "--url", <URL>, "--profile-dir", <dir>, ...])` 调用 Electron。
   在 **stock Electron v42.3.3 与再下载的 v33.4.11（GitHub release 官方包）**上均复现：
   | argv 形态 | 结果 |
   |---|---|
   | `[script, "--url", "about:blank"]`（URL 值在最后） | ✅ 正常执行 |
   | `[script, "--url", "about:blank", "trailing"]`（URL 值后还有参数） | ❌ 即刻退出（-1 / 4294967295，无输出） |
   | `[script, "--profile-dir", <dir>, "--url", "about:blank"]`（调换顺序） | ✅ 正常执行 |
   | `[script, "--url", "x", "--foo", "1"]`（值非 URL 形态） | ✅ 正常执行 |
   - 在被探针替换的 `default_app.asar` 中注入首行日志：失败用例**从未进入 JS** → 早退发生在 Electron C++ 层（与本 App 无关）。
   - 结论：**在本机可获得的 Electron 发行版上，官方 smoke 的 UI 半场无法运行**；需要"官方配发的 Electron 开发运行时"（`HANA_APP_ELECTRON` 指向的独立运行时）才能复跑。**这不是本 App 的缺陷**，且属任务书允许的"受阻则记录原因"。
4. 替代证据（非官方，仅补充）：自建 Electron UI 预检（`tools/m0-checks/ui-precheck.mjs`，v33 运行时，`--disable-gpu`）：
   - **4/4 页面加载成功、exit=0、renderable=true**；
   - 控制台仅两类消息：① Electron 安全提示（file:// 无 CSP，打包后消失）；② 预期内的 SDK 提示（`@hana/app-sdk/ui requires an App iframe route under /api/apps/:appId/ui/`——因为是 file:// 直开而非宿主路由，官方 smoke 会提供该路由）；
   - workspace 页在无宿主时正确落入 error 视图（可见文本 197 字符），panel/settings/task 各有可见内容。
   - 原始输出：`docs/m0-results/07-ui-precheck.txt`。

> 复跑建议（宿主阶段）：在配好官方 Electron 开发运行时的环境执行
> `node <skills>\hana-app-creator\scripts\validate_app.mjs --dir <staging> --smoke --json`，

## 5. 「宿主前缀剥离」假设与本地预演

> **宿主段已实测证实（2026-09-21，见 §8.6-3）：中继侧全程 `stripSurfaceCount=0 / stripQueryCount=0`——宿主在转发前已校验并剥离前缀与 `_surface/<票据>` 段，中继收到的是干净目标路径；中继的防御性清理从未触发（作为保险保留）。**

**设计假设（任务书明确要求标注）**：宿主代理会剥离
`/api/apps/comfyui-hana/routes/_runtime/<runtimeId>` 前缀后再转发，中继收到的应是目标路径（如 `/api/queue`、`/ws`）。中继按此假设设计：**原样路径 → 后端根**。

**防御性处理（超出假设的保险，命中时打日志）**：若宿主未剥离 `/_surface/<票据>/` 段或残留 `?appSurfaceSession=...`，中继会清理后再转发（日志中凭证值打 `[redacted]`）。这保证两种情况都能工作，且留痕可查。

**本地预演**（`tools/m0-checks/host-sim.mjs`，模拟剥前缀 + 转发）：

```
host-sim(127.0.0.1:39252)  --剥掉 /api/apps/comfyui-hana/routes/_runtime/<rid>-->  relay(39251) --> 8188
```

结果（`docs/m0-results/06-prefix-sim.txt`，9/9）：

| 项 | 结果 |
|---|---|
| `GET <prefix>/api/queue` | 200；body 与直连**一致** |

5. 中继对"未剥离凭证"的防御性清理（`_surface` 段 / `appSurfaceSession` 查询参数）是安全侧补充，日志中对凭证值 `[redacted]`；正常（宿主已剥离）时不会触发。
