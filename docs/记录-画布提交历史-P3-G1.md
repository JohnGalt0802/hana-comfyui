## 二、四项验收说明（任务书指定）

### ① 闸门复核结论（附行号证据）

**结论：回跳动作不经 agent op 通道，不受副驾驶写闸门约束，两个名单均无需改动。**

证据（改后文件行号，本次未动这些行，与任务书给的约行号一致）：

- `copilotWriteBlocked`（L2965–2976 改后行号，定义体未动；内容同原 L2700）：首行 `if (!WRITE_OPS.has(opName)) return null;` —— 只对 op 名生效；
- 它**唯一的调用点**在 `api.addEventListener(EVT_CALL, …)` 分发器内（L2986 起，`const blockedDetail = copilotWriteBlocked(msg.op)`），即 `/hana_bridge/call` 经 /ws 推来的 agent op 回执链路；服务端（`__init__.py` `_hana_call`）也只经这条通道下发 op；
- 回跳动作只从弹层按钮 DOM click → `historyRollbackClick()` 触发（L2606–2610），全程不构造 op、不经 EVT_CALL → `copilotWriteBlocked` 根本不会被调用；
- 因此 `COPILOT_WRITE_EXEMPT`（L2957–2962）与 `WRITE_OPS` 都不需要也不应该加入任何条目（方案 §六的判断成立，复核通过）。副驾驶关闭时回跳同样可用。

### ② loadGraphData 失败的原子性依据

实现前复核了前端 v1.55.14 打包源（`comfyui_frontend_package-1.55.14/static/assets/`）：

- `ComfyApp.loadGraphData`（settingStore-X9ZV_dAu.js，offset≈1866877，签名 `loadGraphData(e,t=!0,n=!0,r=null,i={})`）：顺序为 `useWorkflowService().beforeLoadNewGraph(t)`（旧页草稿持久化等，非画布变更）→ `invokeExtensionsAsync("beforeLoadGraph")` → **try 块**（setActiveGraph(null)、missing-nodes 收集等准备）→ 第二个 try 内 `this.rootGraph.configure(e)`，**catch 即 `reportGraphLoadFailure(e)` 后 `return false`** —— 不进入后续的 widget 修正、`afterConfigureGraph`、`afterLoadNewGraph`（活动页保持/激活）；返回 false（而非抛错）也已被桥侧消费：`okGraph === null`（catch）或 falsy 都走失败分支。
- `LGraph.configure`（同 chunk，offset≈512279）：首行防御 `if (e=runtimeOptional(e),!e) return;`（入参非法直接 return，图未动）；随后 `this.events.dispatch("configuring", …)` 被拒绝也 return；节点创建循环中 `Z.createNode` 失败是兜底成错误占位节点（不抛），真正的抛错点（如 subgraph 定义异常）会让整个 configure 终止——此时图已 `clear()` 的极端路径同样表现为「装载失败」，与既有 `canvas.loadWorkflowFile` 共享同一风险面与已验证行为（该 op 自 2026-09-27 起在生产的同一条 `loadGraphData(graph,true,true,aw)` 链路上运行）。
- 结论：**成功 = 整图换血；失败 = 旧图原样（或极小概率清空态，与既有 loadWorkflowFile 等价，非本改动引入的新风险）**。回跳侧任何异常都 catch 在弹层内显红字（L2899–2907），画布不动、不重试、不产生半装载回调链。

### ③ 二次确认状态机（规格 4）

```
点「回到这一版」
  ├─ 无选卡            → 提示「先在上方点选一条提交」，状态不变
  ├─ 当前画布 == 最近提交（简化口径一致）
  │                     → 直接执行（historyRollbackExecute）
  └─ 不一致 / 比对材料不全（最近提交取不到、fetch 失败、签名算不出）
        ├─ 未武装（!armed）→ armed=true + 60s 定时器 + 按钮变「确认回跳（丢弃未提交改动）」
        │                    + 红字警告「当前有未提交的改动，回跳将丢弃。再点一次确认执行」
        ├─ 60s 内再点      → 执行
        ├─ 60s 超时        → armed=false + 按钮复位 + 提示「确认已超时，未执行回跳」
        ├─ 换选其他卡片    → 按钮复位、armed=false（selection 更新后需重新点第一下）
        ├─ 切换 group      → 复位（historyBarOpen 内）
        └─ 收起弹层        → 复位（historyBarClose 内）
执行中 busy=true 防重入（点击忽略）；执行完成/失败均 busy=false。
```

简化口径（方案 §六护栏 3 授权）：`canvas-diff.mjs` 在 Node 侧前端不可用，比对复用桥内 `graphSignature()`（L634，节点数+连线数+逐节点 fnv1a hash，不含位置）的**同款口径**：当前画布取 `graphSignature()` 原值；最近提交快照由 `historySnapshotGraphSig()` 从落盘 graph（`nodes[].id/type/title/widgets_values` + `links` 数）构造同构签名。两边函数族/哈希函数相同；因快照落盘无 widget name/mode 字段，快照侧串接式为 `type:0(title):widgets_values`（已在代码注释标注差异与适用范围——只用于「当前 vs 最近提交」这一对，不要求跨形态哈希一致）。材料不全一律按「不一致」走确认制（宁可多问）。

### ④ 回跳后 `installQueuePromptCapture` 包装仍生效（规格 7）

包装（L2145 起，`installQueuePromptCapture`）包在 `api.queuePrompt` 方法对象上：`api.queuePrompt = async function(...){…orig.apply…}`，安装于 `setup()`、哨兵防重装、**从不还原**。回跳的装载路径是 `app.loadGraphData(graph, true, true, aw)`——上游只重建 rootGraph 内容（`rootGraph.configure`）并经 `activateLoadedWorkflow → store.openWorkflow(aw)` 复用当前活动页对象；`app.api`（q 对象）与 `api.queuePrompt` 方法引用都不在此路径上被替换/重建（前端源码中 queuePrompt 仅定义于 ComfyApp 类、无运行时重写点）。因此回跳后再点运行，仍走被包装的 `api.queuePrompt` → 抓当前画布 → POST history-commit → 时间轴续排新快照（P1 链路原样，无需特殊处理）。agent 经 `canvas.queue` op 的路径也复用同一 `api.queuePrompt`（P1-A2 早已覆盖）。

## 四、边界与不做

- 不做 DAG/分叉可视化、不记 parent（方案：日后加成本很低）；
- 不造「回滚前快照」（污染「提交=运行」语义）；
- 不自动落盘、不自动提交——回跳成功后画布相对文件为「已修改」，保存/再提交由用户决定（成功提示文案已带此说明）；
- 成功提示：规格原文要求「弹层顶部显示 + 装载后关闭弹层」——弹层已关则提示无法留在弹层内，故用同款样式的顶部 toast 展示 5 秒（`historyRollbackToast`，z-index 10002 > 弹层 10001），语义等价、已在代码注释说明；
- 闸门两名单（`WRITE_OPS`/`COPILOT_WRITE_EXEMPT`）零改动（复核结论①）。
