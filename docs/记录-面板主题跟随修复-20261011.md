## 1. 现象与根因

**现象**：用户当前主题为深色 `midnight-contrast`，但左侧功能面板（`contributes.cards[0].functionPanel.route = /panel.html`）整块显示白底，不跟随宿主主题。

**根因（两层，缺一不可）**

1. **明暗判定拿不到快照**：`syncTheme()` 原逻辑只认 `hana.theme.getSnapshot()`：
   ```js
   let dark = snap?.appearance === "dark" || /dark|midnight|contrast|深|夜/i.test(label);
   if (!snap?.appearance && (!label || label === "inherit")) {
     dark = !!(window.matchMedia && window.matchMedia("(prefers-color-scheme: dark)").matches);
   }
   ```
   快照的值来自宿主注入的 URL 参数（`hana-theme` / `hana-theme-appearance` / `hana-css`），**只在宿主推
   `THEME_CHANGED` 时更新**（SDK 侧 `readInitialTheme` + `THEME_CHANGED` 分支）。宿主刚更新过卡片/面板系统后，
   本页确实可能拿不到快照 → `appearance` undefined、`label` 空 → 直接落到 `prefers-color-scheme`
   → 系统主题是浅色时判成浅色 → 面板按浅色渲染（白底）。与现场现象完全一致。

2. **就算判定对了，body class 也管不到白底块**：`panel.html` 里 `body { background: transparent }`，
   暗/亮只靠 `body.t-dark` 切 CSS 变量。但**面板 iframe 自身的画布底色**（UA 默认、根元素 `color-scheme` 决定）
   是白的，而 `color-scheme` 只看**根元素（html）**，`body` 上的 `t-dark` 对它无效。旧的修复路径
   （只切 body class）即使判定正确，也仍会留一块白。

## 2. 改动

### 2.1 `app/ui/assets/panel-status.js`：`syncTheme()` 改三级兜底（+ 幂等 + 订阅兜底）

**三级判定（可靠性从高到低）**

| 级 | 触发条件 | 依据 | 结果 |
|---|---|---|---|
| ① | 快照明确给出 `appearance`，或给出具体主题名 | `appearance === "dark"/"light"`；主题名走原有正则 `/dark\|midnight\|contrast\|深\|夜/i`（**保留原逻辑**） | 直接判定，不依赖 CSS；**判定后再后台补拉一次**主题 CSS（每主题一次、缓存）好上底色 |
| ② | 快照为空 / 只有 `inherit`·`auto` | 拉宿主主题 CSS，取 `--bg`（无则 `--bg-card`、`--sidebar-bg`），按 **luma > 0.5 即浅色** 判 | 判定 + 把面板底涂成该色值 |
| ③ | ②也拿不到（CSS 取不到 / 无可解析色值） | `window.matchMedia("(prefers-color-scheme: dark)")` | 跟系统偏好 |

**色值兜底具体怎么取到 `--bg`**：抄 `workspace.js` 的现成三件套（`parseThemeCssVars` / `cssColorToRgb` / 亮度算法同口径）。
CSS 地址按可靠性排序取候选（`themeCssUrlCandidates()`）：

1. `hana.theme.getSnapshot()?.cssUrl`；
2. 本页 URL 的 `hana-css` 参数（宿主注入）；
3. 由 `hana-theme` 参数拼 `/api/apps/theme.css?theme=<id>`；
4. 兜底 `/api/apps/theme.css`（不带参数 → 服务端默认主题）。

候选逐个尝试，取到 `--bg` 即止；取到后 `parseThemeCssVars` 解析出变量表，`cssColorToRgb` + 相对亮度
`(0.2126R + 0.7152G + 0.0722B)/255 > 0.5` → 浅色。`midnight-contrast --bg = #26343D` → luma ≈ 0.20 → 暗 ✓；
`warm-paper --bg = #F8F4ED` → luma ≈ 0.96 → 亮 ✓。

**为什么加色值兜底**：明暗的权威来源是主题**实际色值**。主题名正则覆盖不了全部主题名（宿主可加新主题），
系统偏好又与宿主主题无关——只有色值不会骗人。

**幂等（可重复调用，宿主推 / 订阅回调 / 4s 轮询都会调）**
- 色值按 URL 缓存（`panelThemeVars` / `panelThemeVarsUrl`），URL 不变不重复 `fetch`；
- 同一 URL 不并发重复拉（`panelThemeInflight`）；已知取不到 --bg 的 URL 进黑名单（`panelThemeVarsFailed`），不再反复重试；
- 结果没变不写 DOM、不打日志（`lastThemeDecision` 比对后才 `classList.toggle` / `console.debug`）；
- 一级判定不依赖 CSS；一级也会在后台补拉一次主题 CSS（供上底色），但同一主题只拉一次（缓存），重复调用不重拉。

**订阅兜底（最后保险）**：保留原 `hana.theme?.subscribe?.(...)`；另加**低频轮询 4s**，仅当当前判定不是一级
（即快照不可用）时才 `force` 重跑（重拉 CSS → 重判）；命中一级后轮询自动退化为空转检查，不再发请求。
再补两条触发：系统 `prefers-color-scheme` change（三级兜底时用）、`visibilitychange` 回到可见时重判。

**顺带治白底的强兜底（还在 2.1 内）**：`applyThemeDecision()` 里
- 把 `t-dark` **同时**切到 `document.documentElement` 与 `body`；
- 同步 `document.documentElement.style.colorScheme = dark ? "dark" : "light"`（解决根因第 2 层）；
- ②级拿到 `--bg` 后直接 `document.documentElement.style.background = --bg 色值`（面板底与宿主底色一致；取不到就保持 transparent，不硬涂）。

### 2.2 `app/ui/panel.html`：2 处 CSS 微调（**必须先改 CSS 才生效**，理由如下）

```css
:root { color-scheme: light; /* 明写：iframe 画布底色由根元素 color-scheme 决定 */ ... }
:root.t-dark { color-scheme: dark; }   /* 新增 */
body.t-dark { ... }                     /* 原有，保留 */
```

**理由**：白底块的直接来源就是**面板 iframe 自身画布**（`body` 已 `background: transparent`）。
这块底色由 UA 按**根元素** `color-scheme` 决定，`body.t-dark` 覆盖不到它。
因此（a）在 `:root` 明写 `color-scheme`，（b）新增 `:root.t-dark { color-scheme: dark }` 作为
「JS 内联样式未生效时的 CSS 侧兜底」。JS 侧的内联 `style.colorScheme` 优先级更高，两条路任一生效即可。

## 3. 自查方法（本次修对了没有）

面板页（左侧状态栏）打开 DevTools console，看两样：

1. **判定依据哪一级 / 结果**：
   ```js
   __comfyPanelTheme
   // → { dark: true, tier: 2, detail: "/api/apps/theme.css?theme=midnight-contrast --bg=#26343D",
   //     at: "2026-10-11T...", cssUrl: "...", snapshot: {...} }
   ```
   期望：`dark: true`；`tier` 为 1（快照可用）或 2（走了色值兜底），**不应为 3**（3 = 回落系统偏好，
   说明快照和色值都没拿到）。次级的 `detail` 直接给出判定用的 `--bg` 值，便于核对。
   判定发生变化时会打一行 `[comfyui-hana] 面板主题判定：dark=… ← 第 N 级（…）`。

2. **DOM 侧生效证据**：
   ```js
   document.documentElement.className      // 期望含 "t-dark"
   document.documentElement.style.colorScheme   // 期望 "dark"
   getComputedStyle(document.documentElement).backgroundColor  // 期望 = 宿主 --bg（#26343D）
   getComputedStyle(document.body).color        // 期望 = 深色文本变量色（#d8d8d8）
   ```
   手动重判：`__comfyPanelThemeRefresh()`（会 `force` 重拉主题 CSS 并返回最新 `__comfyPanelTheme`）。

3. **幂等自证**：连续调两次 `__comfyPanelThemeRefresh()`，Network 面板里对 `theme.css` 的请求次数不翻倍；
   判定结果不变时不产生新的 `console.debug`。
