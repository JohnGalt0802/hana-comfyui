## 3. 设计

### 3.1 核心链路（画布在线）——新增 `canvas.queue`

**等价点 Queue 的精确实现**（v1.53.6 实证）：

```
点 Queue = 命令 Comfy.QueuePrompt → app.queuePrompt(0, batchCount, {intent})
  → 内部: p = await graphToPrompt(); api.queuePrompt(number, p, {...})
  → POST /prompt（body: {client_id, prompt: output, extra_data: {..., extra_pnginfo: {workflow}}}）
```

**桥内最小等效调用：`await app.queuePrompt(0)`**（跑当前画布；不传参则 batch 默认 1）。

**op 定义**：
- 名称：`canvas.queue`（写类，需授权）
- 入参：无（跑当前画布）；可选 `front: boolean`（插队首，对应 QueuePromptFront）
- 出参：`{queued: true, promptId?, number?}`
  - **注**：`app.queuePrompt` 是否向上返回 prompt_id 未确证（api.queuePrompt 层返回 `{prompt_id, number, node_errors}`；app 层包装可能有丢失）。若拿不到，从 ws `execution_start`/`status` 事件或 `/queue` 反查补记。**实现时必须先验这一点**。
- **必须快返**（Python 桥回传超时 6s，`:61`）：queue 只提交不等执行；执行进度由前端原生 UI 呈现，不经过 op 返回值。

**为什么用前端 queue 而非后端 /prompt**："在画布执行"买到的是**状态归属**——队列可见、节点高亮、进度条、中断按钮都是前端原生的；agent 与人在同一个驾驶舱里。

### 3.2 降级链（画布离线）——D2，二期

- 画布离线（桥不可达）时，agent 生图走既有后端路径（`/_relay/submit-file` 或 proxyHttp → /prompt）；
- **标记"待同步"**：app 侧记录（建议 `app-data/pending-canvas.json`：`{createdAt, workflowFile, promptId}`）；
- 画布恢复（shell alive + bridge reachable）后：自动 `loadWorkflowFile` 把该次工作流补进画布 → 清标记；
- 人回来时现场完整：图已产出，工作流在画布上可续作。

### 3.3 默认翻转（agent 生图 canvas 优先）

- `submit` 工具新增参数 `mode: "auto" | "canvas" | "backend"`，**默认 auto**；
- auto 判定：画布在线（shell alive **且** 扩展桥可达）→ canvas 路径（装载 + `canvas.queue`）；离线 → backend + 待同步标记（二期前先输出提示文本）；
- **尊重在跑任务**：若画布当前有执行中任务（`exec.running` 非空），**不抢占画布**——报错提示或等待（细则实现时定）。

### 3.4 装载策略（John 拍板 2026-09-29：复制画布）

agent 生图任务**不直接在用户当前画布上进行**，而是**以当前画布为基础复制一份新画布**，在新副本上装载 / 修改 / 执行：
- 语义：**复制而非覆写**——用户当前画布保持原样（含未保存的改动）；
- 副本承载：agent 的工作流、参数调整、执行与结果；
- 用户当前画布有执行中任务时：**不抢占**（报错提示或等待）；
- 实现：优先看前端有无原生 duplicate 能力，否则利用多页机制（`canvas.pages`）新建页并重建工作流；具体方式实现期定；
- **红线**：不静默覆写用户当前画布；仅当用户明确说「就在当前画布跑」才用当前页。

## 5. 风险与边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| 前端版本差异 | 上述 API 基于 v1.53.6 取证；老版本 `queuePrompt` 签名不同 | 版本假设写入 op 注释；调用处做存在性/签名兜底 |
| 6s 回传超时 | queue 若阻塞超时 | 只提交不等执行；实现后实测耗时 |
| 两腿互斥 | 代理模式下扩展桥加载不了，执行类不可用 | 降级后端（D2）+ 诚实报错 |
| 抢占画布 | auto 模式下 agent 改动用户画布 | 3.4 红线：不静默覆盖；在跑任务不抢占 |
| prompt_id 缺失 | app.queuePrompt 返回值未确证 | 实现时先验；缺失则 ws 反查 |

## 6. 验证计划（一期验收）

1. **单点验证**：`canvas.queue` 提交当前画布 → /queue 出现该任务 → 执行 → 出图；确认前端队列 UI 有反应、节点高亮；
2. **快返验证**：op 返回耗时 < 6s（应 < 1s）；
3. **等效性**：手动点 Queue 与 op 提交，前端表现一致（队列可见、进度原生）；
4. **auto 分流**：画布在线走 canvas；模拟离线走 backend；在跑任务时不抢占；
5. **回归**：既有 submit 路径（backend 模式显式指定时）不回归；感知/修改两段不受影响；
6. **证据留档**：`_temp/` + 验收记录（沿用既有格式）。
