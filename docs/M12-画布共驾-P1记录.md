## 4. 实现中踩到并修掉的四个坑

### 4.1 `ArrayBuffer.isView()` 对响应式 Proxy 失效（最隐蔽的一个）

现象：`node.pos` 的 `constructor.name` 是 `Float64Array`、`String(pos)` 是 `"1279.99,319.99"`，
但 **`ArrayBuffer.isView(pos)` 返回 `false`**，导致按「数组 / view」判断的取值逻辑全部走到 null。

原因：新版前端把节点包在响应式 Proxy 里，而 `isView` 检查的是内部槽，Proxy 不转发。
`Array.isArray` 同理由此不可靠。

修法：**纯鸭子类型** —— 能取到两个 `number` 就当坐标，不做任何类型内省。

### 4.2 `input.link` 已被弃用

前端 console 会打 `input.link is deprecated. Read connectivity via node.isInputConnected(slot)`。
原先逐节点读 `inputs[].link` 收集连线。

修法：**直接遍历 `graph.links`**（Map），既避开弃用警告，也更直接。

### 4.3 「缺 NODE_CLASS_MAPPINGS」→ 启动日志噪音

ComfyUI 的 custom node 加载器要求模块提供 `NODE_CLASS_MAPPINGS` 或 `comfy_entrypoint`，
否则打一条 warning 并在 Import times 里标 `(IMPORT FAILED)`。功能不受影响
（`WEB_DIRECTORY` 的注册**先于**该检查，见 `nodes.py`），但日志脏。

修法：给 `__init__.py` 加两个**空映射**（`NODE_CLASS_MAPPINGS = {}` / `NODE_DISPLAY_NAME_MAPPINGS = {}`）。
日志恢复干净，语义也准确：本包确实不注册任何节点。

### 4.4 定向 sid 会静默丢消息 → 改为广播

`server.py` 实测：`send_json(event, data, sid)` 在 `sid is None` 时**广播给所有连接**，
否则只在 `sid in self.sockets` 时单发。而 ComfyUI 重启 / 页面刷新后前端不会重跑 `setup()`，
我们记录的 sid 可能已失效 → 消息被静默丢弃，表现成超时。

修法：`/call` 一律**广播**（sid=None）。多标签都会响应，路由只取最先回来的那份
（`_pending.pop` 幂等），不影响正确性。

## 6.5 P2 · 变更感知（同日完成）

**目标**：让 agent 知道“人在画布上改了什么”。

**不用事件驱动**：探查发现新版 `@comfyorg/litegraph` 没留可用的变更事件（`graph` 上只有
`onTrigger` / `onConfigure` / `onConnectionChange`，`LGraph` 原型没有任何 `on*`），
所以改用**轮询签名比对**：500ms 算一次轻量签名，变了就记一条并递增 revision。

- 签名**不含节点位置**：拖动节点不该算“画布变化”，否则噪声太大。
- 签名按**节点粒度**存 hash，变更时能算出是哪个节点 `added` / `removed` / `changed`。

**新增只读 op**：

| op | 返回 |
|---|---|
| `canvas.revision` | `{revision, changeCount, nodes, links, lastChangeAt}` —— 只问“变没变”，轻量 |
| `canvas.events` | `{revision, total, changes:[…]}`，支持 `args.since` 做增量查询 |

**实测**：

```
改前：revision=1（载入工作流那一条，10 个节点 kind:"added"）
把 KSampler.steps 8→9：
改后：revision=2
      changed: [{"id":"70","type":"KSampler","kind":"changed"}]
since=1 增量查询：只返回 rev2 那条
```

**中继与 App 的转发层无需改动**（op 是透传的），只加了扩展侧两个 op 与 App 的枚举 / 格式化。

**顺带排掉的一个开发期坑**：宿主内置浏览器里余留了多个 ComfyUI 页面实例，`/call` 广播时
**旧页面会抢先响应**，于是读到过期状态（表现成“改了却没记录”）。
→ 处理：用浏览器 `stop` 清干净；另给扩展加了只读诊断出口 `window.__hanaBridge.state()`
（含 version / revision / ops），便于确认“当前页面到底加载了哪一版脚本”。

## 6.6 P3 · 写入（改画布）

**已实现（最小写入集）**：

| op | 作用 |
|---|---|
| `canvas.setWidget` | 改某节点的某个参数（`{nodeId, name, value}`），返回 before/after |
| `canvas.undo` | 撤销 agent 的上一步写入（最多回退 20 步） |

**前置授权**：App 侧加「允许 agent 修改画布」开关（`app-data/comfyui-hana/allow-write.json`，**默认关**）。
未授权时写入 op 直接报错并提示去设置页打开——agent 改的是人眼前的画布，不给默认放行。

**实测**：

```
初始 steps = 8
setWidget(steps=6) → before:"8" after:"6"
setWidget(steps=4) → before:"6" after:"4"
undo → restored:"6"（stackLeft 1）
undo → restored:"8"（stackLeft 0）
```

### 关键发现：新版前端的撤销机制不吃外部改动

| 探查项 | 结果 |
|---|---|
| `app.canvas.undo` | **undefined**（`LGraphCanvas.undo()` 已被移除，原型上也没有） |
| `app.graph.undo` | undefined |
| `graph.beforeChange/afterChange` | 存在，但**只是生命周期钩子**（触发 `onBeforeChange`/`onAfterChange`） |
| `graph.onBeforeChange` / `canvas.onBeforeChange` | **都不存在** → 钩子没接任何记账 |
| 官方撤销入口 | 命令 `Comfy.Undo` → `ChangeTracker.undo()`（`Comfy.Redo` 同理） |

结论：**外部直接改 `widget.value` 不在前端 undo 记账范围内**，`Comfy.Undo` 对它无效。

**因此实现成两级**：`canvas.undo` 先试官方 `Comfy.Undo`；若图签名没变，就按 **agent 自己记的 before 值栈**
回写，并在返回值里如实标 `via:"agent-rewind"` + `note:"官方撤销对该改动未生效，已按记录回写"`。
不假装官方撤销生效。

**对人的影响（重要）**：人的 Ctrl+Z **不会**撤回 agent 的改动。agent 的改动要用
`comfyui(action="canvas", op="undo")` 撤。这偏离了方案初稿「人的 Ctrl+Z 可撤回」的设想——
是前端架构现实，不是实现取舍。

## 6.7 状态预热（口径修正，同日完成）

**John 的口径**（2026-09-26）：

> 感知不至于如此实时，只要我找你对话时能拿到画布状态就行；不要频繁读内存，没有意义；
> 这件事可以提前做，而不是每次现抓。……我不一定去 hana-comfyui 看画布，很可能就在宿主聊天页跟你对话。

**改动**：把「感知」从「agent 现抓」改成「**前端在变化后主动推、服务端缓存**」。

| 层 | 改动 |
|---|---|
| 前端 | 检测间隔 `500ms → 1500ms`；变化后 **debounce 1.5s** 推 `POST /hana_bridge/state`；页面加载推一次基线 |
| Bridge | 内存缓存 `_state`；`POST /hana_bridge/state`（前端推）+ `canvas.state` op 直读缓存（不走前端、不广播）；`ping` 附 `stateAgeSec` |
| 中继 / App | op 透传，无需改逻辑；App 的 `CANVAS_OPS` 加 `state` 并**设为默认 op** |

**实测**：

```
页面开着：    canvas.state → hasState=true ageSec=21.4 rev=1（10 节点/10 连线）
关掉页面后：  canvas.state → hasState=true ageSec=50.3（快照仍在 ✓）
              canvas.summary → timeout（现抓依赖页面，反证缓存价值）
改一个值后：  rev 1 → 2，且新快照里 steps=7（未现抓，只读缓存）
撤销后：      rev 3，steps 回 8
```

**收益**：ComfyUI 页面**没开着也能拿到上次状态**，正好覆盖「在宿主聊天页对话」的主场景。
代价：一份摘要常驻内存（几十 KB）+ 每次变化一次推送。

## 6.8 结构写入（P3 扩展，同日完成）

John 指定「加节点 / 删节点 / 连线」+「mute / bypass」为核心功能。方案见 `docs/画布结构写入-20260926.md`。

**新增 op（全部 `write: true`，受授权开关约束）**：

| op | 逆操作 |
|---|---|
| `canvas.addNode` `{type, pos?, title?}` | 移除该节点 |
| `canvas.removeNode` `{nodeId}` | 重建（序列化 + 恢复入线与出线） |
| `canvas.connect` `{fromNode, fromSlot, toNode, toSlot}` | 断开 |
| `canvas.disconnect` `{nodeId, slot}` | 重新连上 |
| `canvas.setNodeMode` `{nodeId, mode}` 0/2/4 | 写回旧 mode |

**设计改动：撤销从「记 before 值」升级为「记逆操作闭包」**

快照式撤销会把人在此期间的改动一起回滚，所以改成每种写 op 自带一个逆操作
（栈里存函数，运行时用）。既精确又支持连续撤销。

**实测**：

```
addNode KSampler        → #72，节点 10 → 11（返回 inputs/outputs/widgets）
connect #66.MODEL → #72.model → linkId 83
setNodeMode 2           → mute（原 0）
undo ×3                 → 撤 mute → 撤连线 → 撤节点，回到 10 节点
removeNode #62          → {incomingLinks:0, outgoingLinks:2}，9 节点 / 8 连线
undo                    → 10 节点 / 10 连线（节点 + 参数 + 位置 + 入出线全回来）
disconnect #67.clip     → 10/9；undo → 10/10
错误路径                → 未知类型 / 不存在的槽（还列出可用槽名）/ 非法 mode 均明确报错
```

**修掉一个真 bug**：`removeNode` 的逆操作起初只记了**入线**，漏了**出线**——
删除节点时它的出线会一并消失，恢复后连线数对不上（实测 10 → 8 而不是 10）。
补上出线收集与重连后正确。详见踩坑记录 §10。
