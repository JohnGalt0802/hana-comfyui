# hui 使用问题汇总（2026-10-08）

> 汇总人：hanako（agent 视角）｜场景：用 hui（Hana-ComfyUI）跑「灵魂画手」垫图生图全流程
> 目标：把 agent 用 hui 干活中遇到的问题摆清楚——现象 / 推测根因 / 影响 / 建议，供产品侧改进

## A. 画布交互类

### A1. openWorkflow 用 name 路由超时，改 path 形式即成功
- **现象**：`openWorkflow(name="hui-edit4-narrative")` → `timeout · 前端 6s 内未回传：可能没有打开的 ComfyUI 页面`；彼时实际有 3 个页面在线。改用 `openWorkflow(path="workflows/hui-edit4-narrative.json")` → 一次成功（"已打开并装载，34 节点，落定校验通过"）。
- **推测根因**：name 路由"只发给正打开该工作流名的页面"，新工作流没有任何页面打开着 → 无接收者 → 静默超时；path 形式直接按文件路径加载，不依赖页面列表。
- **影响**：agent 第一次尝试失败，浪费一轮排查；且报错文案（"可能没有打开的页面"）与实际（有页面）矛盾，误导排查方向。
- **建议**：① name 路由在"无匹配页面"时返回明确错误而非超时；② 或名称未命中时自动回退到 path 查找（同名唯一文件时）；③ 报错文案附上"当前在线页面清单"。

### A2. openWorkflow 的 dirty 拦截缺少上下文
- **现象**：切换被拒：`当前图有未保存改动（Qwen21 t2i+edit 质量版 (AgentCopy) …）; 确认丢弃请传 force=true`。
- **评价**：拦截本身正确（保护用户数据）。但对 agent 而言缺两样：① 哪一页在挡路（多页面时页面名足够长/模糊）；② 该页改动来源（agent 自建副本 vs 用户手动改动）——不同来源 force 的决策完全不同。
- **建议**：拦截文案附「挡路页面名 + 改动时间 + 是否疑似 agent 工作页（AgentCopy 链）」，agent 可据此决定是否 force。

### A3. 无法指定"新开页装载"，只能占用当前活动页
- **现象**：agent 想做"把新工作流装到一页里干活"，现有 openWorkflow/loadWorkflowFile 都作用于**当前活动页**——会顶掉用户正看的画布，或反过来被用户页的 dirty 拦住。多页面场景下 agent 无法主动选择目标页。
- **影响**：agent 干活的页面与用户正在看的页面耦合，容易互相打扰。
- **建议**：openWorkflow 支持 `newPage:true`（新开一页装载，不动任何现有页）；或提供 `pageKey` 参数定向装载到指定页。

### A4. 写类 op 需"副驾驶开"，开副驾驶需授权总闸（两步操作）
- **现象**：装载完成后页副驾驶=关 → `queue` 会被写拦截；需先 `copilot enabled=true`（受「允许 Agent 开启画布副驾驶」总闸管辖）再 queue。
- **评价**：v2 设计如此，流程能走通；但 agent 每开一张新工作页都要记得"先开副驾驶再动手"，多一步容易忘。
- **建议**：可选优化——`openWorkflow` 装载成功后，在授权总闸开启的前提下"随装载自动开副驾驶"（或给一个 `autoCopilot:true` 参数）。

## B. 工作流/值传递类（重坑）

### B1. UI→API 转换丢原语节点值（backend 路径）
- **现象**：早期用 backend submit（UI 格式自动转换）时，含原语节点（PrimitiveStringMultiline / PrimitiveInt / PrimitiveBoolean）的图，值被回退成默认或旧值——曾把工作流里旧的"少女"提示词跑出来。走画布路径（openWorkflow + queue）后正常。
- **影响**：出图内容与预期不符（假成功），且难一眼发现。
- **建议**：中继侧 UI→API 转换后做"值一致性校验"（原语节点 widget 值 vs 转换结果 diff），不一致时报警或拒绝提交；或对原语节点走"连线优先+widget 回退"双保险。

### B2. LoadImageOutput 值回退（combo 受控下拉）
- **现象**：LoadImageOutput 的值（受控 dropdown）被硬写 JSON 后，前端把它回卷到"当前已选项"→ 出图带的是上一张旧图。绕法：用 LoadImage + 先 upload 到 input 目录。
- **影响**：出图内容错位（画的是旧参考图），排查成本高（现象隐蔽——图能出来，只是不对）。
- **建议**：桥 setWidget 对 combo 类型先刷新选项再写入、写后即时校验回读；或文档中把"参考图一律走 LoadImage+upload"列为推荐范式。

### B3. AgentCopy 副本名无限叠加
- **现象**：多次复制后页名变成 `Qwen21 t2i+edit 质量版 (AgentCopy) 20261008-1555 (AgentCopy) 20261008-1556 (AgentCopy) 20261008-1556 (AgentCopy) …`——每次在**当前名**基础上再拼后缀，越来越长。曾在提交时撞 `400 Invalid filename`（超长名）。
- **影响**：页面辨识困难；超长名导致提交失败（已有一次实证）。
- **建议**：复制时先剥离旧的 `(AgentCopy) …` 后缀再拼新后缀（始终保持一个）；或改用短哈希 `[A]20261008-1558`；提交前对文件名长度做截断保护。

## C. 执行/交付类

### C1. 画布流程依赖"用户先开着 hui 工作区"
- **现象**：画布类 op（读/写/queue）都要求 ComfyUI 前端页面在线；用户没开工作区时全部不可用。agent 无法自行打开 hui 工作区（属 UI 操作）。
- **评价**：本次因用户开着工作区所以能走通；但这意味着"用户不在场时 agent 不能走画布流程"。
- **建议**：① 给 agent 提供"打开 hui 工作区"的正式工具（打开 App 卡/窗口）；② 或对"画布工作台流程"（openWorkflow+queue）设计降级链（无页面时 fallback 后端 + 记待同步，已有 pending-canvas 机制可复用）。

### C2. agent 侧看不到执行进度
- **现象**：queue 快返 + next-step 回执体验好；但执行中 agent 无法得知"跑到哪了"（只能靠用户看画布或结果回执）。
- **建议**：canvas 增加只读 op `progress`（当前节点/百分比快照），agent 按需查询一次，不打扰用户。

### C3. 空页/未命名页容易迷惑（本次次级现象）
- **现象**：pages 列表出现「(未命名)」页（0.5s 前活跃、副驾驶关）——它其实是用户刚新开的空页；agent 一开始误判为"可能就是 openWorkflow 的目标页"。
- **建议**：pages 输出对空画布页标注 `empty:true`，方便 agent 过滤。

## D. 环境/其他

### D1. 中继 runtimeId 随重启变化
- **现象**：上轮 `8127ebec-…` → 本轮 `6b3bde22-…`（服务重启后新 runtime）。运行无影响，仅记录：涉及 runtimeId 的日志/排查需按当次会话取最新值。

### D2. 用户工作流页与 agent 工作页混在 pages 列表
- **现象**：用户自己的「Qwen21 t2i+edit 质量版」（亦挂未保存改动）与 agent 的一系列 AgentCopy 页并肩出现，agent 需人工辨别"哪些是我的、哪些不能碰"。
- **建议**：agent 创建的副本页统一加可识别前缀/标记（如 `[agent]` 或页级 tag），pages 输出中分组展示。
