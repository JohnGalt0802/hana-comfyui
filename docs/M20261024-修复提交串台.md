## 五、0.14.4 追加：同类残留（John 指示「同类残留修一下」）

上面第 5、6 项已在本版一并修掉。

### 1. 出图产物回填（`reportHistoryImages`）

- **原来**：`execution_success` 时才现取工作流名，距提交数秒到数分钟；而且重试 8 次、**每次重新现取**。
  切了画布会解析到另一张画布的目录，按 promptId 查不到 → 404，重试耗尽 → **丢缩略图**（不写错历史）。
- **现在**：提交时 `rememberCommitIdentity(promptId, identity)` 记账；回填时 `commitIdentityOf(promptId)` 取回；
  请求体用 `withWorkflowId(body, identity)`。表项 TTL 10 分钟，每次写入时顺带清理过期项。

### 2. 回跳后写 HEAD（`historyRollbackExecute`）

- **原来**：`await historyFetchSnapshot` + `await loadGraphData` 之后才取名字。
- **现在**：拿到 `activeWorkflowObj()` 后立刻 `captureWorkflowIdentity()`，head-set 用它。
  必须在换图之前 —— `loadGraphData` 会替换 `app.graph`（含 `graph.id`），之后 `currentWorkflowId()` 可能已指向快照里的旧身份。

### 2. 发现的两个潜在隐患（已修）

**① 判据③会误并（`history_key`）**

原实现：只要「恰一个正式 path 消失」就判为改名跟随。但多个工作流文件可共享同一 id（同源派生）。
若其中一个旧文件被删除，其他文件打开会被误判成「改名」→ 接管 primary 目录 → 两段不同历史并进同一目录。

**修法**：加护栏 `len(rec) <= 1` ——该 id 只登记过一条身份时才判改名跟随，否则直接 mint sideId。
取舍：宁可多拆一个目录，也不误并两段历史。

**② `.meta.json` 没有 path（无法事后核对归属）**

`_write_meta_file` 调用时未传 path，导致本次排查只能靠名字猜目录归属。

**修法**：`_create_node` 增 `path=None` 入参并透传到 `_write_meta_file`；`commit` / `save_commit` 两处调用带上 `path=path`。
不传 path 时不写该字段（不凭空造）。
