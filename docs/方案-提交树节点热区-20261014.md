# 方案 · 提交树节点扩大可点击热区（2026-10-14）

> **用户反馈**：提交树节点有很大面积是拖动的小手（grab），要确保节点区域可点击。

---

## 1. 现状（读码实测）

- `.node`：`width: var(--nw)`（紧凑视角 `colW=28` → `nw≈11.8px`）、`min-height: 22px`、`cursor: pointer`。
- `.tcanvas`：`cursor: grab`（拖动平移）。
- 每格 = `colW × laneH` = 28 × 36 = 1008px²；节点仅 ≈ 11.8×22 = 260px² → **≈74% 的格子面积是 grab**。
- 点节点（12px 宽）极易偏到空白 → 变成拖动。

## 2. 改法：节点叠加透明热区

给 `.node` 加 `::before` 伪元素作为**透明命中区**（不改视觉、不动节点本体）：

```css
#${HISTORY_TREE_ID} .node::before {
  content: "";
  position: absolute; left: 50%; top: 50%;
  width: var(--htr-hot-w, 100%); height: var(--htr-hot-h, 100%);
  transform: translate(-50%, -50%);
  border-radius: 6px;
  /* 无背景：纯命中区。cursor 继承 .node 的 pointer → 热区内是点击小手 */
}
```

- 热区**继承 `.node` 的 `cursor: pointer`**（`cursor` 是继承属性）→ 热区内都是点击小手，不再是 grab。
- 热区是 `.node` 的子部分 → `:hover` 命中它即 `:hover` 节点（现有 `.node:hover { filter: brightness(1.25) }` 自动生效，有视觉反馈）。
- 鼠标按下落在热区 → 事件冒泡到 `.tcanvas` 仍触发 drag 逻辑（`mousedown` 监听在 tcanvas 上），**位移 >3px 才算拖动**（`DRAG_SLOP`）→ 拖拽平移**不受影响**。

**热区尺寸**（JS 按 colW/laneH 算，保证不重叠）：
```
hotW = clamp(baseW + 12, 8, colW - 2)   // 横向：节点+12px，但封顶 colW-2（防相邻重叠）
hotH = clamp(laneH - 8, 16, laneH)       // 纵向：留 8px 行间拖动带
```
⚠️ **必须用 clamp（下限+上限都夹），不能用 `max(baseW+12, colW-2)`**——后者在合并节点（`baseW=baseW≈21.8`）时会算出 33.8 > colW-2=26，**热区盖到相邻列 → 点 A 选中 B**。实测发现，已修。
紧凑视角（colW=28, laneH=36, nw=11.8）：`hotW=clamp(23.8,8,26)=26, hotH=clamp(28,16,36)=28` → 占格子 26×28/(28×36) ≈ **72%**（原 26%）。
保留：格子横向 2px 缝 + 行间 8px 带仍为 grab（拖动提示不丢）。

桥 js → 部署 + **重载工作区页面**（免重启服务）。

## 5. 验收

1. 节点周围一大圈（≈热区范围）都是点击小手，不再一偏就是 grab。
2. 点热区任意处 → 选中节点（单击）/ 弹预览；双击 → 回跳确认框。
3. 在行间带 / 横向缝按住拖动 → 仍能平移（拖拽不回归）。
4. hover 热区 → 节点高亮（brightness 1.25）。
5. 相邻节点热区不重叠（不误选邻居）。

## 6. 成色与风险

- 根因**实测**（尺寸算得：节点 260px² / 格子 1008px²）；改法静态推导。
- 风险低：仅加命中区、不改视觉与事件逻辑；拖拽靠位移判定，仍可用。
- 回滚：`git checkout` 该 js。
