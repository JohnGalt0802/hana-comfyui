# 提示词增强接入 hui（hana-comfyui）— 方案

日期：2026-09-27
状态：**方案**（未实施）
上游：`~/.hanako/skills/qwen-image-2-1-prompter/`（小秘 09-26 安装）

---

## 1. 目标

让 hui 具备**把一句话扩写成 Qwen-Image-2.1 规范提示词**的能力，并把它接进工作流的使用路径：

- 用户给一句人话（"一只橘猫坐在窗台上"）
- 按 skill 的官方八步框架扩写成英文长段落 + 宽高比
- 结果直接进 Qwen-Image 的 `TextEncodeQwenImageEdit*` / `CLIPTextEncode` 节点

## 2. 实测（已验证，非推断）

### 2.1 本地 LLM 可用

```
进程：llama-kvmem-server.exe
端口：127.0.0.1:11438
模型：Qwen3.8-27B-GSQ-RCO-IQ3_XXS-mtp.gguf（status: loaded）
接口：OpenAI 兼容（/v1/models、/v1/chat/completions）
上下文：-c 204800
```

### 2.2 必须关思考

首次调用（`max_tokens=200`，未关思考）→ **content 为空**，200 token 全被思维链吃掉。
加 `chat_template_kwargs: {enable_thinking: false}` → 正常输出。

**结论：调用这个模型必须显式关思考，否则短输出全被推理占满。**

### 2.3 规则整份进 system prompt 才有效

| 做法 | 结果 |
|---|---|
| 一句简单 system prompt | 中文短句 + 出现"高清细节"（规则明令禁止的质量词） |
| **`t2i_rules.md` 全文（10563 字符 ≈ 2527 tokens）** | **完全合规**：英文、约 20 句、方位短语齐、独立光照句、整体收束句、无质量词 |

实测样本（输入"一只橘猫坐在窗台上"）：

```
耗时：21.5s   prompt=2527 tokens   completion=412 tokens
输出：{"rewritten_prompt": "The image is a vertical realistic photograph of an
orange tabby cat sitting on a windowsill, ... The overall composition feels
intimate and serene, ...", "wh_ratio": "2:3"}
```

**结论：规则文件就是现成的 system prompt，不需要重写。**

## 3. 接口设计

### 3.1 规则来源

优先级：

1. 配置项 `promptSkillDir` 指定的目录（默认 `~/.hanako/skills/qwen-image-2-1-prompter`）
2. App 内置副本 `hui/llm/qwen-t2i-rules.md`

内置副本的理由：skill 被卸载/改名时 hui 仍可用；且 App 应当自包含。

### 3.2 LLM 连接

**不预设任何端点**（用户 09-27 明确：不得借用小秘的 27B 服务）。全部交给用户配置：

| 键 | 默认 | 说明 |
|---|---|---|
| `promptLlmBaseUrl` | **空** | OpenAI 兼容 base（本地 / 云端 / 任一端点） |
| `promptLlmModel` | **空** | 空则取 `/v1/models` 第一个 |
| `promptLlmApiKey` | **空** | 本地服务通常不需要 |
| `promptLlmTimeoutMs` | 180000 | 提示词改写是长输出，需给足 |
| `promptLlmEnableThinking` | false | **必须默认为 false**（见 2.2） |

未配置时：工具动作直接返回“请先在设置里配置提示词 LLM 端点”，不静默回退到任何本机服务。

### 3.2.1 与 27B 的关系（实测数据，供用户选型参考）

| 模型 | 大小 | 状态 | 备注 |
|---|---|---|---|
| Qwen3.8-9B-Q6_K | 7.0GB | 未启动 | 做这种结构化改写够用，需自行起服务 |
| Qwen3.8-27B-GSQ-RCO | 9.7GB | 11438 | **小秘常驻，不得占用** |
| Qwen3.6-35B-A3B-MTP | 17.0GB | 未启动 | |
| Ornith-1.5-35B-A3B | 18.0GB | 未启动 | 带视觉（mmproj） |

27B 那一次的 21.5s / 2527 prompt tokens 只能当作**质量上限参考**，不是默认配置。

### 3.3 两个入口

**入口 A：工具动作（我主动调）**

```
comfyui action=enhance-prompt
  brief: "一只橘猫坐在窗台上"     # 必填
  mode: t2i | edit               # 默认 t2i（edit 走 edit_rules.md）
  ratio: "2:3"                   # 可选，不给则由模型决定
  applyTo: "<nodeId>"            # 可选：直接写进该节点的 text 参数
  workflow: "<name>"             # 可选：配合 applyTo 定向到某个页面
```

返回：`{rewritten_prompt, wh_ratio, applied?}`。
给了 `applyTo` 就顺手写进画布（复用已有的 `canvas.setNodeParam` 类写入通道 + 逆操作栈）。

**入口 B：提交前自动增强（可选开关）**

`submit` 时若开启 `autoEnhancePrompt`：

- 只对**文本输入较短**的 TextEncode 节点生效（长文本视为用户已写好，不动）
- 增强结果**写进工作流副本**，不改用户的原始工作流文件
- 结果里回显"已增强 N 条提示词"，让用户知道发生了什么

**默认关**。理由：增强会**改写用户写的东西**，属于"替用户做决定"，必须显式开启。

### 3.4 为什么不做工作流内 LLM 节点

查过：本机 ComfyUI 自定义节点只有 `ComfyUI-MiniMax-H3-Turbo` 和 `hana_bridge`，核心 `comfy_extras` 里只有各种 `TextEncode*`（编码器，不是 LLM）。要"工作流图里带 LLM 节点"就得**再装一个自定义节点**，多一份依赖和不确定性。

而 hui 已经具备"提交时注入节点参数"的通道 —— 把增强放在**提交前**，对用户呈现的效果与"工作流自带 LLM"一样，却不引入新依赖。**取舍：走这条。**

（若以后确实要在画布上看见 LLM 节点，再单独评估装节点。）
