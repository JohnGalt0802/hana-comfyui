## 二、一个必须先定的架构岔路（落点）

**约束（实测）**：工作区壳页（`workspace.html`/`workspace.js`）与内层 iframe 是**跨源**的（iframe 直连 8188 后壳页摸不到 `contentWindow`）。提交数据在 8188 侧（桥的 `history-list`），回跳是画布写操作（要在 iframe 内的桥执行）。

| 方案 | 做法 | 代价 |
|---|---|---|
| **A 壳页底部栏** | 在 `workspace.html` 加底栏；数据走中继 `/_relay/bridge` 取、回跳走桥 op | 需扩中继 op / 新数据通路；壳页与 iframe 状态同步复杂 |
| **B 桥内底部条** | 桥在 iframe 内渲染贴底的可收纳横条（与现有弹层同机制） | 零跨源问题；落点在「画布底部」而非「窗口底部」 |

**主脑倾向 B**，理由：
1. 零跨源改动（复用桥已有的 fetch / 渲染 / 回跳 全链）
2. 与弹层机制同源（同一份 `history-list` 数据、同一回跳函数）
3. 「可收纳展开」在 iframe 内是纯 CSS/DOM 问题，简单

**差别**：B 的"底部"是**画布（ComfyUI 前端）内容的底部**，不是工作区窗口最底部（窗口底部有 titlebar 等壳页元素）。视觉上仍在"下方"，且随画布一起缩放。

> ⚠️ **需 John 拍板**：接受 B（画布底部）还是坚持 A（窗口底部，接受跨源复杂度）。

## 三、树的数据模型（已就绪）

每条 entry（节点）已有：`seq / parent / kind / source / sig / delta / runs / images / blockNames`
- `parent === null` → 根
- `parent === N` → 挂在 #N 下
- 线性连跑时 `parent` = 前一节点 → 一条直链
- 回跳后改再提交 → `parent` = 回跳节点 → **分叉**

**树构建**（前端，`history-list` 返回后）：
```
nodes = entries（按 seq）
children = Map(parent → [子节点])   // parent=null 归根组
```

---

## 四、布局算法（拓扑分层）

- **深度**：`depth(n) = depth(parent)+1`；根 depth=0
- **层**：按 depth 分**行**（行 = 拓扑深度）
- **同层内**：按 seq（入队时间）从左到右
- **横向缩放**：整树宽度自适应容器，节点多时压缩间距（参考全局提交轴的 flex 刻度）
- **连线**：父→子画折线（同层横线 + 跨层竖线），分叉处呈"y"形

**每节点视觉**：
- 刻度式小柱：顶部叠色条（该提交触及的框数），色相按 `(source,kind)` 四色
- 选中高亮；悬停气泡（复用弹层的 `historyBarBubbleShow`）
- 点选 → 回跳（复用 `historyRollbackConfirmOpen` → `historyRollbackExecute`）

## 五、收纳/展开

- **默认收纳**：底部一条细横条，显示"提交树 · N 节点 · M 分支"+ 展开按钮
- **展开**：向上滑出面板，显示完整树
- **收纳状态**：per-page localStorage（沿用 copilot/history HEAD 的键惯例）
- 位置：**贴画布底部**，z-index 低于弹层（弹层 10001），高于画布
