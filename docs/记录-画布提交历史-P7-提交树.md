## 二、布局 / 连线做法

**布局**（骨架已有，本批接线）：
- depth 单遍计算（entries 按 seq 升序 → parent 恒先入表）；孤儿（parent 指向不存在 seq）兜底 depth=0。
- 行 = depth，同层按 seq 从左到右；行内 cell `flex:1 1 0; min-width:10px` 等分压缩，节点多不溢出。
- 刻度柱 `--htr-c` 四色口径复用 `historyTickColor(source)`；`data-kind="save"` 空心环；legacy（blockNames 为 null）淡化；HEAD 金点 `::after`。

**连线**（`historyTreeDrawEdges`）：
1. `historyTreeRenderTree` 返回 `nodeEls: Map<seq, tickEl>`。
2. 渲染清空 `tree.textContent` 后新挂 `<svg class="htr-edges">`（CSS：`position:absolute; inset:0; pointer-events:none; stroke:rgba(255,255,255,.35); stroke-width:1.5; fill:none`，样式骨架已写好）。
3. `requestAnimationFrame` 等一帧布局稳定 → 遍历 entries，`parent` 有效且两侧 tick 都在 `nodeEls` → 用 `getBoundingClientRect` 相对 tree 求坐标：父刻度**底边中点** → 子刻度**顶边中点**。
4. 折线：同 x（|dx|<0.5）直连竖线；异 x → `父底 → 下行 midY（y1+min(10, dy/2)）→ 横移 → 落到子顶`，全部 path 合并成一个 `d`。分叉自然呈 "y" 形（一个 parent 多个 child 各画一条）。
5. 收起（display:none）时 rect 为 0 → 跳过不画；下次展开 refresh 会画。resize 用缓存 entries 重渲染重画，不 refetch。

## 四、未做 / 存疑项

1. **分支计数口径**（`historyTreeUpdateCounts`，上一 worker 已写）：M = 「被 ≥2 个节点指向的 parent 个数」，即分叉点数而非支线数。规格未明确定义 M，沿用了骨架口径，未改。
2. **弹层选中态同步**：树内点选只清树内 `.htr-tick-sel`，不清弹层轴的选中高亮（反之亦然）。两者共享 `historyBarSelection`，回跳执行不受影响；视觉选中态各自独立——规格未要求联动。
3. **不 refetch 时机**：收纳条在收起态下不轮询，计数只在 commit 成功 / 回跳成功 / 展开时更新。外部（如另一页）产生提交不实时反映——规格未要求轮询。
4. **未真机验证**：约束「不部署、不重启、不跑真机」，只做静态语法检查。规格 §七验收项（线性直链 / 分叉 y 形 / 点选回跳 / 收纳持久化 / 横向自适应）待真机验。
5. **`historyTreeOpen` 内存镜像**：切换时同步维护，但当前刷新路径实际读的是容器 `classList.contains("htr-open")`（单一事实源），`historyTreeOpen` 仅作镜像保留（上一 worker 声明的状态变量，未删）。
