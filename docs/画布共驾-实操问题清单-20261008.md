# 画布共驾 · 实操问题清单（2026-10-08）

> 来源：一次完整的手动共驾生图实操（手绘草稿 → 画布装载 → 配置 → 执行 → 产物）。
> 场景：用户开副驾驶共编，agent 在画布完成「Qwen21 t2i+edit 质量版」图生图全流程。
> 结论：主链路（装载 / 改参 / 体检 / 执行 / 取产物）全通；以下为体验与一致性缺口，按严重度排列。

## P1 · openWorkflow 半成功（改名不装载，无错误提示）

- 现象：`canvas op=openWorkflow` 返回 `opened:true`、`activeAfter` 显示已切换；但画布**内容未装载**（仍为原工作流），且页面被置为「有未保存改动」。
- 影响：调用方误以为切换完成；留下「页面名 ≠ 画布内容」的脏态，并卡住后续 loadWorkflowFile。
- 建议：openWorkflow 要么采用完整装载语义（等同 loadWorkflowFile），要么失败时明确报错；不应留下半状态。

## P2 · save 不清 dirty → 装载被拦只能 force

- 现象：先 save 另存到新文件名成功；页面仍标「有未保存改动」，随后 loadWorkflowFile 返回 `blocked:"dirty"`，须 `force:true` 强切。
- 影响：无法用「另存」手段安全腾出页面；force 的丢弃风险需调用方自行盘算。
- 建议：① 提供「另存并切换」语义（save 同时把页面引用切到新文件、dirty 归零）；② 或为「内容已另存」的场景提供免 force 的装载通道。

## P3 · copilot 状态在工具面不可读

- 现象：`canvas` 工具输出（state / summary / pages 等）均不显示 copilot 字段；该字段实际存在于桥 state 缓存（服务端 payload），本次靠直接 POST `/api/hana_bridge/call` 才读到。
- 影响：agent「感知副驾驶开关」没有正规通道；手动共驾路径下（非 submit）没有行为依据。
- 建议：`canvas op=state` 输出抬头补一行「副驾驶：开/关（pageKey=…）」；或新增轻量读 op。

## P4 · probe 视角歧义（壳页腿 / 扩展腿）

- 现象：页面在线时 probe 仍显示 `hasComfyAPI:false / hasGraph:false`（壳页跨源视角），且无字段说明扩展腿是否可达；容易被读成「桥坏」。
- 建议：probe 返回补「两条腿各自可达性 + 耗时」，并标注角色。

## P5 · 工作区冷启动 / 断连自愈缺失

- 现象：工作区 iframe 停在 chrome-error 页（旧加载失败），面板显示「已请求启动…等待就绪 50 秒」+ fetch failed，而**服务实际在跑**；无自动恢复，本次靠 frameReload / 用户重启恢复。
- 影响：「假死状态」误导双方（面板提示「启动服务」可能诱发重复启动）。
- 建议：① iframe 加载失败自动重载一次（或提供显式「重载工作区」按钮）；② 面板状态判定与页面会话解耦，区分「中继不可达 / 服务未跑 / 就绪」三态。

## P6 · events「修改」事件噪音与归因

- 现象：连续 13 个节点集中「修改」记录（疑似主题重载 / 页面重连引发的系统级重配置），与真实编辑混在一起。
- 建议：事件区分来源（user / agent / system），system 重配置不计入 events（或单独标记）。

## P7 · check 误报（SaveImage）

- 现象：`OUTPUT_UNWIRED「输出未接：filename_prefix」`；实际 images 输入已连、filename_prefix 是 widget。属误报。
- 建议：Save* 检查器改看 images 输入侧。

## P8 · canvas.queue 无回执 / 无任务卡（增强项）

- 现象：画布执行快返只有 promptId / 队列号；进度与结果需手动 query，无 submit 那样的任务卡与完成回执。
- 建议（可选）：canvas.queue 也发轻量任务卡（复用 submit 任务桥），或提供完成事件订阅。
