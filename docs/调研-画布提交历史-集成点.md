# 调研：画布提交历史 集成点

> 结论先行（推荐集成方案）
> 落在**三层**：①快照库＝**app 侧**新文件存储（每次运行落一份 graph JSON，复用中继 `/_relay/fs/write` 原子写，类 handoff）；②回滚动作＝**桥侧**新增一个写 op `canvas.restoreSnapshot`（内存 JSON 直接 `loadGraphData` 进当前页，复用 `loadWorkflowFile` 已验路径），app 侧 `CANVAS_OPS` 登记 + 工具 schema；③画布历史工具栏（点块弹层）＝**桥前端扩展** DOM 注入（同 `copilotUiEnsure`，需节点命中测试）。回滚争取纳入 `COPILOT_WRITE_EXEMPT`（理由见下），否则退路＝duplicate 新页后装载（免触发 copilot_off）。

## 1. UI 表面清单（代码确证）
- 页面（`ui/`，index.js 经原生窗/卡片路由托管）：`workspace.html`（工作区壳页＋iframe 装 ComfyUI 官方前端，index.js:3864）、`task.html`（submit/queue 回执卡，index.js:1015）、`envcheck.html`（环境检查卡，index.js:1031）、`panel.html`（左侧状态面板）、`settings.html`（授权开关）。
- 画布上的叠加 UI：`copilotUiEnsure()`（桥 hana-bridge-09205624.js:397）注入到 `app.menu.element`→画布顶栏 `legacy-topbar-container`；锁膜 `filmApply` 注入 `#graph-canvas-container`。**叠加 UI 归桥前端扩展 `hana_bridge` 管，不由 app 侧**。`workspace.js` 只是壳页（主题跟随/帧健康/凭据），**不碰画布内叠加层**。
- 关系：app 层只发桥 op；桥扩展在前端执行并自管 DOM。`copilotUiEnsure` 是桥内的 UI 自举函数，与 `copilot` op 双写方并列（copilot.md）。

## 2. 桥 op 表结构 + 新增改动面（代码确证）
- 注册表：`CANVAS_OPS`（index.js:2040-2080），每项 `{drive:"canvas.xxx", desc, write?}`；`drive` 即桥侧 `OPS` 键（hana-bridge-09205624.js:1169）。写类另入 `WRITE_OPS` 集合（:2160），豁免入 `COPILOT_WRITE_EXEMPT`（:2178）。
- 新增一个 op 的完整改动面：
  1. 桥侧 `bridge/js/hana-bridge-*.js`：`OPS["canvas.restoreSnapshot"]` 实现 + 加入 `WRITE_OPS`；视情况加 `COPILOT_WRITE_EXEMPT`。
  2. app 侧 `index.js`：`CANVAS_OPS` 加条目（带 `drive`/`desc`/`write:true`）+ `bridgeArgs` 透传清单（约:2990 的循环）+ 特殊 settle 逻辑（如落定校验）。
  3. 工具 schema：canvas `op` 的 `enum`（约:4783）和 `description` 同步（manifest 经 `tools.expose-to-model` 透出，manifest.json:26）。
  4. 文档：`canvas.md` / `copilot.md` 补 op 与豁免理由。
- 注意：桥扩展文件有多个带时间戳副本（09205624 为当前活动），改需同步当前活动文件。

## 3. 现有 op 能否担「回滚到快照」（代码确证）
- `loadWorkflowFile`（:1338）：`app.loadGraphData(graph,true,true,aw)` 装进**当前页**，但**读自文件**（`/api/userdata/<file>`），无内存 JSON 入口；带 dirty 保护。→ 能装当前页，但**必须经文件**。
- `openWorkflow`（:1434）：按 name/path 从已存列表 `loadGraphData` 进当前页；同样读文件/列表。→ 同上，且要求已存。
- `duplicate`（:1604）：`loadGraphData(state,true,true,wf)` 开**新临时页**，原布零改动（copilot.md 实测）。→ 适合「fork 出历史页」，不能回滚当前页。
- `patch`（:735）：意图级多编辑，原子回滚；`PATCH_FORBIDDEN` 已禁 `loadWorkflowFile/openWorkflow/organize`。→ 需算全图 diff 成 edits 序列，**无「整图替换」原语**，脆弱。
- `undo`（:2067）：仅撤 agent 上一步。→ 非时间点快照恢复。
- `visual`（:2074）：仅锁/高亮标记。→ 不涉及结构。
- **结论（确证）**：**没有**「不经文件、直接把内存 JSON 装载当前画布」的 op。入口＝新增 `canvas.restoreSnapshot`，复用 `loadWorkflowFile` 的 `loadGraphData(graph,true,true,aw)`（去掉 fetch，graph 直接传参）；或退路＝先把快照写临时文件再 `loadWorkflowFile`。

## 4. v2 约束影响（代码确证）
- 硬约束：写类 op 在「当前活动页副驾驶未开」时拒，app 层 `if (spec.write)` 闸门（index.js:2975，`copilot` 走总闸特判）+ 桥层 `copilotWriteBlocked`（:2201）/ `COPILOT_WRITE_EXEMPT`（:2178）= `{openWorkflow, duplicate, save, copilot}`。
- 豁免理由（桥注释:2180）：`openWorkflow`=「打开」、`duplicate`=「复制」＝无副驾驶画布仅允两类动作；`save`=副本流程第2步（落盘先于开副驾驶，不注入新变更）；`copilot`=自身开关（否则鸡生蛋）。
- 回滚能否争取豁免：**可争取**。理由＝回滚是「用户点历史节点」这个显式指令触发的「打开那一刻的状态」，语义贴近 `openWorkflow` 的「打开」豁免（用户主动、非 agent 自发改写）；且快照由本功能自存、内容确定、可 `force` 覆盖 dirty。但注意它**改写当前页内容**（与 open 切页不同），最稳设计＝退路：`duplicate` 副本 → `loadWorkflowFile` 装快照（两豁免 op 拼出回滚，零 copilot_off 冲突）。
