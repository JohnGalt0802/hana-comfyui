## 一、现状（实测）

- live 画布**无分组能力**：`addGroup/setGroup/removeGroup` 仅存在于 `source="file"` 的 patch 通道（`app/lib/canvas-edit.mjs`），活画布无对应 op。
- 目标画布上差分放大支路节点 = **#29–#41**（13 个，见 `docs/施工-差分放大支路-实做记录-20261013.md`）。

## 二、能力设计：桥新增三个组 op（live）

对齐 file 版语义（`canvas-edit.mjs`），在活画布上实现：

| op | 入参 | 语义 |
|---|---|---|
| `canvas.addGroup` | `{title, nodeIds?, bounds?, color?}` | 新建分组；`nodeIds` 给了则自动算 bounds（含 PAD=20）；`bounds=[x,y,w,h]` 显式优先 |
| `canvas.setGroup` | `{index\|title, title?, nodeIds?, bounds?}` | 改组的标题 / 归属节点 / bounds |
| `canvas.removeGroup` | `{index\|title}` | 删除组（**不移除节点**） |

**前端原语**（已探明）：
- `new LGraphGroup(title, id?)`（`settingStore-*.js` offset≈290672）；`graph.add(group)` 挂入。
- 矩形：`g.setBounds(x,y,w,h)` / `g._bounding`（运行时）/ `g.bounding`（序列化）；读取顺序参考桥内 `historyGroupRect` 的口径（boundingRect → _bounding → _pos+_size → bounding）。
- 归属：`graph.groups` 数组；`graphBlocks()` 归组口径是"节点 pos 落在 group.bounding 内"——故 bounds 必须真的框住节点。

**可回退**：每个 op 用 `withChange` + `pushUndo`（addGroup 的逆=移除该组；removeGroup 的逆=重建同 bounds 的组）。

**写门**：三者均为**结构写入**（改画布），进 `WRITE_OPS`，**不**进 `COPILOT_WRITE_EXEMPT`（需副驾驶）。

**app 侧**：`CANVAS_OPS` 登记三 op（`write:true`）+ 工具面 enum/description 补。
