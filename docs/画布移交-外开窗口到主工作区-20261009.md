# 画布移交（外开窗口 → 主工作区）· 方案（2026-10-09）

## 背景与动机
- agent 无法程序化打开「主工作区卡」（宿主主权区）；干画布活时自开**宿主原生窗**（`window op=open`，装 `/workspace.html`，2026-10-08 已实现）。
- 壳页桥为**单桶**：窗口壳页与主工作区壳页同刻仅一（并存会互抢画布 op）。
- 需求（用户提出）：外开窗口里加按钮「放入 hui 画布」；当 hui（主工作区）启动时，能把该实例（的画布）直接塞进 hui 画布。

## ⚠ 修订 1（2026-10-09 晚，John 定 · 首轮真机验收后）

**语义修正（取代下文「设计」节中与装载/覆盖相关的条款）**：

1. 「放入 hui 画布」= 把窗里的画布**加入** hui——以**新开一张画布页**的形式进入，**不覆盖**、不触碰 hui 当前画布（其内容与未保存状态均**无关**）；无需用户处理任何东西。本项即《hui-使用问题汇总-20261008》A3「新开页装载」诉求的落点。
2. 开窗定位（口径钉死）：开窗是**权宜之计**——解决"agent 无法自行起 hui 画布前端"；hui 前端在线时 agent **直接用 hui 干活、不开窗**。
3. 接管动作**不得使用** `loadWorkflowFile` 直作用于当前页（其语义=装载到当前画布=覆盖）。改为「新开页装载」（newPage 形态：参考 A3 建议给 openWorkflow/loadWorkflowFile 加 `newPage:true`，或复用 duplicate 的新页机制）。
4. dirty 保护与本链无关（不覆盖即无冲突）；原「桥侧 dirty 拒绝」作为本链的门槛作废（桥侧保护保留给其他装载场景）。

**真机问题定位（2026-10-09 19:29，首轮移交失败）**：

| 环节 | 结论（成色：机制分析 + 时间对拍；take 无日志，链条为高可信推断） |
|---|---|
| 按钮 write（取快照→落盘→写标记） | ✅ 正常（19:29:47 完成；快照 10 节点 / 10248 B，落 `_handoff-1791545387723.json`） |
| 接管 take（检查标记→装载） | ❌ 未触发——接管检查只在**卡页加载瞬间**执行一次且「无标记即撤」；本次卡页 19:29:37 加载、按钮 19:29:47——检查先于标记 10s，错过即永不重查；标记滞留至今 |
| 修复要求 | 接管触发覆盖**任意操作次序**：加载后短窗轮询（约 2~3s 间隔、~60s）+ 页面可见性/焦点变化时重查；保证"按按钮后数秒内（或 hui 下次活跃时）自动接住" |

**修订 1 生效后首验（2026-10-09 19:58，滞留场景）**：reload 触发卡页自动重载 → 短窗轮询发现 19:29 滞留标记 → 自动接住。宿主日志：`19:58:40 画布移交：已接住 workflows/_handoff-1791545387723.json（新开页 workflows/_handoff-1791545387723 (2).json，via bridge）`——「标记滞留 → 下次活跃自动接」实测通过。

**真机第二场（A 场景：卡先开、后按钮，2026-10-09 20:0x）**：按钮 write ✓（20:01:59，10 节点、取源正确）；自动接住 ✗ 未发生——触发缝：卡页 60s 短窗（19:58 重载后）已于 19:59 过期，按钮晚于窗口 2 分半；「焦点/可见性重查」在嵌套环境未送达（切窗/发消息均未触发）。手动 reload 补位：`20:05:03 已接住 _handoff-1791547319900.json（新开页 … (2).json，via bridge）`。**结论：接住不能赌触发时机，需常驻哨兵（修订 1.1）。**

**真机第三场（A 场景重演，2026-10-09 20:45-46）**：宿主重启恢复工具面后重演——按钮 20:45:57 → **哨兵巡检至 20:46:23 自动接住**（新开页 `_handoff-1791549957548.json`，via bridge；**零人工、首度全自动**）。链路验收通过；感知问题待补：等待期静默 24s（用户误报「没卵用」）；拟优化：巡检拍频 30s→10s + 「正在接住…」进行中提示 + 按钮文案预期管理。

**修订 1.2（方向，2026-10-09 晚 · 用户点题）**：拍频为兜底件；在线场景应「点击直发」——按钮写快照后**定向投递** `canvas.loadWorkflowNewPage` 给在线 hui 实例（多页面定向机制，2026-09-27 已验证），秒级开页、当场可见；巡检降级为低频离线兜底。**✅ 已实现并真机通过（2026-10-09 21:06：落盘→定向直发成功 335ms，sid=21a1cf5e…；用户当场见证）**；实现要点见踩坑记录 §35。

**修订后验收标准**：
- A（hui 开着、含未保存画布）：窗里按「放入」→ 数秒内 hui 中**新出现一张画布页**（内容 = 窗里快照）；当前画布原样（内容与 dirty 均不动）；顶栏提示。
- B（hui 未开）：按「放入」→ 窗谢幕；之后**任意一次**打开/加载 hui → 自动新开一张画布页。
- 无标记零打扰；同一标记只接一次；既有 canvas ops 与「复制工作台」五步回归无影响。

**修订 1.1（补丁，2026-10-09 晚 · 第二场真机后定）**：卡页接住巡检加「常驻哨兵」——短窗（2.5s×60s）结束后接续**低频巡检（30~45s 一次 peek，有标记即接）**；可见性/焦点加速保留。目标行为：**任意时刻按「放入」，≤45s 内自动接住、无人工**（按钮文案「将自动接住」与之对齐）。

## 设计：保存 → 让位 → 接管（v1 原文，部分条款以修订 1 为准）

**1) 窗口按钮「放入 hui 画布」**（仅窗口态显示，卡态不显示）
- 动作：取当前画布全量（UI JSON）→ 保存为工作流文件（`userdata/workflows/_handoff-<ts>.json`，中继写盘）→ 写移交标记（app-data `handoff.json`：`{file, ts, from:"window"}`）→ 提示「已放入；打开 Hana 里的工作区卡即可接住」→ **自动关闭本窗口**（让位，释放单桶）。

**2) 主工作区（卡）启动接管**
- 壳页 ready 后查询移交标记 → 有则调 `loadWorkflowFile` 加载该工作流 → 清除标记 → 顶栏提示「已接住来自独立窗口的画布」。
- 标记滞留（卡未开）：下次启动仍可接。

**3) 边界与约束**
- 窗口态辨识：宿主原生窗为裸窗口（`window.top === window`）；卡态为宿主内嵌。具体以实测为准。
- 若主工作区卡已在线（单桶冲突）：窗口按钮提示「主工作区已在；请先在其上继续操作」，或仅写标记留待。
- 不做跨壳页实时接力（单桶约束下不可行）；本移交为一次性状态转移。

## 组件与改动面
| 组件 | 改动 |
|---|---|
| `app/ui/workspace.js` + `workspace.html` | 窗口态按钮 + 移交动作 + 卡态启动检测与接管提示 |
| `app/index.js` | 移交标记读写路由（`handoff`：write/peek/clear；落 app-data） |
| 复用 | 中继 `/_relay/fs/write`（原子写工作流文件）；桥侧画布全量获取（`canvas.get` 或桥内序列化） |

## 验收
- 窗口态：按钮仅窗口出现；点击后文件+标记落盘、窗口关闭、提示正确；
- 卡态：启动检测 → 自动加载 → 提示 → 标记清除；无标记时零打扰；
- 单桶不冲突；既有行为（frameReload、画布 ops 等）不受影响；
- 真机两步（人工）：开窗点按钮 → 开卡接住。
