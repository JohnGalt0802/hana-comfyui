## 一、P4 的真实缺陷（已实测定位）

**现象**：弹层缩略图位置一直是数字占位，重启 ComfyUI 后更明显。

**根因（实测）**：

```
17 个 promptId 的 GET /history/{promptId} 全返回 {}   ← 内存态被清空（ComfyUI 22:52 重启）
磁盘上 35 张图仍在，GET /view?...&preview=webp;75 → 200 image/webp   ← 图没丢
```

**结论**：P4 取图走 `/history/{promptId}`，那是 **ComfyUI 内存态，重启即失**。数据源选错了。
不是缓存问题（上一条判断不完整，此处更正）。

**修法**：出图后把**产物文件名**持久化到磁盘（不存字节），UI 直接读磁盘索引拼 URL，**彻底不碰 `/history`**。

## 二、接口契约（冻结，两个执行方按此对齐）

### 2.1 新增端点 `POST /hana_bridge/history-attach-images`

**请求**：
```json
{ "workflow": "<工作流名>", "promptId": "<uuid>",
  "images": [ { "filename": "a.png", "subfolder": "", "type": "output" } ],
  "at": "<ISO，可选>" }
```

**响应**：`{ "ok": true, "status": 200, "file": "<sidecar 文件名>", "count": <累计张数> }`
**错误**：400 缺 workflow/promptId/images 非法；404 索引里无该 promptId；500 IO。

**行为**：在索引里按 `promptId` 找到那条 entry → 取其 `file` 基名 → 写/合并 sidecar 文件
`<基名>.images.json`（**同 promptId 重复上报按 filename+subfolder+type 去重合并**，幂等）。

**sidecar 内容**：`{ "promptId": "...", "images": [...], "updatedAt": "<ISO>" }`

> 为什么用 sidecar 而非改索引行：索引是 **JSONL 追加写**（天然无竞态）。回填要改已写行，
> 会破坏追加语义。sidecar 是 per-commit 独立小文件，可独立更新、无并发竞态。

### 2.2 改 `GET /hana_bridge/history-list`

每条 entry **新增两个合并字段**（由后端读 sidecar 拼出）：
- `runs`: `[ { "promptId": "...", "at": "...", "images": [ {filename,subfolder,type} ] } ]`
  （沿用 P5a 定义的形态；本次单 run，P5b 与合并语义共用）
- `images`: 上述 runs 里所有 images 的**扁平合并**（便捷字段，供 UI 直接用）

无 sidecar 的 entry → `runs: []`、`images: []`。

### 2.3 UI 缩略图 URL（唯一取图口径）

```
原图  : /view?filename=<enc>&subfolder=<enc>&type=<enc>
缩略图: 上述 + &preview=webp;75        （后端就地转 webp，实测 10x 压缩）
```
经 `api.apiURL(...)` 补前缀（实测 `/api/view?...` 与 `/view?...` 均 200 + image/webp）。
**禁止再调 `/history/{promptId}`。**

### 2.4 版本标志（John 要求：一眼看出换没换版）

弹层头部显示桥的构建号短串（如 `11225527`），淡色小字。值取 `BUILD_TAG` 尾部。

## 三、P6 提交历史框形态（John 定稿）

锚定分组框**标题栏上方**的横向时间轴：

```
        ┌───────────────────────────────────────┐
        │ 2. Prompt & size · 7 次提交     ⚙11225527│  ← 头部（末端显示构建号）
        │   ▏ ▏▍ ▏  ← 刻度（左旧右新，按时序）    │  ← 横轴
        │ 10:02                        11:47      │
        └───────────────────────────────────────┘
        ┌───────────────────────────────────────┐
        │ 2. Prompt & size                       │  ← 分组框标题栏
        └───────────────────────────────────────┘
```

- **默认态**：只有轴 + 刻度，无其他内容
- **触发**：点 bounding 框弹出，再点（或点空白 / ✕）关闭
- **降级**：无框 → 作用于功能块（角色块）（现有 `graphBlocks` 已支持）
- **悬停**：同主题气泡 = 时间 + 较上次变更的节点名（读 entry.delta，无则退化为块名）
- **单击**：展开该提交的缩略图（多图横向滚动）；**鼠标移开自动关**
- **双击**：确认框「回到该提交节点」（复用 P3 的 `historyRollbackExecute`）
- **四色**：`(source, kind)` 2×2 —— 色相分谁（user 冷色 / agent 暖紫），形态分跑/存（实心 / 空心环）。
  本批数据里 source 恒 user、kind 恒 run（退化两色），**UI 按 2×2 实现，等 P5b 通数据**。

## 五、出图回填的捕获点（定死）

**桥前端**（与 `queuePrompt` 捕获对称，同一处代码）：

```
api.addEventListener("executed", e)      // 逐节点，e.detail.output 带产物
  → 累积到 pendingImages[prompt_id].push(...)
api.addEventListener("execution_success", e)   // 一次运行结束
  → POST history-attach-images { workflow, promptId, images }
  → 清 pendingImages[prompt_id]
```

- 兜底：`execution_error` / `execution_interrupted` 时清该 promptId 暂存。
- 幂等：后端按 filename+subfolder+type 去重，重复上报无害。
- 降级：上报失败只 `console.warn`，不影响画布。
- **不在桥里重算 sig**（CSP 下桥不能 import ESM，抄一份 = 双维护）。签名一律后端算。
