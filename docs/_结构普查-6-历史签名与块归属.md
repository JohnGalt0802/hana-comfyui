## 0. 速读结论（给改这两个函数的后来者）

1. **`graph_sig_ignoring_seed`（签名）**：逐节点 `type + "|" + widget段`，每节点段先 FNV-1a，再整体 FNV-1a；跳过 seed 类 widget；**不含 links、不含 mode/title/位置/node id**。与 JS `graphSigIgnoringSeed` **必须同串**，哈希口径在两处逐字节对齐。
2. **跨语言同串证据**：两文件头部注释均写「必须给出同一串」；JS 单测 `canvas-history.test.mjs` §12/§16 用**硬编码基准值**（`c1271398`、`cac7e860`）做跨语言断言。⚠️ 本仓**无 Python 单测文件**（find 无 `test*.py`），Python 侧无自动化同串校验。
3. **`compute_delta`（delta）**：返回 `{changed:[{id,title,fields}], added:[{id,title}], removed:[{id,title}]}`；**完全不含连线维度**（只索引 nodes，links 一字未比）。
4. **`blockNames`（框视角名列表）**：是**读取时**由 `_block_names_for_entry` 现算的，索引行**不存** blockNames，只存 `blocks`。它**既含 group 框名，也含 role 块名**（加载/文本/采样/输出/其他）——因为 `blocks` 数组由桥前端 `graphBlocks` 同时产出 `source:"group"` 与 `source:"role"` 两类，`_block_names_for_entry` 不过滤 source。
5. ⚠️ **行号偏差提示**：`docs/_结构普查-3-桥后端与中继.md` 里给的 `_block_names_for_entry:895`、`list_commits:937`、`commit:665` 等已是**旧快照行号**；本文件以实测为准（见各条）。改代码前请用 Read 再核一次。

## 1. `graph_sig_ignoring_seed` 完整算法（history_store.py）

### 1.1 函数本体与逐段口径

**定义与主体**：`history_store.py:159-171` `graph_sig_ignoring_seed(graph)`

**逐节点算法（事实）**：
- 取 `g = graph`；`nodes = g["nodes"]`（非 list → `[]`）。
- 对每个 `n`（非 dict 跳过）：
  - `typ = str(n["type"])` 或 `""`（`history_store.py:165`）。
  - `part = _fnv1a_hex("%s|%s" % (typ, _widgets_part(n)))`（`history_store.py:166`）。
- `return _fnv1a_hex("|".join(parts))`（`history_store.py:168-171`）。

**widget 段构造**：`_widgets_part(node)` `history_store.py:136-156`
- 优先 `widgets_values_named`（dict 且非空）：对每个 key `k`，若 `_SEED_WIDGET_RE.search(k)` 命中则**跳过**，否则 `out += "k=canon_value(v);"`（`:140-145`）。
- 否则 `widgets_values` 为 list：按位置 `out += "widget_%d=canon_value(val);"`（`:147-149`）。
- 否则 `widgets_values` 为 dict：跳过 seed 类 key，其余 `out += "k=canon_value(v);"`（`:150-153`）。

**FNV-1a 口径（事实）**：`_fnv1a_hex(s)` `history_store.py:87-94`
- 常量 `_FNV_OFFSET_BASIS = 2166136261`（`history_store.py:77`），`_FNV_PRIME = 16777619`（`history_store.py:78`）。
- `h = _FNV_OFFSET_BASIS`
- 对 `s.encode("utf-8")` 的每个 byte：`h ^= byte; h = (h * _FNV_PRIME) & 0xFFFFFFFF`
- 输出 `format(h, "08x")`（8 位小写十六进制，左补 0）。

**规范化取值**：`_canon_value(v)` `history_store.py:123-133`
- `None` → `""`；`bool` → `"true"/"false"`；`dict/list` → `_canon_json`（排序键紧凑 JSON）；数值 → `_js_num_str`（整数值无小数尾）；其余 → `str(v)`。

### 1.2 哪些字段参与 / 为何 links 不在内

| 维度 | 是否参与 | 位置 | 说明 |
|---|---|---|---|
| `node.type` | ✅ | `:165` | 节点类型 |
| `node.widgets_values_named`（跳过 seed） | ✅ | `:140-145` | 按名 widget |
| `node.widgets_values`（位置 / dict，跳过 seed） | ✅ | `:147-153` | 按位置或按名 |
| 节点 `id` | ❌ | — | 不参与 |
| 节点 `title` / `mode` / `pos`（位置/尺寸） | ❌ | — | 不参与 |
| `graph.links`（连线） | ❌ | — | **完全不参与** |
| `linkCount` / `nodeCount` | ❌ | — | 不参与（仅快照/索引行计数，不进签名） |

**links 不在内的原因（事实，来自 docstring）**：`history_store.py:163` 注释明确「与桥 js graphSignature() 同族但更简化（**不含 mode/title/位置/连线数；不含节点 id**）」。该函数定位是「合并判定用的稳定指纹」——只在两次提交「结构语义相同」时返回同串，从而让「同一画布换个随机 seed 再跑」被识别为同一节点、可走 `mergeInto` 合并。**【推断】** 连线被刻意排除，是因为合并不关心边是否重排，只关心节点及其非 seed 参数的集合是否一致；这样随机 seed 变化仍可合并且不会因连线微调而分叉。

### 1.3 JS 侧同一算法（镜像）

`canvas-history.mjs:268-272` `graphSigIgnoringSeed` 主体与 py 同构；底层 `fnv1aHex` `:200-208`（UTF-8 手写字节 + `Math.imul(h, FNV_PRIME) >>> 0`）、`widgetsPart` `:236-260`、`SEED_WIDGET_RE = /seed/i` `:235`、`FNV_OFFSET_BASIS = 2166136261` `:181`、`FNV_PRIME = 16777619` `:182`。两处常量与逐字节算法一致（见 §2 注释）。

## 3. `compute_delta` 完整返回结构（history_store.py）

**定义**：`history_store.py:236-269` `compute_delta(prev_graph, next_graph)`

**前置（事实）**：`prev_graph` 非 dict → 返回 `None`（`:238-240`）。否则
- `prev = _index_nodes_by_id(prev_graph)`、`nxt = _index_nodes_by_id(next_graph)`，两函数**只取 `nodes`**（`history_store.py:175-187`），**完全忽略 links**。

**返回结构（事实）**：

| 字段 | 形态 | 来源 | 行号 |
|---|---|---|---|
| `changed` | `[{id, title, fields}]` | prev、next 同 id 节点，type 不同或 widget 值不同 | `:247-264` |
| `added` | `[{id, title}]` | 在 next 不在 prev 的节点 | `:241-243` |
| `removed` | `[{id, title}]` | 在 prev 不在 next 的节点 | `:244-246` |

- `changed` 项：`fields` 先查 `type` 不同 → 加 `"type"`（`:256-259`），再 `_changed_widget_names(a,b)` 追加变化的 widget 名（`:260`）；空 fields 不入列表（`:261-264`）。
- `title` 来源：`_node_title(n)`（`history_store.py:189-192`）——`title` 非空用 title，否则 `type`，否则 `""`。
- 三者均按 `_id_sort_key`（数值按数值、否则字符串，对齐 JS）排序（`:266-268`）。

**是否含连线维度（事实）**：**完全不含**。`compute_delta` 只比对 `nodes` 的 id/type/widgets；`_index_nodes_by_id`、`_widget_entries`、`_changed_widget_names` 全都不碰 `links`。连线变化不会在 delta 里体现。

**JS 镜像**：`canvas-history.mjs:346-394` `computeDelta`，结构逐字段一致（`changed:{id,title,fields}` / `added:{id,title}` / `removed:{id,title}`）。

## 4. `_block_names_for_entry` 完整实现与返回（块归属 / blockNames）

**定义**：`history_store.py:1327-1367` `_block_names_for_entry(entry)`

**逻辑（事实）**：
1. `e = entry`（非 dict → `{}`）。
2. `delta = e.get("delta")`；`if not isinstance(delta, dict): return None`（`:1334-1336`）。
3. `blocks = e.get("blocks")`；`if not isinstance(blocks, list): return None`（`:1337-1339`）。
4. 收集 `hit_ids` = 所有 `delta.changed/added/removed` 项的 `id`（统一 `str()`）（`:1340-1350`）。
5. 遍历 `blocks`：`b` 非 dict → `return None`（`:1352-1353`）；`ids = b.get("nodeIds")` 非 list → `return None`（`:1354-1356`）；若任一 `str(i) in hit_ids` → `names.append(str(b.get("name")) or "")`（`:1357-1360`）。
6. `return names`（`:1367`）。

**三种返回值语义（事实，见 docstring `:1317-1332`）**：
- `None` —— 无法判定：旧数据（delta 非 dict）/ blocks 非 list / 任一 block 缺 nodeIds。
- `[]` —— 有数据但没碰任何框（delta + blocks 完整，无一命中）。
- `[名字…]` —— 命中框名列表（按 blocks 顺序，name 缺省补 `""`）。

### 4.1 blockNames 到底含哪些名字？（group 还是 role）

**结论（事实）**：**既含 group 框名，也含 role 块名（加载/文本/采样/输出/其他）**。理由：
- `_block_names_for_entry` **不过滤 `source`**，只是把 `entry.blocks` 里「nodeIds 命中」的每一块的 `name` 收进来（`:1357-1360`）。
- `entry.blocks` 由桥前端 `graphBlocks()` 产出，该函数**同时产出两类块**（见 `hana-bridge-15021810.js:2890-2980`）：
  - `source:"group"`：`graph.groups` 框内节点（name = 组 title 或 `组N`，`:2973`）。
  - `source:"role"`：未入任何组的节点的角色兜底桶，name ∈ {`加载`,`文本`,`采样`,`输出`,`其他`}（`:2935-2976`，ROLE_RULES 见 `:2899-2903`）。
- 归组口径为「group 优先、未归组才走 role」（`:2940-2961` 的 `continue`），所以两类块可同时存在于 `blocks`，blockNames 也就能同时含两者。

**name 来源与 source 字段（事实）**：
- `name`：`_norm_block` 中 `"" if b.get("name") is None else str(b.get("name"))`（`history_store.py:330-341`）；实际总由 `graphBlocks` 的 `dedupName(...)` 提供（组名/角色名去重加 `#k`）。
- `source`：`_norm_block` 中 `src if isinstance(src,str) and src else "group"`（`:331-336`）——缺省兜底为 `"group"`；真实值只可能是 `"group"` 或 `"role"`（由 `graphBlocks` 写入）。

⚠️ **推断**：`blockNames` 是「本次提交碰过的框/块的**名字**列表」，用于 UI 的「框视角过滤」（`hana-bridge-15021810.js:5628` 等扫 `ent.blocks[].name`）。它**不含** nodeIds、不含 color，仅名字。

## 5. blockNames 如何进索引行 / 传参链 / normalize_entry 缺省补全

### 5.1 关键澄清（事实）：blockNames 不进索引行，索引行只存 `blocks`

- `build_index_line`（`history_store.py:733-762`）产出字段**不含** `blockNames`；只有 `blocks`（`"blocks": _norm_blocks(m.get("blocks"))`，`:759`）。
- `blockNames` 是**读取时现算**：`list_commits`（`history_store.py:1369` 起）对每条主行 `norm["blockNames"] = _block_names_for_entry(e)`（约 `:1396`），即拿原始 entry 的 `blocks` + `delta` 现场算。

### 5.2 `blocks` 进索引行的传参链（事实）

  → 上报 body.blocks                hana-bridge-15021810.js:2767 reportHistoryCommit / :2791 body.blocks = blocks
  → 桥 py POST /hana_bridge/history-commit

- `_norm_blocks`（`history_store.py:343-353`）：非 list → `[]`；逐块 `_norm_block`（剔除非 dict 块）。

### 5.3 `normalize_entry` 对旧数据的缺省补全（事实）

`normalize_entry`（`history_store.py:766-793`）：**只读补全，不改磁盘、不改入参**（`out = dict(e)`）。
- `parent` → `_norm_parent`（`:778`）
- `kind` → `_norm_kind`（缺省 `"run"`，`:779`）
- `sig` → 字符串否则 `""`（`:780-781`）
- `delta` → dict 否则 `None`（`:782-783`）
- `blocks` → `_norm_blocks(e.get("blocks"))`：旧条目无 blocks → `_norm_blocks(None)` → `[]`（`:784`）
- `runs` → 有数组则归一；无 `promptId` → `[]`；否则用顶层 `promptId/at` 造单元素（`:785-792`）

**对 blockNames 的影响（事实）**：`list_commits` 调 `_block_names_for_entry(e)` 时传的是**原始** `e`（非 `norm`）。旧数据 `e` 缺 `delta`/`blocks` → 函数首两个判定（delta 非 dict / blocks 非 list）→ 返回 `None`（无法判定）。这与 §4 的 `None` 语义一致。新数据（有 delta + blocks）→ 正常返回名字列表或 `[]`。
