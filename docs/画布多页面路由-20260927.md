## 0. 问题

ComfyUI 的图是**每个页面实例各自一份内存**。而我们的指令走 ComfyUI 自带 `/ws` 广播，于是：

- **多个页面同时开着**时，每个都执行同一条指令，**各改各的**（节点 id 各自计数、图内容不同）
- `canvas.save` 存到哪个实例的图**不可控**（看谁先回）
- agent 说"加个节点"，**落到哪个页面**上它自己也不知道

单页面时一切正常；一旦多开（工作区 + 浏览器标签，或没关掉的旧标签）就乱。

---

## 1. 思路（John 提的）

**用「工作流」当页面的身份**：

> 一个页面对应一个工作流名称，对应一个 json 文件

于是：

- 每个页面**上报自己打开的工作流**（名字 + 路径）
- Bridge 维护 `sid → 工作流` 的账
- agent 要动某个工作流时，**按工作流名定向**，不再广播
- `canvas.save` 不传名字时，**每个页面存自己那份** → 天然不冲突

---

## 2. 设计

### 2.1 前端上报（每页一份身份）

扩展在 `hello` 与**状态推送**时带上：

```json
{ "clientId": "<sid>", "href": "...",
  "workflow": { "name": "Qwen21 Turbo EasyCache t2i", "path": "workflows/Qwen21 ….json", "modified": true } }
```

- 名字取自 `app.workflowManager.activeWorkflow`（`filename` / `name`），拿不到就用 `(未命名)`
- **切换 / 重命名工作流**也要重报：把"当前工作流名"纳入已有的 1.5s 签名比对，一变就重推

### 2.2 Bridge 记账

`_frontends: { sid → {workflow, at, href} }`（替代原来的单个 `_frontend.sid`；`_frontend` 保留作"最近一个"兼容）。

新增只读 op **`canvas.pages`** → 当前在线页面清单：

```json
{ "ok": true, "data": { "pages": [ { "sid": "ab12…", "workflow": "Qwen21 …", "ageSec": 3.2, "href": "…" } ] } }
```

agent 靠它知道"现在有谁在、各自开着什么"。

### 2.3 定向

`/hana_bridge/call` 增加可选 `workflow` 参数：

- 给了 `workflow` → 在账里找**名字匹配**的 sid → 定向发送（`send_sync(event, data, sid)`）
- 找不到 → **明确报错**（`no_page`，并附当前页面清单），**不退回广播**（避免误伤别的页面）
- 没给 `workflow` → 保持广播（向后兼容；单页面时行为不变）

### 2.4 落盘按页面分工

`canvas.save` 不传 `name` 时用**该页面自己打开的工作流名**（前端侧已有实现）。
多页面各自存各自的文件，不再互相覆盖。

---

## 3. 不改的事

- 中继不用改（op 透传）
- **单页面的行为完全不变**（广播照旧工作）
- 不做"多页面实时同步"（ComfyUI 本身没有这个机制）

---

## 4. 验证计划

1. 开一个页面（打开 `Test workflow`）→ `canvas.pages` 显示它
2. 再开一个页面（打开另一个工作流）→ `canvas.pages` 显示两条
3. 按 `workflow` 定向 `addNode` → **只有目标页面变了**，另一个不动
4. 两个页面各自 `save` → 各存各的文件，互不覆盖
5. 定向一个不存在的 workflow → 明确报错并列出当前页面

---

## 5. 风险

| 项 | 处理 |
|---|---|
| 两个页面打开同一个工作流 | 账里出现两个同名 sid → 定向时**都发**（它们本就是同一份图），并在返回里说明有几个页面收到 |
| 工作流未命名（新图） | 名字用 `(未命名)`；仍可按 `sid` 定向 |
| 页面关了没清账 | 每次上报覆盖 + 带 `at`；`canvas.pages` 只列 `ageSec` 未过期的 |
| 名字含中文 / 空格 | 原样匹配，不做规范化（前端报什么就是什么） |
