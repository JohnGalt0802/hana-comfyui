## 一、缺口与拍板

**缺口一**：提交历史里，节点/连线变动**无任何标识**；且——更深的根因——**纯连线改动会被判为「没变」而合并、根本不生成新节点**。

**缺口二**：画布无 bundle 框时，单击功能块**永远开不出**提交历史框（入口只认框）。

**用户拍板**（卡 `c_mv9j9431_1_q96o`）：
- q1 = **把连线纳入合并签名**：连线一变就出新节点
- q2 = **符号**标识变动（＋/－/⇄ 之类）
- q3 = **单击任意节点** → 开该节点所属「角色块」的历史框
- q4 = 过滤＝**只显示碰过该块/该节点的提交**（沿用现有「框视角过滤」语义）
- 补充：「先做一下试试效果」

## 三、缺口一设计（数据层 + 表现层）

### 3.1 签名纳入连线（数据层）
**原则**：不用「连线条数」（删一条又加一条会被误判成没变）；用**端点对集合**。

- 每条 link → 规范化端点串 `originNodeId:originSlot>targetNodeId:targetSlot`
- 全部 link 的端点串**排序**后拼接
- 最终 `sig = fnv1a(节点部分 + "#L#" + 连线部分)`（分隔符取不会与节点部分歧义的字面量）
- **口径版本前缀**：新签名统一加 `v2:` 前缀
- **先探明**：落盘快照的 `links` 真实格式——UI 格式可能是**对象数组** `[{id,origin_id,origin_slot,target_id,target_slot,type}]` 或**数组数组** `[[id,o,os,t,ts,type]]`；两种都要兼容（执行单以实测为准）
- **三处同源**：py:159 + js:268 + 测试基准（§12/§16 需重算）

### 3.2 delta 加连线维度（数据层）
`compute_delta` 返回增加 `links`：
```json
"links": {
  "added":   [{"from":{"type":"KSampler","slot":0}, "to":{"type":"VAEDecode","slot":0}}],
  "removed": [ ... ]
}
```
「改接」自然表达为 removed+added。双份同步：py:236 + js:346 + §13 断言。

### 3.3 UI 符号（表现层）
- **刻度**：`historyBarTickMake`（桥 `:3994`）内条堆后追加符号 span，仿现有 `×N` 徽标（`L4017-4022`）
- **树节点**：`historyTreeRenderTree` 内联构造（桥 `:5665-5719`）同构加符号
- 符号语义：节点 → `＋n`/`－n`；连线有变 → `⇄`（可组合，如 `＋2 ⇄1`）
- 数据源：`ent.delta`（新结构）；旧条目无 `links` → 不显示符号（自然退化）

### 3.4 兼容与迁移
- **sig 版本前缀**：旧条目 `sig` 无 `v2:` 前缀 → 判为**不可比** → 不合并、生成新节点（一次性代价，之后口径一致）
- 旧 `delta` 无 `links` → UI 不显示连线符号
- **不迁移**旧数据（旧 sig 是哈希，无法反推）

## 四、缺口二设计（表现层，只改桥）

### 4.1 开框入口扩展
`historyOnCanvasMouseDown`（桥 `:4535`）：在「无 group → 收起」（`L4603`）**之前**，插入「无 group → 命中节点 → 取角色块名 → 开框」。
- **有 group 时行为完全不变**（优先 group，不拦截）
- 节点命中 API 需探明（`graph.getNodeOnPos` 等）

### 4.2 节点 → 角色块名（复用，不新建口径）
新增 `historyRoleBlockNameOfNode(node)`：消费 `graphBlocks` 输出，找 `source==="role"` 且 `nodeIds` 含该节点的块 `name`。**不改 `graphBlocks` 本体**。

### 4.3 开框带角色块
- 新增状态位 `historyBarRoleName`（仿 `historyBarGroup`）
- 新增 `historyBarOpenRole(roleName)`：轻封装 `historyBarOpen`；标题显「角色块：<名>」
- **过滤复用**：`historyBarLoad`（桥 `:4331`）——有 `historyBarRoleName` 则 `curBlock = roleName`，比对式不变（`ent.blockNames.includes(curBlock)`）；旧数据（`blockNames` 非数组）仍保留不筛

### 4.4 边界
| 场景 | 行为 |
|---|---|
| 有 group，点框 | 开 group 框（现状不变） |
| 有 group，点节点 | 仍按 group（不拦截；**可扩展点**，本期不做） |
| 无 group，点节点 | 开该节点的角色块框，过滤=touched |
| 无 group，点空白 | 收起（现状不变） |

## 八、风险 / 未决（成色：推断，待验证）

1. **连线格式**（对象数组 vs 数组数组）未实测 → 执行单**必探**，两种都兼容。
2. **本仓无 py 单测** → 必须 py↔js 同串交叉验证（否则口径漂移无守护）。
3. **id 漂移假设**：连线端点用 node id，假设「同会话内稳定」；跨会话（重载）时可能判为「变了」（视为合理）。
4. **版本前缀的旧数据代价**：首次提交可能生成一个「假变更」节点（一次性）。
5. 桥换 tag + 部署 + **重启服务**需先告知用户，定时机。

## 九、验收标准（对照用户拍板）

- [ ] 纯连线改动（节点未动）→ 生成新提交节点，不被合并（q1）
- [ ] 提交刻度/树节点上可见变动符号，能区分节点增删与连线变化（q2）
- [ ] 无 bundle 框时，单击任一节点 → 开出该节点所属角色块的历史框（q3）
- [ ] 该框只显示碰过该块的提交；旧数据保留不筛（q4）
- [ ] 有框时行为与改动前一致（无回归）
- [ ] 旧历史数据不报错、不误判
