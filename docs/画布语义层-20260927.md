## 0. 一页摘要

**问题**：agent 现在能操作画布，但每一步都在「原始 JSON 里人肉翻找 + 手动验证」——

- 今晚实测：读一次全量 53,617 字符（27 节点 / 32 连线，其中约 95% 与当下任务无关）；
- 「尺寸自定义」改造 = 4 版脚本、12 次写调用、3 次中途诊断；
- 百来次思考里约七成花在"猜前端行为、验证结果、对齐状态"，而非任务本身。

**方向（John 定调）**：不给 agent 加"眼睛"（截图/视觉通道已否，那等于让人读汇编）。
给**数据通道升级表示法**：打通「原始 JSON → 高度凝练的结构化表达」的链路。

**命题两半**：

1. **编译**（读）：物理布局（nodes/links/坐标/widgets）→ 逻辑布局（功能块、链路、参数、异常）。
2. **语言**（写）：读与写同构——query 选得中的东西，patch 就改得动。

合起来 = **画布的 LSP**：大纲、诊断、追踪、重构。不是新发明，是把 IDE 给代码的那套语义服务，给到画布。

**分期**：P1 投影过滤器（最小改动）→ P2 体检 + 追踪 → P3 大纲/语义块 → P4 写向语言（patch 事务 + 宏，与既有 draft 合并）。

## 1. 问题陈述（实测）

| 环节 | 现状（今晚实测） | 代价 |
|---|---|---|
| 读 | `get` 全量 53,617 字符进上下文 | token 血拼、95% 噪音 |
| 查 | 手动翻 inputs 数组对 link id、跳 links 表找源头 | 一步问题五步动作 |
| 写 | 意图拆成 12+ 个原子 op，逐个发、逐个验 | 出错面 ×14 |
| 验 | 再拉全量对账 | 每步 doubling |
| 状态 | 画布 / 文件 / 快照三源人工对齐 | 纯管理开销 |

**反方向已否**：截图给 agent「看」。agent 的原生通道是数据，无歧义、可编程、可验证；视觉通道留给「评估产出图」（另一课题），不进操作链路。

## 2. 层级模型（L0–L4）

| 层 | 名称 | 内容 | 今晚这图的示例 |
|---|---|---|---|
| L0 | 原始 | UI JSON 全量 | 53,617 字符 / 27n / 32l |
| L1 | 投影 | 选子图 + 选字段（过滤器） | `get {select:"#8,#27,#28", fields:["inputs","widgets_values"]}` |
| L2 | 分组 | 功能块识别（语义折叠） | `尺寸{ #27,#28→#8 } 文本{ #6→#12→#18 } 采样{ #20→#23→#24→#25 }` |
| L3 | 符号 | 紧凑摘要 + 异常标注 | `size 1248×832 (custom) \| issue #7 悬空` |
| L4 | 语言 | 可写：patch / 宏（意图级） | `patch { insert "size.custom"(1248,832) }` |

对照示例（查「#8 的 width 连没连」）：

```
【L0 汇编版·实际干的】
get 全量 → 翻 #8.inputs 找 link=38 → 跳 links 表确认源头 #27
→ 读 #27.widgets_values[0]=1248                     （5 步，5 万字符过眼）

【L3 高级版·目标】
trace(#8.width)  →  #27.value = 1248                （1 步）
或摘要直读：  size: #27(1248)→#8.width ✓ | #28(832)→#8.height ✓
```

## 3. 三个视图（v0 能力集，草样）

全部为**读向**，数据侧实现（见 §6），不改前端。返回一律走 agent 通道的 JSON（见 §5.4）。

### 3.1 大纲 `outline`——"这图长什么样"

```
outline {}            # 默认 detail=blocks
outline {detail:"nodes", select:"文本"}   # 下钻某块看节点级
```

返回草样：

```
Qwen21 t2i 质量版 · rev71 · 27n/32l
├ 尺寸  #27(1248) #28(832) → #8
├ 文本  #6 → #11 → #12 → #13..16 → #18      [PE: on]
├ 采样  #20 → #23 → #24 → #25               [karras ×20 · res_multistep · EasyCache on]
└ 加载  #2→#26→#23 ｜ #4→#12 ｜ #5→#18,#24
issues: #7 悬空
```

块识别规则（v0，显式优先、可覆盖）：

1. 画布自带 `groups`（组框）→ 直接采用；
2. 节点标题规范（编号/角色词，如「④ 调度器」「尺寸」）→ 归块；
3. 兜底：节点类型角色分类（`*Loader`→加载；`TextEncode*`/`TextGenerate`→文本；`*Sampler*`/`*Scheduler*`/`*Guider*`/`Noise`→采样；`Save*`/`Preview*`→输出；其余→工具）。
4. 块内按数据流排列；跨块连线显示为块间箭头。

### 3.2 体检 `check`——"哪儿不对"

```
check {}
check {rules:["dangling","residue"]}   # 可按规则集裁剪
```

检查项（v0）：

| code | 说明 |
|---|---|
| `DANGLING` | 节点无任何连线（悬空） |
| `DISCONNECTED_IO` | 有上游/下游断口的关键链路（如 SaveImage 无输入） |
| `MUTED_BYPASSED` | mute / bypass 中的节点（非默认态） |
| `MISSING_REQUIRED` | 必填输入未接（前端本就拦，作为兜底） |
| `DOMAIN_*` | 领域规则，可选注册（如"宽高应为 16 的倍数"） |

返回草样：

```json
{"ok":true,"issues":[
  {"level":"warn","code":"DANGLING","node":7,"title":"Output size","msg":"输出无连接（0 条）"}
]}
```

### 3.3 追踪 `trace`——"这个参数从哪来、到哪去"

```
trace {node:8, slot:"width"}            # 默认向上游
trace {node:25, slot:0, dir:"down"}     # 向下游
```

返回草样：

```json
{"ok":true,"path":[
  {"node":27,"type":"PrimitiveInt","out":0,"value":1248},
  {"node":8,"in":"width","link":38}
],"summary":"#27.value=1248 → #8.width"}
```

## 4. 最小语法草样（v0）

### 4.1 选择器（P1 只做必要子集）

| 形式 | 含义 |
|---|---|
| `#8` / `#8,#27` | 按 id（并集） |
| `type=PrimitiveInt` | 按类型 |
| `title~尺寸` | 按标题包含 |
| `#8/up` `#8/down` | 邻接（预留，P2 用） |

### 4.2 投影

`fields` 白名单：`title, type, mode, inputs, outputs, widgets_values, pos, size`。

### 4.3 文本符号（人机共用，紧凑格式）

- 连线：`#27.value=1248 → #8.width [INT]`
- 块：`尺寸{ ... }`
- 异常前缀：`! #7 悬空`

### 4.4 写向（P4，与本期 patch 草案合并）

```json
{"op":"patch","edits":[
  {"disconnect":{"nodeId":8,"slot":"width"}},
  {"addNode":{"type":"PrimitiveInt","title":"宽度","as":"w"}},
  {"setWidget":{"nodeId":"$w","name":"value","value":1248}},
  {"connect":{"fromNode":"$w","fromSlot":"INT","toNode":8,"toSlot":"width"}},
  {"save":{}}
],"verify":true,"dryRun":false}
```

三点要求：`as/$` 变量引用（同批引用新建节点）；**原子性**（失败逆序回滚，复用既有逆操作栈）；**verify**（执行后自动对照终态；`dryRun` 只做预检：槽存在性、类型兼容）。

## 5. 设计原则与协议

### 5.1 原则四条

1. **token 经济**：摘要的压缩比是第一位指标（目标：主链场景 10× 以上）。
2. **无歧义**：一切可确定性解析（不靠自然语言理解）。
3. **读写同构**：读得出的对象，写就改得动；新增读能力时评估对应写能力。
4. **可下钻（底线）**：任何摘要都可回 L0 验证；抽象层永远不是信息黑洞。数据是最终真相。

### 5.2 协议（对齐既有格式约定）

- agent 工具/路由通道：**JSON**（`{ok, op, data, warnings, rev}`）。
- UI 卡/人看的：照旧渲染人话卡片，格式层分开，互不影响。
- 错误：`{ok:false, code, detail, candidates?}`（如 `SLOT_MISSING` 附可用槽名）。

### 5.3 与前端行为知识的关系

- **读向（L1–L3）不依赖前端行为**：纯对 JSON 的变换，可单测、可对历史快照跑。
- **写向（L4）依赖前端**：§23 的行为坑清单继续积累（重试类毛刺沉进桥，如 widget 槽首连自动重试）。

## 6. 架构落点（"编译在数据侧，执行在前端"）

| 能力 | 落点 | 说明 |
|---|---|---|
| L1 投影 / L2 折叠 / L3 摘要 / check / trace / outline | **app 层（数据侧）** | 输入是现抓的 JSON，纯函数变换；与前端版本解耦、可单测、可对缓存快照跑 |
| 现抓 JSON（get/prompt）、全部写 op、patch 执行器 | **前端桥** | 只有它能碰 `app.graph`；patch 把既有 handler 纯函数化后组合 |
| op 表 / 工具面 / 返回格式（JSON 化） | **app `index.js`** | `get` 加 `select/fields` 参数；新增 `outline/check/trace/patch`；返回组装分层（agent=JSON，UI=人话） |

数据流：`agent → app(编译/回答) →（需要时）中继 → 桥 → 前端`；读向尽量在 app 层止步，少一次桥往返。

## 7. 分期

| 期 | 交付 | 改动面 | 验收 |
|---|---|---|---|
| **P1 投影** | `get {select, fields}`；agent 通道返回 JSON 化 | app 层解析 + 格式化（小） | 读 #8/#27/#28 相关 <2KB；不用再拉全量 |
| **P2 体检+追踪** | `check`、`trace` | app 层纯函数（中） | `check` 报出 #7 悬空；`trace(#8.width)` 一步得 1248 |
| **P3 大纲** | `outline`（块识别 v0） | app 层（中） | 27 节点 → 4–5 块，一屏读完 |
| **P4 写向** | `patch` 事务（+ 宏雏形） | 桥（执行器）+ app op 表 | 今晚的"尺寸改造"一次 patch 完成；失败自动回滚 |

每期独立可用，不追求大爆炸；P1 即可显著降思考量。符号体系的**固化**（是否成为正式"画布符号"）放到 P1–P4 用出习惯之后，再拍。

## 8. 边界与风险

| 项 | 处理 |
|---|---|
| DSL 陷阱（发明大一统语言） | v0 只做投影 + 摘要 + 事务写；语法从用法里长，不反向发明 |
| 抽象层信息黑洞 | 可下钻写进协议（§5.1-4）；摘要带 `rev`，可对账 |
| 块识别误判 | 显式优先（groups/标题）+ 兜底有解释（每个块显示组成来源） |
| check 误报疲劳 | 默认只报核心规则；领域规则需显式注册 |
| 与 ComfyUI 前端耦合 | 读向零耦合（数据侧）；写向的毛刺处理沉进桥，不散到 agent |
| "compiler 漂移" | 折叠逻辑带版本号（semantic rev）；行为变化时可对同一输入回归比对 |

## 9. 近期验收场景（拿今晚的图跑）

对象：「Qwen21 t2i 质量版」（27n/32l，rev71）。

1. `get {select:"#8,#27,#28", fields:["inputs","widgets_values"]}` → <2KB，直读连接与数值。
2. `trace {node:8, slot:"width"}` → `#27.value=1248 → #8.width`。
3. `check {}` → 报出「#7 悬空」。
4. `outline {}` → 尺寸/文本/采样/加载 四块成纲。
5. （P4 后）同一张图的"尺寸自定义"改造 → 单次 `patch` 完成 + verify 回执。

度量口径：完成同一任务的**读向回合数**与**过眼字符数**；目标较现状各降 70% 以上。
