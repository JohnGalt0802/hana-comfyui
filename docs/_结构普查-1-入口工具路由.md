## 4. shellBridge（壳页桥单桶机制）

### 4.1 结构
- 定义：`const shellBridge = { lastSeenAt, lastHello, queue:[], pending:Map }` — **行号 2086–2091**
- `SHELL_ALIVE_MS = 5000` 与 `shellAlive()`（lastSeenAt 距今 < 5s）— **行号 2093–2094**
- 单桶说明：窗口壳页与主工作区壳页**共享**同一心跳/队列，同刻仅一壳页（注释 **行号 3862 / 4120**）

### 4.2 四个原语（hello/poll/result/status）
| 原语 | 行号 | 机制 |
|------|------|------|
| `hello` | 5064 | 壳页上线心跳：写 `lastSeenAt=now`、`lastHello=body` |
| `poll` | 5075 | 壳页取走 `queue.splice(0,20)` 的 op；写 `lastSeenAt`；返回 `{ops,count}` |
| `result` | 5081 | 壳页回传：按 `body.rid` 查 `pending`，命中则 `clearTimeout` + `resolve({ok,data,error})` + 删除；返回 `{matched}` |
| `status` | 5098 | 暴露 `alive / lastSeenAgoMs / queued(queue.length) / inflight(pending.size) / hello` |

### 4.3 队列与 pending（调用侧）
- `shellCall(drive, args, timeoutMs=20_000)` — **行号 2095–2103**
  - 生成 `rid = sh_<time36>_<rand>`；挂 `setTimeout` 超时（超时删 pending 并 reject「壳页未在超时内回传」）；`pending.set(rid,{resolve,timer})`；`queue.push({rid,op,args})`
  - 超时默认 20s（**行号 2095**）
- `frame.reload` 特殊处理：**行号 5119** — 仅 `queue.push`，不登记 pending（壳页回帖 matched:false 无害）

### 4.4 双桥调用（壳页腿优先，扩展腿回退）
- `canvasBridgeInvoke(drive, args, timeoutMs)` — **行号 2146 起**
  - `shellAlive()` 为真 → 先 `shellCall`（壳页腿，legMs 透传）；失败/壳页不支持 → `bridgeCallExt`（扩展腿 `/_relay/bridge`，extMs 默认 30s）
  - 壳页腿恒守 20s 默认、扩展腿 30s 默认；显式 timeoutMs 两条腿一致（L6 修正 **行号 2155 注释**）

### 6.3 与 manifest 的关系
- manifest（`app/manifest.json`）`capabilities` 数组声明本 App 向宿主请求的能力词：
  `app/runtime.execute` / `app/runtime.local-machine` / `app/runtime.network` / `app/resources.read` / `app/tools.expose-to-model` / **`app/tasks.manage`** / **`app/session.start-turn`** / **`app/windows.manage`**
- 关系：manifest 声明「请求哪些词」；运行时由宿主经 `app:capabilities` 总线返回每项 `status`；`hasCapability` 据此放行。即 manifest 是**授权清单（声明）**，总线返回是**实际授予态（运行时判定）**。
- ⚠️ 不一致点：`CAP_STAGE_FILE = "app/session.stage-file"`（55/1784/4870）在代码中被查询，但**未列入 manifest 的 `capabilities` 数组**。可能由 `app/session.start-turn` 隐含或宿主按需授予，本次普查未进一步溯源 [未覆盖]；若宿主仅按 manifest 授予，则该词 `hasCapability` 恒为 false，`result stage` 会被自动跳过。
