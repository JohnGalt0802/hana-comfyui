# 壳页当桥：画布通道搬到工作区壳页 — 方案

日期：2026-09-27
状态：**实施中**
起因：用户指出「一直在 8188 裸端口搞，hui 里没有」；并要求跳出「让扩展进代理页面」的死路，从宏观重切。

---

## 1. 旧路为什么在 hui 里走不通

旧路：桥住在 ComfyUI 里（`custom_nodes/hana_bridge` 的前端扩展），靠 ComfyUI 提供的 `/extensions/<node>/<file>.js` 加载。

**在 hui 工作区里这条路是死的**，实测：

```
POST 127.0.0.1:8188/hana_bridge/hello   → {"ok": true}
POST 127.0.0.1:40836/hana_bridge/hello  → {"ok": true}
POST 127.0.0.1:14500/hana_bridge/hello  → {"error":"forbidden",
                                            "reason":"missing_credential"}
```

原因：工作区 iframe 挂在宿主 `…/routes/_runtime/<id>/` 下，**它的源是 hana server（14500）**。
而 ComfyUI 前端与桥 js 拼的都是**绝对路径**（`/extensions/…`、`/scripts/…`、`/hana_bridge/hello`），
会丢掉 `_runtime/<id>/` 这段前缀 → 打到 14500 根上 → 403。

于是：**画布能显示**（页面本身由 14500 正常提供），但**扩展加载不了、hello 上报也失败** → 桥永远看不到人。

**这不是配置问题，是路径模型不兼容**：ComfyUI 前端假定自己挂在域名根上。

## 2. 宏观重切：桥该住在壳页

关键观察（**壳页自己的代码早已证明**）：

```js
// workspace.js L77-78
const win = els.frame.contentWindow;
settings = win && win.app && win.app.ui && win.app.ui.settings;

// workspace.js L278
const cv = win.app && win.app.canvas;
```

**代理模式下壳页与 iframe 同源**，壳页直接够得到 `iframe.contentWindow.app`。
既然连 `app.ui.settings`、`app.canvas` 都能摸，「主题跟随」就是这么实现的，
那 `app.graph` / `app.workflowManager` / `app.extensionManager` 一样够得着。

**旧桥当初住在 ComfyUI 里，是因为假设「壳页够不着 window.app」；代理模式下这个假设反了。**

## 3. 新架构

```
agent
  → hui 工具（comfyui action=canvas op=…）
  → App 后端 index.js（/comfyui-hana/canvas → actionCanvas）
  → 壳页桥（工作区壳页轮询待办 → 执行 → 回传）
  → iframe.contentWindow.app
  → 画布
```

**执行者从「ComfyUI 扩展」换成「工作区壳页」，通道从 WS 换成 HTTP 轮询。**

### 3.1 后端（index.js）

- `shellBridge` 状态：`lastSeenAt` / `pending`（rid → resolve/timeout）/ `queue`（待执行 op）
- `POST /comfyui-hana/shell/hello`：壳页报到，记 lastSeenAt
- `GET  /comfyui-hana/shell/poll`：壳页取待办，返回 `{ops:[{rid,op,args}]}`
- `POST /comfyui-hana/shell/result`：壳页回结果 `{rid, ok, data, error}`
- `shellAlive()`：`lastSeenAt` 在 5s 内
- `actionCanvas`：**优先 shellBridge；无壳页时退回原 hana_bridge 逻辑**（两条腿并存）

### 3.2 壳页（workspace.js）

- 启动后每 **800ms** 轮询 `/comfyui-hana/shell/poll`
- 对每个 op，取 `els.frame.contentWindow.app` 执行
- 结果 POST 回 `/comfyui-hana/shell/result`

**最小 op 集（先做这两个，验方向）**：

- `pages`：报当前工作区开着哪个工作流
- `openWorkflow {name|path, force}`：经 `app.extensionManager.workflow.openWorkflow` 打开；
  默认拒绝覆盖未保存改动（`activeWorkflow.isModified()`）

**其余 op（summary/get/prompt/setWidget/addNode…）随后按同法补齐**；
本层只碰 `iframe.contentWindow.app`，与旧桥的 op 实现可逐条对应搬过来。

## 4. 得失

| | 旧路（ComfyUI 扩展） | 新路（壳页当桥） |
|---|---|---|
| 代理模式 | 403，走不通 | **同源，通** |
| 连接方式 | 得改直连 | **不用动** |
| 主题跟随 | 直连就失效 | **照旧** |
| 部署依赖 | 要装 custom_nodes | **不用** |
| 共驾语义 | 可能不是同一张画布 | **本来就是同一张** |
| 工作区未开 | 可用（若页面在） | **不可用（明确报错）** |

**新增的约束（必须显式处理）**：工作区没开时，壳页桥不可用。
此时 `actionCanvas` 要**明确报错说明**，不能静默、更不能假装成功。

## 5. 生效方式

| 改动 | 生效 |
|---|---|
| `app/index.js`（后端路由） | 重启宿主 |
| `app/ui/workspace.js`（壳页） | 重载 App / 刷新工作区 |
