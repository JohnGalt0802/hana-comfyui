## 二、N1 双保险的触发时机

**主（事件）**：
- `LGraphCanvas.setGraph(newGraph)` 内 `dispatch("litegraph:set-graph", {newGraph, oldGraph})`（仅 `e!==t` 时），`dispatch` 落到 `this.canvas`（画布 **HTMLCanvasElement**）上，`bubbles:true`。
- 桥在 `app.canvas.canvas`（fallback `canvasEl`）上挂 `litegraph:set-graph` → 用户切工作流 / 换图瞬间即回调 `historyOnWorkflowSwitch()`（刷新树 + 收弹层）。
- 挂点与既有「点击命中」同源（同一元素），`app.canvas` / 元素晚到时由 `scheduleHistoryGroupInstallRetries` 的四档延迟（500/1500/3000/6000ms）补装；元素重建则由 `WeakSet` 视为新元素重入自愈。

**兜底（轮询）**：
- `pollGraph`（已由 `setInterval(..., CHANGE_POLL_MS=1500)` 常驻）内已有 `lastWorkflowName` 比对，`wfChanged` 为真即调同一入口 `historyOnWorkflowSwitch()`。
- 覆盖「延迟重试窗口（6s）之后 canvas 元素才重建、主监听丢失」的场景。**未新开任何定时器**。
- 顺序：主监听先到即刷（即时）；轮询最迟 1.5s 后补一次（幂等，重复刷新无副作用——`historyTreeRefresh` 有 `historyTreeReqId` 竞态哨兵，`historyBarClose` 幂等）。

**两路共用同一入口 `historyOnWorkflowSwitch()`**：① 刷新提交树；② 弹层开着才收起（`historyBarEl` 非空判定），关闭走既有 `historyBarClose()`，与「点空白收起」同语义。
**异常**：三处回调（事件、轮询、延迟安装）全部 try/catch 吞 + `console.warn`，不影响画布。

## 三、N3 兼容口径

- **写**：快照（`.history/<wf>/NNNN-xxxx.json`）**不含 `blocks`**；索引行（`index.jsonl`）**含完整版 `blocks`**（`name` + `source` + `nodeIds`，经 `_norm_blocks` 归一：非列表 → `[]`）。二者不再重复。
- **读新快照**（无 `blocks`）：`read_snapshot` 原样返回 JSON 对象，无该字段也正常（消费方按缺省处理）。
- **读旧快照**（带 `blocks`）：`read_snapshot` 不做字段过滤，`blocks` 原样读回，不报错。
- **索引侧不变**：`list_commits` / `build_index_line` / `normalize_entry` / `_block_names_for_entry` 照旧（框视角 `blockNames` 依赖索引行 `blocks`，链路不受影响）。
- **schemaVersion 不 bump**（字段缺席向后兼容）。
- **入参兼容**：`build_snapshot(..., blocks=…)` 与 `_create_node(..., blocks=…)` 签名保留，传了也被忽略，无调用点需要改。
