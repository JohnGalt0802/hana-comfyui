## 0. 一页摘要

**口径修正**：agent 与人不是持续对话，所以**事件流（P2）不是刚需**；
真正的刚需是 —— **在每次对话开始时，一份新鲜的画布状态已经在手边**。

**做法**：把「感知」从「agent 现抓」改成「**前端在变化后主动推、服务端缓存**」：

- 扩展侧：保留轻量签名比对，但**检测间隔放宽**（500ms → 1500ms），且**只在变化后 debounce 推送一次**；
- Bridge 侧：新增缓存端点，保存「最近一次画布摘要 + 时间戳 + 来源 sid」；
- agent 侧：新增 `canvas.state`（读缓存，零往返）；`canvas.summary` 保留（现抓，作兜底与校验）。

**核心收益**：**ComfyUI 页面没开着也能拿到上次的状态**（缓存留在服务端），
这就把「感知」从「依赖此刻页面在线」变成「手边有一份可用的快照」。

## 1. 动机

John 的原话（2026-09-26）：

> 我说的感知也不至于如此实时，只要我找你对话时你能感知到就好了，
> 所以可能只需要一个当前状态的检查，而不是频繁读内存，那样没有意义，
> 因为我们的对话并非持续态，只要在我找你对话时你能拿到一个画布状态就可以了。
> 只不过这个工作可以通过你设计的机制去提前做，而不是每次现抓。

拆成三条：

1. **不需要实时**：对话不是持续态，事件流（P2 的 revision/events）价值有限。
2. **需要在对话开始时就有**：状态要「手边有」，而不是「我去问才去抓」。
3. **可以提前做**：把抓取动作从「调用时」提前到「变化后」。

---

## 2. 现状与差距

| 现状 | 差距 |
|---|---|
| `canvas.summary` 现抓（App → 中继 → 8188 → 广播 → 前端 → 回传） | 每次都要走完整往返；且**页面没开就抓不到** |
| 扩展每 500ms 算签名 | 频率对「非持续对话」来说过高（虽然很轻） |
| `canvas.revision` / `canvas.events` | 是「变化明细」，对「拿一份当前状态」来说是额外负担 |

## 3. 设计

### 3.1 数据流

```
[变化发生]
  前端扩展（签名比对，间隔 1.5s）
     ↓ 变化后 debounce 1.5s，POST /api/hana_bridge/state
  Bridge（Python）内存缓存：{ at, revision, summary, sid }
     ↑
  中继 /_relay/bridge（op=canvas.state）
     ↑
  App（comfyui action=canvas op=state）
     ↑
  agent：零往返拿到「最近一次状态 + 时间戳」
```

### 3.2 前端（`js/hana-bridge.js`）

- 签名检测间隔：`500ms → 1500ms`（口径修正：不需要实时）。
- 变化后 **debounce 1500ms** 再推，避免连续拖动时刷屏。
- 页面加载完成时**推一次基线**（原本只靠 `hello` 上报 sid，现在顺带上报摘要）。
- 推送内容复用 `graphSummary()`，外加 `revision` 与 `at`。

### 3.3 Bridge（`__init__.py`）

- 新增 `POST /hana_bridge/state`（前端推，同源，不校验 token；只存摘要）。
- 内存缓存：`_state = { at, revision, summary, sid }`（进程内，单份）。
- 新增 `GET /hana_bridge/state`（供中继读缓存，需 token）。

### 3.4 中继 / App

- 中继 `/_relay/bridge` 支持 `op=canvas.state` → 读 Bridge 的 `GET /hana_bridge/state`
  （**不广播**，直接取缓存）。
- App 的 `CANVAS_OPS` 加 `state`，并把**默认 op** 从 `summary` 改为 `state`（对话开始时最常用）。

### 3.5 兜底与诚实

- 缓存带 `at`；返回里**始终显示状态的时间戳**，让 agent 能判断「这是 3 秒前还是 20 分钟前」。
- 缓存为空或过期（默认 > 300s）→ 自动回退**现抓**（`canvas.summary`），并标注 `via:"live"`。
- 多前端：缓存记录来源 `sid`；多标签时取最近推送者（与 P1「广播取先到者」口径一致）。

---

## 4. 不做的事

- 不做长连接事件流推送（口径修正：非持续对话，价值有限）。
- 不做画布截图 / 视觉感知（另一条路，另议）。
- 不改 P1 的读取能力，只加一层缓存。

---

## 5. 风险

| 项 | 说明 | 处理 |
|---|---|---|
| 缓存过期 | 页面关了、长时间无变化 | 带时间戳 + 超时回退现抓 |
| 多前端来源混乱 | 多个页面各推各的 | 记录 sid，取最近 |
| 缓存与真实不一致 | 推送漏了 / 失败 | 保留现抓入口做校验；`revision` 可比对 |
| 常驻内存 | 一份摘要，几十 KB | 可忽略 |

---

## 6. 工作量

小：前端扩展 ~40 行、Bridge ~30 行、中继 ~10 行、App ~20 行。
可与「P3 扩展（加 / 删节点 / 连线）」分开做，互不影响。
