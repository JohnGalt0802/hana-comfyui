# 方案 · 修复「未保存画布保存后提交历史全丢」（2026-10-14）

> **用户报告**：未保存画布保存后，所有提交节点全丢。**数据丢失级**。
> **根因（已确证，见 `docs/排查-提交历史保存后丢失-20261014.md`）**：历史按工作流**显示名**做目录键；未保存画布以临时名累积提交，保存（另存并切换）后名字变正式名 → 读历史的键变成新名 → 命中空目录 → 表现为"全丢"。旧数据仍躺在旧名目录里。

---

## 1. 修法总览

**核心**：**改名时，把旧名目录的历史迁移到新名目录**（跨目录 move/merge）。不动 ComfyUI 前端产物（零改动铁律），改动集中在桥 js + 桥 py。

**两个触发点**（覆盖 agent 保存与用户手动保存）：
- **A. `canvas.save` op**（agent 保存）：链上，`saveAs` 前后拿到 `before/after` 名 → 直接迁移。**最可靠**。
- **B. `historyOnWorkflowSwitch`**（用户手动保存/另存触发换图）：名字变化时，用**图签名**区分"改名"vs"换图"，判为改名才迁移。

**后端新增**：`/hana_bridge/history-migrate` 端点 + `history_store.migrate_history(from, to, user_dir)`。

---

## 2. 关键设计：如何区分「改名（该迁移）」与「换图（不该迁移）」

`historyOnWorkflowSwitch` 现在只做"名字变了 → 刷新树"。若不加区分地迁移，会把"打开另一张工作流"误当成改名，把 A 的历史搬到 B。**必须区分**。

**判据：图签名**。
- 会话级新增基线 `lastWorkflowGraphSig`（与 `lastWorkflowName` 一起维护）。
- 名字变化时：`newSig = 当前图的归一化签名`；若 `newSig === lastWorkflowGraphSig` → **同一张图、只是改名** → 迁移；否则 → **换了图** → 不迁移，只更新基线。
- 依据：保存改名**不改图内容** → 签名相同；打开另一张工作流 → 图内容不同 → 签名不同。
- 边界：打开一张"内容恰好与上一张相同"的工作流 → 罕见误判为改名 → 迁移（**合并式，不丢数据**，仅历史合并），可接受。

**图签名**：需要桥侧可用。检查桥内是否已有等价函数（`graph_sig`/`graphSignature`）；若无，用「节点数 + link 数 + 节点 id 集合」的轻量稳定签名（不必与 py 的 `graph_sig_ignoring_seed` 完全一致——此处只用于"两张图是不是同一张"的本地比对）。

## 3. 后端（`history_store.py` + `__init__.py`）

### 3.1 `history_store.migrate_history(from_name, to_name, user_dir)`

```python
def migrate_history(from_name, to_name, user_dir):
    """改名迁移：把 <from> 的历史目录内容并入 <to> 的历史目录。
    · 源目录不存在 → {ok:True, moved:0, note:"src_missing"}（无事）。
    · 目标目录不存在 → os.rename(from_dir, to_dir)（整体搬移，最快）。
    · 目标已存在 → 合并：读目标 next_seq 作 offset；逐条源主行 seq+=offset、
      parent（若 ≥1）+=offset；快照文件 <seq>-id.json 改名移入；.images.json sidecar 同步改名；
      mergeInto 行的目标 seq 同样 +offset；追加到目标 index.jsonl。源目录清空后删除。
    · 幂等：from==to（净化后同名）→ 无事。
    """
```

- 合并时**重编号 seq + parent**（避免与目标 seq 冲突 + 保持父子引用自洽）。
- 快照文件名首段是 seq（`%04d`），随新 seq 改名。
- `.images.json` sidecar 名字与快照同名，同步。
- 全部操作在**同一目录树内**（`.history/` 下），失败可回滚（先复制到临时名再改，或操作前记清单）。

## 4. 桥 js（`hana-bridge-<tag>.js`）

### 4.1 `canvas.save` op 迁移触发（A）

在 ② 另存并切换链里，`saveAs` 前取 `before = curName`，返回前取 `after = expectAfter`；`done` 后若 `before` 与 `after` 净化名不同 → 调迁移：
```js
if (after && before && after !== before) {
  void postJson("/hana_bridge/history-migrate", { from: before, to: after })
    .catch(() => {});
}
```
（fire-and-forget + 静默失败；不阻断保存。）

### 4.2 `historyOnWorkflowSwitch` 迁移触发（B）

维护 `lastWorkflowGraphSig`；名字变化且签名相同 → 调 `/hana_bridge/history-migrate {from: lastWorkflowName, to: name}`，**在 `historyTreeRefresh()` 之前**（迁移完成后刷新才拿到数据；fire-and-forget 时至少同轮不阻塞）。再 `lastWorkflowName = name`、更新 `lastWorkflowGraphSig`。

### 4.3 浮层「点外部关闭」（用户另一条需求，同批）

- 新增 `bindOutsideClose(container, onOutside)`：`pointerdown` 捕获阶段，`target` 在 `container` 内则不关、否则关；返回解绑函数。
- **树预览**：`container = historyTreeEl`，`onOutside = historyTreeShotsHide`（点树外=关；点树内交给节点 click 的 toggle/切换）。
- **弹层预览**：`container = historyBarEl`，`onOutside = historyBarShotsHide`。
- **回跳确认框**：`container = 确认框自身 box`（点框外=关）+ **Esc** 关。
- 所有浮层关闭时**解绑**（防监听堆积）。

## 7. 验收标准

1. **主 bug**：未保存画布跑几次 → 保存成正式名 → 提交树/历史框**仍显示全部提交**（旧提交迁移到新名目录）。
2. **不误迁移**：打开另一张工作流 → 各自历史**不混**。
3. **浮层关闭**：树/弹层预览点外部关；确认框点外部 + Esc 关；既有 toggle/切换/双击不回归。
4. 已有历史（磁盘上 5 个正式名目录）**不受影响**。

## 8. 成色与风险

- 根因**已实测确证**（探针文档，磁盘孤儿目录为证）；修法为**静态推导**，未真机复现。
- **风险点**：
  1. 合并路径的 seq 重编号/parent 自洽 —— 靠单测覆盖。
  2. "改名 vs 换图"判据在**内容恰好相同**时误判 —— 已知、可接受（合并不丢数据）。
  3. py 端点需**重启服务**才可用。
- 回滚 = `git checkout` 相关文件 + 重新部署 + 重启。
