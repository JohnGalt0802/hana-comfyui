## 一、隐藏节点：语义定为「短路」

隐藏 A 时，把 A 的所有子节点的 parent 改挂到 A 的 parent（回溯到**最近的可见祖先**），再把 A 剔除。

**为什么不是纯过滤（实测，Qwen质量版00002 / 182 主行）**

| 做法 | 节点 | 泳道 | 孤儿 |
|---|---|---|---|
| 原样 | 182 | 8 | 0 |
| 短路隐藏 `1180`（2 个子） | 181 | 8 | **0** |
| 短路隐藏 `1181`（叶子） | 181 | **7** | 0 |
| 短路隐藏 `1182`（1 个子） | 181 | 8 | 0 |
| **只过滤不短路** | 181 | **9** | **2** |

纯过滤会让 `1181`/`1182` 变孤儿，各自开新泳道，图断成两截。

**分支处理**：不需要特殊逻辑。`1180` 有两个子节点，短路后 `1178` 直接分叉到两个子，泳道数维持 8。`commitGraphLanes` 按 parent 重新分配即可。

**已验证的边界**

| 场景 | 结果 |
|---|---|
| 连续隐藏两个（级联） | 0 孤儿（回溯必须级联，见下） |
| 隐藏后再提交，新提交 parent 指向被隐藏节点 | 自动挂到最近可见祖先（9999 → 1182），0 孤儿 |
| 隐藏整条泳道（22 个） | 0 孤儿，泳道 8→7 |
| 恢复（重新渲染原始 entries） | 182 / 8 泳道 / 0 孤儿，与隐藏前一致 |
| 隐藏 HEAD | 禁止（`sanitizeHidden` 剔除）；否则小黄点消失 |
| 隐藏根节点 | 禁止；否则子节点集体变孤儿 |

**关键实现约束**：短路必须**级联回溯**（被隐藏节点的 parent 可能也是隐藏节点）；提交新记录必须先并入原始列表再整体 applyHidden，顺序反了会漏掉新节点。

## 二、性能：实测与优化

### 优化前实测

**算法层**（`commitGraphLanes`，含 `scoreOf` 的 O(n²)）

| 节点数 | 总耗时 | 去掉 `scoreOf` | `scoreOf` 占比 |
|---|---|---|---|
| **182（当时）** | **0.65 ms** | 0.08 ms | **87%** |
| 1000 | 4.35 ms | 0.18 ms | 96% |
| 2000 | 16.74 ms | 0.34 ms | 98% |
| 4000 | 58.00 ms | 0.69 ms | 99% |

`scoreOf` 上方注释写明「不做重排……只算代价，纯供诊断用」，却每次渲染都算。

**数据层**（`history-list` 响应，182 条）

| 项 | 大小 |
|---|---|
| 总计 | **427.3 KB** |
| `runs` | 179 KB（42%） |
| `blocks` | 94 KB（22%，前端只用 blockNames） |
| `images` | 69 KB |
| `delta` | 30 KB |

### 三项优化

| # | 改动 | 效果 |
|---|---|---|
| P0-1 | `scoreOf` 改为按需（`window.__hanaLaneDebug` 才算），`cost` 字段保留为 0 | 算法 0.65→**0.08 ms**（182 节点） |
| P0-2 | `list_commits` 返回瘦身：`runs` 只留 `{promptId, imageCount}`，`blocks` 去 `nodeIds` | 响应 427.3→**293.4 KB**（省 31.3%） |
| P0-3 | `historyTreeRefresh` 加 200ms 防抖（改名 `...Now` + 外壳合并） | 5 连发只发 1 个 fetch，5 个 Promise 都正常 resolve |

**等价性验证**：`scoreOf` 关/开跑同一份 60 节点随机图，`lanes` 与 `nodes` 序列化完全相同，只有 `cost` 从 `{cross:15,score:30}` 变全 0。
**数据完整性**：`sum(imageCount)=953` 与 `sum(len(entry.images))=953` 一一对应；磁盘索引未动。

**阈值判断**：500~1000 个提交开始有感（响应 1~2 MB、算法 2~4 ms），2000 个会明显卡（算法 17 ms + 全量重建 DOM）。当前 182 个距离很远。

## 三、实现（四个任务并行/串行）

| # | 任务 | 产出 |
|---|---|---|
| W1 | `app/lib/history-hide.mjs` 纯函数 | 101 行 + 单测 12 例（`resolveVisibleParent` / `applyHidden` / `sanitizeHidden` / `HIDDEN_LS_PREFIX` / `indexBySeq`） |
| W2 | `history_store.py` 响应瘦身 | +56/−4，测试 144→146 |
| W3 | 桥 P0 + 隐藏核心接入 | `scoreOf` 按需、refresh 防抖、L3293 兼容 `imageCount`、内联 lib 逻辑（**71 行核心与 lib 逐行一致**，多出的 37 行是桥侧 localStorage 三个函数）、`visibleEntries` 替换、连线同源 `historyTreeShownEntries` |
| W4 | 交互 + 历史框同步 | 节点右键菜单、泳道右键（两步确认）、历史框 `visibleShown`、计数「可见 / 总数」 |

**隐藏状态存储**：`localStorage`，键 = `hana.history.hidden.v1:` + 画布身份（id 或名字）+ `:` + path。按画布隔离，换画布不串。

**泳道右键只作批量选择器**：状态仍按 seq 存，泳道重排后藏的仍是具体提交（实测隐藏 `1181` 会让 `l6`/`l7` 合并，泳道编号会变，所以不能拿泳道当状态单元）。

## 四、口径统一

- **HEAD 在所有视图都不可隐藏**：树与历史框的 `sanitizeHidden` 都传 `historyTreeHead.seq`（历史框原本传 null，已统一）。
- 隐藏不影响数据：只作用于渲染副本，原始 entries 与 `index.jsonl` 完全不动，恢复即原样。

## 七、0.14.9：泳道眼睛 + 隐藏 N 恢复入口（John 后续要求）

**起因**：右键隐藏后图上没任何标记，不知道藏了什么；泳道右键「隐藏本行」也不直观。John 要求：泳道序号左侧加小眼睛，像 PS 图层那样点眼睛隐藏。

**一处必须先说清的技术矛盾**：PS 的图层是静态列表（行固定、藏了还在），我们的泳道是算法实时分配的——短路会让子节点上挂、泳道重排。实测隐藏 `1181` 就让 `l6`/`l7` 合并、`l7` 消失。所以「点眼睛藏起来、再点眼睛放回来」在短路语义下做不到。

**John 选定**：眼睛只管藏，行跟着消失；恢复走收纳条入口。

### 实现

| 部分 | 做法 |
|---|---|
| 泳道眼睛 | `.htr-laneeye`，`left: 2px`、12×12、行内垂直居中、**常显**；常态 opacity .45，hover 转实；颜色走 `--htr-sub` → `--htr-fg` |
| 点击行为 | 收集该行当前可见 seq（排除 HEAD/根）→ `historyTreeHiddenApplyChange(集合 ∪ 该行)`；可隐藏数为 0 时置灰不可点 |
| 事件区划分 | 眼睛挂 `left 2~14px` 且 `pointer-events:auto`；泳道右键的 `contextmenu` 仍只挂 `.htr-laneaxis`（含 18px 宽整行高的 `::before` 命中区）。落在眼睛上目标就是眼睛，其余整行归泳道，两者不重叠 |
| 收纳条入口 | `.htr-hidden-btn`，有隐藏时显示「隐藏 N」，样式与 `.htr-count` 同族、可点 |
| 恢复面板 | `.htr-hidden-panel`：标题「已隐藏 N 个提交」、每行 `#seq` + 「恢复」、底部「全部恢复」；挂 body、fixed 定位在入口上方（空间不足翻下方）、视口内钳 8px |
| 关闭策略 | Esc / 点面板外 / 再次点入口 / 失焦 / 滚动或缩放 / 重渲染；与右键菜单互斥 |

**没有幽灵点**：节点的 x 位置会随短路重排漂移，幽灵点会指向错的地方。
