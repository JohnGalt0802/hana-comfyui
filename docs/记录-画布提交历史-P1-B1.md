`handleHistoryCommit` 内部步骤（均返回 `{status, ok, ...}`，不 throw）：
1. 取 `workflow`（string，trim）；空 → `{status:400, error:"需要 workflow（工作流名）"}`。
2. 取 `graph`；非普通对象（null/数组/裸值）→ `{status:400, error:"需要 graph（画布快照对象）"}`。
3. `workflowsDir` 非字符串/空 → `{status:500, error:"无法解析 ComfyUI 工作流目录（安装探测未就绪？）"}`。
   - 注：**校验顺序**为 workflow → graph → workflowsDir；`mkdir` 在三者都通过之后。
4. `historyDir(workflowsDir, workflow)` → 目标目录；索引路径 `<dir>/index.jsonl`。
5. 读已有索引：`existsSync` 为真才 `readFileSync` → `parseIndex().entries`；读失败 → 500。不存在 → 空数组。
6. `nextSeq(entries)` → `seq`；`snapshotFileName(seq, promptId)` → 文件名。
7. `buildSnapshot({graph, promptId, seq, at, source})` → `JSON.stringify` → 字节数。
8. 体积：`bytes > MAX_SNAPSHOT_BYTES` → `{status:413, error, size}`，**不写盘**。
9. `buildIndexLine({seq,file,promptId,at,source,nodeCount,linkCount})` → 一行 JSONL（不含 graph）。
10. `mkdirSync(dir, {recursive:true})` —— 目录不存在就自建（**收口在本端点路径内**）。
11. `writeFileAtomic(absFile, text)` —— 原子写快照（`.tmp` → rename）。
12. `appendFileSync(indexPath, line + "\n")` —— **追加**一行索引（绝不读全文重写）。
13. 成功 → `{ok:true, status:200, seq, file, dir}`。

## 二、接口行为（实测确定）

```
POST /_relay/history/commit
请求体: { workflow, promptId, graph, at, source }
```

- **成功**：HTTP 200，体 `{ ok:true, seq:<number>, file:"0001-a3f9c2e1.json", dir:"<绝对路径>" }`
- **失败**：HTTP 400（缺 workflow / 缺 graph / body 非法 JSON / 序列化失败）
  或 413（快照序列化后 > 14 MiB）或 500（目录解析失败 / 读索引失败 / mkdir 失败 / 写盘失败 / 追加失败），体 `{ ok:false, error:"<文案>" }`（413 额外带 `size`）。
- **权限**：**未加 controlKey 校验**。任务书契约未要求、且既有 `/_relay/fs/stat`、`/_relay/fs/read` 同属「无 key 的只读为主」档；本端点属写入类，**是否要挂 controlKey 为未决项**（见 §四）。改动仅新增分支，不触碰任何现有端点的鉴权。
- **体积上限**：14 MiB（`MAX_SNAPSHOT_BYTES`），写上限 16 MiB 留裕量。
- **落盘**：快照 `<dir>/<snapshotFileName>`（原子写）；索引 `<dir>/index.jsonl`（追加写）。

## 四、未决项（交主脑定）

1. **controlKey 鉴权**：本端点写盘，但契约未要求 key。当前**不挂** controlKey（与 fs/read、fs/stat 同档；若挂会与「中继只做路由接线」的调用方约定不一致）。**待主脑定是否补 `x-comfy-relay-key` 校验。**
2. **工作流目录候选口径**：`resolveWorkflowsDir()` 用「首个存在的候选」，都缺时退回首个候选交给 `mkdirSync` 自建。候选中包含 `安装根/ComfyUI/user/default/workflows`（外层布局），在便携版上若「安装根/user/default/workflows」与它同时存在，会取前者——与 app 侧 `comfyUserDirCandidates()` 的候选顺序一致，但**未经真实便携版实测**（本机为源码安装 `D:\ComfyUI\ComfyUI`，推断口径一致）。
3. **`source` 缺省**：body 不带 `source` 时，`buildSnapshot` 内 `normalizeSource` 归一为 `"unknown"`（非 `"user"`）。调用方（桥/app）是否总是显式传 `user`/`agent` 由上游定；本端点不猜。
4. **响应体是否带 `at`/`nodeCount`**：契约字段为 `{ok,seq,file,dir}`，实测返回严格只这四键（`status` 被拆出作 HTTP 码），未附加任何诊断字段。
5. **并发**：`nextSeq` 读索引与追加写之间无锁。设计文档《方案-画布提交历史》§三已判定「JSONL 追加写天然无竞态」（连点运行最多产生两个不同 seq 的独立快照文件，不会互相覆盖）；但**同一时刻两次提交可能算出同一 seq**（都读到 N 条 → 都取 seq=N+1）→ 文件名撞车，后者原子写覆盖前者。此为设计已接受的边界，本端点未额外加锁。**若主脑要求强唯一，需另立机制（不在本任务范围）。**
6. **索引文件名**：取 `index.jsonl`，与 A1 记录（§四.1）中「任务书 JSONL 口径」一致；方案文档旧文写作 `index.json`，以任务书为准。
