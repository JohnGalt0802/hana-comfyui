# 方案 · 提交树双击回跳不出确认框（守卫不一致）（2026-10-14）

> **现象**（John 2026-10-14）：在底部「提交树」里点节点，**回跳确认框不出现**，回跳无法触发。

---

## 1. 根因（既有缺陷，非今晚引入）

**已用 git 对比确认**：`a5df2b7^`（旧桥 `hana-bridge-10121817.js`）与当前新桥的 `historyTreePick` / `historyRollbackConfirmOpen` **逐字相同**；守卫 `if (!historyBarEl || ...)` 在 `7688272`/`56b525b`/`5cbbc3c`/`27b13a9`/`9201c04` 各版本均存在 → **长期缺陷，非本轮改动引入**。

**矛盾点**：

| 函数 | 守卫 | 语义 |
|---|---|---|
| `historyRollbackExecute()`（L4684 附近） | `if (!historyBarEl && !historyTreeEl) return;` | 两容器**任一**即可；注释明写「确认框可由底部提交树触发（弹层未开时也允许回跳）」 |
| `historyRollbackConfirmOpen()`（L3899） | `if (!historyBarEl \|\| historyRollback.busy) return;` | **硬要求弹层 `historyBarEl` 存在** |

**触发链**：提交树节点**双击** → `historyTreeNodeClick` → `historyTreePick`（L5561）→ `historyRollbackConfirmOpen(tick, ent)` → 弹层未开（`historyBarEl === null`）→ **直接 return，确认框不出现**。

**为什么确认框本可以不依赖弹层**：`historyRollbackConfirmOpen` 内部用 `document.body.appendChild(box)` + `position:fixed` 定位（CSS `#hana-history-bar-confirm { position:fixed; z-index:10003 }`），**不依赖 `historyBarEl`**。`historyBarEl` 只在那句守卫里被用到——纯多余门槛。

**次要缺口**：`historyRollbackExecute` 的**失败路径**写成 `if (historyBarEl) { historyRollbackBtnReset(); historyBarTip(...) }`——弹层不在（树单独触发）时，回跳失败**静默无声**。

---

## 2. 修法（最小改动）

### 2.1 守卫对齐（核心）

`historyRollbackConfirmOpen` 首行守卫改为与 `execute` 同口径：

```js
// 改前
if (!historyBarEl || historyRollback.busy) return;
// 改后
if ((!historyBarEl && !historyTreeEl) || historyRollback.busy) return;
```

效果：
- 弹层开 → 行为不变（横轴双击回跳照旧）；
- 弹层关、只有树 → 确认框也能出（挂 body、fixed，不依赖弹层）。

### 2.2 失败提示兜底（补齐"半个功能"）

`historyRollbackExecute` 的 catch 里，失败提示当前只在 `historyBarEl` 存在时显示。改为：弹层在 → 原样（红字）；弹层不在但树在 → 用 `historyRollbackToast`（一次性 toast，已有函数）报错，不静默。

```js
} catch (err) {
  console.warn(LOG_TAG, "P3-G1 回跳失败", err);
  historyRollback.busy = false;
  if (historyBarEl) {
    historyRollbackBtnReset();
    historyBarTip("回跳失败：" + String((err && err.message) || err), true);
  } else if (historyTreeEl) {
    historyRollbackToast("回跳失败：" + String((err && err.message) || err));
  }
}
```
（`historyRollbackToast` 现为绿色成功样式；若复用为失败，可加可选 `isError` 参数改色，或新增 `historyRollbackToastError`。由执行者按最小改动取一，勿大改。）

### 2.3 不动

- `historyTreeNodeClick` 的单击/双击消歧（单击=选中+缩略图预览；双击=回跳）**不动**——与横轴同口径。
- `historyRollbackClick`（弹层内「回到这一版」按钮）守卫 `!historyBarEl` **不动**——它在弹层内，弹层必须在。
- 横轴 `historyBarTickClick` 链路 **不动**。

## 5. 验收标准

1. **弹层开着**：横轴双击 → 确认框照旧出现（不回归）。
2. **弹层关着、只有底部树**：树里**双击**节点 → **确认框出现**（锚在节点附近），点「回跳」→ 执行回跳。
3. 树里**单击**节点 → 仍是选中 + 缩略图预览浮层（不变）。
4. 回跳失败时（如快照取不到）有可见提示，不静默。

## 6. 成色与风险

- 修法为**静态推导**（守卫矛盾 + 确认框不依赖弹层，均已读代码坐实），**未真机复现**。
- 真机验收：弹层关着，在底部树双击一个节点，看确认框是否出现。
- 低风险：守卫放宽一处 + 失败提示补一个 else 分支；回滚 = `git checkout` 桥 js + 重新部署。
