# ComfyUI-Hana 前端操作层：Agent 基于画布工作

## 目标

让 agent 和人基于**同一个 ComfyUI 前端画布**协作：
- agent 能感知画布当前状态（节点、连线、参数）
- agent 能修改画布（加节点、改参数、连线）
- agent 能触发执行（等效人点 "Queue"）
- 人和 agent 共享同一份 `window.app.graph`，无状态分裂

**约束：不修改 ComfyUI 本体源码和前端打包产物。**

---

## 架构

```
agent (comfyui tool, 新 actions)
    ↕
relay (comfy-relay.mjs, 新增路由 + WS 消息处理)
    ↕ HTTP (127.0.0.1:relayPort)
注入 JS (window.__hana_api, 运行时挂载)
    ↕ 直接调用
ComfyUI 前端 (window.app, LiteGraph)  ← 人也在用这个
    ↕ (原有)
ComfyUI 后端 127.0.0.1:8188
```

中继在代理前端 HTML 时，在 `</body>` 前 append 一段 `<script>`。
不修改 ComfyUI 的打包产物，只在运行时挂在已有的全局对象上。

## 1. 注入 JS（`hana-frontend-api.js`）

文件位置建议：`app-data/comfyui-hana/inject/hana-frontend-api.js`

```javascript
// hana-frontend-api.js
// 注入到 ComfyUI 前端，提供 agent 可操作的前端 API 层
// 由 comfy-relay 在代理 HTML 时 append

(function () {
  'use strict';

  // ---- 就绪等待 ----
  function waitApp() {
    return new Promise((resolve) => {
      const check = () => {
        if (window.app && window.app.graph) resolve(window.app);
        else setTimeout(check, 100);
      };
      check();
    });
  }

  // ---- 核心 API ----
  const api = {
    /**
     * 获取画布完整状态（UI 格式）
     * 返回: { nodes: [...], links: [...], version: 0.17 }
     */
    async getCanvas() {
      const app = await waitApp();
      return app.graph.toJSON();
    },

    /**
     * 获取画布的 API 格式（可直接 submit 的 prompt 对象）
     * 返回: { "1": { class_type, inputs }, "2": { ... }, ... }
     * 注意: 函数名需验证，可能是 app.graphToPrompt() 或 app.graphToAPIFormat()
     * 如果不存在，fallback: 手动遍历 nodes 构建
     */
    async getAPIFormat() {
      const app = await waitApp();
      // 首选: 前端自带的转换
      if (typeof app.graphToPrompt === 'function') {
        return app.graphToPrompt();
      }
      if (typeof app.graphToAPIFormat === 'function') {
        return app.graphToAPIFormat();
      }
      // fallback: 手动构建
      return buildAPIFromGraph(app.graph);
    },

    /**
     * 执行画布当前图（等效人点 Queue）
     * 返回: { prompt_id, status }
     */
    async execute() {
      const app = await waitApp();
      const [prompt, outputs] = app.graphToPrompt();
      const resp = await fetch('/prompt', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ prompt, front: true })
      });
      const data = await resp.json();
      return { prompt_id: data.id, status: resp.status };
    },

    /**
     * 添加节点
     * @param {string} classType - 节点类型 (如 "KSampler", "CLIPTextEncode")
     * @param {number} x - 画布 x 坐标
     * @param {number} y - 画布 y 坐标
     * 返回: { node_id }
     */
    async addNode(classType, x, y) {
      const app = await waitApp();
      const constructor = LiteGraph.LiteGraph.Node.prototype.constructor;
      // 通过前端已有的节点构造器
      const node = app.createNode(classType);
      if (!node) return { error: 'unknown class_type: ' + classType };
      node.pos = [x, y];
      app.graph.add(node);
      return { node_id: node.id };
    },

    /**
     * 设置节点输入参数
     * @param {number} nodeId
     * @param {string} inputName
     * @param {*} value
     */
    async setWidget(nodeId, inputName, value) {
      const app = await waitApp();
      const node = app.graph.getNodeById(nodeId);
      if (!node) return { error: 'node not found: ' + nodeId };
      const widget = node.widgets?.find(w => w.name === inputName);
      if (!widget) return { error: 'widget not found: ' + inputName + ' on node ' + nodeId };
      widget.value = value;
      return { ok: true };
    },

    /**
     * 连接两个节点
     * @param {number} fromNode
     * @param {number} fromSlot
     * @param {number} toNode
     * @param {number} toSlot
     */
    async connect(fromNode, fromSlot, toNode, toSlot) {
      const app = await waitApp();
      const from = app.graph.getNodeById(fromNode);
      const to = app.graph.getNodeById(toNode);
      if (!from || !to) return { error: 'node not found' };
      const output = from.outputs[fromSlot];
      const input = to.inputs[toSlot];
      if (!output || !input) return { error: 'slot not found' };
      const link = app.graph.connect(from, fromSlot, to, toSlot);
      return { link_id: link ? link.id : null };
    },

    /**
     * 断开连线
     * @param {number} linkId
     */
    async disconnect(linkId) {
      const app = await waitApp();
      const link = app.graph.links.get(linkId);
      if (!link) return { error: 'link not found: ' + linkId };
      app.graph.removeLink(linkId);
      return { ok: true };
    },

    /**
     * 删除节点
     * @param {number} nodeId
     */
    async removeNode(nodeId) {
      const app = await waitApp();
      const node = app.graph.getNodeById(nodeId);
      if (!node) return { error: 'node not found: ' + nodeId };
      app.graph.remove(node);
      return { ok: true };
    },

    /**
     * 保存画布到 ComfyUI 的 userdata/workflows/
     * @param {string} name - 工作流文件名（不含 .json）
     */
    async saveWorkflow(name) {
      const app = await waitApp();
      const json = app.graph.toJSON();
      const resp = await fetch('/userdata/' + encodeURIComponent(name) + '.json', {
        method: 'PUT',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(json)
      });
      return { status: resp.status, saved: resp.ok };
    },

    /**
     * 加载工作流到画布（替换当前画布）
     * @param {string} name
     */
    async loadWorkflow(name) {
      const app = await waitApp();
      const resp = await fetch('/userdata/' + encodeURIComponent(name) + '.json');
      if (!resp.ok) return { error: 'load failed: ' + resp.status };
      const json = await resp.json();
      app.graph.clear();
      app.graph.fromJSON(json);
      return { ok: true, nodeCount: app.graph.nodes.length };
    },
  };

  // ---- fallback: 手动构建 API 格式 ----
  function buildAPIFromGraph(graph) {
    const result = {};
    for (const node of graph.nodes) {
      if (node.mode === 4) continue; // 跳过 muted 节点
      const inputs = {};
      for (const w of (node.widgets || [])) {
        inputs[w.name] = w.value;
      }
      for (const input of (node.inputs || [])) {
        const linkId = input.link;
        if (linkId) {
          const link = graph.links.get(linkId);
          if (link) {
            const fromNode = graph.getNodeById(link.origin_id);
            if (fromNode) {
              inputs[input.name] = [fromNode.id, link.slot];
            }
          }
        }
      }
      result[node.id] = { class_type: node.type, inputs };
    }
    return result;
  }

  // ---- 挂载 ----
  window.__hana_api = api;
  window.__hana_api_ready = true;

  // 调试: 控制台可见
  console.info('[hana-frontend-api] injected, window.__hana_api available');
})();
```

### 待验证项

| 项 | 说明 |
|---|---|
| `app.graphToPrompt()` 返回签名 | 前端版本不同可能返回 `[prompt, outputs]` 或仅 `prompt`。需实测确认 |
| `app.createNode(classType)` | 部分版本可能叫 `LiteGraph.createNode` 或通过 `app.nodeTypes` 查。需实测 |
| `LiteGraph` 全局是否可用 | 前端打包后 `LiteGraph` 可能挂在 `window.LiteGraph` 或模块内部。fallback 路径不依赖它 |

| 节点 `mode === 4` | LiteGraph 中 muted 节点的值可能是 `NODE_MODE.MUTED`。需确认枚举值 |

## 2. Relay 路由（`comfy-relay.mjs` 新增）

在 `comfy-relay.mjs` 中新增以下处理逻辑（不改动现有 WS 代理和 HTTP 代理）：

```javascript
// ---- 新增: 前端 API 代理 ----

// 2a. 在代理 HTML 响应时 append 注入脚本
function injectScript(html) {
  const script = fs.readFileSync(INJECT_JS_PATH, 'utf-8');
  const tag = `<script>${script}</script>`;
  if (html.includes('</body>')) {
    return html.replace('</body>', tag + '\n</body>');
  }
  return html + tag;
}

// 2b. 新增路由: GET /comfyui-hana/canvas
//     前端执行 __hana_api.getCanvas() 并返回
// 实现: 向已连接的前端 WS 发送指令，等回传
async function handleCanvasRequest(ws, timeoutMs = 3000) {
  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => reject(new Error('canvas timeout')), timeoutMs);
    const msgId = 'hana_canvas_' + Date.now();

    const handler = (data) => {
      const msg = JSON.parse(data);
      if (msg.id === msgId) {
        clearTimeout(timer);
        ws.on('message', handler); // 移除
        resolve(msg.payload);
      }
    };
    ws.on('message', handler);
    ws.send(JSON.stringify({ type: 'hana_exec', id: msgId, call: 'getCanvas' }));
  });
}

// 2c. 新增路由: POST /comfyui-hana/frontend
//     通用前端操作: { op: "addNode|setWidget|connect|...", args: [...] }
async function handleFrontendRequest(ws, body, timeoutMs = 3000) {
  const { op, args } = body;
  const allowed = ['addNode', 'setWidget', 'connect', 'disconnect',
                    'removeNode', 'execute', 'getCanvas', 'getAPIFormat',
                    'saveWorkflow', 'loadWorkflow'];
  if (!allowed.includes(op)) {
    return { error: 'unknown op: ' + op };
  }
  const msgId = 'hana_fe_' + Date.now();
  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => reject(new Error('frontend op timeout')), timeoutMs);
    const handler = (data) => {
      const msg = JSON.parse(data);
      if (msg.id === msgId) {
        clearTimeout(timer);
        resolve(msg.payload);
      }
    };
    ws.on('message', handler);
    ws.send(JSON.stringify({ type: 'hana_exec', id: msgId, call: op, args }));
  });
}

// 2d. 前端侧 WS 执行桥（注入 JS 的另一半，或并入 hana-frontend-api.js）
//     监听 relay 发来的 hana_exec 消息，调用 __hana_api 方法，回传结果
```

**前端侧 WS 执行桥**（并入 `hana-frontend-api.js` 末尾）：

```javascript
// ---- WS 执行桥 ----
// 监听 relay 通过 WS 发来的 hana_exec 指令，执行 __hana_api 方法，回传结果
(function () {
  function waitForWS() {
    return new Promise((resolve) => {
      const check = () => {
        if (window.app?.canvas?.ws || window.__hana_ws) resolve();
        else setTimeout(check, 200);
      };
      check();
    });
  }

  // ComfyUI 前端有自己的 WS 连接到后端
  // 中继需要拦截这个 WS 或在旁边开一条独立 WS
  // 方案: 中继在 HTML 中注入一个独立 <script> 建立到 relay 的 WS
  // 见下方 "独立 WS 通道" 说明
})();
```

### 独立 WS 通道（关键设计决策）

ComfyUI 前端已有的 WS 是连 8188 后端的，中继不能直接复用。
注入 JS 需要一条**独立的 WS 连到 relay**：

```javascript
// 注入 JS 中建立独立 WS 到 relay
const relayWs = new WebSocket(`ws://${location.host}/comfyui-hana/ws`);
relayWs.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  if (msg.type === 'hana_exec') {
    const method = window.__hana_api[msg.call];
    if (method) {
      method(...(msg.args || []))
        .then(result => relayWs.send(JSON.stringify({ id: msg.id, payload: result })))
        .catch(err => relayWs.send(JSON.stringify({ id: msg.id, payload: { error: String(err) } })));
    } else {
      relayWs.send(JSON.stringify({ id: msg.id, payload: { error: 'unknown method: ' + msg.call } }));
    }
  }
};
window.__hana_ws = relayWs;
```

relay 端对应：

```javascript
// relay 新增 WS endpoint: /comfyui-hana/ws
// 接受前端注入脚本的连接，用于 hana_exec 消息往返
wsServer.on('connection', (ws, req) => {
  if (req.url === '/comfyui-hana/ws') {
    // 存储引用，供 handleCanvasRequest / handleFrontendRequest 使用
    frontendWs = ws;
  }
});
```

## 3. comfyui 工具新增 actions

在 `comfyui` 工具的 action 枚举中新增：

| action | 参数 | 说明 |
|---|---|---|
| `canvas` | 无 | 返回画布完整状态（UI 格式 JSON） |
| `frontend` | `op`, `args[]` | 通用前端操作（addNode / setWidget / connect / execute / saveWorkflow / loadWorkflow 等） |

`execute` 操作通过 `frontend` action 实现，不单独开 action：

```
comfyui(action="frontend", op="execute")  →  等效人点 Queue
comfyui(action="canvas")                  →  感知画布
comfyui(action="frontend", op="addNode", args=["KSampler", 400, 300])  →  加节点
comfyui(action="frontend", op="setWidget", args=[1, "steps", 30])     →  改参数
```

## 4. 人 agent 共存

- 人和 agent 操作的是**同一个 `window.app.graph`**
- agent 加个节点，人立刻在画布上看到
- 人改了参数，agent `action="canvas"` 读到的是最新值
- agent 执行走 `graphToPrompt()` → `/prompt`，跟人点 "Queue" 同一条路径
- 没有第二份状态，不存在分裂

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 前端加载时序：`window.app` 未就绪 | `waitApp()` 轮询 + 超时；relay 侧 3s 超时返回 "canvas not ready" |
| 前端大版本更新导致 API 签名变化 | 注入 JS 做成可热替换文件；`buildAPIFromGraph` fallback 不依赖前端内部方法 |
| 人 agent 并发编辑冲突 | LiteGraph 无锁，但操作是离散的（一次改一个节点），实际冲突概率极低；极端情况画布可回滚（前端有 undo） |
| 独立 WS 连接被前端刷新断开 | relay 检测到 WS 断开后，下次 HTML 代理时重新注入；agent 操作超时返回明确错误 |
| 安全：注入 JS 可被前端其他脚本看到 | 本地 127.0.0.1 环境，无外部暴露；`__hana_api` 命名带下划线前缀避免与前端全局冲突 |

## 9. 补充研究：官方 Extension 机制（优先于 raw injection）

### 发现

ComfyUI 有**正式的前端 extension 机制**，比 raw HTML injection 更稳定：

- 创建 ComfyUI custom node 包，`__init__.py` 导出 `WEB_DIRECTORY`
- 前端自动从 `web/` 目录加载 JS 文件
- 通过 `app.registerExtension({...})` 注册 hook
- **monkey-patching / hijacking 已被官方标记 deprecated**

### 推荐实现方式

```
comfyui_hana_bridge/
├── __init__.py          # 极简: 只导出 WEB_DIRECTORY
│   from pathlib import Path
│   WEB_DIRECTORY = str(Path(__file__).parent / "web")
│   __all__ = []
├── web/
│   └── js/
│       └── hana-bridge.js   # 全部逻辑在这里
```

`__init__.py` 零 Python 逻辑，只是让 ComfyUI 知道有一个前端 JS 要加载。
所有能力实现都在 `hana-bridge.js` 中，通过 `registerExtension` 正式注册。

### 优势对比

| | Raw HTML injection | 官方 Extension |
|---|---|---|
| 稳定性 | 依赖中继 HTML 代理正确性 | ComfyUI 自带加载机制，前端原生支持 |
| 版本兼容 | 前端大版本可能改变 HTML 结构 | extension API 是稳定的公共接口 |
| 可发现性 | 用户看不到注入了什么 | 在 ComfyUI 的 extension 列表中可见 |
| 热替换 | 改注入文件即可 | 改 JS 文件即可，reload 前端生效 |
| 依赖 | 需要中继做 HTML 改写 | 只需把包放到 ComfyUI 的 custom_nodes/ 目录 |

### 结论

**优先走官方 extension 机制。** relay 不需要做 HTML injection，只需提供 WS endpoint 供 extension JS 连接。extension 在 `setup()` hook 中建立到 relay 的独立 WS，后续指令走这条 WS。

## 10. 能力矩阵（完整操作列表）

### A. 感知（读状态）

| 操作 | 方法 | 说明 |
|------|------|------|
| 读画布完整状态 | `app.graph.toJSON()` | UI 格式：nodes + links + widgets |
| 读画布 API 格式 | `app.graphToPrompt()` | 可直接 submit 的 prompt 对象 |
| 读执行中节点 | `app.runningNodeId` | 当前执行到哪一步 |
| 读执行历史 | `/history` API | 每次提交的完整 prompt + 结果 |
| 读队列状态 | `app.ui` / `/queue` | 待执行/执行中任务 |
| 读节点类型列表 | `/object_info` | 所有可用节点及其参数 schema |
| 读图片结果 | `/view` | 执行产出的图片 |

### B. 修改（写画布）

| 操作 | 方法 | 说明 |
|------|------|------|
| 添加节点 | `app.createNode(type)` + `graph.add(node)` | 等效人双击画布 |
| 删除节点 | `graph.remove(node)` | 等效人选中删除 |
| 设置参数 | `node.widgets.find(w).value = x` | 等效人改输入框 |
| 连线 | `graph.connect(from, slot, to, slot)` | 等效人拖连线 |
| 断线 | `graph.removeLink(linkId)` | 等效人点击断开 |
| Mute 节点 | `node.mode = 4` | 等效人右键 mute |
| Undo/Redo | `app.graph.undo()` / `app.graph.redo()` | 等效人 Ctrl+Z |
| 视图操作 | `app.canvas.scale` / `offset` | 缩放平移（非必须） |

### C. 执行

| 操作 | 方法 | 说明 |
|------|------|------|
| 执行画布 | `app.graphToPrompt()` → POST `/prompt` | 等效人点 "Queue Prompt" |
| 中断执行 | POST `/interrupt` | 等效人点 "Interrupt" |
| 清队列 | POST `/queue` | 清空待执行 |

### D. 文件操作

| 操作 | 方法 | 说明 |
|------|------|------|
| 保存工作流 | POST/PUT `/userdata/{name}.json` | 等效人 Ctrl+S |
| 加载工作流 | GET `/userdata/{name}.json` → `graph.fromJSON()` | 等效人 Load |
| 列工作流 | GET `/userdata/` | 列目录 |

### E. 不需要的操作

| 不需要的 | 原因 |
|----------|------|
| 像素级画布渲染 | agent 读结构化 JSON，不需要"看到"画布 |
| 鼠标/键盘事件模拟 | 直接调底层方法，等效但不经过输入设备 |
| DOM 操作 | 不需要点按钮，调 `app.queuePrompt()` 就够 |
| 前端 CSS/布局 | agent 不关心视觉呈现 |
| 拖拽动画 | 不需要模拟视觉过渡 |

## 11. 人 agent 共驾：需求点与实现

### 场景 1：人画布，agent 读并建议

- 人自由操作画布
- agent `action="canvas"` 读当前状态
- agent 分析（比如"这个采样器 steps 太低"），给出建议
- 人决定是否采纳

**实现**：只需 `getCanvas` + agent 侧推理。无需写操作。

### 场景 2：agent 改参数，人确认

- agent `action="frontend", op="setWidget", args=[id, "cfg_scale", 5.0]`
- 人立刻在画布上看到参数变了
- 人如果不同意，Ctrl+Z 回退

**实现**：`setWidget` + LiteGraph undo 天然支持回退。

### 场景 3：agent 执行，人看结果

- agent `action="frontend", op="execute"`
- 前端自动显示进度（原有 WS 事件驱动）
- 人看到出图

**实现**：`execute` 走 `graphToPrompt` → `/prompt`，前端原有进度显示自动工作。

### 场景 4：人执行，agent 看进度

- 人点 "Queue"
- 前端 WS 收到 `executing` 事件
- relay 转发给 agent
- agent 知道当前在执行什么

**实现**：relay 已有 WS 事件代理（原有功能），agent 通过 `action="status"` 读。

### 场景 5：agent 建图，人接手

- agent 从 scratch 建一个工作流（addNode + connect + setWidget 序列）
- 人看到完整图出现
- 人接手微调

**实现**：agent 序列操作，人在画布上实时看到节点逐个出现。

### 场景 6：冲突处理

- 人和 agent 同时改同一节点
- 概率低（操作离散），但可能发生
- 缓解：agent 操作前 `getCanvas` 确认最新状态，不盲写
- 极端情况：人 Ctrl+Z 回退
