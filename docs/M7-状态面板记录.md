# M7 · 状态面板（显存释放 + GPU/CPU/内存图表）记录

**日期**：2026-09-22
**版本**：v0.3.0 → v0.4.0
**需求**：整页工作区左侧栏（functionPanel「ComfyUI 状态」）加两个功能——
① 显存释放按钮（语义对齐 llama 监视器的「清空 GPU 缓存」）；② GPU/CPU/内存实时状态图。

## 实现

| 层 | 改动 |
|---|---|
| 中继 `runtime/comfy-relay.mjs` | 新增 `GET /_relay/metrics`：GPU 走 nvidia-smi（4s 缓存 + `CHILD_ENV` 补环境，llama-monitor 同款踩坑修复）、CPU 走 os.cpus 间隔采样（1.5s 定时器）、内存走 os.totalmem/freemem |
| app `index.js` | 新增 `GET /comfyui-hana/metrics`（透传中继）、`POST /comfyui-hana/release`（经中继反代后端 `/free`，body `{unload_models,free_memory}`）|
| 面板 `ui/panel.html` + `ui/assets/panel-status.js` | 图表区六条曲线（GPU 利用率/显存/温度/功耗 + CPU + 内存，任务管理器风格右对齐滚动，60 点窗口，1s 轮询）+「释放显存」按钮（内联反馈：释放中/已释放/失败）|

## 关键决策：零新增能力

- 最初按 llama-monitor 思路准备加 `app/process.spawn`（宿主侧采 GPU）。实测推翻：**受管 runtime 的 local-machine profile 自己就能跑 nvidia-smi**（llama-monitor 引擎 `/status` 返回完整 GPU 且 `gpuSource` 为空 = 引擎侧自采成功），故采集放中继，**capabilities 与 network 声明零变更**，reload 不触发权限审批。
- 「释放显存」只做 ComfyUI 自己的 `/free`，**不越界杀 llama/kvmem 进程**（那是 llama 监视器的职责）。

## 实测发现（重要）

- release 前后显存 **11732 MiB → 11732 MiB 无变化**。原因是**当时的显存大头不在 ComfyUI**：
  - ComfyUI 的 `/system_stats` 显示 `torch_vram_total ≈ 32 MiB`（基本没占）；
  - 12GB 卡上占大头的是常驻的 `llama-kvmem-server.exe`（27B + 200K ctx）。
  - 结论：功能正常（后端确实收到 /free），只是当时无模型可卸。跑过 Qwen-Image 等大模型后再点，才会看到回落。
- 边界：本按钮只管 ComfyUI 侧；要和 llama 抢显存时，llama 侧去 llama 监视器释放。
