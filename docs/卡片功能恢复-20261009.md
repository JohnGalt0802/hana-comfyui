# 卡片功能恢复 · 方案（2026-10-09）

## 背景与动机
- v0.11.1（`12bbc05`）"卡片中心精简"执行偏差：**意图**＝卡片中心不列多余卡；**实际**＝连"流内任务卡功能"一并删除（`task.html`/`task.js`/`envcheck` 卡页删除、`index.js` 的 `details.card`/`cardInstanceId` 全移除、`/comfyui-hana/task` 路由移除、manifest 卡注册移除）。
- 用户裁定（2026-10-09）：**恢复原有卡片功能；多余的卡不进卡片中心。**
- 参照物（"妥善解决"）：hana-downloader-app —— `contributes.cards` 只留常驻卡（下载管理器）；任务卡走**工具返回值 `details.card` + `details.bridgedTool` + 稳定 `cardInstanceId`**（宿主 0.978.0+ 原生支持），随工具调用实时内联在聊天流。

## 设计（照下载器姿势）
1. **submit / 画布执行（canvas.queue）回执**：恢复 `details.card`（含 `bridgedTool`）——title「ComfyUI 生成 · {label}」、route `/task.html`、稳定 `cardInstanceId = sha256(appId:promptId)` 前 20 位（`a_` + hex）。
2. **envcheck 卡**：`service envcheck` 在 GPU 阻断时恢复 `details.card`（route `/envcheck.html`，title「检测到其他模型占用 GPU」）。
3. **卡页与数据源**：恢复 `ui/task.html` + `task.js`、`ui/envcheck.html` + `envcheck.js`（以 `12bbc05^` 为功能蓝本，按宿主主题与现行 SDK 适配）；恢复 `/comfyui-hana/task` 路由；卡片 route 为静态页、不带 query。
4. **manifest 不动**：不加 `contributes.cards` 注册——卡片中心保持干净（工作区卡维持现状）。
