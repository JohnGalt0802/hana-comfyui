# hui 相比 cui 的增强与实效 · 总结（2026-10-09）

> 缘起：John「现在总结一下 hui 相比单纯 cui，多了哪些功能，做了哪些 agent native 优化，以及这些优化能否落到实处提高效率」。
> 对照物：**cui＝裸的 ComfyUI**（官方界面 + custom_nodes 那一侧）；**hui＝Hana-ComfyUI 集成层**。

## 一、功能增量（三层）

**① 界面层（人用）**：官方前端零改造进 Hana（整页卡 / 拆窗 / 原生窗），主题跟随宿主色板；左侧状态面板（GPU/CPU/内存曲线、释放显存）；顶栏服务控制。对比裸 cui：不用切浏览器、管家统一。

**② 调度层（agent 的核心增量——裸 cui 对 agent 完全封闭）**：
- 任务桥：一句话提交（三形态/参数注入）→ 宿主正式任务 + 任务卡 + 完成回执；查询/取回/取消/上传；4MiB+ 大工作流可交（M13）。
- 画布共驾：agent 直接读/改人正在看的同一张画布。读——摘要/全量/体检/追踪/大纲/diff；写——改参/加删节点/连线/保存/专属 undo/patch 事务/排布/装载/执行/复制/锁与高亮。
- 画布语义层：把"图"翻译成 agent 能懂的结构（体检清单、连线路由、功能块大纲、投影裁剪、语义 diff）。
- 多页面定向：多张画布并存时按工作流/实例精确投递，不误伤别页。
- 工作区自开 + 画布移交：agent 需要画布时自己开窗干活；干完「放入 hui 画布」，秒级送回主工作区（2026-10-09 实测 335ms）。
- 副驾驶（共编）机制：写闸门（未开副驾驶不可写）、授权总闸、规则（先复制副本；改动可视化）。

**③ 环境层**：服务全生命周期（计划任务拉起、独立于 Hana 存活、起停/体检/清理/就绪等待）；环境自举（缺服务/缺窗口自动补齐再继续）；安装引导；本体一键更新；大文件提交绕宿主隧道限制。

## 二、agent native 优化（为 agent 而设计）

纲领（2026-09-29，John 定）：**agent 的每一步都要发生在"人能看、能接、能改"的地方**（人机共驾）。围绕它：

1. 手与眼：同一张画布的完整读写 + 语义层（看懂优先于看全）。
2. 身份与边界：写闸门/授权总闸防越位；「用户主动」与「agent 代理」分界（画布移交绕写闸门的理由＝「用户亲手点的放入」）。
3. 失败即指引：停下必给「原因＋选项＋去哪处理」，不硬闯、不干等。
4. 自举：干活的路径上没有「先请人开门」。
5. 行动经济学：快返（不原地等待）、任务可查可取消、产物自动回流。
6. 提示词即工程：工具描述与技能手册把操作纪律内嵌进 agent 语境。

2026-10-09 晚新增：点击＝事件直达（335ms）、非破坏加入（不碰当前画布）、兜底哨兵＋工具面三态处置表。

## 三、能否落到实处、提高效率（成色分层）

**已实测、有证据**：

| 链 | 证据 |
|---|---|
| 任务提交/回执/取回 | 宿主段 17/17；多轮真机；4.57MB 大工作流 E2E |
| 画布共驾读写 | 多轮真机（尺寸改造/装载/排布/追踪/副驾闸门） |
| 环境自举 | 2026-10-09：服务缺→自举拉起（约 49s）；授权缺→停下给选项 |
| 工作区自开 | 2026-10-08 首秀；2026-10-09 开窗 5 次以上 |
| 画布移交 | 2026-10-09 全链：26s（哨兵）→ 335ms（定向直发） |
| 语义层 | 2026-09-28 全链验收；后续各批桩测全过 |

**落到实处的「省」**：省沟通（不截图不口述）｜省手工（环境/窗口/服务自举）｜省猜错（失败有码有指引）｜省来回（产物＋回执自动回流）｜省打架（定向单发、写闸门、专属 undo）。

**欠账（诚实列）**：
- 画布移交收尾未决项：快照来源竞态；新页成为活动页的「切视图」；跨实例广播非常态。
- 副驾驶「先开授权再开副驾驶」仍嫌绕。
- 效率的**量化**欠账：目前为定性＋单点数据（335ms/49s/26s），缺体系化对比测度（如「完成一张图 vs 裸 cui 少几步」）——宜列后续评估项。

**结论**：三条主链的「省步骤、省沟通、省手工」已有实测支撑；最新一轮把画布移交从「能」推到「顺」（秒级、当场可见）；离「量化证明」还差一个评估。
