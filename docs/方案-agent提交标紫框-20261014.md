# 方案 · Agent 发起的提交标记为 source=agent（紫框）（2026-10-14）

> **用户诉求**：Agent 通过工具提交画布时，提交历史节点应显示为**紫框**（agent 来源），非蓝框（user）。

---

## 1. 现状（实测 + 查码）

**实测**：用 agent 通道（`canvas.queue`）提交一次，落盘记录 `source=user`（蓝框），非紫框。

**根因（三处）**：
1. `reportHistoryCommit` 的唯一调用（桥 L2683）**没传 `source`** → 默认 `"user"`。
2. `changeSource`（"agent"/"user"/"system"）只用于**画布变更记录**（`changes[]`），且在写 op 的 `finally` 立即复位（L6140）——与提交上报是**两套东西**。
3. `canvas.queue` **不在 `WRITE_OPS`**，执行时 `changeSource` 已是 `"user"`。

→ 当前任何提交都记 `user`；`source`/`kind` 是"为 P8 agent 通道预留"（L2753）但**未接线**。

---

## 2. 修法：给提交单独一个来源标志

**新增模块级标志**（放在 `changeSource` 声明附近，L122）：
```js
// 提交来源（2026-10-14）：与 changeSource（画布变更来源）分开——本标志标记「谁发起了这次运行」。
// canvas.queue（Agent 工具执行）置 "agent"；用户点运行 / Ctrl+Enter 走前端原生，保持 "user"。
let historyCommitSource = "user";
```

**`canvas.queue` op**（桥 L1830）——置位/复位（复用现有 try/finally）：
```js
    const prevCommitSource = historyCommitSource;   // 保存现场（防嵌套）
    historyCommitSource = "agent";                  // ← Agent 发起的执行
    try {
      await app.queuePrompt(front ? -1 : 0, 1);
    } finally {
      api.queuePrompt = orig;
      historyCommitSource = prevCommitSource;       // ← 复位
    }
```

**常驻提交包装**（`api.queuePrompt` 包装，桥 L2660 区）——上报时带上标志：
```js
        void reportHistoryCommit({ graph, promptId, blocks, source: historyCommitSource });
```

**时序正确性**（关键，已在脑中跑过）：
- setup 时 `api.queuePrompt = 常驻包装(native)`。
- `canvas.queue` 执行：`orig = api.queuePrompt`（= 常驻包装）→ 临时替换为捕获包装 → 调 `app.queuePrompt` → 命中捕获包装 → 调 `orig`（常驻包装）→ **常驻包装读 `historyCommitSource`（此刻 = "agent"）** → 上报。
- `canvas.queue` 的 `finally` 在整条链 `await` 完成后才复位 → 上报发生在复位**之前**。✅

**用户原生提交**（点运行 / Ctrl+Enter）：不经 `canvas.queue` → 标志保持 `"user"` → 蓝框（不变）。✅
