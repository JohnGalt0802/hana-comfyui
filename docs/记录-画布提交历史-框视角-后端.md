# 记录-画布提交历史-框视角-后端

## 背景

提交历史弹层现在每条提交都显示在所有框里。需求：**每个框只显示"碰过自己"的提交**。
筛选原料已在数据里，不需要新打 tag：

- 每条 entry 有 `delta`（`{changed:[{id,...}], added:[], removed:[]}`，P5b 起有；旧数据无）
- 每条 entry 有 `blocks`（`[{name, source, nodeIds:[...]}]`，P5a 起带 nodeIds；旧数据只有 `{name,nodeCount}`）

算法：一条提交碰过框 B ⟺ `delta` 里 changed/added/removed 的任一节点 id ∈ `B.nodeIds`。

`_block_names_for_entry` 逻辑（严格照规格）：

```
delta = entry.delta; blocks = entry.blocks
if delta 非 dict → return None
if blocks 非 list → return None
hitIds = set()
for k in changed/added/removed: for x in delta[k]: if x.id 不为 None: hitIds.add(str(x.id))
names = []
for b in blocks:
    ids = b.nodeIds
    if ids 非 list → return None   # 有块但无 nodeIds = 旧数据
    if any(str(i) in hitIds for i in ids): names.append(b.name or "")
return names
```

补充的防御分支（不改变规格语义）：`blocks` 里项非 dict → `None`；`delta[k]` 非 list → 跳过该项；
`delta[k]` 里项非 dict → 跳过该项。

- **id 一律转字符串比较**（`str(...)`）：索引里 `nodeIds` 是 number，`delta` 里可能 number/string，统一避免类型坑。
- **只读计算，不落盘**：`list_commits` 不改索引磁盘内容（有单测守护）。
- 值加进 `list_commits` 返回的每条 entry（`normalize_entry` 的产物上）。

## `blockNames` 三种取值判定说明

| 取值 | 语义 | 触发条件 |
| --- | --- | --- |
| `null` | **无法判定** | `delta` 非 dict（旧数据/缺字段）；或 `blocks` 非 list；或 `blocks` 里任一项缺 `nodeIds` / `nodeIds` 非数组（旧数据只有 `{name,nodeCount}`） |
| `[]` | 有数据但**没碰任何框** | `delta` 是 dict 且 `blocks` 是 list 且每项都有 `nodeIds`；但 changed/added/removed 的 id 无一 ∈ 任何框的 nodeIds（含 `blocks=[]` 情形） |
| `[名字…]` | 命中的框名列表 | 同上数据完整，且至少一个 id 命中；按 `blocks` 顺序，`name` 缺省补 `""` |

判定用**原始索引行**（非 `normalize_entry` 产物）：`normalize_entry` 会把非 list 的 `blocks` 读成 `[]`、
把缺 `nodeIds` 的块补成 `[]`，会抹掉"旧数据"信号，故 `blockNames` 计算走原始 entry。

4. **`nodeIds` 与 `delta.id` 的语义边界**：算法假定 `blocks[].nodeIds` 是画布节点 id（number 语义），
   `delta` 的 id 同源。若桥侧传入的 `nodeIds` 未来改成非节点 id 体系（如组 id），匹配会失效——
   当前数据形态下二者同源，实测已验证正确。
