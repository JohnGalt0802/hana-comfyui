# M9 · ComfyUI 服务起停（启动 / 停止按钮）记录

**日期**：2026-09-23
**版本**：v0.5.0 → v0.6.0
**触发**：用户提问「comfyui-hana 左侧的『重试启动』按钮是做什么的？现在并没有一个拉起或撤下 ComfyUI 服务的按钮，加上这个按钮」。

## 一、先答原问题：「重试启动」到底做了什么

| 事实 | 位置 |
|---|---|
| 按钮只调 `POST /comfyui-hana/relay/start` | `ui/panel.html#p-retry`、`ui/workspace.html#btn-retry/btn-retry2` |
| 该路由只做一件事：`ensureManagedRuntime()` —— 重新拉起**中继**（受管 runtime，`runtime/comfy-relay.mjs`） | `app/index.js` `relay/start` |
| 与 8188 上的 ComfyUI 本体**无关** | 中继是 attach 模式，只反代不改被代理者 |

结论：它重启的是「Hana 里的那个通道」，不是「ComfyUI 服务」。文案有歧义，本轮正名为**「重启中继」**（保留原行为，补 title 说明）。

## 二、新增：服务起停（实测机制，不是推断）

### 补记（2026-09-23 深夜，用户点真按钮后的两处修复）

**问题 1：点启动会弹出一个可见 cmd 窗口。** 计划任务的 `/tr` 直接指向 `.cmd` 时，Windows 会开一个可见控制台
（实测：任务栏多了 `WindowsTerminal → C:\WINDOWS\SYSTEM32\cmd.exe`）。
**修**：再生成一个 `backend-launcher.vbs`，用 `WScript.Shell.Run "cmd /c ""<cmd>""", 0, False`（0 = 隐藏窗口）拉起，
任务改指向 `C:\Windows\System32\wscript.exe //B //NoLogo "<vbs>"`。vbs 内容全 ASCII（wscript 按 ANSI 读脚本，中文会乱）。
实测：启动后无任何带标题的 cmd/terminal/python 窗口，8188 正常就绪；任务 `Last Result: 0`（wscript 非阻塞，比旧法更干净）。

**问题 2：服务启动中的那 30～90 秒，工作区 iframe 直接把中继的 `{"error":"comfy-relay: ComfyUI 后端不可达","code":"BACKEND_UNREACHABLE"}` 当页面渲染。**
（用户点「启动服务」后看到的正是这个，其实服务正在起。）
**修**：工作区新增 offline 覆盖层（不透明，盖住 iframe）：「ComfyUI 服务未运行」+〔启动服务 / 安装引导 / 刷新工作区〕
+ 安装根、上次拉起时间、已等待秒数、上次错误；服务可达后自动收起并重新对齐主题。原「未安装自动弹引导」改为覆盖层按钮（不再自动弹窗）。

### 为什么必须绕「计划任务」这一圈

中继进程由宿主以 `hana-win-sandbox.exe --normal-token-job` 包裹（受限令牌 + job object）。实测（2026-09-23）：

| 实验 | 结果 |
|---|---|
| 沙箱内 `child_process.spawn` / `spawnSync` 是否被权限模型拦 | **可用**（无 `ERR_ACCESS_DENIED`；中继 cmdline 无 `--permission`，与 app 主进程不同） |
| 沙箱内 spawn 长命子进程（`detached: true` + `unref`），父退出后是否存活 | **不存活**（job 连带回收；detached 逃不出去） |
| 用计划任务（`schtasks /create` + `/run`）拉起进程，沙箱退出后 | **存活**（Task Scheduler 以当前用户身份起，天然脱离 job） |
| 受限令牌下调 `taskkill /PID <pid> /T /F` 终止上述进程 | **成功**（8188 停服） |
| WMI `Win32_Process.Create` | **失败**（ReturnValue 9）——弃用 |

所以：**启动 = 计划任务，撤下 = taskkill**。服务因此独立于 Hana 存活（Hana 重启/退出都不影响它），这也符合「服务是长时间驻留、抢显存的主角」这个事实。

### 实现

| 层 | 改动 |
|---|---|
| 中继 | `POST /_relay/backend/start`（controlKey）：`probeEnv`+`customRoots` → 安装根 → venv python → 写启动器 `logs/backend-launcher.cmd` → `schtasks /create /tn HanaComfyUI-Backend /sc once /st 00:00` + `/run`；服务日志 `logs/backend.log`<br>`POST /_relay/backend/stop`（controlKey）：`netstat -ano` 找 8188 LISTENING PID → `taskkill /T /F` → 删启动器任务 → 复核可达性<br>`GET /_relay/backend/proc`：进程态（安装根/python/mainPy/pids/日志/上次错误/上次停止）<br>`/_relay/status` 的 `backend.proc` 带同一份数据（面板数据源）<br>状态持久化 `logs/backend-state.json`（跨中继重启保留） |
| app | 路由 `POST /comfyui-hana/backend/start`、`POST /comfyui-hana/backend/stop`、`GET /comfyui-hana/backend`；工具新增动作 `comfyui(action="service", op=status|start|stop[, path])` |
| UI | 左侧面板按钮组「启动服务 / 停止服务」（按可达性二选一显示，停止需二次确认）；「重试启动」→「重启中继」；工作区顶栏 warn 条 `[启动服务][重启中继]` |
| 文档 | SKILL.md 新增「启动 / 停止 ComfyUI 服务」小节 + 区分中继与服务的口径；工具手册与排错表补条目 |

### 踩坑（实测，已修）

1. **启动器路径含空格必须给 `/tr` 加引号**：`C:\Users\John Galt\...` 这种路径，schtasks 存任务 XML 时不会自己加引号 → 任务 Last Result `-2147024703`（`0x800704C1`）失败；改成 `"/tr", '"' + launcher + '"'` 后任务 Running、服务正常起来。
2. **`/st 00:00` 的 WARNING 无害**：`Task may not run because /ST is earlier than current time.` 是提示当天该时刻已过 —— 正是我们要的（只用 `/run` 手动触发，不要自动定时拉起）。
3. **撤下前强制重查端口**：`pidCache` 有 5s TTL，停止路径里先清缓存再查，避免「端口有监听但 HTTP 不响」时撤不掉。
4. **`proc.pids` 不再依赖可达性**：启动中的中间态（端口已监听、HTTP 未就绪）也要能看见进程，否则面板只会说「不可达」而无从查。

## 四、口径

- **中继 ≠ 服务**：中继随 Hana 生命周期（面板「重启中继」管它）；ComfyUI 服务由计划任务拉起，独立存活（面板「启动/停止服务」管它）。
- 服务一旦由本入口拉起，中继重启不会带走它；反之，服务停掉后工作区 iframe 会显示前端离线，重新点「启动服务」即可。
- 停止是**按端口**找靶子（`netstat`），不依赖进程名，所以用户手工启动的 ComfyUI 也能被这个按钮撤下 —— UI 有二次确认文案（"会终止 8188 上的进程，正在跑的任务会中断"）。
