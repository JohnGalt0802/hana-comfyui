## 0. 一句话结论

agent 操作 hui 的**主链路已经通了**（装载／改参／体检／执行／取产物都跑得通），剩下的卡点集中在四处：**① 授权与页面身份"看不见、对不上"**；**② 一步走错就"假成功"（值错了却看不出来）**；**③ 回执／进度在若干路径上会断**；**④ 少数关键能力卡在宿主侧**。下一轮优化的主线，是**把"不可预期"变成"可预期"**，而不是加新功能。

## 1. 卡点全景（合并去重，按主题）

> 每条后括注来源编号：`K##`＝文档盘点项；`F#-#`＝链路摩擦点。

### A. 授权与页面身份（"能不能写、写在哪"不可预期）
- **A1 写操作硬闸**：写类 op 在当前活动页副驾驶未开时统一拒绝（仅 openWorkflow/duplicate/save/copilot 豁免）；两道闸（写授权 / 副驾驶总闸）**默认关**。（K26/F8-1/F8-2）
- **A2 `save` 另存换文件名 → 副驾驶按页失配、需重开**：副驾驶按 localStorage×页 path 记录，save 产生新 pageKey，装载后活动页已变 → 状态读为"关/未知" → queue 被 `copilot_off` 拒。**本次实操亲身踩到**（save 后 loadWorkflowFile 被拒）。（K19/F2-1〔待真机复核细节〕）
- **A3 副驾驶状态在工具面不可读**：state/summary/pages 均无 copilot 字段，被迫直 POST 桥。（K20/F8-3）
- **A4 页身份混杂/不可辨**：用户工作流页与 agent 副本页混列；空页未标 `empty`；dirty 拦截不带上下文（挡路页名/来源/时间）。（K23/K28/K29/F1-4）

### B. 假成功（值错了却看不出来）—— 最高危
- **B1 `submit` 带 `inputs` 或 inline 对象 → 结构豁免直走 backend（不经画布）**，而 backend 的 UI→API 转换**对原语节点丢值**、`LoadImageOutput` 回卷 → 出图"看着成了其实没成"。（K03/K22/F5-1）
- **B2 `check` 只查三类结构问题，查不出"值对不对"** → 值类正确性只能事后看产物，构成全程逐项核对的"信任税"。（K06/F4-2）
- **B3 行为不一致**：画布忙时 auto 报错退出，而 inline/inputs 却静默走 backend → agent 难预判走哪条路。（F5-3）

### C. 装载与页管理（"进了哪张画布"不可靠）
- **C1 openWorkflow「半成功」**：返回 opened:true 但画布未装载、留 dirty 脏态，卡住后续 loadWorkflowFile。（K18/F1-2）
- **C2 openWorkflow vs loadWorkflowFile 语义混用**（"打开"≠"装入"）。（K25/F1-3）
- **C3 name 路由无匹配页 → 静默 6s 超时**，报错文案与实况矛盾。（K24/F1-1）
- **C4 AgentCopy 副本名无限叠加** → 撞 400 超长被拒（已实锤）。（K21/F2-2）
- **C5 不能指定"新开页装载"**：只能占用当前活动页，与用户页耦合。（K25/F1-5）

### D. 回执与进度（"跑没跑、跑到哪"会断）
- **D1 子代理会话 next-step 永不自动送达**（宿主投递只写桌面会话）。（F6-1）
- **D2 reload 断工具 RPC**：处置阶梯＝路由级调用 → 等 1~2 回合 → 重启宿主（终解）→ 禁反复 reload。（K32/F7-2，本次实测需重启宿主）
- **D3 宿主重启后"工具目录缺 app 工具"**（≠RPC 断），切会话恢复。（F7-4）
- **D4 canvas.queue 无任务卡/无进度 op**，执行中 agent 盲区。（K27/F5-2/F6-3）
- **D5 queue 的 promptId 依赖猴补＋差集**，拿不到时不回传。（K12）

### E. 画布语义层深度（能做，但硌手）
- outline 无下钻（K05）／check 弹药不足（K06，同 B2）／trace 单步（K07）／选择器无邻接（K08）／块识别缺第三级（K09）／返回协议未统一（K10）／undo 撤不动 agent 改动且栈 20 步（K13）／静默截断若干（K14）／视觉包裹只覆盖 3 op（K15）／桥读不到总闸（K16）。
- 写向"建"短板：patch 无组操作/克隆/宏，从零搭图要手写几十条原子 edit（K02）；文件级语义通道缺失（K01）。

### F. 宿主侧（需宿主改动或用户决定）
- **F1 App 窗无防节流参数** → 切走/最小化约 5 分钟桥半死。（K36）
- **F2 整页卡程序化打开无入口**：三路径全证伪，`open-host` 已撤 → agent 拉不起工作区卡。（K37／踩坑 §38）
- **F3 用户不在场时画布流程不可用**（前端须在线）。（K30）
- F4 探活+唤醒哨兵未落地（K38）；"踹探针"保活待验（K39）。
- F5 目录级占用未根除 → 无法走 install+confirm 重装（K35）。

### G. 文档与口径
- **G1 文档-代码滞后**：旧文档称"`_frontends` 死条目无 TTL 未修""bridgeBuild 标签陈旧"，当前代码已含。（K17）

## 2. 根因归纳（为什么老硌）

1. **状态跨层、口径不一**：副驾驶状态存 localStorage（前端）、总闸在 app 层、桥读不到 → 谁都知道一半，agent 拼不出全貌（A1–A4 / K16）。
2. **"写"与"身份"绑死**：写操作按"当前活动页"判定，而"落到哪一页"又由 save/装载时序决定 → 一次顺序错位就失配（A2 / C1 / C4）。
3. **两个执行世界并存**：画布路径（值准、慢）与 backend 直提（快、值可能错）之间**切换不透明**，且后端转换器有已知值缺陷（B1 / B3）。
4. **校验只覆盖结构不覆盖值**：`check` 给不了"值对不对"，把正确性的责任全压到人／产物上（B2）。
5. **回执链有断点**：宿主任务卡与 next-step 只在桌面会话可靠，子代理会话静默丢；reload 又会打断当轮工具 RPC（D1/D2/D4）。
