# 实现记录：提示词增强开关接入 + 增强模型自动装卸（2026-10-23）

## 目标

`moss-image-SFT综合` 画布上原本有一个「提示词增强」模块（组⑥），但它与生图链路断开、且增强用的
llama-server（Gliese-Qwen3.5-9B-Abliterated-Caption Q8_0，端口 8080）需要人工点 #28 按钮加载 /
卸载。本次把它接进主链路，用一个开关控制是否先增强，并把模型的加载、卸载做成执行期自动动作。

## 画布结构（组⑥ 提示词增强｜开关接入）

```
#25 输入提示词（PrimitiveStringMultiline）
 ├─ on_false ──────────────────────────────┐
 └─ #29 增强模型·自动加载 (MOSSLLMAutoLoad) │
        ↓                                  │
    #26 PromptExpand（Qwen 扩写）           │
        ↓                                  │
    #30 增强模型·自动卸载 (MOSSLLMAutoRelease)
        ↓ on_true                          │
    #31 ⑦ 提示词增强开关 (ComfySwitchNode, switch=false)
        ├→ #4  CLIPTextEncode.text（正向提示词）
        └→ #27 ShowText（显示本次真正进图的提示词）
```

- 开关一开：先卸掉 ComfyUI 已加载模型 → 拉起 llama-server → 扩写 → 停 llama-server 释放显存 → 用增强文本生图。
- 开关一关：`ComfySwitchNode` 的 lazy 输入让整条增强链完全不执行（实测日志无任何 `moss-llm-auto` 记录、
  8080 端口未起），直接用 #25 原文生图。
- #27 挂在开关输出上，所以两种模式下它显示的都是「本次真正进图的提示词」。
- #28 MOSSGPUFree 保留为手动兜底（异常中断后残留 llama-server 时点掉）。

## 新节点（扩展在 `custom_nodes/moss-gpu-free/__init__.py`）

| node_id | 显示名 | 行为 |
|---|---|---|
| `MOSSLLMAutoLoad` | 增强模型 · 自动加载 | `unload_all_models` + `soft_empty_cache` + `empty_cache` → `load_llama(...)`（幂等：端口已在监听则不重复启动）→ 透传 text；加载失败抛 RuntimeError 中断执行，不静默降级 |
| `MOSSLLMAutoRelease` | 增强模型 · 自动卸载 | 按端口定位并结束 llama-server（不按进程名乱杀）+ 清 CUDA 缓存 → 透传 text |

`release_llama(port, stop)` 是新加的模块级函数；`GPUFreeExtension.get_node_list` 现返回
`[GPUFree, LLMAutoLoad, LLMAutoRelease]`。原有 `GPUFree`、三个 HTTP 路由、既有八个函数一行未动。

## 两条值得记住的结论

1. **执行顺序天然正确，不需要额外协调。** MOSS 的 loader 走 ComfyUI 的 dynamic VRAM staged 路径
   （日志 `prepared for dynamic VRAM loading ... Staged`），在真正使用前不实占显存；而 #4 需要开关
   的输出，所以增强链先跑完、llama 先释放，MOSS 才真正搬上卡。实测 = 增强前 VRAM 仅 1748 MiB。
2. **`ComfySwitchNode` 的 lazy 输入是这套方案成立的关键。** 它只求值被选中的那一路，因此关闭时
   增强链整段跳过——用普通 Primitive/reroute 那种「两路都算再选」的做法会每次都启动 llama。

  `[GPUFree]`，重启 ComfyUI。
