## 1. 小花副驾驶（邀请机制）

### 1.1 概念

- **默认态**：复制画布（不碰用户当前布）——"不告而取"防线；
- **副驾驶态**：用户主动开启 → agent 可**共同编辑同一画布**——"请而不来"的通道；
- 两者合起来 = 完整协议：**默认尊重，受邀共编**。
- 粒度：**画布级**（哪个布被邀请，就在哪个布共编）；
- 入口：**cui 界面画布栏**（前端是"这块布"的属性，最自然的归属）；
- 性质：**跨端功能**——hana app + cui 插件（hana_bridge 扩展）共同实现。

### 1.2 状态设计

- **保留策略**：**刷新后保留**（John 拍板；开着的意图不应因刷新蒸发）；
- 待定细节（实现期）：持有位置（前端 localStorage / 桥上报 / 双写）与多页粒度映射。

### 1.3 编辑可视化 [MARK · 展开后做]

- 方案（John 提出）：agent 编辑期间——
  - 画布**锁定变灰**；
  - agent 改动的**位置所在框与连线**恢复/变正常颜色；
  - **更改内容与参数黄色高亮**标注；
- 价值：① 防人机同时操作打架；② 清晰展示"哪些改动是 agent 做的"，经手分明；
- 关联想象（MARK）：**基于 markdown 的编辑历史可回溯**（git-like），留池 §5。

### 1.4 行为准则（→ 转 skill）

- 大动作（删节点、重排、换模型等）先说话；小动作（调参、试种子）直接做；
- **不必过于谨慎**（John 指示：尺度放宽，别谨小慎微）；
- 细则不写 AGENTS.md → **转为 cui 相关 skill**（见 §3）。

### 1.5 跨端架构

```
ComfyUI 前端（cui）┌─ hana_bridge 扩展：画布栏小花开关 UI + 每画布 copilot 状态
                   │    └─ 桥（/hana_bridge/call + state 上报）
Hana 侧（hui app）  └─ 读状态 → 决策：开 → 共编同页；关 → 复制副本
                        └─ agent 行为：按 skill 准则执行
```

## 2. 自动拉起服务

### 2.1 环境检查清单（第一步）

- 其他模型在跑？（llama-server / 小秘等已知服务）
- GPU 异常占用？（显存用量、占用进程）
- 内存水位异常？

### 2.2 卡片设计（发现异常时弹出）

| 按钮 | 行为 |
|---|---|
| 重试 | 重新执行检查 |
| 清除其他模型进程 | 按清单处理占用进程（**须列出进程名+PID+占用**；优先优雅停，防 supervisor 打地鼠） |
| 取消 | 放弃拉起 |

### 2.3 拉起与衔接（第二步）

- 环境无误 → 自动拉起 ComfyUI → **等就绪探测通过** → 前端操作；
- 拉起本身无破坏性，可全自动；"清除进程"有破坏性，须卡片确认。
