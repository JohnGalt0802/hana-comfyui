## 数据源契约（探索实测，可直接照写）

### 索引 `index.mcp.json`（597 KB，694 条模板）

顶层是 10 个分类对象组成的数组：

```jsonc
[{ "category": "Image", "description": "...", "templates": [ ... ] }, ...]
```

每条模板：

| 字段 | 必有 | 说明 |
|---|---|---|
| `name` | 是 | 与 `templates/<name>.json` 文件名一致 |
| `title` | 是 | 英文标题 |
| `task` | 是 | 如 `Text to Image` / `Image Edit` |
| `model` | 是 | 模型族名 |
| `freshness` | 是 | `new` / `recent` / `current` / `established` |
| `usage` | 是 | 使用量，可用于排序 |
| `recommend` | 是 | `highly_recommended` / `high` / `top` 等 |
| `description` | 是 | 英文描述 |
| `io` | 是 | `{ inputs: ["text: Prompt"], outputs: ["image: ..."] }` |
| `capabilities` | 否（694 里缺 1） | `{ workflow: [标签...], model_options: { "<节点类名>": ["模型串", ...] } }` |
| `minComfyUIVersion` | 否（694 里缺 3） | 如 `"0.39.1"` |

`capabilities.workflow` 有 53 种标签（`text-to-image` / `image-edit` / `api` / `turbo` / `int8` 等，以实际数据为准，不要写死清单）。
`capabilities.model_options` 是 86 个键、214 条映射。

### 中文索引 `index.zh.json`（724 KB，735 条）

结构与 `index.mcp.json` **不同构**：它是 `{ moduleName, type, category, title, templates[] }` 的对象数组，模板字段多了 `mediaType` / `tags` / `models` / `date` / `size` / `thumbnail` / `requiresCustomNodes`。

中英两份的关系：**mcp 是完整索引的 694 条子集，有 41 条只在完整索引里。** 所以：

- 检索用 `index.mcp.json`（字段规范、体积小）
- 中文标题与描述来自 `index.zh.json`，按 `name` 对齐
- 那 41 条缺中文的，回落英文，不要丢

### 单模板 JSON

前端 UI 格式，`version: 0.4`。**关键：加载类节点（Loader/Sampler）多在 `definitions.subgraphs[].nodes[]` 里，顶层 `nodes` 只有 UUID 引用的 subgraph 节点。**

`properties.models[]` 挂在节点上（不在顶层），三字段：

```jsonc
{ "name": "qwen_image_2.1_int8_convrot.safetensors", "url": "https://huggingface.co/...", "directory": "diffusion_models" }
```

同对象可能有 `cnr_id`（节点来源包，实测多为 `comfy-core`）与 `ver`。**没有 sha256，没有文件大小。**

### 三条必须做对的地方

1. **`collectRequiredModels` 必须递归**。实测：两个模板（图编辑 96 KB、图生视频 71 KB）的加载节点全在 subgraph 里，只看顶层会拿到空数组。
2. **中文检索**。`titleZh`/`descriptionZh` 来自 `index.zh.json`，按 `name` 对齐；对不上的回落英文，并在 `hasZh:false` 上标出来。
3. **版本比较按数值**。`0.43.0` vs `0.39.1` 要比成 43 > 39，不能按字典序。
