## 要做的事

### 接口

```js
export function validateWorkflow(input)
// input: {
//   workflow: object,        // UI 格式或 API 格式，自动判
//   objectInfo: object,      // T1 的裁剪结构
//   adapters?: object,       // 可选，同 convertUiToApi 的 adapters
//   options?: { strict?: boolean, checkEnums?: boolean, checkTypes?: boolean }
// }
// 返回:
// {
//   ok: boolean,
//   format: "ui" | "api",
//   errors: Violation[],
//   warnings: Violation[],
//   stats: { nodeCount, linkCount, unknownCount, checkedEnums }
// }
// Violation: { code, node, title?, field?, message, suggestions?: string[] }
```

`errors` 非空则 `ok:false`。**本函数不抛异常**，任何内部失败都转成一条 `{code:"internal", message}` 的 error，让上层的返回形状保持稳定。

### 检查项（code 词表就这几个，不要自创）

| code | 含义 | 依据 |
|---|---|---|
| `unknown_type` | 节点 class 不在 objectInfo 里 | classes 表 |
| `missing_required` | required 输入既没连线也没 widget 值 | required 表 |
| `enum_mismatch` | COMBO 的当前值不在选项里 | enums 表 |
| `type_mismatch` | 连线的源输出类型与目标输入类型不兼容 | outputs + required/optional |
| `virtual_node` | 命中 UNSUPPORTED_UI_TYPES 且无适配档案 | 适配档案 |
| `subgraph_unexpanded` | 有 subgraph 定义但展开失败 | expandSubgraphs 的 problems |
| `no_output` | 整图没有任何输出节点 | 提交必被拒 |
| `internal` | 本函数自身异常 | catch 兜底 |

### 三条最容易做错的地方

1. **不能只把 `convertUiToApi` 的 problems 转手返回**。那是一串中文句子，没有节点 id。你要自己在转换前先跑一遍结构化检查，转换只用来兜住"它比我先发现的问题"。两边的结论合并，不要二选一。
2. **subgraph 里的节点 id 是 `105:11` 这种带冒号的**。展开后仍要能定位。未知类型的报错必须带上这个复合 id，否则人找不到。
3. **模板类工作流的加载节点藏在 `definitions.subgraphs[].nodes[]`**，顶层 `nodes` 只有 UUID 引用的 subgraph 节点。只检查顶层会全判 unknown。必须展开后再逐个校验。

### 不做的事

- 不做模型文件是否存在的判断。COMBO 选项本身就来自本地 `models/` 目录，`enum_mismatch` 天然覆盖"这个 checkpoint 本地没有"。不要另写一套磁盘检查。
- 不下载、不安装、不修复。只报。
