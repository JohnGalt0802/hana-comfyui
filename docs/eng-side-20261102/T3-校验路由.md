## 现状锚点（探索实测）

## 请求与响应

```
POST /_relay/validate
Headers: x-comfy-relay-key: <controlKey>   （必须，本路由能读任意本机文件）
Body: {
  "path": "D:\\...\\wf.json"      // 三选一：本机文件
  "template": "我的工作流.json"    // 三选一：userdata 里的工作流
  "workflow": { ... }             // 三选一：直接给对象
  "options": { "strict": true, "checkEnums": true }
}
```

响应：

```jsonc
{
  "ok": true,            // 校验通过
  "valid": false,        // 与 ok 同义，保留官方 MCP 的叫法，方便对照
  "format": "ui",
  "errors": [{ "code": "enum_mismatch", "node": "3", "field": "ckpt_name", "message": "...", "suggestions": ["..."] }],
  "warnings": [],
  "stats": { "nodeCount": 27, "linkCount": 30, "unknownCount": 0, "checkedEnums": 12 },
  "source": "file:D:\\...\\wf.json"
}
```

约定：

- URL 层面的成功就是 HTTP 200，**校验不通过也是 200**，靠 `ok`/`valid` 区分。这跟官方 MCP 的姿势一致：`valid:false` 是正常返回，不是异常。
- 只有"读不到文件""后端不可达""JSON 坏了""内部异常"才用 4xx/5xx。
- 三种来源互斥，同时给两个要报 400 并说明。
- `template` 走 `resolveTemplateContent`；`path` 走 safeStat + 读文件，超过现有 `SUBMIT_FILE_MAX_BYTES` 上限要拒绝（复用同一个常量，不要另定）。

## 要做的事

1. 加 handler + 路由分支，两处插入。
2. 拿 objectInfo 只走 T1 的缓存函数。如果 T1 没导出可调用的函数（只有 HTTP 路由），**停下来报告**，不要在 T3 里绕过缓存直接拉后端。这一条是硬要求，因为它是 4.13 MiB。
3. 调 `validateWorkflow`，把结果原样返回，不要在路由层加工或过滤。
4. 不记录、不落盘用户的工作流内容。
