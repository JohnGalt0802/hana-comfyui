## 数据契约（探索实测）

### 映射表 `extension-node-map.json`

两处，结构完全一致：

- `D:\ComfyUI\venv\Lib\site-packages\comfyui_manager\extension-node-map.json`（3341 键，2026-09-27，随 pip 包落盘）
- `D:\ComfyUI\ComfyUI\user\__manager\cache\<hash>_extension-node-map.json`（5718 键，2026-11-01，运行时刷新）

**用 cache 版那份，更全更新。** 文件名前缀是 `simple_hash(channel_url + filename)`，同一 channel 只会保留一个文件，取目录里最新的那个即可。

schema 严格统一，9059 条全是两元组，零例外：

```jsonc
{
  "https://github.com/<owner>/<repo>": [
    ["NodeClassA", "NodeClassB", "..."],
    { "title_aux": "人类可读的包名" }
  ]
}
```

### 反向索引的规模（实测）

- 42838 个类名，平均对应 1.06 个仓库。
- 4% 的类名对应多个仓库，**最多 `PreViewVideo` 对应 18 个**。
- `KSampler` / `CheckpointLoaderSimple` 这类热门名也在表里，能对上含核心仓库 `comfyanonymous/ComfyUI` 的多个结果。

**结论：类名到仓库不是一对一，绝不能取"第一个"就当成答案。**

### 覆盖不到的情况（实测）

`hana_bridge` 和 `comfyui-node-organizer` 注册了 0 个节点类，且不在映射表里。纯前端扩展包映射表覆盖不到，必须显式标为"查不到来源"。

### 已装判定（实测方案）

`custom_nodes` 下 24 个目录，其中 13 个带 `.git\config`：

1. 优先读 `.git\config` 的 remote url，把 `git@github.com:owner/repo.git` 归一化成 `owner/repo`（小写、去 `.git`）。
2. 没有 git 的，用 `pyproject.toml` 的 `name` 或目录名去 `custom-node-list.json`（6061 条）里匹配 URL 尾段。
3. 都匹配不上的（`hana_bridge`、`moss-*` 这类私有包），标为 `unresolvable`，不要瞎猜。

### 三条必须做对的地方

1. **多候选要给全**，并明确告诉使用者"这类名对应多个包，以下是候选"。宁可让人选，也不要断言。
2. **区分 three states**：没装、装了但没加载、表里查不到。三种的下一步动作完全不同。
3. **归一化仓库地址**：`git@github.com:` / `https://github.com/` / 尾带 `.git` / 大小写，都要能对上。

### 不做的事

- 不安装、不下载、不重启。
- 不判断"哪个候选才是对的"，只排序给候选。
- 不读磁盘（已装清单由调用方给）。
