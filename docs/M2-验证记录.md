## 2. 关键设计决策（v0.2）

1. **clientId 配对**：ComfyUI 只把执行事件发给「提交方 client_id 的 WS 连接」（server.py 源码 + 实测）。中继订阅与提交共用**每次启动随机**的 `comfyui-hana-relay-<hex>`。**不复用固定 id**——ComfyUI 旧连接关闭时按 sid `pop`，同名快速重连会误删新连接（已实测复现）。
2. **事件缓存 vs history 双轨**：事件缓存（`/_relay/prompts`）提供实时进度；**history 是终态与产物的权威**。结算逻辑两者兼用（极快/全缓存任务可能 history 先于事件可见）。
3. **任务桥能力门控**：`ctx.tasks.create` 前检查 `app/tasks.manage` + `app/session.start-turn`（`app:capabilities` 账本查询，缓存 30s）；缺任一项 → 不创建宿主任务、工具返回值写明原因、仍走内存跟踪。
4. **管理端点鉴权**：`/_relay/fs/*`、`/_relay/upload` 需 `x-comfy-relay-key`（每次启动随机 controlKey 经私有配置传入；恒定时间比较）；`/_relay/status|prompts|history` 只读开放。
5. **UI→API 转换边界**：经典图自动转换（widget 顺序 + 连线 + seed/control_after_generate 形态）；子图/环绕/静音/旁路/未知节点 → 明确报错并提示「导出（API 格式）」。
6. **timeoutMs 上限**：宿主契约 `ctx.runtime.fetch` 限定 1–30000ms（首测踩到并修复，统一 clamp）。
7. **日志落盘**：解决「受管 runtime stdout 无读取通道」；请求日志同步写 `app-data/comfyui-hana/logs/relay.log`（启动时 >5MiB 滚动 `.1`）。

### 10.1 结论（根因）

**宿主侧边界，不是 comfyui-hana 的缺陷**：宿主的「可靠投递」（app-task next-step）**只写桌面会话**
（`agents/{id}/sessions/*.jsonl`）；**子代理会话**（`agents/{id}/subagent-sessions/direct/*.jsonl`）会被
`_assertActiveDesktopSessionPath`（bundle 内 `deliverCustomMessage` 首行守卫）直接拒绝，抛错被 `_deliverTask`
捕获后仅走 `console.warn`（协调器未接结构化 logger），投递记录保持 `delivered:false`，每 30s 重试一次、永不成功。
本次验证任务（从子代理会话提交）与 hana-downloader 的同型案例完全一致。

1. **app 侧全绿**：宿主任务注册表 `.ephemeral/plugin-tasks.json` 中该任务 `status=completed`、`scope=session`、
