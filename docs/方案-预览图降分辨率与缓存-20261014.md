# 方案 · 提交历史预览图降分辨率 + 缓存（2026-10-14）

> **用户反馈**：提交历史多次提交的节点预览很慢；预览图**尺寸可以照旧，但分辨率应该更低**。

---

## 1. 根因（实测）

| 项 | 实测值 | 说明 |
|---|---|---|
| 原图 PNG | 2,720,111 B | 用户画布出图（2K 级） |
| `preview=webp;75`（当前口径） | 213,792 B | ComfyUI `/view` 只压格式+质量 |
| `preview=webp;75&width=260` | 213,792 B | **尺寸参数无效**（后端 `img.save(format, quality)`，无缩放） |
| `preview=webp;30` | 137,546 B | 降质量仅省 35%（分辨率才是体积主因） |
| 响应头 | **无 `Cache-Control`/`ETag`** | 每次打开都重新下载（~320ms/张） |

**结论**：预览图慢 = ①分辨率未降（2K 原图 → 显示仅 ≤720px）②无缓存（重复下载）。
**降分辨率无法靠改 `/view` 参数实现**（ComfyUI 不支持）。

---

## 2. 方案：桥侧缩图端点 + 磁盘缓存

在 **custom_nodes 桥**内新增缩图端点（不碰 ComfyUI 源码，符合零改动铁律）：

```
GET /hana_bridge/thumb?filename=&subfolder=&type=&w=720&q=72
```

- **缩图**：PIL 打开原图 → `thumbnail((w, w*8), LANCZOS)`（**只缩小、不放大**）→ 存 WEBP(q)。
- **磁盘缓存**：`<user_dir>/.thumb-cache/<sha1(filename|subfolder|type|mtime_ns|w|q)>.webp`；
  命中直接读文件（比 `/view` 每次解码原图**更快**）；原子写（temp + os.replace）。
- **响应头**：`Cache-Control: public, max-age=31536000, immutable`（内容按 hash 稳定）+
  `Content-Type: image/webp`。→ 浏览器二次零下载。
- **失效**：键含原图 `mtime_ns`，图变 → 键变 → 新缓存（旧缓存不误用）。
- **安全**：路径校验同 `/view`（拒 `..`、绝对路径；`type` 仅 output/temp/input），只读。
- **降级**：图不存在 → 404；参数缺失 → 400；PIL 异常 → 500（前端 `onerror` 回退原图）。

**尺寸档位（前端传 `w`）**：
- 树/弹层预览浮层（显示 ≤720px，单图）：`w=720, q=72`
- lightbox 看原图（高清）：`w=1600, q=80`
- （多图小条显示 240px，`w=720` 足够）

**预期收益**：2K 原图 → 720px webp ≈ **213KB → ~25KB（约 8×）**；lightbox ≈ 2.7MB → ~200KB；
加缓存头后**二次零成本**。

---

## 3. 前端接入（`hana-bridge-*.js`）

- `historyImagesToUrls(images)`：
  - `thumbUrl` → `/hana_bridge/thumb?...&w=720&q=72`
  - `fullUrl` → `/hana_bridge/thumb?...&w=1600&q=80`（lightbox）
- **回退保护**（关键）：`<img>` 加 `onerror` → 一次性回退到原 `historyViewUrl(qs + "&preview=webp;75")` /
  原图。→ 即使缩图端点未生效（py 未重启），预览也不裂。
- 走 `historyViewUrl` 同款 URL 构造（`api.apiURL` 补前缀）。

## 4. 生效

| 改动 | 生效 |
|---|---|
| `thumbs.py` + `__init__.py` 端点 | 部署 + **重启 ComfyUI 服务** |

**重启前**：端点 404 → 前端 `onerror` 回退原 `preview=webp;75`（预览不裂，但仍是旧口径）。
重启后新口径生效。

## 6. 验收

1. 树/浮层预览图：体积 **213KB → <50KB**；lightbox：**2.7MB → <300KB**。
2. 二次打开同图：命中缓存（`Cache-Control` 生效，无重复下载）。
3. 图缺失时：`onerror` 回退，UI 不裂。
4. 无功能回归（预览/lightbox/多图翻页正常）。

---

## 7. 成色

- 根因**实测**（三组 URL 对比 + 响应头）；方案为**静态推导**（缩图逻辑与 ComfyUI `/view` 同源，PIL 必装）。
- 风险：① 缩图首次生成耗 CPU（一次，之后命中缓存）；② py 端点需重启。
- 回滚：`git checkout` 相关文件 + 重新部署 + 重启；`_thumb-cache` 可整目录删（可再生）。
