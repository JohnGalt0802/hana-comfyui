## 一、目标与语义

给 hui 加一条**画布提交历史**：每次运行工作流，就把当时的画布状态存成一份快照；历史以**提交为节点**（不是以时间为节点），在画布上可随时回看、可回滚到任一次提交。

三条核心语义（John 定）：

1. **提交 = 运行工作流。** 唯一提交点是前端那个「运行」按钮（Queue Prompt）。不记"改了什么"，只记"跑之前是什么样"。
2. **只保留提交态快照。** 不存两次提交之间的中间编辑。这在 John 的使用节奏里成立——「改一下提交一次」，提交点本就贴着编辑点。
3. **快照跟着工作流走。** 历史是工作流的附属物，放在工作流同级目录；换机器、备份工作流时历史一并带走。

### 为什么不记"变更日志"

时间轴轮询方案（`canvas.events`，1.5s 采样）记的是"变了什么"，天然是流水账，且只活在内存里、刷新即失。**提交态快照把这个问题整个绕开了**：每次提交是一份完整状态，不需要 diff、不需要补丁链，回看时直接查表。

## 二、核心模型：一条时间轴，块是它上面的窗口

这是整套设计的骨架，也是它自洽的原因。

| 概念 | 含义 |
|---|---|
| **提交（commit）** | 一次运行 = 一个提交节点，全局唯一编号 |
| **块（block）** | 画布上的一个区域（分组框，或降级时的功能角色） |
| **块的历史** | **不是**独立记录，而是"这条全局时间轴中碰到过我"的那些提交 |

**为什么必须这样**：一次提交往往同时动了好几个块（换模型 + 改提示词 + 调步数）。若每个块各存一套，"同一件事"会被记多次，"整布回滚"又要问"撤哪个"。**一条轴、块是视图**，两个功能就统一成同一个东西的两个投影。

### 块的识别：框优先，角色兜底

沿用 `lib/canvas-outline.mjs` 已有的两级口径：

| 级别 | 依据 | 块名来源 | 视觉 |
|---|---|---|---|
| ① 框优先 | 节点 `pos` 落在 `groups[].bounding` 内 | 框标题（或序号） | 实线 |
| ② 角色兜底 | 兜不住的按类型归类：加载 / 文本 / 采样 / 输出 / 其他 | 固定角色名 | 虚线 |

**实测（本地 44 份工作流）**：34 份画了框（77%），10 份没画框；`Qwen21 t2i 质量版` 4 框严丝合缝罩住全部 25 节点，无一漏出。

**关键判断**：框有**空间语义**，角色没有。同一次运行按角色切分时，「其他」块会横跨整张布并与其他块交叠（实测横跨 72% 宽度）——**因此回滚的影响面必须按框算，不能按角色算**。

## 三、快照落盘

**位置**：工作流同级，与工作流同名（`user/default/workflows/.history/<工作流名>/`）

```
.history/
└── Qwen21 t2i 质量版/
    ├── index.jsonl                # 索引（JSONL，一行一条元数据；追加写）
    ├── 0001-a3f9c2e1.json         # 第 1 次提交的画布快照（UI 格式）
    └── 0001-a3f9c2e1.thumb.webp   # 出图缩略图（出图后回填）
```

- **每次提交独立文件**：并发连点不会互相覆盖。
- **索引用 JSONL 追加写**：不用整份 `index.json` 读-改-写（那是竞态，连点运行会丢记录）；追加写天然无竞态、不需要锁。
- **快照体积**：实测工作流中位 66.5KB；需在写入前**剥掉 base64 字段**（`PreviewImage` 等内嵌图），否则单份可膨胀到几十 MB。
- **落盘通道**：app 进程受宿主沙箱限制，读写**经中继** `/_relay/fs/*`（详见调研文档）。
- **缩略图回填**：提交瞬间图还没出，出图完成后补挂；失败那一次永久无图，UI 用占位表示。

## 四、捕获点

| 通道 | 覆盖 | 精度 | 结论 |
|---|---|---|---|
| 中继常驻订阅 ComfyUI `/ws` | **任何人**的提交 | 事件级（execution_start） | **主干** |
| 桥侧包装 `api.queuePrompt` | agent 触发的提交 | 点击级 | 补精确态 |

桥现在的猴补是**临时**的（`canvas.queue` op 内用完即还），用户自己点运行抓不到。方案：改为**常驻**包装，与中继互为补充（细节以调研文档为准）。

**不追求"点击那一瞬"**：John 已明确"提交就是运行工作流"，以运行事件为准即可。

## 五、UI 形态

- **常驻渲染**：不做。块边上常驻导航条会占地方（John 明确否掉）。
- **点击块 → 弹出工具栏**：点画布上任一框/块，弹出该块的提交列表（缩略图 + 编号 + 时间 + 来源色标）。点空白或 ✕ 收起。与 ComfyUI 右键菜单同族交互。
- **全局时间轴**：一条横轴，每个提交一个刻度，刻度上按块数堆叠色条（触及哪些块）；点刻度 = 回到那一刻。
- **来源色条**：蓝 = 用户点的运行，紫 = agent 触发的。
- **不命名**：块名只当标签纸（John: "根本不会看框写的啥"）；内部键用序号或坐标，避免框重名冲突。

## 六、回滚（branch 式：原地回跳，不造副本）

选一个历史提交 → 画布**原地**回到那一刻的 widget 值。不新开页、不复制副本。

**为什么不需要副本**：hui 既有「操作对象永远是副本」的约定，是「没有历史可回头」年代的产物——副本是当时唯一的安全网。本功能落地后，**每一次提交本身就是一个存档点**：当前状态只要提交过就在历史里，回跳是可逆的（点回新节点即可）。安全网从「副本」换成了「时间轴」。

**为什么叫 branch**：切到旧节点不销毁任何东西，与 `git checkout` 换工作树同构——不复制仓库，只换当前视图。

**三条护栏**：

1. **先展示、后执行**：点一条提交，画布上会被波及的块立即暖色高亮，并明确告知"之后被改过的 X、Y 也会一起退回"。用户看得见再动手。
2. **影响面按框算**：语义层判定，不依赖美术框的当前状态。
3. **未提交的编辑要拦**：提交过的状态都在历史里，**没提交过的编辑不在**。回跳前若当前画布与最近一次提交不一致（用 `lib/canvas-diff.mjs` 比对），先弹确认。**不自动造「回滚前快照」**——那会往时间轴混进非运行的节点，破坏「提交 = 运行」的语义。

**闸门**：回跳由**用户在画布上点选**触发，走桥前端扩展的本地动作，不经 agent 的桥 op 通道 → **不受副驾驶写闸门约束**（该闸门管的是 agent 写入）。因此**不改 `COPILOT_WRITE_EXEMPT`**，功能在副驾驶关闭时同样可用。（实现前需代码复核，不凭推断。）

**分支结构**：本期不做 DAG / fork 可视化。回跳到旧节点后再提交，新提交在时间轴上续排；日后要显示分叉，可在快照里记 `parent`（点提交时所处节点），成本很低。

**边界**：只回滚参数字段，不回滚出图——已生成的图不消失，等于可以拿新版参数复现旧图。回跳后画布相对文件是「已修改」，保存或再提交由用户决定，不自动落盘。

## 七、边界与红线

- **不碰 ComfyUI 源码与前端打包产物**（零改动铁律）；一切经 custom_nodes 桥与 App 机制。
- **写类 op 受 v2 副驾驶约束**：回滚相关操作需目标页已开副驾驶（豁免争取见调研文档）。
- 需要重启宿主：先说再动，收益清单交 John 定时机；禁止静默重启。
- 同一主题的改动一次改完再交付。

## 八、分期

| 期 | 内容 | 可独立验收 |
|---|---|---|
| **P1 底座** | 提交捕获 + 快照落盘 + index 元数据 | 跑一次工作流，能在磁盘上看到快照与索引 |
| **P2 画布 UI** | 点击块弹出工具栏 + 全局时间轴 | 点块能看到该块的提交与缩略图 |
| **P3 回滚** | 选提交 → 画布原地回跳（branch 式） + 影响面提示 + 未提交编辑拦截 | 选早期提交，画布参数确实回到那一刻，且未保存编辑会被拦 |
| **P4 打磨** | 缩略图回填、base64 剥离、清理策略、来源色标 | — |

## 九、验收标准

每期须满足：

- 有**实测证据**（命令 + 输出 / 文件清单 / 截图），不接受"应该可以"。
- 交付区分「已生效（实测）」与「待重启」。
- 不污染用户数据：测试一律在副本或 `_temp/` 下进行。

## 十、修订记录（2026-10-11 · 与 John 定稿的 P4–P9 版）

> 本节为 P4 之后的新阶段口径。上面 §一–§九 为 P1–P3 原始方案，语义已被本节部分取代；冲突时以本节为准。

### 10.1 UI 形态（推翻 §五 的「弹层列表」）

- **提交历史框**（统一叫法）= 横轴 + 刻度，左旧右新，按时序，**不体现分支**。横轴记时间。
- **弹出位置固定在该分组框标题栏上方**；排布紧凑。
- **弹出方式**：点 bounding 框弹出，再点关闭（单击开/关）。
- **降级策略**：画布没有 bounding 框时，作用于具体功能块（角色块），同 P2 的框优先/角色兜底。
- **默认态**：只显示横轴与刻度，不显示其他内容。
- **悬停**：显示同主题气泡，内容 = 时间 + 较上次提交变更的**节点名称**等。
- **单击**：显示该提交生成的**缩略图**；鼠标移走自动关闭。
- **双击**：弹出确认框「是否回到该提交节点」。

### 10.2 合并与排序（新）

- **合并口径**：同一次触发、工作流**仅随机种子模式变化**的多次运行 → 归为**同一次提交**。点开后是可滚动的多张缩略图。
- **排序降级**：同 button 触发的多次运行，按**实际入队时间**排（符合提交历史框的语义）。
- 其他参数变化（步数/cfg/提示词等）一律算新提交——那些要盯着结果看，不属于抽奖。

### 10.3 缩略图（P4）

- 复用「生成完成的图」那种小方缩略图。
- **点缩略图查看原图**。

### 10.4 提交树（新，全局）

- **提交树整合进 hui 底部**，可收纳展开。
- 参考「全局提交轴」的刻度+堆叠色条视觉：**根据画布实际提交数量自行横向缩放**，在此基础上**体现分叉**。
- **分支布局**：按**拓扑深度分层**，同层内按入队时间排（避免同层缠团）。
- **branch 语义**：在旧节点上改了**有别于原点的内容**再提交 = 在此处 branch 新分支；只是存档则不算。理论上可无限分支。
- **存档节点**：算原节点的**状态别名**（不占独立分支位）；只有在它上面又改了才分叉。

### 10.5 四种来源（2×2，取代 §一 的「提交=运行」单一语义）

提交的来源是 **(谁) × (跑还是存)**：

| | 提交（运行产出） | 保存（主动存档） |
|---|---|---|
| **人** | 人提交 | 人保存 |
| **agent** | agent 提交 | agent 保存 |

- 色相分「谁」（人=冷色系，agent=暖紫系），形态分「跑/存」（实心 / 空心环）。
- **语义升维**：核心语义从「提交 = 运行」改为「提交 = 一个值得记住的画布快照点；运行是最常见的触发方式之一」。存档不生成、不出图。

### 10.6 画布存档工具（新）

- 给 **agent** 暴露画布存档工具：**不进行生成**也能主动保存画布内容。
- 存档节点在框和树里用**不同颜色**区分显示。
- **人也能用**：想法多又不想一张张等跑完时，一个 idea 一个存档。
- 延伸（暂不做，记在此）：把 idea 存档后把画布托管给 agent，按规则择机触发。

### 10.7 Agent native 与隔断（新）

- **感知不对称的解法**：UI 侧的框和树给人用；**打开副驾驶就把框和树的信息暴露给 agent，不打开就不暴露**——用既有开关做权限边界，天然隔离。
- **agent 绝不该静默回滚画布**：回跳会丢弃未提交编辑。有了 10.6 的存档工具，「当前有未保存内容」的拦截就有优雅出路（先存档再回跳），不靠「跑一次再取消」那种笨办法。
- **一鱼两吃**：本体功能（快照存储 + 框历史 + 提交树 + 缩略图）可作 **cui 插件**发布到 cui 社区；**agent native**（op 通道 / 副驾驶暴露 / 存档工具 / 托管调度）是 hui 特有。二者在**存储层**隔断：核心层走 ComfyUI 原生 userdata，不依赖 Hana 中继。

### 10.8 存储切换决策（2026-10-11 主脑定，John 认可「你来决定」）

- **现在就切**：把快照落盘从桥 Python 端点 / 中继迁到 **ComfyUI 原生 userdata API**。理由：数据模型正要换代（P5），此刻切成本最低；「一鱼两吃」是既定目标。
- 若原生 API 能力不足（写不了 JSONL 追加 / 建不了子目录）→ **原生为主 + 桥端点兜底**，差异登记清楚。
