## 0. 一页摘要

把「写入」从**改参数**扩展到**改结构**：加节点、删节点、连线、断线、mute / bypass。

两处设计变化：

1. **撤销从「记 before 值」升级为「记逆操作」**：每种写 op 自带一个逆操作闭包
   （addNode ↔ removeNode、connect ↔ disconnect、setWidget 写回旧值、setNodeMode 写回旧 mode）。
   栈里存函数、运行时用，不需要序列化。
2. **所有新 op 仍是「写」**：受同一个授权开关控制（默认关），且需要 ComfyUI 页面在线。

---

## 1. 新增 op

| op | 参数 | 作用 | 逆操作 |
|---|---|---|---|
| `canvas.addNode` | `{type, pos?, title?}` | 新建节点入图 | 移除该节点 |
| `canvas.removeNode` | `{nodeId}` | 删除节点 | 重建节点（用序列化结果） |
| `canvas.connect` | `{fromNode, fromSlot, toNode, toSlot}` | 连线（slot 可给名字或索引） | 断开 |
| `canvas.disconnect` | `{nodeId, slot}` | 断开某输入 | 重新连上 |
| `canvas.setNodeMode` | `{nodeId, mode}` | `0` 正常 / `2` mute / `4` bypass | 写回旧 mode |

---

## 2. 为什么用「逆操作栈」而不是快照

快照式（写入前存全量 JSON、撤销时整体恢复）有两个问题：

- **会把人在此期间的改动一起回滚**（人改了别处，agent 一撤销就白改）；
- 大图快照不便宜。

逆操作式只回退 agent 自己那一步，精确、便宜，且天然支持"连续撤销"。

---

## 3. 安全与可见性

- 全部标 `write: true`，受「允许 agent 修改画布」开关约束（**默认关**）。
- 每次写入都会进 P2 的变更记录（签名变化），agent 与人两侧都能看到。
- `removeNode` 是最重的（会拆掉连线），实现时**先记完整序列化再删**，保证可回退；
  恢复失败要如实报错，不假装成功。

---

## 4. 验证计划

1. `addNode` 一个 KSampler → 节点出现、拿到 id
2. `connect` 把它接进图 → 连线出现
3. `setNodeMode(2)` → mute 生效
4. 连续 `undo` 三步 → 逐步回退（mute 复原、连线消失、节点消失）
5. 对原图某节点 `removeNode` → 再 `undo` → 节点与连线都回来

---

## 5. 风险

| 项 | 处理 |
|---|---|
| slot 名字 / 索引歧义 | 两种都收，名字优先 |
| 未知节点类型 | `createNode` 返回 null → 明确报错 |
| removeNode 恢复不完整 | 先序列化节点 + 记它的连线；恢复失败如实报错 |
| 人的 Ctrl+Z | 同前（新版前端不吃外部改动），用 `op=undo` |
| 结构性改动面大 | 全部可撤销 + 需授权；不做「清空画布」这类一步摧毁的操作 |
