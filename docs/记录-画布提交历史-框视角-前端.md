## 2. 过滤口径

**唯一筛选点在 `historyBarLoad()` 内**（L3307–3321），只影响渲染：

```
curBlock = historyBlockNameOf(historyBarGroup)   // 当前框名；null = 判不了
shown = curBlock ? entries.filter(ent =>
           blockNames 非数组        → 保留（旧数据 / 异常字段，不参与筛选）
           数组且 includes(curBlock) → 保留
           数组且不含 curBlock       → 丢弃
         )
       : entries                                  // 判不了 → 不过滤（现状）
```

- 计数：`countEl.textContent = shown.length + " 次提交"` —— 头部 N 即该框的 N。
- 过滤后为 0 → 走现有空态节点 `.hhb-empty`；有 `curBlock` 时文案为「这个块没有提交记录」，判不了时保留原文案「这个工作流还没有提交记录」。
- 轴下两端时间跟着 `shown` 的首/末条走，避免头部时间跨度与刻度不符。

### 2.1 框名取法（对齐 `graphBlocks`）

`historyBlockNameOf(group)` 复刻 `graphBlocks()` 的组命名口径，不引用 ESM：

1. 活图 `app.graph._groups` 里 `indexOf(group)` 定当前框序号 `idx`；不在活图里 → `null`。
2. `app.graph.toJSON().groups` 必须与 `_groups` **组数一致**，否则 → `null`（口径不同源）。
3. 两边 title 都非空时再比一次 `trim()` 后的 title，不等 → `null`（防序列化顺序错位）。
4. 归属：节点 `pos` 落在 `bounding` 内（含边界），落多组取第一个 —— 同 `graphBlocks`。
5. 命名：**只对 bounding 内有归属节点的 group 命名**（空 group 不成块、不占名），名 = `title.trim()` 或 `组{gi+1}`（`gi` 为 groups 序号、从 1 起）；按组序进池、重名 `#2`/`#3` 递增去重，与 `graphBlocks` 同款。
   - 角色块名（加载/文本/采样/输出/其他）在 group 名**之后**才进池，只会改名角色块，不会反过来改 group 名 —— 故此处无需模拟角色桶。

### 2.2 「框名对不上 → 退化为不过滤」（关键一条）

**任何一步判不出当前框名，一律退化为不过滤（宁多勿漏），并 `console.warn`；绝不白屏。** 触发条件：

- `historyBarGroup` 为空（非框入口打开）；
- `app.graph` / `_groups` 不可用、或 `group` 不在活图分组里；
- `toJSON()` 抛错 / 无 `groups`；
- 活图组数与序列化组数不一致，或同序 title 对不上；
- 该框是**空 group**（bounding 内无节点）→ 本就不成块，没有可比对的块名。

代码体现：`shown = curBlock ? …filter… : entries`；`if (historyBarGroup && !curBlock) console.warn(…)`。
注意 `blockNames === null`（后端标为「无法判定」）与本节「框名判不了」是两个不同层面：前者不参与筛选、保留并标注；后者整体不过滤。
