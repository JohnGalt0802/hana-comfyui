## 四、未做 / 存疑

1. **未跑真机、未重启**（约束内）。因此本批**只交付「已改」**，不宣称「已生效」。真正的验收判据（方案 §六「重启后缩略图仍在」）需主脑部署 + 重启后复验。
2. **一致性口径仍是 P3-G1 的简化版**：`historyGraphSigForCompare` 与 `historySnapshotGraphSig` 是「同函数族、不要求跨形态哈希一致」的近似对齐（注释已在 L3529 附近说明）。本批只是把该口径**抽出复用**，未改判定强度。
3. **警告行的时序**：确认框先以「无警告」形态出现，异步比对完成后再补行。极慢响应下用户可能先看到无警告→再看到警告行（框高随之变一点）。未做「比对完成前禁用回跳按钮」——那会改变三态交互节奏，超出本批范围。
4. **比对材料取自 `ent`（= list 条目）**：若某条 entry 既无 `file` 又无 `seq`，`historyDiffAgainstSnapshot` 直接返回 `true`（显示警告）。这是刻意的「宁可多提醒」。
5. **`historyFillThumb` 由 async 改同步**：调用方 `historyBarShotsToggle` 同步执行、不再 `void`。若未来有他处需要 await 它，需注意其已无 promise 语义。
