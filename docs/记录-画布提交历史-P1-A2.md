## 四、桥文件命名与引用规则（查明结果）

**规则（代码确证）**：

1. **引用方式——扫描目录，非写死**。桥是 ComfyUI 自定义节点扩展：
   - `app/bridge/__init__.py:45` `WEB_DIRECTORY = "./js"`；ComfyUI `nodes.py:2299-2302` 据此把 `js/` 注册进 `EXTENSION_WEB_DIRS`；`server.py:1317` 静态挂到 `/extensions/hana_bridge/`，`server.py:417-429` `/extensions` 列表**递归返回该目录下全部 `.js`**，前端逐个 import → `app.registerExtension`。
   - **后果**：`js/` 下若有多个非 `.bak` 的 `hana-bridge-*.js`，同页会**双载扩展**（写操作双执行）。`tools/deploy-bridge.ps1` 注释与实现即为此：部署时**清空 `js/` 目录、只放当前活动 `.js`**。
   - `app/index.js` 里**没有**对桥文件名的引用（grep 无匹配）——桥经中继 `/extend…`→`/_relay/bridge`→`/api/hana_bridge/call` 走 op 表，与文件名无关。
2. **文件名格式**：`hana-bridge-<ddHHmmss>.js`（`tools/bridge-reload.ps1:49` 生成），**时间戳纯为浏览器缓存绕过**（该脚本头注释：「浏览器对同一 URL 的 js 会顽固缓存……改名是唯一可靠的绕过方式」）。
3. **构建标识三处同源**（`docs/改动生效范围.md`）：js 文件名 ＝ js 内 `BUILD_TAG`（`:20`）＝ py `BRIDGE_BUILD_TAG`（`__init__.py:69`）。当前三者均为 `2026-10-09 hana-bridge-09205624`。
4. **diag 取文件**：`__init__.py:493-504` 扫 `js/` 下 `hana-bridge-*.js`（排除 `.bak`）取**排序最后一个**。

**旧副本**：`_build/validate/…/hana-bridge-09205624.js`、`_build/pack/…/hana-bridge-28105930.js`、`_build/validate-bmain/…/hana-bridge-08111316.js` 均为 `_build/` 下的**打包/校验 staging 快照**（`tools/validate-app.ps1` 注释：robocopy 一份到 staging 再校验），**非活动、非引用链**，不需同步。`app/bridge/js/` 下的 `*.js.bak-*` 是历史开发备份，部署时按 `.bak` 过滤，也不需同步。

**按实际情况的处理——在原名上就地改，未改名**：

- 改名只在**部署/重载**时才有意义（绕浏览器缓存），本批次明令不部署、不重启、不 frameReload，故不改名。
- 更关键：擅自改名会让 py `BRIDGE_BUILD_TAG` 与文件名失配（违背「三处同源」），而本批次范围仅限桥 js，不该越界改 py。
- 且改名会**多留一个 `.js`**（旧名未删）→ 直撞上述「多文件双载」红线。
- 结论：**就地改 `hana-bridge-09205624.js` 文件名不动**；`BUILD_TAG`(:20) 也未动。待主脑安排部署时，由 `bridge-reload.ps1` 统一改名绕缓存，并**同步 bump js `BUILD_TAG` + py `BRIDGE_BUILD_TAG`**（见「五 · 未决项 1」）。
