## 0. 一页摘要

ComfyUI-Hana 把本机 ComfyUI（`D:\ComfyUI`，v0.37.0，服务在 127.0.0.1:8188）接进 HanaAgent，交付三层价值：

1. **界面**：ComfyUI 官方前端嵌入 Hana 的整页卡/面板/拆窗，操作体验原汁原味；
2. **融管**：App 负责与 ComfyUI 服务的连接、健康、状态展示（v1 连接外部实例，v2 支持由 Hana 托管拉起）；
3. **Agent 原生**：提交工作流、监控进度、取回产物、管理队列全部工具化；长任务遵守 Hana 任务模型（next-step 投递），产物接入会话与卡片。

技术主路线一句话：
**受管 runtime 起"中继"（node 进程）→ 宿主代理路径对外提供 HTTP/WS 通道 → ComfyUI 官方前端利用其原生相对寻址能力，直接从代理路径加载。**

为什么这条路最优：前端**零改造**（相对寻址是官方自带能力，官方明确支持反代子路径）；**WS 有官方代理支持**（`/_runtime/<runtimeId>/` 支持 WebSocket）；**升级自然跟随**（加载的就是当前安装版本）；**同源加载**（代理路径在宿主域下，绕开 ComfyUI 中间件的跨站 403）；iframe 隔离样式（避免 DSHana 踩过的样式污染坑）。

## 1. 定位与原则

### Agent native 落地口径（本项目）

- **P1 工具先行**：所有能力先有工具面，UI 只是可视化；无 UI 环境（自动化、定时任务）能力不减。
- **P2 任务模型对齐**：每次生成长任务 = 一个宿主任务（`ctx.tasks` create/update/complete）；卡片与状态条反映真实任务记录，不另造平行体系。
- **P3 回合纪律**：提交即返回；结果经 `next-step` 投递；审批与关键通知只在回合边界送达（同回合等待会撞宿主 30s 工具回调上限，DSHana 已踩坑）。
- **P4 宿主设施复用**：媒体、文件、预览、通知走宿主通道（resources / documents / previewers / notify），不自造。

## 3. 架构总览

### 组件与进程

```
┌─ HanaAgent 宿主 ─────────────────────────────────────┐
│  App 进程（index.js，v2 App 沙箱，一个 Node 子进程）      │
│   ├─ 工具面：comfyui（status/submit/query/...）          │
│   ├─ 路由面：/comfyui-hana/*（boot-state/状态/控制）      │
│   ├─ 任务桥：ctx.tasks ↔ prompt 生命周期                 │
│   └─ runtime 控制器：拉起/监督中继、状态出口              │
│                                                       │
│  UI（ui/ 静态树，卡片 iframe 内渲染）                    │
│   ├─ workspace.html  整页工作区（内嵌 ComfyUI 前端）      │
│   ├─ panel.html      功能面板（服务状态）                │
│   ├─ settings.html   设置页                            │
│   └─ task.html       任务卡（M2）                       │
│                                                       │
│  宿主代理面：/api/apps/comfyui-hana/routes/...          │
├───────────────────────────────────────────────────────┤
│  受管 runtime：runtime/comfy-relay.mjs（node 中继）      │
│   HTTP/WS 反代 → 127.0.0.1:8188                        │
└───────────────────────────────────────────────────────┘
        ↓ HTTP/WS（loopback，服务端转发，无浏览器跨站限制）
   ComfyUI 服务 127.0.0.1:8188
   （v1：attach 外部实例；v2：可改为受管拉起）
```

### 三条数据流

1. **用户界面流**：卡（ui/workspace.html）→ 内层 iframe（宿主代理路径 `.../_runtime/<id>/`）→ 中继 → 8188。ComfyUI 前端按相对路径推导 API/WS/view 地址，全链路自动经代理。
2. **Agent 工具流**：agent 调 `comfyui` 工具 → index.js 提交 `/prompt` → 任务桥跟踪（经中继状态端点/事件）→ `ctx.tasks` 完成回执（next-step）。
3. **状态流**：中继 `/_relay/status`（聚合后端可达性、队列、计数）← index.js 轮询 → boot-state / 卡片 / 工具 / 面板。

## 4. 关键决策

### D1 前端承载：代理路径直载 + 同源 iframe（主选）
- 做法：ui/ 壳页内嵌同源 iframe，src 指向受管服务代理路径下的 ComfyUI 前端（`/api/apps/comfyui-hana/routes/_runtime/<runtimeId>/`）。
- 理由：前端零改造；WS 官方代理支持；升级自动跟随；绕开跨站 403（请求都发生在宿主域内）；iframe 隔离样式。
- **降级 A**：`embedUrl` 直嵌 `http://127.0.0.1:8188/`（若主链路验证失败；零改造但无集成能力，且依赖 same-site 豁免成立）。
- **降级 B**：把前端产物拷贝进 `ui/` 再经代理（若官方前端相对寻址在代理下出现边缘故障；牺牲升级跟随换稳定性）。
- **不采用**：同文档注入 + 传输层 shim（DSHana 式）。ComfyUI 组件量/样式体量大，污染风险高；且其收益（免跨文档限制）对 ComfyUI 非关键。

### D2 服务管理：v1 attach，managed 预留
- v1 只做 attach（中继转发到外部 8188）。理由：用户现状即脚本拉起外部实例；attach 开发测试不打扰用户服务。
- managed 模式（后续）：受管 runtime `command` 模式直接拉起 `python main.py` 并注册 service，前端入口（代理路径）不变，仅换 runtime。架构已预留。

### D3 中继设计（runtime/comfy-relay.mjs）
- Node 单文件，无第三方依赖；支持两种启动：受管模式（私有配置 JSON 传入）、standalone（本地测试）。
- HTTP 全方法反代 + WS upgrade 反代（双向 pipe）；后端地址可配（默认 127.0.0.1:8188）。
- 状态聚合端点 `/_relay/status`（后端可达性、队列长度、uptime、请求计数），供 index.js 轮询。
- 请求日志走 stdout（宿主受管 runtime 捕获）。
- 退出码语义化；端口随机（38000~52000 段）。
- v1 不修改任何响应内容（主题注入等留到 M3，接口预留）。

### D4 UI 槽位：照 DSHana 组合
- 整页卡（工作区，`realization:"page"` + `siteNavEntry`）；功能面板（服务状态）；拆窗页；设置页。`closable:false`。
- 壳页负责三态（未就绪/就绪/错误）+ 人话报错 + 原始错误折叠；runtimeId 变化即整页重载。

### D5 Agent 工具：单工具 `comfyui`，action 分派
- 动作：`status`（服务/队列/健康）、`submit`（工作流提交：模板+参数覆盖或完整 API JSON）、`query`（任务/队列/历史查询）、`result`（取产物路径+预览）、`cancel`（取消）、`workflows`（工作流列表/读取）、`upload`（图生图输入）。
- 权限：`app/tools.expose-to-model`；工具描述负责当下决策、随包 SKILL 负责全景（DSHana 双层教学法）。

### D6 任务桥
- `submit` → `ctx.tasks.create({callToken, label, delivery:"next-step"})`；完成/失败/interrupt 由 index.js 结算回执（产物路径、耗时、缩略图信息）。
- 中途进度：任务卡轮询 index.js 状态（不依赖 WS 到会话）；关键节点可选 `send-custom`（scope 纪律）。
- 审批边界：同一回合不等待；长任务提交即返回。

### D7 产物回流
- 从 `/history` 解析产物：真实文件路径（`D:\ComfyUI\ComfyUI\output\...`）+ 代理 `/view` URL。
- 卡片显示缩略图；`next-step` 回执文本含路径列表；后续可选 `session:stage-file` 注册进会话文件。

### D8 工程与流程
- 开发仓：`D:\HanakoWorks\ComfyUI\app\`；宿主副本：`C:\Users\John Galt\.hanako\apps\comfyui-hana\`；同步脚本 `tools/sync-to-host.ps1` + hash 校验。
- 安装：复制 + `POST /extensions/install`（批准）；迭代优先 reload，必要时重启（**重启前必须先告知用户**，遵守全局长兜底纪律）。
- 测试节制：不在用户正在运行的实例上主动提交生成任务；验证以只读为主。
