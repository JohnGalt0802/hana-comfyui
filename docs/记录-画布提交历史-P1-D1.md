### 判断与实施

采用分支一：**history-commit / history-list 去掉 token 校验**，对齐 hello/state 的信任模型（8188 同源页面调用、仅本机 127.0.0.1 可达、无写转发）。未在 JS 补头——JS 无 token 途径，补不了也不能补（硬编码 token 进前端文件等于泄密）。

改动（`app/bridge/__init__.py`，改后行号）：
- **:607-609**：`_hana_history_commit` 删除 `if not _token_ok(request) → 403` 两行，原位加 3 行注释写明信任模型（同源页面、只落盘不转发、本机-only、/call 需 token 是因其为中继→外部入口而桥 js 拿不到 token）。
- **:620-624**：`_hana_history_list` 同样删除 token 检查，docstring 补「信任模型同 history-commit（P1-D1）」。
- `_token_ok` 函数体（:180-183）与 `/call` 的调用点保留未动——**没有两边各改一半**：改的是 C1 新加的校验使其对齐既有页面路由，而非反向给 JS 塞 token。
- 运行侧核验：custom_nodes 副本 `__init__.py` 中 `_token_ok` 仅剩定义 :181 与 `/call` 调用 :358 两处，history 两路由已无校验。
