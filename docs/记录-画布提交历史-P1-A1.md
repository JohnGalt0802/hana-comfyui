## 二、边界处理决策

以下为我在实现中为消除歧义所做的选择（与任务书一致处不赘述）：

1. **`sanitizeWorkflowName` 净化顺序**：控制字符 → 路径分隔符/Windows 非法字符 → 去首尾空白与点 → 截断 80 → **再去一次首尾空白与点**（截断可能把结尾切到非法位置留下的余量清掉）。最终为空 → `untitled`。`MAX_NAME_LEN` 按**字符数**（`String.length`）计，非字节数。
   - 决策：首尾的**点**一并去掉（不只是空白）。理由：Windows 不允许文件名以点结尾，`...name...` 这类会写盘失败。任务书只明写「去首尾空白与点」，我按字面执行。
   - 决策：**中间空格保留**（`my workflow` → `my workflow`），不折叠、不替换。

2. **`snapshotFileName` 的 seq**：非有限值（NaN/undefined/字符串非数字）按 `0`；`padStart(4,"0")`；**超过 4 位不截断**（`12345` → `12345-...`），避免序号撞车。promptId 取前 8 位后再剔除非 `[A-Za-z0-9]`，净化后为空 → `noid`。

3. **`buildSnapshot` 兜底**：graph 缺省/非对象 → `{}`，计数按 0；`at` 缺省/空 → 当前时间 `new Date().toISOString()`；`at` 为 `Date` → `toISOString()`，其余原样 `String()`。`graph` 字段**原样嵌入（同一引用，不拷贝）**——因为剥离由 `stripHeavyFields` 单独负责，构造层不做二次拷贝（避免一次提交多拷贝一份几十 KB）。

4. **`stripHeavyFields` 命中口径**：仅匹配 `^data:image/<subtype>;base64,` 的**字符串**（subtype 可含 `.+-`，大小写不敏感）。
   - 决策：**只剥 `data:image/...;base64,`**，不剥其它 `data:`（如 `data:text/plain;base64,`）或**非 base64 的裸 `data:image/png,`**（后者不是内嵌大图，实测工作流里是引用/标记）。任务书只点名 base64 内嵌图，我按字面收紧到这一档。
   - 命中值替换为**空串**（不是删键/删元素）→ 数组长度、对象键全部保留，回放结构不变。
   - `stripped` 记录**相对 graph 根**的路径，形如 `nodes[0].widgets_values[1]`、`nodes[1].inputs[0].image`，按遍历顺序。
   - 深拷贝：递归重建数组/对象；同时**实测断言原对象 `JSON.stringify` 前后字节级不变**。

5. **`buildIndexLine` 字段与别名**：输出字段固定为 `seq / file / promptId / at / source / nodeCount / linkCount`；`file` 接受 `file|fileName|name` 三个入参别名（中继与 app 两侧命名未完全统一，先兼容）。`source` 经归一化；数值经 `toInt` 兜底 0。**不含 graph**（实测断言输出无 `graph` 键）。

6. **`parseIndex` 容错**：按 `\r?\n` 切行；**空行/纯空白跳过、不计入 badLines**（考虑 JSONL 末尾换行与手工空行）。坏行两类都进 `badLines`：① JSON.parse 抛错（记录 `{line, text, error}`）；② 解析成功但**不是对象**（数组/裸值，`error:"not-an-object"`）。缺字段的合法对象**照样进 entries**。全程不抛异常。

7. **`nextSeq` 健壮性**：只统计**有限数值** seq；坏行/非法 seq 忽略；全部非法 → 1（与空等价）。`Math.trunc` 取整。

8. **`latestEntry`**：按数组顺序取**最后一条**（约定索引按提交先后追加，最后即最新），不做时间排序——排序应由写入方保证，读取层保持最简。空/非数组 → `null`。
