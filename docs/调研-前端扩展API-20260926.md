## 1. `window.comfyAPI` 在哪定义、包含哪些命名空间

**结论（实测）**：`window.comfyAPI` **没有单一的中央定义文件**；它由**构建期注入**——每个需要对外暴露的模块，在其编译产物末尾追加一段 `window.comfyAPI = window.comfyAPI || {}` 形式的挂载代码。

- 实测（`static\assets\core-C8yW9NC5.js`，多处，如 @ 片段 `window.comfyAPI.textPreviewWidgets.addTextPreviewWidgets=...`）

**构建期注入（推断，证据较强）**：对 `settingStore-DDHzGrHr.js.map` 与 `api-X7ElNdW-.js.map` 全文搜索字符串 `comfyAPI`，**命中数均为 0**（实测）。即原始 TS 源码里没有 `comfyAPI` 字样，说明这些 `window.comfyAPI.*` 赋值是打包/转换阶段按模块路径生成的，而非源码手写。⇒ 命名空间名**由模块路径派生**，因此会随前端版本增删。

## 2. 官方扩展注册入口 `registerExtension`

**结论（实测）**：真实实现有两个层次，**同时**存在 `app.registerExtension(ext)` 与 `window.comfyAPI.app.app.registerExtension(ext)`（同一对象上的同一方法）。

1. **底层 store 实现**（真正的校验/登记）——`static\assets\extensionStore-BQDxWOi2.js` @1978：
   `function registerExtension(e){if(!e.name)throw Error("Extensions must have a 'name' property.");if(r.value[e.name])throw Error("Extension named '"+e.name+"' already registered.");a.value.has(e.name)&&console.warn("Extension "+e.name+" is disabled."),r.value[e.name]=n(e)}`
   - ⇒ `name` **必填**且**唯一**；被禁用名单中的扩展会告警。
2. **服务层入口**——`static\assets\settingStore-DDHzGrHr.js` @1146520（`useExtensionService=()=>{...}`）内联：
   `registerExtension=n=>{e.registerExtension(n); ... n.keybindings?.forEach(...); n.settings?.forEach(c); n.getCustomWidgets&&(...registerCustomWidgets(e)); ...}`
3. **挂在 ComfyApp 上的兼容方法**——`static\assets\settingStore-DDHzGrHr.js` @1691154（位于 `RR=class ComfyApp` 类体内，类起点 @1662824，导出表 @1697256 之前）：
   `registerExtension(e){useExtensionService().registerExtension(e)}`
   - ⇒ 扩展里常用的 `app.registerExtension({...})` 与 `window.comfyAPI.app.app.registerExtension({...})` 都有效。

**参数对象（实测）**

- 必填：`name`（string）。
- 声明式字段（由服务层直接消费）：`keybindings`、`settings`、`commands`/菜单命令、`bottomPanelTabs`、`getCustomWidgets`、`onAuthUserResolved`、`onAuthTokenRefreshed`、`onAuthUserLogout`。
- `getCustomWidgets` 被以 `getCustomWidgets(app)` 调用（实测 @1146520 片段 `n.getCustomWidgets&&(... n.getCustomWidgets(Q) ...)`）。
- 认证相关 hook 被以 `(user, app)` / `()` 调用（实测 `settingStore-DDHzGrHr.js` @4586818 附近的原始 TS 片段：`extension.onAuthUserResolved?.(user, app)`）。

**生命周期 hook 名（实测：全目录扫描 `invokeExtensions(\`X\`)` / `invokeExtensionsAsync(\`X\`)` 调用点，去重得 17 个）**

```
addCustomNodeDefs, afterConfigureGraph, afterLoadGraph, beforeConfigureGraph,
beforeLoadGraph, beforeRegisterNodeDef, beforeRegisterVueAppNodeDefs,
getCanvasMenuItems, getNodeMenuItems, getSelectionToolboxCommands,
init, loadedGraphNode, nodeCreated, onNodeOutputsUpdated,

```

**hook 调用签名（实测，原始 TS）**：`settingStore-DDHzGrHr.js.map` @4588668 附近 `useExtensionService` 源码：

```ts
results.push(fn.call(ext, ...args, app))          // invokeExtensions
const result = await fn.call(ext, ...args, app)   // invokeExtensionsAsync
// setup 前后会 legacyMenuCompat.setCurrentExtension(ext.name / null)
```

- ⇒ 每个 hook 的**最后一个实参恒为 app 实例**；同步 hook 由 `invokeExtensions` 逐个调用，异步 hook 由 `invokeExtensionsAsync` 用 `Promise.all` 并发调用。
- `KnownExtensionMethods = Exclude<keyof ComfyExtension, number | symbol> & string`（实测，同上源码片段）⇒ 合法 hook 名集合 = `ComfyExtension` 类型的键。
- **未找到**：`ComfyExtension` 接口的**定义文本**（它位于 `@/types/comfy`，被 `src/scripts/app.ts` import，实测）。类型文件不产出运行时代码，**未被 sourcemap 收录**（见第 8 节）。

**核心扩展的实际写法（实测样例）**：`static\assets\core-C8yW9NC5.js` @ 片段 `w().registerExtension({name:"Comfy.PreviewAny",async beforeRegisterNodeDef(e,t){...}})` —— 注意这里 `w()` = `useExtensionService()`，`beforeRegisterNodeDef(nodeType, nodeData)`。

## 3. `window.app` 全局是否还存在

**结论（实测）**：**存在**。在 app setup 完成后赋值，且 `window.graph` 一并挂出。

- 实测（`static\assets\GraphView-Cx5xBruY.js` @569586）：
  `...await Z.setup(a.value), ..., window.app=Z, window.graph=Z.graph, me.value=!0, Z.canvas?.graph&&(...)`
- **同一实例（实测推导）**：
  - `GraphView-Cx5xBruY.js` 从 `./settingStore-DDHzGrHr.js` 以别名 `i as Z` 导入该对象（实测：`GraphView-Cx5xBruY.js` @6493 附近的 import 列表含 `i as Z,`，其 `from` 为 `./settingStore-DDHzGrHr.js`；实测 `settingStore` 导出表中含 `Q as i`）。
  - `settingStore` 中 `Q=new RR`（`RR=class ComfyApp`），并且 `window.comfyAPI.app.app=Q`（@1693238）。
  - ⇒ `window.app === window.comfyAPI.app.app`（同一个 ComfyApp 单例）。
- 兼容替代物（若某些注入场景下 `window.app` 尚未赋值，即 app setup 前）：`window.comfyAPI.app.app`；图对象经 `app.graph`（getter）获取。实测 `RR=class ComfyApp` 定义里 `get graph(){return this.rootGraphInternal}`、`get rootGraph(){...}`（@1662824 起）。

> 因此旧扩展普遍依赖的 `window.app.graph` 在本版本**仍可用**，但仅在 app setup 之后存在。

## 4. 画布 → API prompt 转换函数

**结论（实测）**：函数名 **`graphToPrompt`**；**无** `graphToAPI`（全目录扫描 `graphToAPI` 命中数 = 0）。

- **独立函数**：`static\assets\settingStore-DDHzGrHr.js` @1623658
  `var graphToPrompt=async(e,t={})=>{ ... return{workflow:r,output:a} };`
- **原始 TS 一级证据**：`settingStore-DDHzGrHr.js.map` 内 `sourcesContent` 的 `../../src/utils/executionUtil.ts`：

```ts
export const graphToPrompt = async (
  graph: LGraph,
  options: { sortNodes?: boolean } = {}
): Promise<{ workflow: ComfyWorkflowJSON; output: ComfyApiWorkflow }> => { ... }
```

- **返回值**：**对象 `{ workflow, output }`** ——
  - `workflow` = 前端工作流 JSON（含 `extra.frontendVersion`）；
  - `output` = API 格式 prompt（`{ [nodeId]: { inputs, class_type, _meta } }`）。

  ⚠️ **不是** `[prompt, extra_data]`（旧版语义）。本版本全程未出现该二元组返回值/`extra_data` 解构（实测：全目录 `extra_data` 仅出现在 zod schema 定义处，如 `api-X7ElNdW-.js` @37143/@52683/@52981/@71874；未见 `graphToPrompt` 返回它的代码）。
- **挂点**：ComfyApp 实例方法（`static\assets\settingStore-DDHzGrHr.js` @1680410，位于 ComfyApp 类内）：
  `async graphToPrompt(e=this.rootGraph){return graphToPrompt(e,{sortNodes:$().get("Comfy.Workflow.SortNodeIdOnSave")})}`
  - ⇒ `await window.app.graphToPrompt()` / `await window.comfyAPI.app.app.graphToPrompt()`（可选传入 graph）。
- **配套提交**：`ComfyApi.queuePrompt`（`static\assets\api-X7ElNdW-.js` @ 片段）签名为 `async queuePrompt(promptNumber, promptData, options)`，其中 `promptData` 被解构为 `{ output, workflow }`，请求体含 `client_id`、`extra_data.extra_pnginfo.workflow`。
  - ⇒ 标准链路：`const {workflow, output} = await app.graphToPrompt(); await api.queuePrompt(0, {workflow, output})`（方法形态为实测；整句为标准用法 `推断`）。
- 实测唯一内部调用样例（`settingStore` @1532853）：`let i=await Q.graphToPrompt(); addViewRestore(i.workflow); JSON.stringify(i[n],...)`（`n ∈ {workflow, output}`），与对象返回一致。

## 7. `/userdata` 工作流读写：api 上是否有现成方法

**结论（实测）**：**有**。`ComfyApi` 提供 5 个 `/userdata` 方法。**没有** `saveUserData`（全目录搜索 `saveUserData` 无匹配；仅有 `storeUserData`）。

- 实测（`static\assets\api-X7ElNdW-.js` @85400–@86045）：
  - `async getUserData(file, options?)` → `fetchApi('/userdata/'+encodeURIComponent(file), options)`
  - `async storeUserData(file, data, options={overwrite:true, stringify:true, throwOnError:true, full_info:false})` → `POST /api/userdata/<file>?overwrite=..&full_info=..`，`stringify` 时 body 为 `JSON.stringify(data)`
  - `async deleteUserData(file)` → `DELETE /api/userdata/<file>`
  - `async moveUserData(src, dst, options={overwrite:false})` → `POST /api/userdata/<src>/move/<dst>?overwrite=..`
  - `async listUserDataFullInfo(dir)` → `GET /api/userdata?dir=..&recurse=true&split=false&full_info=true`
- 原始 TS 一级证据（`api-X7ElNdW-.js.map` 的 `../../src/scripts/api.ts`，含 JSDoc）：

## 10. 汇总：对方案设计最相关的 5 条硬事实

1. **没有中央 `comfyAPI` 定义**；命名空间是构建期注入、按模块路径派生 ⇒ **不可硬编码依赖 `window.comfyAPI.<x>` 列表**，应优先 `window.app` / `window.LiteGraph` / `api` 单例，并对缺失做兜底（`实测`）。
2. `graphToPrompt` 返回 **`{ workflow, output }` 对象**（不是 `[prompt, extra_data]`）；提交用 `api.queuePrompt(n, {workflow, output})`（`实测`）。
3. `window.app`、`window.graph`、`window.LiteGraph` 仍存在且指向单例；但 `window.app` 仅在 app **setup 之后**赋值（`实测`）。
4. 事件订阅走 `api.addEventListener('executing'|'executed'|'progress'|'progress_state'|'status'|...)`；`executing` 的 detail 是**节点 id**（`实测`）。
5. `/userdata` 读写有 api 原生方法（`getUserData`/`storeUserData`/`deleteUserData`/`moveUserData`/`listUserDataFullInfo`），**无** `saveUserData`；扩展的**官方类型定义未随包发布**，但 **403 个 sourcemap 内嵌原始 TS 源码**可作二级证据（纯类型文件除外）（`实测`）。
