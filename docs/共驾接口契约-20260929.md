## 1. 新 op（桥侧实现 ↔ app 侧消费）

| op | 入参 | 出参 | 语义 |
|---|---|---|---|
| `canvas.queue` | `{front?: boolean}` | `{queued: true, promptId?, number?, via: "app.queuePrompt"}` | 执行当前画布（等效点 Queue）。**快返**：只提交不等执行；front=true 插队首 |

## 2. copilot 状态（桥 → app；v2 起 UI 与 Agent 双写）

- 桥 state 对象新增：`copilot: {enabled: boolean, pageKey?: string, updatedAt: number}`
- 数据源：前端开关 UI（用户点击切换）与 Agent（`canvas.copilot`，v2 2026-10-08 增补）——**双写方，均即时上报**；**刷新后保留**（localStorage 持久化）
- app 读取该状态用于：submit 路径判断、读侧标注与写拦截交叉参考；写经 `canvas.copilot`（受总闸管辖）

## 3. app 侧行为

### 3.1 submit mode=auto（默认）
- `submit` 新参数 `mode: "auto" | "canvas" | "backend"`（缺省 auto）
- 判定：画布在线（shell alive + 桥可达）→ canvas 流程；否则 backend + §3.3 记账
- canvas 流程（v2「复制工作台」五步，详见 §7.3）：
  1. 当前画布有执行中任务（`exec.running` 非空）→ **报错退出**（不抢占；提示"画布忙，可显式 mode=backend"）
  2. 前置双闸：写授权 ＋ 副驾驶总闸，任一关闭 → 降级 backend（回执带原因与指引）
  3. `canvas.duplicate` → `canvas.save`（副本落盘：`<原名去尾> (AgentCopy) YYYYMMDD-HHmm`，重名递增）→ `canvas.copilot{enabled:true}` → `loadWorkflowFile` → settle → `canvas.queue`
  4. 返回 `{mode: "canvas", pageKey?, promptId?}`
- **红线**：一律在副本页工作，不得覆写用户当前画布（用户明确要求同页的人工例外除外）

### 3.2 visual 自动包裹（写类 ops）
- 包裹对象：`canvas.patch`、`canvas.organize`、`canvas.commands`（loadWorkflowFile 大变更由实现者判断是否包）；**包裹不分 copilot 开关**（一致性优先）
- 动作序列：操作前 `{action:"lock"}` → 操作后 `{action:"highlight", nodes:<改动清单>}`；**异常时 `{action:"clear"}`**
- 三动作语义（桥侧实现，防呆）：
  - `lock`：撤旧高亮 + 置锁（灰膜 + "小花正在操作"提示 + 阻断误操作）
  - `highlight`：**先撤锁与旧高亮**，再对 nodes/edges 黄标；高亮保留至下次 lock / clear / 页面刷新
  - `clear`：全撤
- 改动清单来源：从写操作结果提取；不可得时退化为"操作涉及节点"

### 3.3 D2 待同步（backend 降级记账 + 惰性回填）
- backend 产出时记 `pending-canvas.json`（app 数据目录，沿用项目惯例）：`{createdAt, workflowRef, promptId, note}`
- 惰性回填：app 在 canvas 类 op 或 shell/状态查询时检测——画布恢复（shell alive + 桥可达）→ 复制副本并装载该工作流 → 清标记；失败保留并附原因

## 7. v2 增补（2026-10-08 · 副驾驶规则 v2 落地）

### 7.1 新 op `canvas.copilot`（见 §1 表）

- 桥侧复用 `copilotWriteState`（localStorage 按页写）+ 顶栏按钮刷新（`copilotUiRender`）+ 即时 `pushStateSnapshot`（不等防抖）。
- 拦截口径：**只受 app 层「允许 Agent 开启画布副驾驶」总闸管辖；不受目标页当前状态影响**（否则鸡生蛋：未开的布永远开不了）。桥读不到设置——总闸只在 app 层生效（如实边界）。
- 工具层：`CANVAS_OPS.copilot`（write:true）；门控为总闸特判（不受写授权）。

### 7.2 写拦截（硬约束）与 `copilot_off`

- 桥侧兜底：写类 op 在「当前活动页副驾驶未开」时统一拒绝 → `{ok:false, error:"copilot_off", detail:<指引>}`；判定实时（关了立即恢复受限）。
- 名单以现有 `WRITE_OPS` 为基；**豁免：`canvas.openWorkflow`（打开）/ `canvas.duplicate`（复制）/ `canvas.save`（落盘）/ `canvas.copilot`（开关自身）**（豁免理由见桥 js `COPILOT_WRITE_EXEMPT` 注释）。`frame.reload` 不在名单（维护性操作），维持豁免。
- 工具层：把 `copilot_off` 转译为友好文案＋如何开启的指引（「仅可打开 / 复制 / 落盘……① 顶栏「副驾驶·开」 / ② 授权后 agent 奉命开启」）。

### 7.3 submit canvas 路径（v2「复制工作台」五步）

`duplicate` → `save`（副本落盘：`<原名去尾> (AgentCopy) YYYYMMDD-HHmm`，重名递增）→ `canvas.copilot{enabled:true}` → `loadWorkflowFile` → settle → `queue`。

- 「copilot 开 = 共编同页」自动分支**去除**（降为「用户明确要求」的人工例外）。
- **总闸关或写授权关 → 降级 backend**（回执说明原因＋指引）；`canvas-busy` 仍不降级。
- 待同步回填（§3.3）同口径升级（复制 → 落盘 → 开副本副驾驶 → 装载）。

### 7.4 读侧标注（全保留 + 标注）

- `canvas.state`：副驾驶行（v2 口径「该画布副驾驶：开 / 关（仅可读、不可写）/ 未知」）。
- `canvas.pages`：逐页副驾驶标注（精确版：桥 py `_frontends` 逐页记录，本次上报更新、不冲刷；从未上报页＝「未知」，不借别页值）。
- 内容类读 op（summary / get / check / trace / outline / prompt / running）：尾注副驾驶状态行。
