# hui 生图效率复盘 · 进一步总结（2026-10-08）

> 在《画布共驾-实操问题清单》（8 条）与《hui-使用问题汇总》（10 条）之上，回答一个更高层的问题：
> **为什么"按理说应该行云流水"的 hui，实操起来处处碰壁、效率偏低？**
> 结论先行：碰壁全部发生在「编排层」，生成层零败绩；根因是三层错配 + 两笔隐性税。

---

## 一、碰壁分布（今天的账本，按环节）

生成层战绩：十余张图（t2i×4、垫图×7、v6 渲染×1），单张 20~50 秒，画布路径值忠实、质量稳定。
而围绕着"每次生成"的编排工序，几乎每一环都收过摩擦税：

| 环节 | 今天实际撞到的 | 性质 |
|---|---|---|
| 环境探测 | 工作区没开 → probe 超时；iframe 黑屏假死（早段）；probe 壳页腿误导 | P4/P5 已修；探测仍费轮次 |
| 装载 | openWorkflow name 超时（改 path 成功）；dirty 拦截无上下文（人工判断 force）；不能指定新开页 | A1/A2/A3 **未修** |
| 值 | LoadImageOutput 硬写被回卷 → 首张垫图翻车（"少女"拼接图）；后端路径丢值 → 04 翻车；check 误报 | B2/B1 未修（靠画布路径+upload 范式规避） |
| 身份 | 副本链每张叠一层 `(AgentCopy)` → 04 撞 400 超长被拒；用户页/agent 页混列辨认 | B3 **修复漏项**（见 §三）；D2 已修一半 |
| 执行 | 无实时进度（只能手查）；queue 回执已改善（P8） | C2 部分 |
| 收尾 | 页面链残留、脏态遗留（切回干净工作流打断链条） | 惯例操作 |

一句话：**每张图的"生成"是 30 秒的事，"把意图变成一次正确的执行"是 10+ 道工序的事。**

## 二、三层错配 + 两笔隐性税（"按理说"与"实际"的落差来源）

### 错配 1 · 时序：修复与生效不同步
修复全链 11:37 前完成（8+1 项修复、规则 v2、双轮质检），但"生效三线"是当天逐线推进的：宿主 12:38 前后启动、ComfyUI 服务 15:15 重启（py 15:16 加载）、宿主 app 15:4x reload、页面多次重载。
→ 今天的实操体验横跨「旧代码 / 半新 / 新代码」三个运行态。**一部分"碰壁"其实是"修了还没穿上"。**

### 错配 2 · 覆盖：修复批 vs 下一层新账
修复批（P1–P8 + 补丁批 + v2 批）对准的是首轮 8 条。下午实操撞上的是**任务书范围外**的问题：值回退（B2）、后端丢值（B1）、name 超时（A1）、副本链（B3）……
→ 修复的轮次追不上暴露的轮次。这是"清单驱动式修复"的固有节奏，不是失败，但需要意识到。

### 错配 3 · 范式：零件 vs 装配线
所有 op 单测都好，但没有一条被当作产品打磨的**生图主干道**：最短路径、每步自带反馈、例外路径有预案。
→ 现状是"每个单点都能过，单点之间的缝都要 agent 来缝"。

### 隐性税 A · 信任税
因为值被回卷过、丢过，agent 的心智模型被迫升级为「全程画布 + 逐项核对 + 落定验证」。策略正确（保正确性），代价是整条流程变重：副本仪式、超时等待、手动验证。**这是今天最大的隐性成本。**

### 隐性税 B · 隔墙税
agent 看不见界面。人"看一眼"的事，agent 是"查询-操作-验证"三段式；任何状态不可见（进度、副驾驶、脏来源）都变成额外回合。

## 三、新发现 · 副本链修复漏项（代码级实锤）

- **现象**：下午实操副本链继续叠加到 400 超长被拒（04 Mono 掉到后端并丢值）。
- **现场页名**：`Qwen21 t2i+edit 质量版 (AgentCopy) 20261008-1555 (AgentCopy) 20261008-1556`。
- **根因**（`app/index.js` `agentCopyBaseName`）："原名去尾"清理清单为 `.json`、`(N)`、`(Copy)` 三种后缀，**唯独没清 `(AgentCopy) YYYYMMDD-HHmm` 本身**。而复制总是从"当前活动页"（=上一轮落盘的副本页）出发，于是每轮净增一层。
- **即**：《使用问题汇总》B3 的建议原文是"剥离旧的 `(AgentCopy) …` 后缀再拼新后缀"，实现时漏掉了那个最关键的尾。
- **建议修复**：正则补 `\s*\(AgentCopy\)\s*\d{8}-\d{4}(\s*\(\d+\))?$` 一类清理；或改短名方案（`[A]ddHHmm`）；提交前加文件名长度截断保护。
- **附带教训**：修复批的验收缺"真实链条回放"场景。下一批验收标准里应补：**用实际产生的多轮副本名作为测试夹具**。

## 四、今天确立的资产（别只记坏的）

1. **生成层**：画布路径的值忠实性经过 7+ 张实战验证（t2i 会丢值的原语链，画布路径 0 翻车）。
2. **修复全链**：问题 → 四路深挖 → 三批修复 → 两程收尾 → 双轮质检，当天闭环；含对抗性复核与"逆替换 diff"级别的严谨度。
3. **规则 v2**：副驾驶硬约束 + 授权开关 + 五步工作台，已在下午实操中真机走过（暴露的问题即 §三，属可修范围）。
4. **流水线本身**：这套"发现→深挖→派修→质检→生效"的机制资产化了，第二轮会快很多。

## 五、下一步动作候选（优先级）

**第一批（高频落地，直接消摩擦）**
1. 副本链修复补完（`(AgentCopy)` 去尾 + 截断保护 + 多轮名夹具）——今天 400 实锤；
2. `openWorkflow` name 未命中回退 path（或明确报错替代静默超时）；
3. 值机制做终局选择：LoadImageOutput（刷新选项+回读校验）或把「LoadImage + upload」写死为标准范式；
4. dirty 拦截附上下文（挡路页名 + 改动来源/时间）。

**第二批（体验与预判）**
5. 执行进度只读 op；空页标注；副本页 `[agent]` 分组/标记；
6. 装载→开副驾驶的授权内合并（减少仪式步骤）。

**长期（结构性）**
7. UI→API 转换器值一致性的真机验证重开（04 翻车即负样本）；
8. 用户不在场时的画布能力（壳页腿代理模式）——自动化天花板。

**一句话**：hui 已经过了"能不能"的阶段，卡在"顺不顺"的阶段。今天的碰壁几乎全是"做得到、但要绕"，下一阶段的课题是**把每个"绕"变成"直"**：为生图场景铺一条被当作产品打磨的最短主干道。
