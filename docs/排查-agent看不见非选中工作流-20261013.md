# 排查：agent 看不见「非选中工作流」（app agent-native 能力缺失）

**日期**：2026-10-13 凌晨
**触发**：John 指「我说 00012 没开着，而它开着且副驾驶开着」——质疑 agent 能否感知非选中画布。
**成色**：`[实测]` 命令/源码证据 · `[源码]` 前端打包产物可核。

---

## 一、现象

用户在同一 ComfyUI 页面里用**工作流多标签**打开了 `0001` 和 `00012`，当前停在 `00012`（副驾驶已开）。而 agent 侧：
- `canvas pages` 报的都是 `Qwen21 t2i 质量版 (0001)`，**没有 00012 的条目**；
- 问 `canvas summary` 拿到的是**某一页**的图（25 节点），无法指定看 00012。

---

## 二、根因 `[实测]`

### 桥的感知粒度 = 「页面（clientId）」，不是「工作流标签」

桥每 10s 推送（`hana-bridge-*.js`）：
```js
POST /hana_bridge/state {
  sid: api.clientId,                       // 一个浏览器页面 = 一个 clientId
  workflow: currentWorkflowInfo(),         // ← 取 activeWorkflowObj()
  copilot: copilotStateForPush(),
}
```
`currentWorkflowInfo()` / `activeWorkflowObj()`（桥 L157/L195）读的是：
```js
app.extensionManager.workflow.activeWorkflow   // ← 只取「当前选中的那一个」
```

py 侧账本：`_frontends[sid] = { workflow, copilot, ... }`（`__init__.py` `_note_frontend`）。
`canvas.pages` → `_pages_payload()` 逐 sid 输出。

**关键**：ComfyUI 前端的**工作流多标签不换 clientId**（同一个页面）。所以：
- 同一页面里打开的 N 个工作流标签 → **只有一个 sid 条目**，名字永远是 `activeWorkflow`（当前选中的）；
- 非选中的标签 → **桥结构性看不见**（它们从不产生独立身份）。

### 前端其实有全量列表，桥没读 `[源码]`

前端打包产物 `settingStore-X9ZV_dAu.js` / `GraphView-CDjciZjE.js` 里：
- `openWorkflows`——**一个页面里所有已打开工作流的数组**（GraphView 的 Tab 条就是遍历它渲染的）；
- `activeWorkflow`——当前选中项。

→ **数据源是现成的**，只是桥只读了 `activeWorkflow`，没读 `openWorkflows`。

### 12 条同名 `(0001)` 的解释
那 12 个 sid 是 **12 个不同浏览器页面**，各自停在 `(0001)`（多开的标签页）。与你真正用的 00012 **不是同一页面** → 自然不在同一 sid 下。

---

## 三、能力缺口定性

**agent native 的核心承诺**是「agent 读的正是人眼前那张图」（桥注释原文）。但现实是：
- agent 只能感知**每个页面的当前选中工作流**；
- **同页面内的其它打开工作流**（含用户正在编辑的那个，只要不是当前 Tab）→ 完全盲区；
- `canvas` 的定向（`workflow=` 参数）也**只能命中"当前选中"的页面**，命中不了"同页非选中标签"。

→ 这是**结构性缺失**，不是配置或调用问题。

---

## 四、修复方案（分层，待评估）

| # | 方案 | 改动面 | 能力 | 风险 |
|---|---|---|---|---|
| **A** | **桥上报 `openWorkflows` 全量列表**：state 增加 `openWorkflows: [{name,path,key,dirty}]`；py 账本按 (sid × workflow) 记多条目；`canvas.pages` 展开为"页面 × 每个打开的工作流" | 桥 js + py + app 展示 | agent 能**枚举**同页所有打开工作流；定向仍受限于"能否写非选中标签" | 中（需改 py 账本结构 + pages 响应形状） |
| **B** | **A + 可写非选中标签**：桥增加 op「切换到指定 workflow 标签 → 再操作」（`openWorkflow(path)` 前端本就支持） | 在 A 基础上加一个 op | agent 能**读且写**任意打开的工作流（切 Tab → 操作 → 切回） | 高（切 Tab 会改变用户视线焦点，需人机共驾约束） |
| **C** | **最小化**：`canvas.pages` 每页附 `openWorkflows` 名列表（只读枚举），定向仍只对活动页 | 桥 js 一处 | agent 至少**知道**同页还开着哪些 | 低 |

**推荐路径**：先 **C**（低风险、立刻消除"盲区"的最大部分：agent 至少能列出所有打开的工作流并告知用户），再评估 **B**（写能力需与"副驾驶/授权"铁律对齐——写非选中标签是否算越权？）。
