## 一、根因结论（一句话）

历史**完全按工作流「显示名」（filename/name）落盘做目录键**，而**保存（saveAs）会改写该名字**——未保存画布以临时名（如 `Unsaved Workflow …`）累积的提交，在保存成正式名后，前端读历史的键变成新名、命中一个**空目录**，旧历史原封不动留在旧名目录里，于是「提交节点全丢」。当前无任何「改名时迁移历史目录」的逻辑，根因假设**成立**。

## 三、确证的复现路径

1. 新建/打开一张**未保存**画布 → 前端 `wf.filename` 为临时名（`Unsaved Workflow …`，`wf.isTemporary===true`）。
2. 在该画布上跑若干次 → 桥在每次运行结束上报 `POST /hana_bridge/history-commit`，`workflow = currentWorkflowInfo().name` = **临时名** → 写入 `.history/<净化临时名>/`（如 `Unsaved Workflow (AgentCopy) 20261014-0034 (Copy)`）。
3. 用户点保存并命名（如 `Qwen21 t2i 质量版 (00012)` 之外的新正式名）→ 走 `canvas.save` 的②另存并切换链，`svc.saveAs(wf, newPath)` → `wf.filename/name` 变为**正式名**，活动页身份切换。
4. 保存后打开/刷新提交树 → `historyOnWorkflowSwitch()` 用**新名**调 `history-list` → 命中 `.history/<净化正式名>/`（**空 / 新目录**）→ 显示 0 条。旧临时名目录里的 4 条提交虽在磁盘，但**没有任何入口再以旧名查询**，故"全丢"。

**键漂移链条：`Unsaved Workflow …`（临时名） ⇒ 保存 ⇒ 正式名 ⇒ 同一 `history_dir()` 算出不同目录 ⇒ 旧目录孤立。**

## 四、修法可行性评估

### 已查到的前端保存方法真实名称与签名（决定修法能否落地）

桥已实测并硬编码调用（L2324、L2360、L2382、L2424）：

- `app.extensionManager.workflow.saveWorkflow(wf)` —— 同名保存全链（写盘 + `changeTracker.reset` + 清 dirty + 清 draft）。**签名：`saveWorkflow(workflow: ComfyWorkflow): Promise<void>`**。
- `app.extensionManager.workflow.saveAs(wf, newPath): ComfyWorkflow` —— 另存为，返回**新**工作流对象（临时页保存走这条）。**签名：`saveAs(workflow, path: string): ComfyWorkflow`**（同步返回 adopted）。
- `app.extensionManager.workflow.createNewTemporary(baseName, state): ComfyWorkflow` —— 建临时页（L1577、L1842）。

> 以上为桥源码注释明确标注"源码核对/可用"，且桥运行期已成功调用，可视为**落地事实**而非推测。保存成功后的可监听信号：① 桥 `canvas.save` 返回值带 `activeAfter`（= adopted.filename）、`switched`；② `wf.changeTracker.reset`（同名保存）；③ `litegraph:set-graph` 事件（换图监听，L4535）——但**没有"保存成功"的专用事件**，只能从 save op 返回的 `activeAfter` 或换图事件推断改名。

### 修法①：桥包装保存方法捕获改名 → 调后端迁移端点

- **可行，但需要新增后端端点 + 桥在 save op 返回后触发**。
- 步骤：桥 `canvas.save` 的②链里，saveAs 前后分别取 `before=wf.filename`、`after=adopted.filename`；若不同，POST 新端点 `/hana_bridge/history-migrate` `{from, to}`，后端 `shutil.move(history_dir(from), history_dir(to))`（已存在则合并 index.jsonl + 快照，防覆盖）。
- 难点：① 同名保存链（①）不改名，无需迁移；② 并发/重复迁移的幂等（目标已存在时合并而非报错）；③ 前端包最小化、改桥即可、不动前端产物。
- **落地成本：中**（桥 ~20 行 + 后端一个端点 + 单测）。

### 修法②：换更稳的键（推荐，治本）

- 改用**稳定身份**做目录键。桥已能拿到的稳定字段：`wf.path`（磁盘相对路径，唯一）或 `wf.key`（前端 Tab 稳定身份，`openWorkflowsInfo` 已用）。
- 将 `currentWorkflowInfo().name` 的"名"语义换为"路径/key 派生键"，`history_dir` 与所有 `history-*` 端点的 `workflow` 参数统一改用该稳键（前端上报也改为传稳键）。
- 优点：从根消除"改名漂移"，顺带修复"同名多开""Copy 后缀"等造成的目录分裂（见磁盘上大量 `(Copy)/(0001)` 目录）。
- 难点：① 需前后端键一致迁移（旧目录按名、新目录按 path 的兼容期）；② `wf.path` 在未保存时是 null/临时，仍需保留"临时页用临时名、落盘后用 path"的两段逻辑，或统一用 `wf.key`（临时页也有 key）。
- **落地成本：中-高**（键口径变更影响 4 个端点 + 前端上报 + 历史目录重映射）。

### 修法③（过渡，最低成本）

- 在 `canvas.save` ②链、`historyOnWorkflowSwitch` 里**保存前后**做一次"按旧名目录→新名目录"的轻量合并（直接复用修法①的迁移端点，但只在改名时跑）。先把"丢数据"止血，再评估是否上修法②换稳键。
