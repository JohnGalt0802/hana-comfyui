## 0. 目标

```
检查环境 →（异常）卡片[重试/清除/取消] →（正常）自动拉起 → 等就绪（轮询）→ 前端操作
```

## 1. 现状与缺口

**已有（约八成，复用）**：`service start/stop/status` 全链（计划任务+vbs）｜就绪探测（5s 轮询）｜面板/覆盖层｜auto-start 开关（默认关）。
**缺**：① 环境检查 ② 卡片 ③ 等就绪 ④ 去重 ⑤ 清除动作。

## 2. 设计（v2 修订）

### 2.1 环境检查（中继侧）

**入口**：op `service envcheck`（独立可调）；start 时自动先跑。

| # | 项 | 手段 | 判定 |
|---|---|---|---|
| 1 | GPU 计算进程 | `nvidia-smi --query-compute-apps` | 存在非 ComfyUI 进程 → **异常** |
| 2 | 显存水位 | `nvidia-smi --query-gpu` | >85% → 警告（可继续） |
| 3 | 端口 8188 | TCP 探测 | 占用且健康 → 无需拉起（衔接）；占用且不可达 → **异常**（残留，分类处理） |
| 4 | 系统内存 | 可选（一期略） | — |

**关键实现约束（老哥）**：
- **分类靠映像名 + 命令行**（`llama-server.exe` / `python main.py`），**不靠显存数值**（WDDM 下 per-process 显存可能 N/A）；
- **nvidia-smi 可用性必须实测**（受限令牌下可能列表不全/权限不足）；**失败降级**：跳过 GPU 检查 → 只警告不阻塞，卡片只报不做；
- **排除"正在启动的 ComfyUI 自身"**：用 `backend-state.startedAt` 窗口 + 路径匹配，防止启动窗口内把自己标成异常；
- **输出附一次性快照 token**：`{ok, warnings[], blockers[], processes[{pid,name,cmdline}], gpu:{}, snapshotId}`。

### 2.2 卡片（异常时）

**形态（老哥裁定：不用降级）**：走 app 内验证过的两条通道——
- 聊天流卡片（submit 的 `details.card` → /task.html 为现成先例；卡片页用 `hana.api.fetch` 拉路由）；
- 交互卡 `window.card.emit`（点击作为消息唤醒 agent）。

**唯一窄点做一次 spike**：聊天内卡片按钮**直接 POST 路由**（现有任务卡只做过 GET）。通则全通；不通再退回"面板提示+文字指令"。

**卡片内容**：标题 + 明细（进程名/PID/说明）+ 提示"清除将丢失其上下文/缓存" + 按钮：

| 按钮 | 行为 |
|---|---|
| 重试 | 重跑检查 |
| 清除其他模型进程 | 仅对**快照内**进程优雅停 → 复查 → 继续拉起 |
| 取消 | 终止流程 |

**安全边界（v2 收紧，红线）**：
1. **不收调用方传入的任意 PID**（防端点注入）：clear 只认 envcheck 的**一次性快照 token**；中继按自带快照复核 pid+启动时间+映像名，**列表外全拒**；
2. **必须扣除启动中的 ComfyUI 自身**；**去重判定排在阻断逻辑之前**（先判"是否已在启动"，再谈异常）；
3. **8188 残留分两类**：监听者是 ComfyUI → "清除并重启"；**无关进程 → 只报告不杀**；
4. **杀后等 2-3s 复查**：被重新拉起 → 报告来源，**不循环杀**；
5. 软停（taskkill 无 /F）留作无害步骤但**不依赖**（llama-server/KVMem 无卸载接口，实质需强杀）；
6. PID 启动时间取数走**候选链**（受限环境 Store 版 PowerShell 会拒绝访问，需实测可用手段）。

### 2.3 拉起与就绪（v2 重写）

- **start 维持快返受理**（现状）——**不做单次长阻塞**：宿主 `ctx.runtime.fetch` 上限 30s（现 start 用 25s），90s 单次等待不成立；
- **新增 wait/status 轮询**：单次 ≤25s，总 deadline **120–150s**，由调用方按节奏轮询；
- **超时语义**：到点只报"仍在启动"+日志路径，**不杀进程**；"启动失败清计划任务"**仅限"进程确实没起来"**；中继现成 90s 看门狗文案与新语义对齐；
- **去重放中继**（三路 start 都走 `/_relay/backend/start`，天然全覆盖）：in-flight 标志 + **state 文件 `startedAt` + 计划任务状态兜底**（防中继重启丢内存标志）；
- 与 auto-start 开关**无冲突**（默认关保留正确）。

### 2.4 与现有 auto-start 的关系

保留不动（机器重启后自动恢复场景）；本方案是 agent 主动拉起（工具路径），互不依赖。

## 4. 验收（v2 补 G/H）

| 场景 | 步骤 | 期望 |
|---|---|---|
| A 顺畅 | 无异常 → 拉起 | 检查通过 → 拉起 → 就绪 → 前端操作 |
| B 占用 | 小秘在跑 → 拉起 | 卡片列出进程 → [清除] → 清理 → 继续 |
| C 取消 | B 中取消 | 无副作用 |
| D 重试 | 自行关闭后重试 | 复查通过 → 继续 |
| E 去重 | 连续两次 start | 不重复创建；返回"启动中" |
| **G 防自杀** | 启动窗口内二次 start | **不得出现"杀自己"卡片**；正确判为"已在启动" |
| **H 反复拉起** | 清除后被 supervisor 拉起 | 报告来源，不循环杀 |
| F 回归 | 既有 start/stop/status/面板 | 不回归 |

## 5. 风险与降级

- nvidia-smi 缺失/受限 → 降级"只警告不阻塞"（实测驱动）；
- PID 取数受限 → 候选链实测；
- 超时 → 明确报"仍在启动"+日志（不杀）；
- 与 **Llama 监视器"一键清空 GPU"（/release）语义重叠** → 两处用户口径对齐（提示文案层面）。

---

**接口契约（派活锚点）**：
- `service envcheck` → `{ok, warnings[], blockers[], processes[{pid,name,cmdline}], gpu{}, snapshotId}`
- `service clear {snapshotId, pids[]}` → `{cleared[], refused[], recheck}`（中继快照复核）
- `service wait` → `{state: starting|ready|failed|timeout, readyInMs?, detail?}`（单次 ≤25s）
- `backend-state.json` 扩展：`{starting: bool, startedAt, lastStartResult}`
