# 更新入口修复方案 · 20260927

**日期**：2026-09-27
**作者**：hanako（主脑）
**触发**：John —— 「hana-comfyui 点更新后好像没任何反应，抓一下日志看看；这个需要优化一下，让前端能看到更新进度」
**状态**：本次即做
**前置**：M11 的 `canvas`… 更正：M11 的**更新入口**（`docs/M11` 未单独记录，实现散在 `panel-status.js` / `comfy-relay.mjs`）

---

## 0. 诊断结论（实测）

| 检查项 | 结果 |
|---|---|
| 中继日志里 `/_relay/update` 痕迹 | **无** |
| `logs/update-state.json` | **不存在** → 更新任务**从未启动** |
| 宿主日志 `_relay/update` | **无** |
| App 路由注册 | `…|theme|update*` **齐全** |
| `applyUpdate` 第一行 | **`window.confirm(...)`**，为假则 `return` |

**根因**：`applyUpdate` 用 `window.confirm` 做二次确认。工作区是**沙箱 iframe**，
`confirm` 被静默拦截 → 返回 `false` → 函数**一声不响地 return**。表现就是"点了没反应"。

**顺带发现**：宿主日志里 `version=0.6.0`，而实际加载的是 `v0.8.0` —— `APP_VERSION` 常量没跟着升。

---

## 1. 修什么

### 1.1 去掉 `window.confirm`，改「两步点击」

沙箱下不能指望 modal。改成按钮自身承载确认：

- 第一次点「更新」→ 按钮变「**再点一次确认更新**」（红色警示态），`u-note` 同步提示
- 3 秒内不再点 → 自动复原为「更新」
- 期间再点 → 真正执行

好处：不依赖 modal、意图明确、误触有缓冲。

### 1.2 点击即刻反馈（把反馈提到最前）

现在 `u-note` 的"已发起…"写在 `confirm` 之后；改后**第一行**就给反馈，
并把按钮置 `disabled`，避免连点。

### 1.3 让更新进度可见（本就该有，一并确认）

- 保留 2 秒轮询 `/comfyui-hana/update/status`
- 阶段文案：`stopping → fetching → pulling → installing → done/failed`
- 日志尾从 10 行提到 **30 行**（`git pull` / `pip install` 的输出更有参考价值）
- 显示**已耗时**（从任务开始时间算），长任务里这个最有安抚作用

### 1.4 顺带修版本号

`APP_VERSION` 从 `0.6.0` 升到与 manifest 一致（当前 `0.9.0`）。

---

## 2. 不改的事

- 更新流程本身（停服务 → `git pull --ff-only` → `pip install`）不动
- 中继的 `/_relay/update*` 不动
- 「检查更新」按钮不动（它本来就没有 modal）

---

## 3. 验证计划

1. 点「更新」→ 按钮变「再点一次确认更新」，`u-note` 立刻有字（**不弹窗**）
2. 3 秒不点 → 自动复原
3. 连点两次 → `POST /comfyui-hana/update` 发出，`update-state.json` 出现
4. 轮询显示阶段推进 + 日志尾 + 已耗时
5. 宿主日志的 `version=` 与实际一致
