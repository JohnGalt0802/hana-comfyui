# 方案 · 历史主键改为「画布身份 id」（2026-10-14）

> **用户决策（已拍板）**：① 另存为新文件 = 分家（新画布新历史）；② 共享 id 组 = 首次发现就换新 id 各算各的（mint）；③ 现有 6 个按名目录现在就按 id 重排。
> **根因**：历史目录以工作流**显示名**为键，改名/另存致键漂移（见 `docs/排查-工作流身份机制-20261014.md`、`docs/排查-提交历史保存后丢失-20261014.md`）。
> **前端机制（源码实证）**：JSON 顶层 `id`（uuid）是持久身份；`renameWorkflow` 保 id、`saveAs` 换新 id；**临时画布保存走 rename（保 id）**。

---

## 1. 主键设计

**历史目录键 = 画布身份 id**（`.history/<uuid>/`），名字退为纯显示。

- **从哪里取**：桥侧 `app.graph.id`（`loadGraphData` 会把 JSON 的 id 带进 `app.graph.id`）；兼容取 `activeWorkflowObj().activeState?.id`。
- **目录内容**：`index.jsonl` + 快照 + sidecar（原样），**新增 `.meta.json`**：`{ "id": "<uuid>", "name": "<显示名>", "path": "<相对路径>", "updatedAt": "<iso>" }`（供人类辨认 + 兜底定位）。
- **改名自动跟随**：rename 保 id → 历史目录键不变 → **用户报的 bug 从根消失**。

### 兼容与兜底（读路径）

`history_key(candidate)` 解析顺序：
1. 有有效 `workflowId`（uuid）→ **查 claims 表**决定键（见 §3）。
2. 无 id（老画布）→ 用 `sanitize_workflow_name(name)` 作键（老逻辑）；**首次写入时 mint 一个 id 记入 claims**，此后走 id。
3. 回退查找：按 id 找不到目录时，回退按名目录（兼容期，也兼容重排前）。

## 3. mint（共享 id → 各算各的）

**场景**：多张画布文件共享同一 id（17 个 `hui-*` 共 `9053fa54`、5 个 `minimax_*` 共 `e3f2b845` 等）。

**⚠️⚠️ 第二处致命缺陷（2026-10-14 二次实测复现）：已保存画布「改名」仍会 mint**
上一条修正解决了「临时→正式」，但「已保存画布改名」（同 id，path 旧→新，旧文件被 move 走）仍触发 mint → 键变 → 历史丢。实测：`改名前键=22222222…` → `改名后键=eb2fe864…` → 查历史空。根因：**用 path 当"变没变"的判据**，而 path 恰恰随改名变。

**终极判据：基于「文件系统事实」，而非任何会变的值。**
- 事实：同一时刻一张画布只占一个文件；改名时**旧文件消失**；两张共享 id 的画布**各自文件都在**。
- 故判据问「旧文件还在不在」，不问「值变没变」。

**算法（`history_key`）**：claims 结构 = `{ "<id>": { "<identity>": "primary"|"<sideId>" } }`（identity = TEMP 哨兵 / path / name）；返回时 `"primary"` 映射回 id 本身。
```
def history_key(name, id, user_dir, path, temporary):
  if not valid_uuid(id): return sanitize(name)
  identity = TEMP if temporary else (path or name)
  rec = claims.get(id) or {}
  if identity in rec: return rec[identity]          # 幂等
  if TEMP in rec and identity != TEMP:              # 临时→正式：升级
      key = rec.pop(TEMP); rec[identity] = key; 写回; return 解析key
  missing = [k for k in rec if k != TEMP and not 文件存在(k)]   # 消失的正式 path
  if len(missing) == 1:                             # 恰一个消失 → 单张改名 → 跟随
      key = rec.pop(missing[0]); rec[identity] = key; 写回; return 解析key
  if not rec:                                       # 首次认领
      rec[identity] = "primary"; 写回; return id
  side = uuid4(); rec[identity] = side; 写回; return side   # 两张独立 → mint
```
（`解析key`：`"primary"`→id，否则→sideId。`文件存在(k)` = `os.path.isfile(os.path.join(user_dir, k))`，仅对非 TEMP 的正式 path 有意义。）

**覆盖场景**：临时→正式（升级）✅；单张改名（旧文件消失→跟随）✅；两张独立共享 id（都还在→mint）✅；幂等 ✅。**已知边界**：多张同时消失（无法确定哪一个改名）→ 按 mint/初次处理，不丢数据。

---

**初版判据（已被上面取代，存档）** → **改名本身就触发 mint**（name 变 → 判为"异身份" → 分配 sideId → 键变 → 历史查空），**原地复现原 bug**（改名跟随失效）。用 **path** 当判据同样错（rename 时 path 也变）。

**正确判据：identity 归一化为「临时态 vs 已落地路径」**
```
identity = TEMP("__temp__")   若 temporary（未保存画布）
         = path               若已落地文件有相对路径
         = name               兜底（无 path）
```
- 首次见 id → `owner = identity`，键 = id。
- 再见同 id、**identity == owner** → 键 = id。
- 再见同 id、**owner == TEMP 且新 identity 是正式 path** → **owner 升级**为 path（同一张画布从临时落地），键 **仍 = id** → 历史跟随 ✅。
- 再见同 id、**两个不同的正式 path** → **冲突 → mint**：为后者分配 `sideId`（新 uuid，持久化 `paths[path] = sideId`），键 = sideId → 各算各的。
- 再见同 id、identity 已登记 sideId → 复用（幂等）。

> **关键**：`temporary` 标志由桥上报（`workflowTemporary(wf)`）；后端据此把临时画布归入 TEMP 身份，**不受其显示名变化影响**。这样「临时跑图 → 保存为正式名」全程键 = id，历史自动跟随。

**机制**（`claims` 登记表，存 `<user_dir>/workflows/.history/.claims.json`）：
```json
{ "<uuid>": { "owner": "<TEMP|path>", "paths": { "<TEMP|path>": "<lastSeen-iso|sideId>" } } }
```
> **不改画布文件**：mint 出的新身份只登记在后端 claims（`sideId`），不污染用户的模板/存档文件。效果等同"各算各的"，风险最小。
> **兜底**：claims 丢失/损坏 → 回退 id 键（可能短暂混，不丢数据）。

**桥/端点需补**：所有 history 调用带上 `workflowPath`（`wf.path`，临时为 null）与 `workflowTemporary`（bool）；5 端点透传；`history_key` 增 `path`/`temporary` 参数。

## 4. 保存路径对齐（关键洞，必须一起修）

**问题**：桥 `canvas.save` 现在对"名字变了"一律走 `svc.saveAs` → **换新 id**；而前端原生对**临时画布**走 `renameWorkflow` → **保 id**。二者不一致，只换主键不补这里，hui 内保存照样断。

**修法**：桥 `canvas.save` 的"另存并切换"链改为**对齐前端语义**：
- 临时画布（`isTemporary`）保存为正式名 → 调 `svc.renameWorkflow(wf, newPath)` + `svc.saveWorkflow(wf)` → **保 id**（历史自动跟随）。
- 已存文件另存新名 → 维持 `svc.saveAs` → 换新 id（= 分家，符合用户决策①）。

## 5. 重排脚本（现有 6 目录，一次性）

**脚本** `tools/reorder-history-by-id.mjs`（或 .ps1）：
1. 全量备份 `.history` → `_backup/history-reorder-<ts>/`。
2. 遍历 `.history/<名>/`：读其快照 `graph.id`（首条带快照的提交）。
3. 建 id → 目录 映射；幂等（已是 id 目录则跳过）。
4. `os.rename(<名目录>, <id目录>)`；写 `.meta.json`。
5. **孤儿**（id 无对应画布，如 `Unsaved Workflow…(Copy)` gid `923cfd3c`）→ 移入 `.history/_orphans/<名>/`。
6. 输出变更清单（旧名 → 新 id + 行数 + 快照数）。

**预期映射**（据身份矩阵）：

## 7. 验收标准

1. **主 bug**：临时画布跑几次 → 保存为正式名 → 历史**仍在**（id 未变，自动跟随）。
2. **改名**：画布改名 → 历史跟随（id 未变）。
3. **另存分家**：已存文件另存新名 → 新文件新历史，旧历史留旧文件。
4. **mint**：两个共享 id 的画布分别跑图 → 历史**不混**（一主一 side）。
5. **重排**：6 目录重排后，各画布历史条数不变、可正常读取。
6. **兼容**：无 id 老画布（`Qwen21 提示词增强器`）跑图 → 正常记历史（mint 后走 id）。
7. 已有历史无丢失（备份可回滚）。

## 9. 风险与回滚

- **风险 1**：claims 并发写（多页同时跑图）→ 用「读-改-写 + 原子替换（temp+os.replace）」+ 文件锁兜底。
- **风险 2**：id 目录与名目录并存期的读口径 → 统一"先 id 后名"回退，不双写。
- **风险 3**：mint 判定"同 id 异 path"依赖 path 稳定；改名后 path 变但 id 不变 → 不误判（同 id 视为同一张，更新 primary path）。
- **回滚**：`git checkout` 相关文件 + 重新部署 + 重启；数据回滚 = `_backup/history-reorder-<ts>/` 整体恢复。
