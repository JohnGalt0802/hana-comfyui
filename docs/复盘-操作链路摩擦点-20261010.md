# hui（Hana-ComfyUI）操作链路摩擦点复盘 · 2026-10-10

> 主线：agent 用 hui 完成一次生图的端到端链路。仅梳理**摩擦点 / 易错点**（现象 / 为什么硌 / 证据 / 严重度）。
> 证据缩写：`SKILL`=SKILL.md；`canvas`/`submit`/`copilot`/`service`/`trouble`=references/*；`坑`=踩坑记录.md（§n）；`共驾清单`=画布共驾-实操问题清单-20261008.md（Pn）；`汇总`=hui-使用问题汇总-20261008.md（An/Bn/Cn）；`复盘`=hui-效率复盘-进一步总结-20261008.md（§n）。
> 严重度：高＝链路卡死/假成功/回执丢失；中＝多一轮排查或易误判；低＝已修或仅性能税。

## ① 找 / 开目标工作流（在线页面池、定位、openWorkflow vs loadWorkflowFile）

**F1-1 · openWorkflow 用 name 路由静默超时，且报错文案与现状矛盾**
- 现象：`openWorkflow(name=…)` 在「无任何页面打开着该工作流」时静默 6s 超时，报「可能没有打开的页面」——而当时实际有 3 个页面在线（仅没开目标工作流）。改 `path=` 一次成功。
- 为什么硌：agent 第一次尝试失败，报错方向误导排查；name 路由「只发给正打开该名的页面」的语义对 agent 不透明。
- 证据：`汇总` A1；`坑` §18（openWorkflow 走工作流服务层）；`共驾清单` P1。严重度：**中**

**F1-2 · openWorkflow「半成功」：返回 opened:true 但画布不装载，还留下 dirty 脏态**
- 现象：返回 `opened:true`、`activeAfter` 显示已切换，但 `summary`/`events` 仍是旧图；页面被置为「有未保存改动」，并卡住后续 `loadWorkflowFile`。
- 为什么硌：调用方误以为切换完成，脏态让后续装载被 `blocked:"dirty"` 拦下——半状态比报错更危险。
- 证据：`共驾清单` P1；`坑` §18（"打开"与"显示"可不同步）。严重度：**高**

**F1-3 · openWorkflow 与 loadWorkflowFile 语义混用**
- 现象：两者都作用于**当前活动页**，但 openWorkflow =「在前端打开/切到某已保存工作流（服务层状态变，画布未必换）」，loadWorkflowFile =「读文件 + loadGraphData 直接替换当前画布」。要"进画布"必须用后者。
- 为什么硌：概念误用会撞 F1-2（开了 ≠ 装了），或被 dirty 拦。
- 证据：`坑` §18；`canvas` loadWorkflowFile / openWorkflow 段落。严重度：**中**

**F1-4 · 页面身份与定向失效（多页面时）**
- 现象：前端 1.53.6 无 `workflowManager` → `pages` 恒「(未命名)」、真名定向恒 `no_page`（`坑` §24，已修「(未命名)」但依赖 `activeWorkflowObj`）；`_frontends` 死条目无 TTL，`hits[0]` 截胡定向 → 活页收不到、静默 6s 超时（`坑` §25，未修）。
- 为什么硌：多页面场景下「定向到哪一页」不可靠，死条目会让所有定向调用吃 6s 超时。
- 证据：`坑` §24 / §25。严重度：**中**

**F1-5 · 无法指定「新开页装载」，只能占用当前活动页**
- 现象：openWorkflow/loadWorkflowFile 都作用于当前活动页 → 会顶掉用户正看的画布，或被用户页 dirty 拦（后已有 `loadWorkflowNewPage` 接管「放入」语义，`坑` §34）。
- 为什么硌：agent 干活页与用户页耦合，易互相打扰；多页面下无法主动选目标页。
- 证据：`汇总` A3；`坑` §34。严重度：**中**

## ② 复制工作台五步（duplicate → save → copilot → loadWorkflowFile → queue）

> v2 固定顺序（`submit` canvas 路径 / `copilot` v2 流程）：复制副本（原布零改动）→ 副本落盘 → 开副本副驾驶 → 装载到副本 → settle 断言活动页=副本页 → queue。

**F2-1 ·〔特别核对〕save 落盘后活动页引用变更 → 按页记录的副驾驶失配，需重开**
- 现象：v2 五步顺序为 **先 `save` 落盘（命名 `<原名去尾> (AgentCopy) YYYYMMDD-HHmm`）→ 再 `copilot` 开副本副驾驶 → 再 `loadWorkflowFile` 装载**。`copilot` 存储按页独立（localStorage key = `hana.copilot.v1:<ws>:<hashPath>`，pageKey = **活动 workflow path**）。`save` 产生的是新文件名（新 pageKey），而 `copilot` 若按 save 前的页面 path 记录，则 `loadWorkflowFile` 装载后活动页 path 已变 → 新页副驾驶状态读为「关 / 未知」，执行 `queue`（写类 op）会被 `copilot_off` 拒，需再开一次。
- 为什么硌：副本流程里「开副驾驶」这一步的生效对象与「装载后实际活动页」错位，副驾驶需每换一次页身份就重开，步骤脆弱。
- 证据：`copilot` v2 流程 / 存储-按页独立 / 状态链路；`canvas` 写拦截豁免理由「save 先落盘再开副本副驾驶，顺序要求」；`共驾清单` P2（"save 另存到新文件名成功；页面仍标未保存改动"）。严重度：**高**〔注：文档未明写 save 会切 activeWorkflow，副驾驶失配为依「按页记录」机制的推断，需真机复核〕

**F2-2 · AgentCopy 副本名无限叠加，撞 400 超长被拒**
- 现象：页名叠成 `…(AgentCopy) 20261008-1555 (AgentCopy) 20261008-1556 (AgentCopy)…`，越叠越长；提交时撞 `400 Invalid filename`。
- 为什么硌：复制总是从「当前活动页」（=上一轮落盘的副本页）出发，而 `agentCopyBaseName` 清理清单漏了 `(AgentCopy) YYYYMMDD-HHmm` 本身，每轮净增一层。
- 证据：`汇总` B3；`复盘` §三（代码级实锤 `app/index.js agentCopyBaseName`，修复建议已提，状态："修复漏项 B3"）。严重度：**高**（已实锤撞 400）

**F2-3 · 副驾驶「按页记录」→ 副本链每层都是新页，需逐页开；切换后状态「未知」≠「关」**
- 现象：`copilot` 状态存 localStorage、按页独立、刷新保留；`state`/`pages`/内容读 op 尾注标注，但退化口径"其余未知"，精确版待桥 py 升级。
- 为什么硌：agent 在副本上工作，每一层新页都要重新开副驾驶；状态不可见时不敢写（怕 copilot_off）。
- 证据：`copilot` 存储 / 状态链路；`canvas` 副驾驶标注段。严重度：**中**

**F2-4 · 副驾驶总闸（「允许 Agent 开启画布副驾驶」）关 → 副本上无法开副驾驶 → 画布路径整体走不了**
- 现象：`canvas.copilot` 只受总闸管辖；总闸关时技术层面无法开启任何画布副驾驶，submit 的 canvas 路径因此不可走（停下 + 选项）。
- 为什么硌：两道授权闸任一关，整条画布主干道中断，只能 fallback backend（丢值风险）。
- 证据：`copilot` 授权开关 / 硬约束；`submit` mode 判定。严重度：**高**

**F2-5 · duplicate 是临时页，刷新即清理、无落盘——依赖 save 保身份**
- 现象：副本初始为临时页（命名 `*(Copy).json`），刷新即清、无落盘影响；须 `save` 落盘获文件身份。
- 为什么硌：未 save 的副本一刷新就消失，操作中途刷新会丢工作页。
- 证据：`canvas` duplicate 段。严重度：**低**

## ③ 改参数（setWidget / patch 事务 / 节点定位）

**F3-1 · connect 后必须 get 验证 `input.link`，桥 ok ≠ 真连上；widget 转换槽首次 connect 可能静默失败需重试**
- 现象：给 widget 槽 connect 未报错但未连上，重试一次才成；`canvas` 路由返回是「人话文本」非 JSON。
- 为什么硌：只看桥回执会误判连接成功，出图节点缺输入。
- 证据：`坑` §23③ / §23④；`canvas` 写操作纪律「改后拉 get 核对」。严重度：**中**

**F3-2 · 自动增长槽断开后收缩改名（StringFormat values.*）**
- 现象：断 `values.b` 后原 `values.c` 补位成新 `values.b`；照旧名再断报"本来就没连线"。
- 为什么硌：同一批 disconnect/connect 后槽名会变，按缓存名操作必错；每次都要重新 `get`。
- 证据：`坑` §23②。严重度：**中**

**F3-3 · patch verify 批次终态误报回滚（三类合法批）→ 已改即时化**
- 现象：disconnect+connect 同槽、同槽多次 setWidget、[setWidget X, removeNode X] 被 verify 误判回滚（`ok:false`）；已修复为「每条执行后即时核验」。
- 为什么硌：已修，仅作版本提醒——老行为会让正确编辑被整体回滚。
- 证据：`坑` §26。严重度：**低（已修）**

**F3-4 · 逆操作漏（connect 直替丢旧连线 / setWidget 回滚写空对象）→ 已修**
- 现象：直替连接撤销后原连线永久丢失；同批删除后 setWidget 回滚静默无效果；已修（记 prevRec、按 id 重寻）。
- 证据：`坑` §27。严重度：**低（已修）**

**F3-5 · 并发：patch 执行窗内到达的写 op 被 collector 吸收 → 误伤 undo → 已修**
- 现象：长批 save 期间别的写 op 逆操作被吸进复合撤销，undo 顺手回退无关修改（2/3 命中）；窗口已收窄。
- 证据：`坑` §29。严重度：**低（已修）**

**F3-6 · canvas 路由返回「人话文本」非 JSON，别 ConvertFrom-Json 硬解析**
- 现象：addNode/connect/save 返回 `已新建 #28…` / `已连线…` 文本；结构化数据一律拉 `get`。
- 为什么硌：agent 解析陷阱，硬 JSON 解析会崩。
- 证据：`坑` §23④。严重度：**中**

**F3-7 · 节点定位靠 select 投影裁剪，大图全量 get 几万字符**
- 现象：27 节点全量 get 实测 53,617 字符；须先 `select=#8,#27` + `fields=…` 砍字段。
- 为什么硌：性能税 + 上下文浪费。
- 证据：`canvas` get 投影裁剪段。严重度：**低**

## ④ 体检（check；悬空 / 未接 / mute·bypass）

**F4-1 · check 误报（SaveImage OUTPUT_UNWIRED filename_prefix）**
- 现象：SaveImage 的 `filename_prefix` 是 widget（images 输入已连），却被报「输出未接」；属误报。
- 为什么硌：需人工判断无害，浪费一轮核对；误报累积会削弱 check 可信度。
- 证据：`共驾清单` P7。严重度：**中**

**F4-2 · check 不查「值对不对」——值类问题完全查不出**
- 现象：check 只查 DANGLING / OUTPUT_UNWIRED / MUTED_BYPASSED；原语节点丢值（B1）、LoadImageOutput 回卷（B2）这类"图连着但值错"查不出。
- 为什么硌：值正确性只能事后看产物，构成「信任税」（全程逐项核对）。
- 证据：`canvas` check 段；`汇总` B1/B2；`复盘` 隐性税 A。严重度：**中**

## ⑤ 发起执行（canvas.queue vs submit；submit 的 inputs 会直走后端这条）

**F5-1 · submit 结构豁免：inline 对象 / 非空 inputs → 直接走 backend（不经画布）**
- 现象：`workflow` 为 inline 对象（非 `{template}` 单键）或带非空 `inputs` → 形态判定前置、直接走 backend；回执注明「未上画布：inline/inputs 形态直走后台提交」。
- 为什么硌：后端 UI→API 转换对原语节点会丢值（B1）、LoadImageOutput 会回卷（B2）→ 出图内容与预期不符且假成功（"少女"旧提示词、旧参考图）。这是整条链路最隐蔽的假成功源。
- 证据：`submit` 结构性豁免段；`汇总` B1/B2；`canvas` UI→API 转换边界（子图/环绕/静音/未知节点明确报错）。严重度：**高**

**F5-2 · canvas.queue 无回执 / 无任务卡**
- 现象：queue 快返只有 promptId / 队列号，进度与结果需手动 `query`；不像 submit 有 next-step 任务卡与完成回执。
- 为什么硌：画布路径下 agent 看不到实时进度，只能等产物或靠用户看画布。
- 证据：`共驾清单` P8；`汇总` C2。严重度：**中**

**F5-3 · 行为不一致：auto 画布忙→报错退出不抢占，但 inline/inputs 却静默走 backend**
- 现象：画布有执行中任务时 submit(auto) 报错退出（不静默改走后端）；而 inline/inputs 形态又会静默直走 backend——"想后端得显式 mode=backend"与"被动 backend"并存，易误判。
- 为什么硌：agent 难预判一次 submit 到底走哪条执行位置。
- 证据：`submit` mode 判定 / 例外·画布忙。严重度：**中**

**F5-4 · queue 空图被服务端校验拒（prompt_no_outputs），不静默假成功**
- 现象：无输出节点时提交被拒，op 如实报"提交被拒"，不假成功。属**正确行为**，仅提示 agent 需识别该回执。
- 证据：`canvas` queue 段。严重度：**低（正向）**

**F5-5 · queue 返回 promptId 可能缺失（忙 / 差集兜底）≠ 未提交**
- 现象：画布忙或捕获不到时 promptId 缺失，靠 /queue 前后差集反查；仍拿不到如实返回不带 promptId。
- 为什么硌：agent 不能因为没有 promptId 就判定提交失败。
- 证据：`canvas` queue 段。严重度：**低**

## ⑥ 进度与回执（宿主任务卡、next-step 投递）

**F6-1 · 子代理会话 next-step 永不自动送达**
- 现象：宿主 next-step 可靠投递只写桌面会话；子代理会话发起的 submit 宿主任务 `_assertActiveDesktopSessionPath` 静默拒绝、每 30s 重试但永不送达；返回值会标注，需 `query`/`result` 主动取。
- 为什么硌：从子代理会话提交后"没有自动回执"，容易被当成失败或卡住。
- 证据：`submit` 任务桥与投递 / 子代理会话边界。严重度：**高**

**F6-2 · 无 callToken 调用降级为仅内存跟踪（不投递）**
- 现象：按钮通道等无 callToken 调用同样降级，回执不投递，需主动 query/result。
- 证据：`submit` 任务桥段。严重度：**中**

**F6-3 · 执行进度 agent 不可见**
- 现象：canvas 无只读 `progress` op，跑中只能 query（且 queue 无卡）；用户不在场时 agent 完全盲区。
- 证据：`汇总` C2；`共驾清单` P8。严重度：**中**

**F6-4 · 环境自举链分阶段（preparing → 后台准备 → 自动继续 / 停下）**
- 现象：auto 探测到环境缺会快返「环境准备中」回执 → 后台起服务/拉窗 → 就绪自动走完五步；但 envcheck 阻断 → 停下不自动清障，需 `service clear` 后重提；静态预检前移，"引用不可装载"立即停下（`canvas-unloadable`）。
- 为什么硌：submit 返回可能是 preparing/blocked 而非 promptId，agent 需理解三态不误判为完成。
- 证据：`submit` 环境自举链 / 待同步段。严重度：**中**

## ⑦ 取产物与交付（result、会话文件、reload 时机）

**F7-1 · result「尚未完成」需等几秒重试 / 先 query**
- 现象：产物未落时 result 报"尚未完成"，属时序，等几秒即可。
- 证据：`trouble` 排错表。严重度：**低**

**F7-2 ·〔特别核对〕reload 断工具 RPC，处置阶梯**
- 现象：App reload 会重载新代码，但**当轮** agent 工具 RPC 断（`RPC peer closed; cannot call callback.tools.execute`）；§33 一度定"回合级自愈、不需重启"，§36 当晚两例实测推翻（等用户消息、二次 reload 均未恢复，**重启宿主才恢复**）。
- 处置阶梯（§36 订正）：① reload 后断 RPC **先别动**——走**路由级调用**继续干活（`POST /api/apps/comfyui-hana/routes/comfyui-hana/<action>`，Bearer token 取 `~/.hanako/server-info.json`；边界：仅路由能力可达，`window open` 等 SDK 动作仍须工具面）；② 等 1~2 个用户回合再试工具；③ 仍未恢复 → **重启宿主（终解，两次实测）**；④ **禁止反复 reload**（疑打断重建）；⑤ 预防：生效动作集中克制、勿穿插验收。
- 为什么硌：重新部署/改代码后当前会话工具全失灵，链路直接断；处置选错（反复 reload）反而更慢。
- 证据：`坑` §19 / §33 / §36。严重度：**高**

**F7-3 · reload 重启中继 → 跑着的长任务断**
- 现象：reload 还会重启中继（受管 runtime），进行中的生图任务会被打断；reload 前应先查中队长任务。
- 为什么硌：部署与在跑任务抢跑，产物未出。
- 证据：`坑` §13 / §33。严重度：**中**

**F7-4 · 宿主重启后工具目录缺 app 工具（"未找到工具：comfyui"）**
- 现象：宿主重启后会话恢复早于 app 加载数秒，工具目录不含 app 工具；报"未找到工具"（≠ RPC 断）；切到另一对话再切回即恢复（10 秒）；等待/disable-enable/reload 均无效。
- 为什么硌：与 RPC 断症状相似但处置不同（切会话 vs 路由级 vs 重启宿主），需先看回执字样。
- 证据：`坑` §37（工具面三态：RPC 断 / 目录缺工具 / 就绪）。严重度：**中**

**F7-5 · 产物定位与入会话**
- 现象：产物在 `output\<subfolder>\<filename>`；`result(stage:true)` 尝试入会话文件。
- 为什么硌：仅提示——filename_prefix 会进子目录，需按 path 取。
- 证据：`trouble` 数据日志段；`submit` result 段。严重度：**低**

## ⑧ 权限与状态（两开关；副驾驶按页记录；write 拦截与豁免名单）

**F8-1 · 写拦截 copilot_off（硬约束）**
- 现象：写类 op 在「当前活动页副驾驶未开」时统一拒绝 `{ok:false, error:"copilot_off"}`；仅 `openWorkflow`/`duplicate`/`save`/`copilot` 豁免，`frameReload` 不在写名单。
- 为什么硌：链路硬闸——未开副驾驶的画布上，除"打开/复制/落盘/开开关"外一切写操作被拒。
- 证据：`canvas` 写拦截段；`copilot` 硬约束。严重度：**高**

**F8-2 · 两道授权开关默认关、即开即生效**
- 现象：①「允许 agent 修改画布」(写授权) ②「允许 Agent 开启画布副驾驶」(总闸)；任一关 → submit 停下 + 选项（去开开关 / 显式 `mode=backend` / 先不跑），不静默改走后台。
- 为什么硌：整条画布主干道依赖两闸全开；默认全关意味着 agent 上手第一件事往往是"被停下"。
- 证据：`copilot` 授权开关；`submit` mode 判定。严重度：**高**

**F8-3 · 副驾驶按页记录 + 状态工具面不可读**
- 现象：① 存 localStorage 按页独立、刷新保留；② 状态链路退化（未知≠关），`state` 快照行 / `pages` 逐页 / 内容读 op 尾注标注；但精确版待桥 py 升级；③ 实操中 `canvas` 输出一度不显示 copilot 字段（`共驾清单` P3），agent 感知副驾驶无正规通道，被迫直 POST 桥。
- 为什么硌：agent 拿不准"当前页副驾驶开没开"，开错会撞 F8-1。
- 证据：`copilot` 存储/状态链路；`共驾清单` P3。严重度：**中**

**F8-4 ·〔特别核对〕多页面：广播 vs 定向**
- 现象：桥 `/call` 广播（sid=None）在**单实例**等价点对点，但**多实例**下=复制指令（每个页面各自一份图内存，各改各的、各自计数 id，落盘"谁先回存谁的图"不可控，`坑` §7/§11）；定向 sid 失效会静默丢消息（`坑` §6④）；现按 `workflow` 名定向（`canvas` workflow 参数），但死条目截胡 6s 超时（`坑` §25 未修）。
- 为什么硌：多页面并存时，"指令发给了哪个实例、回的是哪份图"不可控；脏脏死条目让定向全部超时。
- 证据：`坑` §6④ / §7 / §11 / §25；`canvas` 多页面定向段。严重度：**中**

**F8-5 · 总闸只在 app 层生效（桥读不到设置）**
- 现象：`copilot` 开关只受 app 层总闸管辖，桥侧只兜底 copilot_off 写拦截；桥无法感知"总闸是否开"。
- 为什么硌：桥与 app 两处分责，错误提示可能只说"副驾驶关"而非"总闸未授权"。
- 证据：`copilot` 硬约束边界。严重度：**低**

**F8-6 · visual（lock/highlight）属写类 op，未开副驾驶也受写拦截；app 侧写 op 自动 lock 包裹不分开关**
- 现象：`visual` 同属写类，未开副驾驶被拒；而 app 层 patch/organize/commands 自动做 lock→操作→highlight 包裹（异常 clear），包裹不分 copilot 开关。
- 为什么硌：lock/高亮虽是"安全提示"，仍受副驾驶闸门约束，未开副驾驶时连可视化标记都做不了。
- 证据：`canvas` visual 段；`copilot` 经手分明段。严重度：**低**

## 特别核对汇总（题述四问）

1. **save「另存并切页」→ 新页副驾驶需重开**：见 **F2-1**。v2 五步顺序为 "save 落盘（新文件名）→ copilot 开副本副驾驶 → loadWorkflowFile 装载"；副驾驶按**活动 workflow path** 记录，save 产生的新文件名 = 新 pageKey，装载后活动页 path 已变 → 副驾驶失配、需重开。文档未明写 save 切 activeWorkflow，此失配为依机制推断（已标 [需真机复核]）。`共驾清单` P2（save 后页面仍标未保存）侧面印证"落盘≠切页就绪"。
2. **多页面广播 vs 定向**：见 **F8-4 / F1-4 / F1-5**。广播=复制指令（§7/§11）；定向 sid 静默丢（§6④）；现按 workflow 名定向，死条目截胡 6s 超时（§25 未修）；副本链叠加让"按页辨别"更难（D2）。
3. **UI→API 转换器已知限制**：见 **F5-1 / 汇总 B1 / B2 / `submit` 转换边界**。支持经典图；**子图 / 环绕节点 / 静音或旁路节点 / 未知节点类型**明确报错需改导出 API 格式；原语节点值丢（B1）、LoadImageOutput combo 受控下拉回卷（B2）——后端直提的隐蔽假成功源。4MiB+ 大文件已由中继直读直提修复（`坑` §31 / M13）。
4. **reload 断工具 RPC 处置阶梯**：见 **F7-2（§36 订正）**。① 走路由级调用继续干活（SDK 动作仍须工具面）；② 等 1~2 用户回合；③ 仍不行→重启宿主（终解，两实测）；④ 禁止反复 reload；⑤ 预防：生效动作集中克制。配套：reload 重启中继会断长任务（F7-3），宿主重启后"未找到工具"走切会话（F7-4 / §37）。
