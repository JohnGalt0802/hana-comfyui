## 1. 常驻轮询开销 · graphSignature()

**测量方法**：桥内 `graphSignature()`（L719）为模块私有，不可经 `window.__hanaBridge` 直接调；按 L719 同款逻辑（逐节点 `fnv1a(type:mode:title:widgets)` + 链接计数 + 串接 hash）在 `evaluate` 中复刻，跑在真实 `app.graph` 上。`performance.now()` 包 10 次取均值。另在合成图上测缩放。

**实测数字**
- 真实画布（42 节点 / 57 链接）：**0.69 ms/次**（10 次均值）。
- 算法缩放（合成图，links≈1.36×nodes）：42→0.21ms、81→0.21ms、98→0.25ms、200→0.49ms、500→1.03ms。

**成色**：实测（复刻算法跑在真实 `app.graph` 上，口径与 L719 一致）。

**结论**：纯签名成本极低（<0.3ms @ <100 节点），`setInterval(pollGraph, 1500)`（L6136，间隔 1.5s）占空比可忽略。

## 2. 提交历史 DOM 渲染开销 · historyTreeRenderTree + historyTreeDrawEdges

**测量方法**：展开提交树（`#hana-history-tree` 点 `.htr-toggle`），`performance.now()` 包覆；重渲染用 `.htr-view-btn`（视角切换，不 refetch）触发 3 次取稳值。统计 `#hana-history-tree .node`、`.htr-edges path`、`.lanes` 后代总数。

**实测数字（81 节点树）**
- 首次展开端到端（含 151KB `history-list` fetch + 解析 + 渲染 + 连线）：**818 ms**（墙钟）。其中 JS 工作量 ≈ fetch 网络 33ms + 解析/渲染/连线 ~70–100ms，余量为浏览器合成与 rAF 等待。
- 重渲染（视角切换，不 fetch）：同步 DOM 构建 **15.6 ms** + rAF 连线/绘制 **52.7 ms** ≈ **68 ms** 总（view-btn 点击到下一帧完成）。视角切换 3 次稳定：78.8 / 78.2 / 79.3 ms（含 ~70ms 等待稳定，实际约 8ms 同步 + 53ms 连线）。
- DOM 节点：**`.node` 按钮 81 个**；`.lanes` 内后代总数 **629**；**SVG path 1 条**（所有连线段合并进单个 `path`，DOM 友好）。

**外推**：68 节点（任务原值）按线性估计约 44–48ms（强制布局部分近常量，非严格线性）。

**成色**：实测（真实展开 + 真实视角切换）。

## 3. rAF 里的强制布局 / layout thrashing

**测量方法**：注入计数器统计 `Element.prototype.getBoundingClientRect` 调用次数；`performance.now()` 包覆 edges 段。阅读 L5899–6028 确认读写顺序。

**实测数字**
- edges 函数内对 81 节点共调用 `getBoundingClientRect` **165 次**（≈2×n 子/父 + 树自身 1），与任务 #3 预期的「2×n 次」吻合。
- edges 段整体（1 次强制整树同步布局 + 165 读 + 1 写 `svg.innerHTML` + paint）：**52.7 ms**（1406px 宽树）。

**thrashing 判定（读源码 + 实测）**：`historyTreeDrawEdges` 先循环 **读全部 rect**（L5942–5989），再在循环外 **一次性写** `svg.innerHTML`（L6028）——读全 / 写一次，**非逐节点读写交错**，不构成经典 layout thrashing；但 DOM 变更（renderTree）后首读 rect 会触发 **1 次整树强制同步布局**。

**成色**：实测（计数器 + performance 包覆）+ 源码复核。

## 6. 高频路径清单（grep 桥内 setInterval / requestAnimationFrame / window 级 addEventListener）

| 钩子 | 位置 | 频率 | 用途 | 归属 |
|---|---|---|---|---|
| `setInterval(pollGraph, 1500)` | L6136 | 每 1.5s | 签名比对 + 变更感知 + state 推送（debounce 1.5s）；被历史子系统复用做「换工作流」兜底（N1 fix） | **既有（变更感知，早于提交树）；被提交历史复用** |
| `requestAnimationFrame(historyBarFollowTick)` | L3413/3420 | 每帧（仅浮层打开时） | 历史浮层/气泡位置跟随画布缩放（`historyBarFollowStart` L3417，由 overlay 打开调用 L4372） | **提交历史引入**；overlay-gated，静止无浮层时不消耗 |
| `window resize` → 防抖 120ms 重渲染 | L5623 | 仅窗口 resize 且树 open | 重画连线（不 refetch） | **提交历史引入**；事件型，非连续 |
| `window mousemove` / `mouseup` / `blur` | L5583/5605/5606 | 仅拖拽树时 | 横向/纵向拖拽滚动 | **提交历史引入**；事件型 |
| `litegraph:set-graph`（canvas 元素监听） | L4683 | 换工作流时 | 触发 `historyOnWorkflowSwitch` → `historyTreeRefresh`（fetch+render） | **提交历史引入**；事件型 |
| `document pointerdown`（点击消歧/回跳确认） | L5864 | 用户交互 | 提交树点选回跳 | **提交历史引入**；交互型 |
| `document keydown`（lightbox / rollback 确认） | L3689/4107 | 用户交互 | 灯箱/回跳二次确认 | 通用（含提交历史） |
| `window message` | L2595 | 事件 | 壳↔桥 postMessage 桥协议 | 既有通用 |

**关键确认**：`pollGraph` 在稳态（无编辑、无换流）下只做签名（0.21ms）+ copilot 检查，**不调用 `historyTreeRefresh`**（仅 `historyOnWorkflowSwitch` 返回 true 即真换流时才 refresh，L4663）。→ 1.5s 轮询 **不渲染提交树**，渲染只发生在用户展开/切视角/换工作流等离散动作。

**overlay-follow rAF 真实开销**：实测单帧跟随操作 **0.0033 ms/op**（1 次 `getBoundingClientRect` + 1 次 `style` 写）；仅在历史浮层/气泡显示时循环。背景标签页 rAF 被节流到 ~1fps（测得 30 帧 26s 系节流伪影，非真实成本）。

## 开销排序（从小到大）

1. **可忽略**：pollGraph 签名 0.21–0.69ms / 1.5s；overlay rAF 0.0033ms/帧（静止 0）；resize/drag/mouseup 事件型（常态 0）。
2. **小**：tree 重渲染（不 fetch）≈ 8ms 同步 + 53ms 连线 ≈ **68ms**，且只发生于离散用户动作，非轮询。
3. **中**：提交上报上传 ≈ **60KB/次**（带宽，仅跑图时）。
4. **大（一次性，可感知卡顿）**：首次展开端到端 **818ms**，其中 151KB 网络 fetch ~33ms + 解析 + 渲染 + 连线 ~70–100ms + 合成。

**最大瓶颈**：首次展开的 151KB 同步 fetch + 全量渲染（~0.8s 卡顿感）。次瓶颈：edges 段 ~53ms 强制布局 + 绘制（每次重渲染）。

## 优化机会清单（按收益 / 风险排序）

| # | 机会 | 预期收益 | 改动面 | 风险 | 归属 |
|---|---|---|---|---|---|
| 1 | 历史列表分包/懒加载或精简返回字段（剥离渲染未用字段；或按视口分页/增量追加） | **高**：首开 151KB→几十 KB，首开时间砍半 | 后端 `history-list` 返回结构 + 前端消费 | 低（只读取，向后兼容加 query） | 提交历史引入 |
| 2 | 视角几何缓存（time/compact 的 `xOf`/`geom` 算一次存起，切换不重算） | 中：切视角 68ms→<20ms | 小（renderTree 内 memoise） | 低 | 提交历史引入 |
| 3 | edges 免去 gBCR：改用 renderTree 已算的节点相对坐标（left/top）算连线，仅跨泳道贝塞尔需父/子中心 | 中：~53ms→<10ms（省 165 次 gBCR + 1 次整树强制布局） | 中（drawEdges 改坐标来源，需核对折叠/渐隐/trim 边界） | 中 | 提交历史引入 |
| 4 | SVG 复用：path 元素复用（`setAttribute('d', d)`）替代 `svg.innerHTML=html` 整串重建 | 低–中：减 GC/字符串解析 | 极小（1 行） | 低 | 提交历史引入 |
| 5 | DOM 增量更新：HEAD 移动时只 append 新节点，而非 `tree.textContent=""` 全清重建 81 节点 | 中：增量 <5ms vs 全清 15ms | 中（需 diff entries） | 中 | 提交历史引入 |
| 6 | 提交前剥离 base64 内嵌图（与落盘层 `history_store.py` L701 一致，前端 body 用 `app.graph.toJSON()` 可能含 LoadImage 预览大图） | 中：防极端体积（正常 60KB；贴大图可 MB 级） | 小 | 低 | 提交历史引入 |

**推荐优先级**：先做 #1（收益最高、风险最低，直击 818ms 首开）+ #3（直击每次重渲染 53ms）。#2/#4/#5 为次级打磨。

## 引入 vs 既有 标注

- **提交历史引入**：`history-list` 网络 fetch（151KB）、tree DOM 渲染（15+53ms）、edges 强制布局、overlay rAF 跟随、resize/drag 监听、`litegraph:set-graph` 监听、`reportHistoryCommit` 上报（60KB）、#1–#6 优化点。
