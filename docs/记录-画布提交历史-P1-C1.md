- `POST /hana_bridge/history-commit`（L607-619）：`_token_ok` 鉴权（403）→ `_history_user_dir()` → `await _json(request)` → `_history_commit(body, user_dir)` → 按 `status` 拆 HTTP 码（400/413/500/200）。响应体只含 commit 结果字段。

## 语义对齐（JS 版 → Python 版）

逐段照搬 `app/lib/canvas-history.mjs`（37 项单测通过）+ `app/runtime/history-commit.mjs`：净化/文件名/快照构造/剥离/索引行/解析/序号全部同口径；`commit` 流程顺序同 `handleHistoryCommit`（缺字段 400 → 读索引 → next_seq → 序列化 → 体积防护 → mkdir → 原子写 → 追加索引）。

**已知偏差（1 处，规格要求如此）**：`snapshot_file_name` 的 promptId 段字符集。JS 版剔除连字符（`[^a-zA-Z0-9]`，见 canvas-history.mjs L102）；本批规格写 `[A-Za-z0-9-]`（保留连字符），Python 按规格实现。promptId 为 UUID 时前 8 位均为十六进制，两种口径实际结果一致；前端若从 JS 版口径切换需留意。

其余实现细节：
- 原子写：同目录 `<file>.tmp` → `os.replace`（同卷 rename，Windows 上原子）；写失败清理残留 .tmp。roundtrip 用例断言 .tmp 不残留。
- 体积防护 14 MiB（`MAX_SNAPSHOT_BYTES`）在 `os.makedirs` **之前**判定，超限不落任何盘上痕迹（有测试断言 `.history` 目录不存在）。
- 索引追加：`open(index_path, "a")` 单行追加，绝不读全文重写。
- `at` 传 `datetime` → 转 UTC ISO 毫秒精度 + `Z`（形态对齐 JS `toISOString()`）；naive datetime 视作 UTC。
- JSON 序列化 `ensure_ascii=False` + 紧凑分隔符（中文直存，与 JS `JSON.stringify` 形态一致）。

## 路由注册实机验证为何留到部署批次

- 路由挂在 `PromptServer.instance.routes`（aiohttp 支架）上，只有 ComfyUI 以「加载自定义节点」的方式启动才会注册；本机开发仓与运行副本由主脑统一安排，本批禁止部署/重启/frameReload，因此无法在不违规的前提下起真实 8188 验证。
- 纯逻辑层（净化/命名/落盘/索引/查询）已由 33 项单测覆盖；路由层剩下的实机不确定性集中在：① `import folder_paths` / `from app.user_manager import …` 在 load_custom_node 加载语境下是否可达（源码结构推断成立）；② `get_user_directory()` 在实际部署（可能有 `--user-directory` 参数或 portable 布局）下的返回值；③ token 鉴权与中继/前端调用方对接。这三点均属「起服务才能测」，留给部署批次。
