## 2. Ⅰ 语义层自身欠账（计划内未竟）

| # | 条款 | 现状 | 影响 |
|---|---|---|---|
| Ⅰ-1 | **outline 无下钻**（`detail/select` v0 未做） | 只见「块」，进不去节点级 | 方案自定「可下钻底线」断链：想看块内明细要回退拉全量 get（token 血拼回归） |

## 3. Ⅱ 面向「数据层搭建」的扩展缺口（新账）

### Ⅱ-1 【最大】文件入口缺失
语义读（投影 / 体检 / 大纲 / 追踪）与语义写（patch）**目前都只对「活画布」开放**（工具面 canvas.* 全系经桥读活画布）。
对一份工作流 JSON 文件，没有正式的语义级通道：
- lib 三个模块是纯函数、天然可对文件跑（测试即对样本 JSON 跑），但**未工具化**；
- 写向 patch 执行器在桥侧（依赖前端 before 栈 / 重试 / 落定），**无文件版**；
- hui-edit 是另一条「手工编辑 JSON」的线，**与语义层未合流**。

**影响**：「后端搭、前端现」没有正规工具面——agent 想搭图只能退到手工改 JSON。
**有利条件**：这是**接线工程**（lib 现成、工具面现成、桥 op 清单现成），不是造新引擎。

### Ⅱ-2 写向「建」的短板
patch edit 白名单 7 种（已核实 `PATCH_ALLOWED`）：`addNode / setWidget / connect / disconnect / setNodeMode / removeNode / save`。
- **无组操作**（建/改/撤 groups）——而用户图基本靠组组织，块识别也优先吃 groups；
- **无克隆/复制子图**；**无宏**（方案 §7 的「宏雏形」未交付）；
- 结果：从零搭一张图 = 手写几十条原子 edit，效率与一致性都差。

### Ⅱ-3 UI→API 转换器覆盖度
`lib/workflow-tools.mjs convertUiToApi` 为「经典图子集」：mute/bypass、子图 / Reroute / Primitive / GroupNode、缺连线等情形汇总 throw；named↔位置交叉校验仅 8 类型；seed 副值跳过为启发式。
**影响**：无头验证 / 提交（中继直提路线）的适用面受限；对含子图的现代工作流走不通。
（对「前端呈现」主线不构成阻塞——前端自己会转。）

### Ⅱ-4 读写两侧无共享模块
读向 lib 在 app 层；写向关键件（verify / slot 解析 / 类型启发式 / 回滚）在桥侧独立实现。两侧无共享模块，存在**语义漂移风险**（同类逻辑双份写）。

## 5. 完善批次建议（待拍板）

**批一 · 打通数据层入口**（解锁「后端搭 → 前端现」）
- 读：**文件源语义读**（project / check / outline / trace 对文件 JSON 生效）；
- 写：**文件版 patch**（同一套 edits 语言，语义级改文件 + 落盘）；
- 建议口径：在现有 canvas 工具面加 **source 维度（live | file）**，维持单面工具（备选：独立 op 面）；
- 验收（端到端小品）：数据层搭一张小图 → 落文件 → 起 hui 载入 → 前端所见与数据一致。
- 注：涉及运行态的验收到时先请示时序。

**批二 · 语义层补强**
- Ⅰ-1 下钻 + Ⅰ-2 check 扩容（MISSING_REQUIRED + DOMAIN_* 首批：16 倍数 / 步数 / 尺寸）+ Ⅰ-3 trace 多级 + Ⅰ-4 邻接 + Ⅱ-2 的组操作（白名单扩容评估）。

**批三 · 工程化**
- 宏 / 模板雏形（搭图批处理）+ 两版 diff + Ⅰ-6（符号层 / semantic rev / 返回协议）。

排序逻辑：批一解锁新路线（且是接线工程，成本可控）；批二升现有共驾体验；批三进阶工程化。

#### A-5 其他｜链路与机制常数

- 双腿派发 `canvasBridgeInvoke`：壳页腿（同源直控 iframe，SHELL_ALIVE 5s）优先→失败回退扩展腿（`/_relay/bridge`→py `/call`）；probe 特判两腿各探一次。

### D. 疑似缺口线索（探员原列，只列不判）

1. 语义层三个模块只服务「读向」；写向关键件在桥侧独立实现，两侧无共享模块。
2. 桥 `canvas.get` 忽略入参（源码注释自述）——工具面白名单仍会透传 nodeId/slot 等。
3. L3「符号层」无独立产物：无紧凑符号模型/异常前缀渲染。
4. L4 无宏系统（方案含「宏雏形」，交付仅 patch 事务）。
5. semantic rev 未见实现；也无同输入回归比对口径。
6. check 的 rules 参数、MISSING_REQUIRED、DOMAIN_* 均未实现（现仅 3 码）。
7. outline 无 detail/select 下钻；块的「组成来源解释」仅 `source: group/role` 一个字段。
8. select 邻接语法未实现；选择集仅 3 种 term。
9. 工具面 `get` 投影在 app 层消费；全量 `get` 仍会整份过桥+隧道+60k 截断（无分页/服务端裁剪）。
10. 自动视觉包裹只覆盖 patch/organize/commands 三个 op。
11. 桥侧对「允许 Agent 开启画布副驾驶」总闸无感知——copilot op 的开启权限只在 app 层生效。
12. queue 的 promptId 依赖猴补+/queue 差集；差集不唯一时不回传 promptId。
13. undo 先调官方 `Comfy.Undo` → 再 agent-rewind；「撤销 agent 之外的改动」语义不可达。
14. `loadWorkflowFile` 快返；调用方需自行 settle/对账。
15. `visual` 连线黄标的 linkRenderer 包裹层在 graph 切换后失效，靠下一次 highlight 自动重挂。
16. lock 膜不吃键盘事件（文档自认「键盘不拦，命令层自判」）。
17. 状态不一致：验收/踩坑记载「死条目无 TTL 未修」，当前 py 已含 TTL；`bridgeBuild` 标签陈旧，当前 `BUILD_TAG` 已更新。
18. 双页面「仅目标页执行」形态未构造；py 侧 stale/liveCount 语义未在生效窗口实测。
19. lib 三套测试只跑合成样本图；前端行为坑不在单测覆盖内。
20. 静默截断若干（events 50 / commands 200 / visual 各 200 / widget 160 字符）。
