### 关键实现口径
- 取图接口：`api.fetchApi("/history/" + encodeURIComponent(pid))`；返回结构按探查 `{ [promptId]: { outputs: { <nodeId>: { images: [...] } } } }` 解析。
- 缩略图 URL = 原图 URL + `&preview=webp;75`（后端 `/view` 的 `preview` 分支就地转 webp，实测返回 `image/webp`，**不自写编码**）。
- `subfolder` 为空串时仍带 `&subfolder=`（对齐 `viewPathOf` 口径）。
- 多图（batch / 多输出节点）：同一 run 的 `outputs[*].images[*]` 全量收集 → 横向小条，溢出横向滚动。
- 降级：**无 promptId / 无图 / 取图失败 → 保留原 seq 灰底占位**，不留空白。

## 2. 复用了什么 / 新写了什么 / 竞态怎么处理

### 复用（未改）
- **App 侧 `viewPathOf`（`app/index.js:640`）的 URL 口径**：`view?filename=..&subfolder=..&type=..`，缩略图用同 URL 加 `&preview=webp;75`。桥内未 import、未调用 App 侧代码，仅抄口径。
- **ComfyUI 后端 `/view?preview=webp;75`**：现成 webp 源，零新增编码（探查 §1.2 实测）。
- **前端 `api.fetchApi` / `api.apiURL`**：桥既有取数手段（`HISTORY_LIST_PATH` 同族），未新引入依赖。
- **现有弹层样式族**：`.hhb-*` 深色系 + `historyBarStyleEnsure()` 注入，lightbox 沿用同族命名与色值。
- **现有竞态哨兵 `historyBarRequestId`**（`:2372`，`historyBarClose` `:2436` 递增）：未改机制，只在回填处沿用。
- **既有卡片点击 / 选中逻辑**：缩略图 `<img>` 点击 `stopPropagation`，不触发卡片选中，不影响既有提交捕获与回跳命中。

### 新写
- P4 取图三件套：`historyImagesFor` / `historyViewUrl` / `historyFillThumb`。
- Lightbox：`historyOpenLightbox` / `historyLightboxClose` + 对应样式。
- 桥里此前**没有**任何取图/取 history 的代码（探查 §2.2 已定论），故为新增；未与既有代码重复。

### 竞态处理
1. `historyFillThumb(reqId, …)` 在 `await historyImagesFor` 之后、写 DOM 之前校验 `reqId !== historyBarRequestId` → 弹层已收起或已切到别的 group 时**丢弃**，不写 DOM。
2. 额外兜底 `thumb.isConnected`：节点若已被 `cards.textContent = ""` 清掉，也不再写。
3. `historyBarLoad` 原有的 `reqId` 校验（`:2588`）保持不动；`historyBarOpen` 的 `++historyBarRequestId`（`:2724`）、`historyBarClose` 的 `++` 保持不动 —— 哨兵语义与原来一致。
4. 取图失败 `catch` 只 `console.warn`，不抛、不影响弹层其它逻辑。
5. Lightbox 为独立单例（`historyLightboxClose` 幂等先去旧），不参与 `historyBarRequestId`，与弹层开关解耦。

### 5.1 取图 URL 链路（实测，非推断）

```
原图  /view?filename=qwen21_quality20_02591_.png&subfolder=&type=output
      → 2584763 字节  Content-Type: image/png   魔数 \x89PNG
缩略  /view?...&preview=webp;75
      →  256490 字节  Content-Type: image/webp  魔数 RIFF....WEBP
      → 压缩比 10.1x
```
`/api/view?...` 与 `/view?...` **两条路径均 200 + image/webp**（`api.apiURL` 加的 `/api` 前缀落点正确）。

### 5.2 弹层内缩略图（真实路径）

CDP headless 环境下 `Input.dispatchMouseEvent` 的 pointerdown 能到达 canvas 元素（元素级探针实测 `pointerdown:1/pointerup:1/click:1`），但**不触发 litegraph 处理器**（环境特殊性）；改用手动调 `LGraphCanvas.prototype.processMouseDown.call(canvas, 真 PointerEvent)` 打开弹层（等价于用户点击命中的同一条代码路径）：

```
弹层文本："Qwen21 t2i 质量版 (00012)  17 条提交"
卡片占位：17 个 .hhb-thumb
回填 <img>：3 个（对应 3 条有 promptId 且有图的提交）
每条 img src：/api/view?filename=qwen21_quality20_0259N_.png&subfolder=&type=output&preview=webp;75
```
- 页面内 `fetch(img.src)` → `200 image/webp 199334 字节 魔数 RIFF`（图真能取到）。
- `new Image()` 强制加载 → `loaded:true, 1024×1024`（图真能渲染）。
- 弹层内 `<img ... loading="lazy">` 在 headless 里 `naturalWidth:0`（惰性未触发）；改 `eager` 后截图可见缩略图。已据此把 `img.loading` 从 `lazy` 改为 `eager`（弹层点开即看，lazy 会让图延迟出现）。
- **lightbox**：点缩略图 → `#hana-history-lightbox` 出现，`img.src` = 不带 `preview` 的原图 URL（已截图确认 1024×1024 原图显示）。
