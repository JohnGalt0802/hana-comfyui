# 调研：ComfyUI 前端扩展机制现状 + 现成「agent 操作画布」方案

- 调研日期：2026-09-26
- 目标环境：本机 ComfyUI 源码安装 `v0.37.0` + `comfyui_frontend_package` `1.53.6`
- 硬约束：不改 ComfyUI 本体源码、不动前端打包产物
- 检索工具：anysearch（general + code 域），web_fetch 辅助
- 说明：本文件为**外部公开资料**整理，结论均带来源链接；凡未经一手验证处标注 `[需实测]` / `[不确定]`

---

## 0. 结论速览（TL;DR）

1. **官方扩展的唯一正规入口**：自定义节点包导出 `WEB_DIRECTORY` + 前端 `app.registerExtension({name, ...hooks})`。前端已是 ES module，`import` 自 `/scripts/app.js`。官方文档主页 = `docs.comfy.org/custom-nodes/js/javascript_overview`。
2. **类型包存在且现行**：`@comfyorg/comfyui-frontend-types`（npm，版本号跟随前端，如 1.51.5）。
3. **执行事件订阅**：`import { api } from "../../scripts/api.js"` 后 `api.addEventListener("<type>", handler)`；自定义消息类型两端各自注册即可。
4. **前后端通信 canonical 做法**：Python 侧 `PromptServer.instance.routes` 注册 aiohttp 路由（HTTP + WebSocket 同一个 routes 对象）。社区通用，官方文档有专门章节。
5. **独立 WebSocket 到另一本地端口**：技术上可行，但**前端装了 CSP**（issue #7823 显示存在 CSP 实现，会拦外部连接），`connect-src` 可能挡 `ws://` 到别的端口 —— `[需实测]`。建议优先复用 `/ws` 自带通道或 `PromptServer.routes`，别另开端口。
6. **现成方案**：官方有 Comfy MCP（本地 first-party，走 comfy-cli，属**任务/API 级**、不操作画布）与 Comfy Agent（in-app，private alpha，**确实操作画布**）；社区里 **ComfyUI-Copilot（5.5k★）**、**artokun/comfyui-mcp-panel**（画布内 autonomous agent，`add/wire/move/tweak` 全量 parity）最接近「agent 操作画布」。详见 §5。

### 1.2 当前推荐写法（原文要点）
来源：<https://docs.comfy.org/custom-nodes/js/javascript_overview>

> 扩展三步：① Python 模块导出 `WEB_DIRECTORY`；② 把 `.js` 放进该目录；③ 用 `app.registerExtension` 注册。

官方示例（**ES module**，import 主 app 对象）：

```js
import { app } from "../../scripts/app.js";

app.registerExtension({
  name: "a.unique.name.for.a.useless.extension",
  async setup() {
    alert("Setup complete!");
  },
});
```

要点（原文）：
- 所有 `.js` 会被浏览器在页面加载时自动 import，**不需要指定入口文件**；只有 `.js` 会被自动加载，`.css` 等需自行以 `extensions/<custom_node_subfolder>/the_file.css` 路径编程注入。
- 「最常用、往往唯一需要的钩子」= `beforeRegisterNodeDef(nodeType, nodeData, app)`；`setup()` 适合挂事件监听/菜单。
- **重要警告**：老式的「hijack 原型方法」（改写 `nodeType.prototype.xxx`）已被标注 **Deprecated**，官方要求优先用官方 API（Context Menu API、官方 hooks）。

### 1.3 官方 Extension API 一览（ComfyUI_frontend README）
来源：<https://github.com/Comfy-Org/ComfyUI_frontend>（Developer APIs 段，README 内示例）

README 直接给出各 API 的 `app.registerExtension` 用法，包括：
- `settings`：新 Settings API，读用 `app.extensionManager.setting.get/set`
- `commands` + `keybindings`：注册命令与快捷键（核心 keybinding 不可覆盖）
- `menuCommands`：注册顶栏菜单项
- `registerSidebarTab`：`app.extensionManager.registerSidebarTab({id, icon, title, type, render})`
- `bottomPanelTabs`、`aboutPageBadges`、toast（`app.extensionManager.toast.add`）
- `getSelectionToolboxCommands`：**画布选中项的工具箱命令**（v1.10.9+），对「操作画布」很关键
- 桌面版注意：`window.prompt/confirm/alert` 在 Electron 不可用，改用 `app.extensionManager.dialog.*` / `toast.addAlert`

### 1.4 类型包（TypeScript）
- npm：<https://www.npmjs.com/package/@comfyorg/comfyui-frontend-types>（安装：`npm i @comfyorg/comfyui-frontend-types`）
- 版本镜像前端：调研时见 `1.51.5`（<https://libraries.io/npm/@comfyorg%2Fcomfyui-frontend-types>），对应前端大版本线一致

## 2. `WEB_DIRECTORY` 机制：自定义节点包里提供前端 JS

来源：<https://docs.comfy.org/custom-nodes/js/javascript_overview>

机制：
- 在自定义节点目录里建子目录（惯例叫 `js`），在 `__init__.py` 导出 `WEB_DIRECTORY = "./js"`。
- 服务器把该目录下的**所有 `.js`** 在页面加载时自动注入/import；路径前缀为 `extensions/<包名>/`（`WEB_DIRECTORY` 的值由服务端插入，路径不含子目录名）。
- `GET /extensions` 可列出所有注册了 `WEB_DIRECTORY` 的扩展（见 §4）。

### 骨架代码

`custom_nodes/my_pack/__init__.py`
```python
from .nodes import NODE_CLASS_MAPPINGS, NODE_DISPLAY_NAME_MAPPINGS

WEB_DIRECTORY = "./js"
__all__ = ["NODE_CLASS_MAPPINGS", "NODE_DISPLAY_NAME_MAPPINGS", "WEB_DIRECTORY"]
```

`custom_nodes/my_pack/js/my_extension.js`
```js
import { app } from "../../scripts/app.js";      // 相对 js 文件，解析到 /scripts/app.js
import { api } from "../../scripts/api.js";       // 事件/HTTP 客户端

app.registerExtension({
  name: "com.example.mypack",
  async setup() {
    // 订阅执行事件（见 §3）
    api.addEventListener("execution_start", (e) => {
      console.log("[mypack] execution_start", e.detail?.prompt_id);
    });
  },
  async beforeRegisterNodeDef(nodeType, nodeData, app) {
    if (nodeType.comfyClass === "MyNode") {
      // 针对自定义节点类型的官方 hook 用法
    }
  },
});
```

## 3. WebSocket 事件订阅 / 发送，及「另开一条 WS」的可行性

### 3.1 后端 → 前端的执行事件（订阅）
来源：<https://docs.comfy.org/development/comfyui-server/comms_messages>

- 事件由 `PromptExecutor` 经 `PromptServer.send_sync` 推送；前端 `api.js` 的 socket 监听器把已知消息类型包装成 `CustomEvent` 并派发。
- 扩展在 `setup()` 里注册：`api.addEventListener(message_type, handler)`；未知类型会被自动加入已知列表。
- `handler(event)` 里取 `event.detail`（服务端发的 dict）。
- **内置消息类型**（原文表）：`execution_start`(`prompt_id`)、`execution_error`、`execution_interrupted`、`execution_cached`、`execution_success`(`prompt_id`,`timestamp`)、`executing`(`node`=节点 id,`prompt_id`，`node=None` 表示结束)、`executed`(`node`,`prompt_id`,`output`)、`progress`(`node`,`value`,`max`)、`status`(`exec_info.queue_remaining`)。
- 注意：`executed` **不是**每个节点完成都发，只在节点返回 ui 更新时发（需主函数 `return {"ui": ..., "result": ...}`）。

### 3.2 前端 → 后端：自定义消息
来源：同上
- 前端：`api.addEventListener("my.custom.message", handler)`
- 后端（一般在节点主执行函数里）：
  ```python
  from server import PromptServer
  PromptServer.instance.send_sync("my.custom.message", {"node": node_id, "other_things": ...})
  ```
- 取 `node_id`：在 `INPUT_TYPES` 的 `"hidden": {"node_id": "UNIQUE_ID"}`。

### 3.3 另开一条独立 WebSocket 到「另一个本地端口」的服务
- 结论：**技术上可以**（浏览器 `new WebSocket("ws://127.0.0.1:<port>/...")` 是标准能力），但有两个现实约束：
  1. **CSP**：ComfyUI 前端存在 CSP 实现。issue #7823（2026-01-01，已 closed）标题即「CSP Policy Blocks api.comfy.org…」，文中提到 CSP 会「block all external API connections…**ws://**」。说明 `connect-src` 是真实存在的闸门；若默认头不含目标 `ws://127.0.0.1:<port>`，连接会被浏览器拒绝。**默认安装的 CSP 具体值 `[不确定]`，必须对本机 `v0.37.0 + 1.53.6` 实测响应头。**
     来源：<https://github.com/Comfy-Org/ComfyUI_frontend/issues/7823>
  2. **mixed-content / 页面 origin**：ComfyUI 页面是 `http://127.0.0.1:8188`，连 `ws://` 同协议无 mixed-content 问题；只要目标也是 `ws://`（非 `wss://`）即 OK；反之前端为 https 时会出问题。
  3. `connect-src` 语义参考：<https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src>
- **建议**：优先复用 ComfyUI 自带 `/ws` 通道（§3.2 自定义消息），或用 §4 的 `PromptServer.routes` 承载，避免为「agent 通道」另开端口带来的 CSP/防火墙/多进程生命周期问题。若确实要独立通道，把它做成**由自定义节点 Python 侧**在 `PromptServer.instance.routes` 上注册的 WS 路由（同源同端口，无 CSP 风险）。

## 4. Python 侧注册自定义 HTTP / WebSocket 路由

来源（官方权威）：<https://docs.comfy.org/development/comfyui-server/comms_routes>

### 4.1 内置路由（节选）
- `GET /` 加载页面；**`GET /extensions`** 列出注册了 `WEB_DIRECTORY` 的扩展；`GET /features`；`GET /object_info`（所有节点定义）；`POST /prompt`（提交）、`GET /prompt`（队列状态）；`/queue`、`/history`、`/interrupt`、`/free`；`/upload/image`、`/upload/mask`、`/view`；`/userdata*`；`/models*`；`/system_stats`。
- **`/ws`**：实时双向通道，推送执行/进度/队列事件（消息类型见 §3.1）。

### 4.2 自定义路由的标准写法（官方原文）
```python
from server import PromptServer
from aiohttp import web

routes = PromptServer.instance.routes

@routes.post('/my_new_path')
async def my_function(request):
    the_data = await request.post()      # dict of posted values
    MyClass.handle_my_message(the_data)
    return web.json_response({})
```
- 官方提醒：**不要把处理函数定义在 class 里**，`@routes.post` 装饰器做很多事；函数体里再调 classmethod。
- 只读用 `@routes.get`。
- 前端调用（官方示例）：
  ```js
  import { api } from "../../scripts/api.js";
  const body = new FormData();
  body.append('message', message);
  body.append('node_id', node_id);
  api.fetchApi("/my_new_path", { method: "POST", body });
  ```

### 4.3 是否社区通用做法
- **是**。官方文档专门有 Custom routes 章节；第三方文章/项目普遍采用：
  - Snyk 安全分析《Hacking ComfyUI Through Custom Nodes》把「用 `@PromptServer.instance.routes.HTTP_METHOD` 注册自定义端点」列为标准能力：<https://labs.snyk.io/resources/hacking-comfyui-through-custom-nodes/>
  - 社区「把 ComfyUI 变成 REST API」的自定义节点：<https://www.reddit.com/r/comfyui/comments/1kef4xo/made_a_custom_node_to_turn_comfyui_into_a_rest_api/>
  - React/TS 写自定义节点的教程：<https://dev.to/netanelben/creating-a-custom-node-for-comfyui-using-react-ts-20g0>
- **WebSocket 路由**同样可挂在 `routes` 上，但**已知有坑**：issue #5054「custom nodes with in `PromptServer.instance.routes` for connect websocket doesn't work」—— `[不确定]` 具体版本影响，做 WS 路由前建议先实测。
  来源：<https://github.com/Comfy-Org/ComfyUI/issues/5054>
- 相关背景：<https://github.com/Comfy-Org/ComfyUI_frontend/issues/7483>（扩展加载/前端 API 相关 issue，见 §6）

### 5.3 与本项目的差异点（供你判断复用面）
- 上面**操作画布**类（官方 Comfy Agent、ComfyUI-Copilot、artokun/mcp-panel）都是**在浏览器页面内**注入前端扩展来改 LiteGraph 图；这与 Hana-ComfyUI「不改本体、不动打包产物」的约束方向一致 —— 即**用自定义节点包 + WEB_DIRECTORY 注入扩展**是唯一被官方认可、又能落地的路径。
- 纯 MCP 类（comfy-mcp、joenorton 等）只到「提交 API 格式工作流」，**读不到/改不到用户正在编辑的实时画布状态**，无法满足「人机共驾同一张画布」。

## 6. 已知坑

### 6.1 扩展加载失败的常见症状与排查
- **症状**：页面 UI 里没有该扩展的入口；`beforeRegisterNodeDef`/`setup` 未执行；控制台报模块加载/语法错误。
- **排查入口**：
  - `GET /extensions` —— 列出所有注册了 `WEB_DIRECTORY` 的扩展。**若你的扩展不在列表里**，说明 Python 侧没导出 `WEB_DIRECTORY` 或包未被加载。（<https://docs.comfy.org/development/comfyui-server/comms_routes>）
  - 浏览器 DevTools console + network —— 看 `.js` 是否 404/语法错误/CSP 拦截。
  - 启动日志 —— 自定义节点 import 失败会在服务端日志体现；Manager 问题另见 <https://docs.comfy.org/manager/troubleshooting>。
- **Manager 侧常见坑**（影响节点包能否装上）：安装路径必须为 `ComfyUI/custom_nodes/<pkg>`，避免双层嵌套 / 压缩包直解 / 带 `-main` 后缀；`security_level`（`strong/normal/normal-/weak`）会拦 git-url 安装；Windows `Overlapped Object` 与 SSL 证书问题有专门配置项。来源：<https://docs.comfy.org/manager/troubleshooting>
- 社区讨论：Manager/扩展「装了但不显示」「静默失败」：<https://www.reddit.com/r/comfyui/comments/1piu9pc/comfyuimanager_no_longer_displays_after_latest/> ・ <https://forum.comfy.org/t/manager-button-not-showing/4024>

### 6.2 与前端大版本升级的兼容问题
- **前端独立发版**：`ComfyUI_frontend` 每日/高频发版，与本体的 `comfyui_frontend_package` 版本可脱钩；老版本前端包会与新版自定义节点不兼容（例：Impact Pack 报「outdated frontend package `<1.16.9`」）。来源：<https://forum.comfy.org/t/outdated-frontend-package-issue/2335>
- **类型包版本缺失**：`@comfyorg/comfyui-frontend-types` 曾出现某几个小版本未发布（issue #5597）：<https://github.com/Comfy-Org/ComfyUI_frontend/issues/5597>；早期还有「类型未导出」（#2083）。→ 锁定与你 `1.53.6` 对应的类型包版本，别 `latest`。
- **官方弃用趋势**：文档明确把「原型 hijack」标注 Deprecated，要求迁移到官方 API（Context Menu API、官方 hooks）。跨版本升级时，hijack 写法**最先碎**。来源：<https://docs.comfy.org/custom-nodes/js/javascript_hooks>
- **CSP 变化风险**：前端引入 CSP 后，任何「向非页面 origin 发请求/开 socket」的扩展都可能被新版本 CSP 拦（#7823）。升级前端时**必须回归测试**这一点。
- **相关 issue 追踪**：<https://github.com/Comfy-Org/ComfyUI_frontend/issues/7483>、<https://github.com/Comfy-Org/ComfyUI_frontend/issues/10769>

### 6.3 对本设计（人机共驾）最需要注意的三点
1. **通道选型**：优先走 `/ws` 自带消息通道（自定义消息类型）+ `PromptServer.routes` 自定义 HTTP 路由；**不要**为 agent 通道另开端口（CSP 风险，§3.3）。
2. **「读画布」的两条路**：前端扩展里直接读 `app.graph`（LiteGraph 对象，实时、准确）；或后端侧用 `/object_info` + 提交的 `/prompt` JSON 间接推断（不准）。官方 CQL（<https://github.com/Comfy-Org/cql>）提供图查询思路。
3. **「改画布」不要 hijack**：用官方 hooks/Selection Toolbox/Context Menu API，避免 `nodeType.prototype.*` 覆写（已 Deprecated，升级即碎）。
