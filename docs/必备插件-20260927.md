## hui 入口机制（本次新增）

`app/runtime/comfy-relay.mjs` 的 `startBackendService()` 增加自动检测：

- 探测 `venv/Lib/site-packages/comfyui_manager` 存在 → 启动参数追加 `--enable-manager`（未装则不加，兼容原行为）；
- 启动日志与返回值均带 `manager=on/off` 标记，便于排查。

效果：经 hui 启动的 ComfyUI 天然带 Manager 后端 + 前端内置管理界面（装插件、切版本、更新都在工作区内完成）。本机 venv 已装 `comfyui_manager==4.2.2`，实测生效。

与官方集成对齐的要点（[blog.comfy.org](https://blog.comfy.org/p/meet-the-new-comfyui-manager)）：非 Desktop 安装需 `pip install -r manager_requirements.txt`；Manager 4.x 的**前端 UI 内置在 ComfyUI 前端**（1.53.6 已含 `comfyManager` service），旧式 `/extensions` 列表里**不会**出现 Manager —— 不要用 `/extensions` 判断是否启用。

## 验证记录（2026-09-27 晚）

1. hui 停服 → 启服，launcher 重新生成含 `--enable-manager`；启动返回 `manager: true`；服务 24.4s 就绪。
2. backend.log 启动段：7 插件全部输出加载时间行，无 IMPORT FAILED。
3. Manager 后端 API：
   - `GET /v2/manager/version` → `V4.2.2`
   - `GET /v2/customnode/installed` → 9 包（7 新 + MiniMax-H3-Turbo、node-organizer），全部 `enabled: true`
   - `GET /v2/manager/db_mode` → `cache`
4. 运行实例 argv（`GET /system_stats`）含 `--enable-manager`；`GET /api/features` 返回 `extension.manager.supports_v4=true`、`supports_csrf_post=true`，前端据此进入新版 Manager UI（界面「管理扩展」按钮，判定代码在 GraphView chunk：需 argv 含 `--enable-manager`）。
5. 前端扩展（`/extensions`）确认 rgthree / Custom-Scripts / Crystools / VHS / essentials / KJNodes / Impact 的 JS 均已注册。

无害警告两则（可忽略）：
- KJNodes `PatchTritonVAE` 节点不可用（缺 triton；Windows 需 `pip install triton-windows`，仅该实验节点受影响）；
- Manager `matrix sharing` 禁用（缺 matrix-nio；社区分享功能，本机不用）。

## 遗留

- **sam2 未装**（Impact-Pack 的高级分割节点用）：`pip install git+https://github.com/facebookresearch/sam2` 三次尝试均卡在下载初期（~0.03MB 停滞），已止损。Impact 对 sam2 是**软依赖**（`find_spec` 探测，未装仅 warning），核心功能不受影响。后补：网络好的时段可试 `git clone --depth 1` + 本地 `pip install .`，或下载 release 包手动装。
