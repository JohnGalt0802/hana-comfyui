## 0. 一句话架构

- **桥 py**（`app/bridge/__init__.py`）跑在 **ComfyUI 进程内**（`127.0.0.1:8188`），负责注册路由、鉴权、壳页状态缓存、提交历史落盘转发。
- **history_store.py** 是落盘的**纯逻辑模块**（零 ComfyUI 依赖，可单测），被桥 py 的 history-* 端点调用。

### 1.2 鉴权口径

- **`/call` 校验 `X-Hana-Token`**：token 首次加载时 `secrets.token_urlsafe(32)` 随机生成，落在同目录 `.token`（`:178` `_load_token`，`:169` `TOKEN_FILE`）；中继读同一文件比对（见 §4.3）。`8188` 绑 `127.0.0.1`，本机之外不可达。
- **`/hello`、`/result`、`/state`、`/ping`、`/diag`**：只接受同源前端请求，不额外校验 token（只读阶段无写能力）。

- `_token_ok` 比较用 `secrets.compare_digest`（`:225`）；`CALL_TIMEOUT_SEC` 默认 6s（env `HANA_BRIDGE_TIMEOUT`，`:110`）。

### 2.4 `mergeInto` / `save` / `kind` 语义

- **`kind`**（`_norm_kind` `:275`）：白名单 `run`/`save`；非法/缺省→`run`。`run`=跑出来的，`save`=主动存档的。
- **`save` 语义**（`save_commit` `:846`）：永远新建一个 `kind="save"` 节点（无 promptId、不参与合并判定）；delta 相对 head（索引末条）算，parent=head。
- **`mergeInto` 语义**（`commit` `:724`）：仅当 `kind=="run"` 且 headSeq 可读且其快照 graph 的归一化签名（忽略 seed）与本轮相同 → 追加一行 `mergeInto` 标记行（**不改已写行、不写新快照**），返回 `{merged:True, targetSeq:headSeq}`；否则新建节点（parent=headSeq、delta=相对 head 的 compute_delta）。`list_commits` 折叠：mergeInto 行不单独成 entry，其 promptId 并入目标节点 runs（`:937-985` `_node_runs` `:1200`）。
- **`user_dir` 解析**（桥 py 侧 `_history_user_dir` `:553`）：`os.path.join(folder_paths.get_user_directory(), _user_manager.default_user)` → 单用户实际 `user/default`；依赖缺失抛 RuntimeError 并在端点内报 500（不猜路径）。

## 3. 中继：`app/runtime/comfy-relay.mjs`

### 3.1 做什么

- 受管 Node 单文件（无第三方依赖，v0.5），把宿主转发来的请求 **HTTP/WS 全量反代**到本机 ComfyUI（默认 `127.0.0.1:8188`）。
- 反向做**服务进程管理**（启动/停止 ComfyUI 后端，绕 Windows 计划任务脱离沙箱 job）、**状态聚合**（`/_relay/status`）、**进度事件缓存**（订阅后端 `/ws`）、**主机指标**（GPU/CPU/内存）、**安装位置探测**、**更新检查**、**主题同步**、**fs 读写代理**等管理面。
- 启动：受管模式 `node comfy-relay.mjs <runtime-config.json>`（由 App `ctx.runtime.start` 拉起，配置 0600 自删）；standalone `node comfy-relay.mjs --standalone --port <port> --backend 127.0.0.1:8188`（`comfy-relay.mjs:30-37`）。退出码：`0/1/2/3/7`（`:60`）。

### 3.2 与 `127.0.0.1:8188` 的关系

- 后端地址常量：`backend = { host:"127.0.0.1", port:8188, ... }`（`:146`）。中继是 8188 的**反向代理 + 管理器**，自身监听 `server.listen(config.port, "127.0.0.1", ...)`（`:3085`）。
- HTTP 反代 `proxyHttp`（`:2088`）：`http.request({host: backend.host, port: backend.port, path: sanitizeTarget(req.url)})` 转发；上游超时 `config.upstreamTimeoutMs`；`upstream.on("error")` 调 `markBackendDown`（`:397`）。
- WS 反代 `proxyUpgrade`（`:2173`）：把 `upgrade` 请求透传到 8188。
- 后端可达性探测 `probeBackend`/`probeQueue`（`statusPayload` `:2028`、`startBackendEvents` `:1935` 订阅后端 `/ws`）；「慢」/「死」分类（`classifyProbeError` `:387`，慢连续 2 次才翻不可达）。
- **桥链路特殊**：中继 `/_relay/bridge`（`:2714`）把 `POST /api/hana_bridge/call` 转发到 8188，带 `x-hana-token`（读 `readBridgeToken` `:1520`）；原因：ComfyUI CSP `connect-src 'self'`，前端连不出 8188，须由中继代转 `:2716-2719`。

## 4. `history-commit.mjs`（已弃用档案）

- 顶部声明（`:1-2`）：**已弃用（2026-10-12）**——中继落盘通道 `POST /_relay/history/commit` 无任何调用方。原因：桥页面直连 8188（跨源）够不到中继该路由（见 `__init__.py:578`），P1 最终改道桥 py 端点 `/hana_bridge/history-commit`（`history_store.py`）。
- **职责（原 P1-B1）**：接收一次提交上报→写快照文件+追加一行 JSONL 索引。原请求体 `{workflow, promptId, graph, at, source}`；返回 `{ok, status, seq, file, dir}`。
- 保留原因：仅作档案参考。停留在 P1 旧结构——**无** `parent`/`kind`/`sig`/`runs`/`delta`/`mergeInto`/`sidecar`；若将来恢复中继通道需先补齐这些字段并与 `history_store.py` 对齐。
- 关键导出：`MAX_SNAPSHOT_BYTES = 14 MiB`（`:57`）、`INDEX_FILE_NAME`（`:59`）、`handleHistoryCommit`（`:76`，调用 `canvas-history.mjs` 的 `buildIndexLine`/`buildSnapshot`/`historyDir`/`nextSeq`/`parseIndex`/`snapshotFileName` + 共享 `writeFileAtomic`）。
