# 调研：画布提交历史 P2 · 拆工落点（点击块弹出提交工具栏）

> 只读侦察，未改任何代码/运行态。已定稿需求见 `docs/方案-画布提交历史.md`（P2 期）。
> 标 `[确证]`=源码已读；`[调研]`=前一轮叠加层调研文档（坐标/同步部分）；`[未决]`=待实测。

## 结论先行

- **拆独立文件可行，但推荐并入主桥单文件。** 理由：ComfyUI 把整个 `WEB_DIRECTORY`（`app/bridge/js/`）递归扫出所有 `*.js` 注入前端（见下 §1），所以放第二个名不同的 `.js` 一定会被加载、不会丢。但桥的加载/自检/通信是围绕「一个活动桥文件」构建的（`__init__.py` 的 `/hana_bridge/diag` 只认 `hana-bridge-*.js` 活动文件、`manifest`/构建流程也单文件），多文件会引入双载状态、构建与诊断复杂度；P2 弹层只是往 `#graph-canvas-container` 挂一个 DOM + 复用 `app.registerExtension` 里已有的 `setup`，并入主桥最省事、最一致。若坚持拆文件，必须用一个**不同 extension name**（如 `hana.bridge.historybar`）各自 `registerExtension`，否则同名扩展会互相覆盖。
- **块命中怎么做：** 挂 `LGraphCanvas.prototype.processMouseDown` 包裹（rgthree 同款先例，直接可用），在点击时用官方 `app.canvas.convertEventToCanvasOffset(e)` 反算画布坐标，再用 litegraph 现成 `getGroupOnPos(x,y)` 命中 group；命中即弹工具条。group 归属判定可直接复用 `lib/canvas-outline.mjs` 的纯函数逻辑（它是 ESM 模块，在浏览器里需以 Blob/动态 import 或内联复制方式引入，不能 `import` 桥全局作用域——见 §2 未决）。

## 五条证据

### §1 桥文件能否多文件共存（extension 注册 / 目录加载）`[确证]`
- 前端把所有扩展 `.js` 扫出来注入：`server.py:424` 的 `GET /extensions` → 遍历 `nodes.EXTENSION_WEB_DIRS`，对每目录 `glob.glob(join(dir,'**/*.js'), recursive=True)` 全部加入；`server.py:1316` 再把每个目录挂成 `/extensions/<name>` 静态路由。→ **`js/` 下两个不同名 `.js` 都会被加载**，不存在「只有注册 extension 的生效」的选择机制。
- `EXTENSION_WEB_DIRS` 以 **模块名** 为键（`nodes.py:2299-2302`：`EXTENSION_WEB_DIRS[module_name]=web_dir`，键是桥 `__init__.py` 的模块名，不是文件名）。桥 `WEB_DIRECTORY="./js"`（`__init__.py`），整目录被服务。
- `app.registerExtension` 同名重复注册：前端 `app.extensions` 是数组、按 `name` 遍历执行生命周期（`rgthree.js` 调 `app.extensions.map(... ext[method])`）。两个文件若都用 `name:"hana.bridge"`（`hana-bridge-1011005836.js:2307`），后加载的会再 push 一份同名扩展，生命周期跑两遍、且 `setup` 内 DOM 单例逻辑会被重复执行（dup 移除只能挡本文件内重复）。→ **同名会双载/覆盖，必须用不同 name。**
- 桥单文件是「约定+构建流程」：活动桥由 `diag` 只认 `hana-bridge-*.js` 最新一份（`__init__.py` `/hana_bridge/diag`），`.bak-*` 不参与（`__init__.py` 扫文件时 `".bak" not in f`）。多文件并存会让活动桥判定与构建脚本更复杂。

### §2 groups 前端读取 + 归属判定 `[确证/部分未决]`
- 运行时 groups 形状：`app.canvas.graph.groups`（UI 格式，同 `graph.toJSON()`）。字段确证自 `lib/canvas-outline.mjs`：
  - `groups[].title`：字符串（空则回退 `组{i}`，`canvas-outline.mjs` L 组名分配段）。
  - `groups[].bounding`：`[bx,by,bw,bh]` 四元数值数组（归属判定用，`canvas-outline.mjs` `g.bounding` 读取段：`pos[0]>=b[0] && pos[0]<=b[0]+b[2] && pos[1]>=b[1] && pos[1]<=b[1]+b[3]`）。
  - 颜色：`title_color`/`color` 字段存在（comfy group 对象标准字段，[未决] 本仓库未直接读源码，仅方案文档引用）。
- 桥前端**没有**现成 group 归属函数：`hana-bridge-1011005836.js` grep `groups|bounding` 零命中。只有 `pollGraph`/`pushStateSnapshot` 推快照，未做块归属。
- `canvas-outline.mjs` 归组逻辑是纯函数（无 ComfyUI/浏览器依赖），可直接复刻：
  - 两级口径已实现（group 优先 / 角色兜底，`canvas-outline.mjs` outlineGraph 内 `groupOf` 与 `ROLE_RULES`）。
  - **但在桥前端直接 `import` 不行**：它是 ESM（`export function outlineGraph`），桥 js 是全局脚本、依赖 `window.app`，浏览器里跨文件 import 受 CSP（`connect-src 'self'`，`__init__.py` 注释已说明）与加载顺序限制。→ 进桥需复制纯函数体、或改为构建期打包/内联（[未决] 选哪种，见未决项 2）。

### §3 点击命中 group（钩子）`[确证]`
- 安全挂法：包裹 `LGraphCanvas.prototype.processMouseDown`（rgthree 已实装且线上运行）：`rgthree.js:279-307` 先存原函数、`processMouseDown.apply(this,...)` 后派发自定义事件；桥照做即可在「不破坏原生交互」前提下拿到每次鼠标按下。
- 命中 group 用官方 API：`app.canvas.convertEventToCanvasOffset(e)`（[调研] 叠加层.md 证据 2 确证，内部 = `getBoundingClientRect` + `convertCanvasToOffset`）；再用 litegraph 现成 `getGroupOnPos(x,y)`（前端包 `core-BqXsSkPi.js:3:23440` 定义，返回该坐标下的 group）。双保险：`graph._groups` 也存分组（`rgthree.js:311` 用 `graph._groups`，comfy 内部别名）。
- 标题栏 vs 块内命中区：[未决] 需求只说「点任意分组框」，先用 `getGroupOnPos` 全框命中；若只要标题栏触发，需额外判断 `y < group.pos[1]+标题高度`（叠加层.md 未决项 3 已列）。

### §4 弹层与现有 UI 层次 `[确证]`
- `copilotUiEnsure()` 挂顶栏（`hana-bridge-1011005836.js:397-434`）：挂到 `app.menu.element`，**无显式 z-index**（随官方顶栏层，非浮层）。
- `filmApply` 锁膜：`position:absolute; inset:0; z-index:9999; pointer-events:auto`（`hana-bridge-1011005836.js:461`）。弹层是「小工具条」不是全屏遮罩（[调研] 叠加层.md 证据 4：只给工具条本体 `pointer-events:auto`，**不要** `inset:0`，否则吞画布交互）。
- 层次建议：弹层 z-index 取 **10000+（>锁膜 9999）**，因提交查看不参与锁定态；但更稳的是用 `position:fixed` 挂 `#graph-canvas-container` 外溢出（[调研] 叠加层.md 证据 4：容器无 `overflow:hidden`，浮层可溢出不被裁）。
- `#graph-canvas-container` 再确认：id 确证（`[调研]` 叠加层.md 证据 1，主模板 `y('div',{id:'graph-canvas-container'})`）；本仓库桥 `filmApply` 也用 `getElementById("graph-canvas-container")`（`hana-bridge-1011005836.js:451`）作为 portal 目标。`position` 未设 fixed（容器由官方布局，弹层用 fixed 自行定位最稳）。

### §5 桥 Python history-list 是否够 P2 用 `[确证]`
- 现有 list 端点 `GET /hana_bridge/history-list?workflow=<名>`（`__init__.py` `@_ROUTES.get("/hana_bridge/history-list")`），返回 `list_commits()` 结果（`history_store.py:list_commits`）：`{ok, status, entries[], badLines}`。
- `entries[]` 每条字段（`history_store.py:build_index_line`）：`seq / file / promptId / at / source / nodeCount / linkCount`。
  - **够 P2 的「时间 / 来源 / 序号」**：`at`（ISO UTC 毫秒）、`source`（user/agent/unknown，对应方案来源色标）、`seq`（序号）齐全。
  - **缩略图占位**：`entries` **不含**缩略图字段；`.thumb.webp` 文件名约定已在方案文档（`docs/方案-画布提交历史.md` 三节：`0001-a3f9c2e1.thumb.webp`），但 `history_store.py` **没有任何 thumb 处理**（grep `.thumb|thumb.webp|thumbnail` 在 `app/` 仅方案文档命中，`.py` 零命中）。
- 缩略图将来最顺加法（P4）：按 `file` 推导同目录 `.thumb.webp`（`file.replace('.json','.thumb.webp')`），端点返回时按需拼 URL；或在 `build_index_line` 增 `thumb` 字段并回填（需改 `history_store.py` + 落盘时生成 webp）。→ 当前 list 不改也够 P2（缩略图先占位），P4 再补。
