## 2. 遗留小项②：cancel 定向取消实测（经宿主真实工具）

脚本：`tools/m3-checks/test-cancel.mjs`（run: `node tools/m3-checks/test-cancel.mjs`；前置：8188 队列为空）

方法：提交"慢任务 A"（512²→×2×3 缩放链 lanczos，纯 CPU，约 2.2s；参数带 run-id 去缓存）→ 运行中在其后排队"快任务 B" → 经 `comfyui(cancel)` 先删 B（队列删除）再中断 A（`/interrupt {prompt_id}` 定向）。

结果（10/10 PASS，另有 2 条 INFO；见 `tools/m3-checks/logs/cancel.txt`）：

| 步骤 | 结果 |
|---|---|
| 前置：队列为空 | ✅ |
| 提交 A（去缓存参数） | ✅ promptId=7e2896e2…（+0.05s 已进入执行） |
| 提交 B（排队）→ cancel B | ✅「已将 22b38a72… 从 ComfyUI 队列移除」；B 从队列消失（+0.12s） |
| cancel A（运行中定向中断） | ✅「已请求中断正在执行的 7e2896e2…」（+0.15s） |
| A 的 history 终态 | **completed=false / status=error / 含 `execution_interrupted`**（+0.42s） |
| ComfyUI 服务端证据 | `_run21.err`：`Interrupting prompt 7e2896e2…` → `Processing interrupted` |
| App 任务结算 | **state=canceled**（+0.93s，经任务卡路由读取） |
| 结束队列 | ✅ 已清空 |
| 产物清理 | ✅ `comfyui_hana_m3*` 残留=0（含校准图 3 张） |

**结论：定向取消两条路径全部实测可用**——①排队中 → 精确从队列删除；②执行中 → 定向中断（节点边界生效）→ history/事件 → App 任务桥结算为 `canceled`。

附注（首轮遇到的问题与处理）：首轮 A 的图被校准跑全量缓存（0.25s 完成），中断落在最后一个节点边界之后 → 未生效（`Interrupting prompt` 有、`Processing interrupted` 无）。修法：测试用唯一缩放参数去缓存；该现象同时证明了 ComfyUI 中断"只在节点边界消费"的语义。
