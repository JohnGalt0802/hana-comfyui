## 1. 一句话

hui 提供的是**人机共驾体验**：哪怕是人让 agent 生图，agent 也应在**画布前端**完成这一动作，而不是后端生图。agent 交付的不只是一张图，还有一条**人可复用、可编辑、可优化的前端画布工作流**。

## 2. 含义拆解

### 2.1 对 agent 行为

- 生图动作"在画布上发生"：工作流**载入画布 → 在画布执行 → 结果与工作流都留在画布**；
- "后端黑箱生图"不得作为默认路径。仅在画布不可用（如无人打开页面）时允许降级，且降级必须**明确标记**，并在画布恢复后**补齐同步**；
- agent 的交付物清单 = **图 + 工作流**（节点、参数、连接关系完整；必要时附说明）。

### 2.2 对用户体验

- 每张图都**可追溯、可续作**：打开画布即见完整工作流——改参数重跑、换种子探索、另存为模板；
- 人不是"收图方"，是**共同驾驶者**：agent 的每一步都发生在人可以看、可以接、可以改的地方。

### 2.3 验收口径（今后新增/修改功能按此验收）

| # | 口径 | 说明 |
|---|---|---|
| 1 | **可见性** | agent 生图后，用户打开画布可看到该次生图的完整工作流（节点与参数） |
| 2 | **可编辑** | 工作流处于人可操作状态（非只读快照、非纯日志、非"仅存文件"） |
| 3 | **可复用** | 用户可在其上重跑 / 修改 / 另存 |
| 4 | **降级诚实** | 若因画布离线走了后端路径，须明确标记，并在回归时补齐同步 |

## 3. 与既有设计的关系

- 本理念是「画布共驾方案」（20260926）与「画布语义层」（20260927）之上的**纲领**；
- 技术能力已就绪大半：工作流载入、节点操作、语义层、自动排布、组织（organize）；
- **差距在"默认路径"**：现状 agent 生图习惯走后端提交，画布更新是"已有能力"而非"默认动作"。本理念要求**翻转默认**。

## 4. 方向（主脑拟，待细化）

- **D1**：把 agent 生图的默认路径改为「画布加载工作流 → 画布发起执行」；
- **D2**：画布离线时的降级通道 + 回归同步机制（对应口径 4）；
- **D3**：本理念的验收口径并入 `AGENTS.md` 与 `待办与验收清单.md`，成为硬验收项。
