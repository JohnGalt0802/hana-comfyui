## 二、关键机制（已读透，供实现参考）

### 2.1 前端数据源 `[源码]`
`app.extensionManager.workflow` 上有：
- `activeWorkflow`——当前选中（桥现在只读它）；
- `openWorkflows`——**一个页面里所有打开工作流的数组**（前端 Tab 条就是遍历它渲染）。
每个 workflow 对象含 `name / filename / path / key / isModified`（dirty）。

### 2.2 副驾驶机制（正好是写门地基）`[源码]`
- copilot 状态**按 `pageKey`（= 该工作流 path）分键**存 localStorage（`hana.copilot.v1:<ws>:<hash(pageKey)>`）——`copilotLsKey(pageKey)`。
- 写门 `copilotWriteBlocked(op)`（桥 L5367）读 `copilotReadState()` → `copilotPageKey()` → **`activeWorkflow`** 的 pageKey。
- → **推论**：只要"操作非当前工作流时，先把 `activeWorkflow` 切到目标"，写门**自动**用该目标工作流自己的副驾驶状态判定。**这正面满足 John 的要求**，无需新增权限机制。
- ⚠️ 切 `activeWorkflow` = **改变用户视线焦点**（前端会切 Tab）。必须：操作完**切回原标签**；且**仅在有明确目标时**切（不静默乱切）。

### 2.3 已有的"切换工作流"原语
桥已有 `canvas.openWorkflow`（打开并完整装载）与 `svc.openWorkflow(path)`——但那是"激活/装载"，用于"切 Tab"需评估是否够轻（是否触发重绘/丢草稿）。**实现单需先探明"切 Tab 的最小原语"**。
