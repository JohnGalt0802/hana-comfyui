# Qwen-Image-2.1 三层加速工作流 · 零基础详解手册

对应工作流：`Qwen21 Turbo EasyCache t2i.json`
环境：ComfyUI 0.37.0 · RTX 4070 SUPER 12GB · 实测 6 步 / 1248×832 / 23 秒

> 本文从「ComfyUI 是什么」讲起，假设你完全没用过。想直接查参数，看同目录的《节点与参数说明》（速查版）。

---

# 第一部分：先把 ComfyUI 想明白

## 1.1 它是什么

ComfyUI 是一个**可视化编程画布**。你在画布上摆方块、用线连起来，点一次"运行"，它就按连线把数据从一头流到另一头。

- 每个方块叫一个**节点**，本质是一个函数。
- 线叫**连接**，代表数据的流向。
- 数据是**带类型的**：图像(IMAGE)、潜空间(LATENT)、模型(MODEL)、文本编码器(CLIP)、条件(CONDITIONING)、整数(INT)、字符串(STRING)……类型对不上的两个口连不起来。
- 执行顺序不是你摆的位置决定的，是**依赖关系**决定的。ComfyUI 从"输出节点"往回倒推：要存图，得有图；要有图，得先解码；要解码，得先采样……一路推到最前面，然后依次执行。

所以你看这份工作流，虽然连线看起来乱，但只要盯住"**数据从哪来、到哪去**"，就能读懂。

## 1.2 一次文生图，机器到底做了什么

这是理解所有参数的前提。整个过程分五步：

**第一步：把文字变成模型能懂的数字。**
你的提示词先经过**文本编码器**（Qwen-Image 用的是 Qwen3-VL，一个 8B 的视觉语言模型），变成一大串向量。这叫**条件（conditioning）**，之后每一步去噪都要参考它。

**第二步：造一张纯噪声图。**
不是像素意义上的图，而是一张**潜空间图（latent）**。它一开始只有随机噪声，什么都没有。

**第三步：反复去噪。**
**采样器**拿着这张噪声图，反复调用主模型：每一步都问模型"这些噪声长什么样？"，然后减掉一部分。假如图片是一块大理石，这一步就是拿凿子一下下敲出雕像。敲的次数就是**步数（steps）**。普通模型要敲 20~40 下，Viggle Turbo 只要 6 下。

**第四步：解码成像素图。**
潜空间图交给 **VAE 解码器**，放大成真正的像素图。

**第五步：存盘。**
`SaveImage` 把图写进 ComfyUI 的 `output/` 目录。

## 1.3 几个必须懂的词

**潜空间（Latent）**
图像的压缩表示。Qwen-Image 的 VAE 把 16×16 像素压成 1 个潜空间像素，所以 1024×1024 的图在潜空间里只有 64×64。去噪全程在潜空间里做，算力省得多，最后才解码回像素。工作流里的 `EmptyLatentImage` 造的就是这个。

**步数（Steps）与 Sigma 调度**
每一步去噪时，"噪声还剩多少"由一个数值描述，叫 **sigma**。sigma=1.0 代表纯噪声，sigma=0 代表完全干净。一串 sigma 值（从 1.0 递减到 0）就是**调度表**。普通 KSampler 用内置的调度器曲线（比如 `simple`、`normal`），而这个工作流用的是 Viggle 提供的**自定义 sigma 表**，因为蒸馏模型只认它训练时的那一套步点。

**CFG（Classifier-Free Guidance）**
一种"放大提示词影响力"的技术：同时算一遍正向提示和负向提示，把两者的差值乘以一个系数。`cfg=1` 等于不放大（只用正向），`cfg=7` 就是强烈放大。**Turbo 蒸馏模型训练时完全没有 CFG**，所以工作流里用的是不带 CFG 的 `BasicGuider`，负面提示词留空是对的。

**VAE**
变分自编码器，负责"像素 ↔ 潜空间"两个方向的转换。编码器把像素压成潜空间（图生图、编辑时用），解码器把潜空间还原成像素（出图时用）。

**文本编码器 / CLIP**
把文字（还能带上参考图）转成向量的那个模型。Qwen-Image 用的是 Qwen3-VL 8B。

**DiT（Diffusion Transformer）**
Qwen-Image 主模型的结构，32 层、7B 参数，一个 Transformer。

**LoRA**
一小块"外挂补丁"，挂在主模型上改变它的行为，不用重训主模型。文件很小（几百 MB 到一两 GB），加载时叠加。

**蒸馏（Distillation）**
把大模型的"多步慢工"教给小模型的"少步快工"。Viggle Turbo 就是一个**学生**：它学了 40 步老师模型的产出，但自己只要 6 步就出相似结果。

**缓存（Cache）**
采样时有些步骤变化很小，缓存技术判断"这一步可以跳过，直接复用上一步的结果"。省时间，但跳过多了会糊。

# 第二部分：这份工作流在做什么

## 2.1 数据流全图

```
UNETLoader ──► ViggleTurboLora ──► EasyCache ──┐
                                                ├──► BasicGuider ──┐
CLIPLoader ──► TextEncodeQwenImage21 ───────────┘                  │
                                                                   ├──► SamplerCustomAdvanced ──► VAEDecode ──► SaveImage
EmptyLatentImage ──────────────────────────────────┬───────────────┘
                                                   └──► ViggleTurboSigmas ──┘
RandomNoise ──────────► SamplerCustomAdvanced
KSamplerSelect ───────► SamplerCustomAdvanced

（旁支：Prompt ──► [PE 组，可选] ──► TextEncodeQwenImage21 的 prompt 输入）
```

从左往右读：模型、编码器、尺寸、噪声、采样器五路数据，最后汇进 `SamplerCustomAdvanced` 完成采样，再解码、存盘。

## 2.2 三层加速分别落在哪

| 层 | 对应节点 | 做了什么 |
|---|---|---|
| 第 1 层 · 步数蒸馏 | `ViggleTurboLora` + `ViggleTurboSigmas` | 把 40 步压到 6 步 |
| 第 2 层 · 跳步缓存 | `EasyCache` | 跳过变化小的采样步 |
| 第 3 层 · 量化 | `CLIPLoader`（int8 文本编码器） | 用 8 位整数版权重，省显存 |

# 第三部分：逐节点详解

下面每个节点都会说清三件事：**它在图里干什么、每个参数是什么意思、改了会怎样**。

## A 区 · 模型加载

### #2 `UNETLoader` — 加载主模型

**作用**：把扩散主模型（DiT）从硬盘读进显存。这是整个工作流的核心部件，也是最大的文件。

**参数**：

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `unet_name` | `qwen_image_2.1_bf16.safetensors` | 文件名，列出的是 `ComfyUI/models/diffusion_models/` 目录里的所有模型。这里选的是 Qwen-Image 2.1 的 **bf16** 权重（13.25 GB）。同目录还有个 `int8_convrot` 版（约 7 GB），体积小一半。 |
| `weight_dtype` | `default` | 加载时的精度转换。<br>• `default`：按文件原样加载（推荐，尤其用官方文件时）<br>• `fp8_e4m3fn`：以 FP8（8 位浮点）加载，省显存，画质略降<br>• `fp8_e4m3fn_fast`：FP8 的快速变体，用更快的矩阵乘核，通常更快，但数值略有差异<br>• `fp8_e5m2`：另一种 FP8 格式，动态范围更大、精度更低 |

**输出**：`MODEL`——一个装载好的模型对象，此时还没加 LoRA、没加缓存。

**怎么选 bf16 还是 int8**：bf16 精度高。int8 省一半显存，理论上在 12GB 这种小卡上更舒服，但**本机 9-21 实测过一轮：25 步 1024px，int8 用了 55 秒，bf16 只用 40 秒**，int8 反而慢，所以这台机器保留了 bf16。这只是本机结论，不代表 int8 本身不好。

---

### #3 `ViggleTurboLora` — 挂载加速 LoRA

**作用**：把 Viggle Turbo 这个"少步学生"补丁挂到主模型上。挂了它，模型才会用 6 步出图。

**参数**：

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `model` | ← `#2` | 上游传进来的模型 |
| `lora_name` | `Qwen-Image-2.1-viggle-turbo-v0.2.1-6step-lora-r128.safetensors` | 要挂的补丁文件。下拉列出 `models/loras/` 里所有 LoRA，选错文件就没效果或直接报错。这里选的是 **r128** 版（680 MB）。仓库另有个 **r256** 版（1.4 GB，rank 更高、细节略好、更慢）。 |
| `strength` | `1.0` | 补丁的影响强度。1.0 = 全量。**必须保持 1.0**：这个 LoRA 训练时 alpha 等于 rank，1.0 才是它被训练出来的样子。调大调小都会失真。 |

**输出**：`MODEL`——挂了 LoRA 的模型。

**这个节点为什么特殊（重要）**：
它是 Viggle 提供的**自定义节点**，和 ComfyUI 自带的 `LoraLoaderModelOnly` 干的是同一件事，但内部做法不同：

- 自带加载器会把 LoRA 的增量**合并（merge）进主模型权重**。对 bf16 权重来说，这个合并是**有损的**——Viggle 实测平均只保留约 70% 的更新量，某些早期 MLP 层只剩约 40%。
- Viggle 这个节点**不合并**，而是在每次前向计算时实时叠加（数学上是 `y = Wx + BAx`），无损。

代价是每步计算慢约 10~25%。**所以这份工作流里千万不要把 #3 换成普通 LoRA 节点**，画质会掉。

---

### #26 `EasyCache` — 跳步缓存（本工作流新增）

**作用**：采样时判断"这一步的变化是不是很小"，是的话直接复用上一步的计算结果，跳过这次模型前向。这是第 2 层加速。

**参数**：

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `model` | ← `#3` | 上游模型 |
| `reuse_threshold` | `0.2` | 复用阈值（0~3.0）。每一步会算"输入相对上一步的变化率"，低于这个值就跳过。**调大跳得更多、更快、更可能糊**。0.2 是官方默认。 |
| `start_percent` | `0.15` | 从采样进度的 15% 处才开始考虑跳步。前面 15% 是**构图关键期**，不能省。 |
| `end_percent` | `0.95` | 到进度 95% 处停止跳步，收尾几步保留完整计算。 |
| `verbose` | `false` | 开启后（`true`）控制台会打印哪些步被跳过了，调试用。 |

**输出**：`MODEL`——包了缓存逻辑的模型。

**它和 Turbo 的关系（要说清楚）**：
6 步本来就很短，`EasyCache` 顶多能跳 1~2 步，收益有限；而 6 步的 sigma 表是蒸馏时精心设计的，跳步还可能伤质量。所以：
- **想验证它值不值**：选中这个节点，按 `Ctrl+B` 把它**旁路（bypass）**，用同一个 seed 再跑一张，对比。
- 它真正的用武之地是**跑 25/40 步的基础模型**时，那种场景下跳几步能省很多。

---

### #4 `CLIPLoader` — 加载文本编码器

**作用**：加载把文字（和参考图）变成向量的那个模型。这是**第 3 层量化**的落点。

**参数**：

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `clip_name` | `qwen3vl_8b_int8_convrot.safetensors` | 文本编码器权重。这里是 **Qwen3-VL 8B 的 int8 量化版**（8.71 GB）。可换成 bf16 版（17.5 GB，更准但显存翻倍）。 |
| `type` | `qwen_image` | 告诉 ComfyUI「这个文件属于哪类模型」。**必须选 `qwen_image`**。选错的话 ComfyUI 会用错误的预处理规则，出来的条件是垃圾。 |
| `device` | `default` | `default` = 跟主模型一样放 GPU；`cpu` = 强制放 CPU（省显存但极慢，一般不用）。 |

**输出**：`CLIP`——加载好的文本编码器。

---

### #5 `VAELoader` — 加载 VAE

**作用**：加载负责"像素 ↔ 潜空间"转换的 VAE。

**参数**：

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `vae_name` | `qwen_image_2.1_vae_bf16.safetensors` | Qwen-Image **2.1** 专用 VAE。它有两个特殊之处：**64 通道**、**16 倍空间压缩**，而且带 **alpha 通道**（所以能直接生成透明背景）。<br>**不能跟 1.0 的 VAE 混用**（目录里那个 `qwen_image_vae.safetensors` 是旧的），否则解码出的图颜色、结构都会错。 |

**输出**：`VAE`。

## B 区 · 提示词

### #6 `PrimitiveStringMultiline`「Prompt」— 提示词输入

**作用**：一个多行文本框，存放你要画的画面描述。

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `value` | 一段英文描述 | 提示词正文。 |

**为什么要单独开一个节点**，而不是直接写在别处：这样同一段文字可以被多个节点引用（比如 PE 改写组要读它，`PreviewAny` 也要显示它）。

**写提示词的要点**：Qwen-Image 2.1 对**描述性长句**响应最好——像"照片里看到了什么"那样写，而不是关键词堆砌。它对**画面内文字排版**也很强（海报、UI 稿、信息图这类）。

## C 区 · 尺寸

### #7 `ResolutionSelector`「Output size」— 画幅计算器

**作用**：你给一个"比例 + 目标总像素"，它算出宽和高，喂给下游的 `EmptyLatentImage`。省得自己算。

**参数**：

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `aspect_ratio` | `3:2 (Photo)` | 画幅比例。8 个选项：<br>`1:1 (Square)` 方形<br>`2:3 (Portrait Photo)` 竖版照片<br>`3:2 (Photo)` 横版照片<br>`3:4 (Portrait Standard)` 竖版标准<br>`4:3 (Standard)` 横版标准<br>`9:16 (Portrait Widescreen)` 竖屏<br>`16:9 (Widescreen)` 宽屏<br>`21:9 (Ultrawide)` 超宽<br>括号里的英文只是命名，不影响计算 |
| `megapixels` | `1` | 目标总像素（单位：百万像素，范围 0.1~16.0）。**1.0 MP ≈ 1024×1024**。计算方式：总像素 = megapixels × 1024²，再按比例拆成宽高。<br>要 **2K 原生输出**：1:1 时把这里调到约 `4.0` → 2048×2048 |
| `multiple` | `32` | 算出的宽高各自取整到该倍数（8~128）。**保持 32**，理由见下 |
| `preview` | — | 前端实时显示算出来的宽高，只读 |

**为什么 `multiple` 要 32**：Qwen-Image 的 VAE 是 16 倍空间压缩，潜空间尺寸最好是整数。32 是 16 的两倍，更保险；设成 8 在某些尺寸下会算出非整数潜空间边长，可能引发尺寸错位。

**本工作流的结果**：`3:2` + `1 MP` + `multiple 32` → **1248 × 832**。

**一个提醒**：Viggle 的 Turbo 学生主要是在 **1024² 和 2048² 面积**上训练的（算术上对应 1 MP 和 4 MP 附近）。偏离太远，画质会下降。

**输出**：两个整数 `width`、`height`。

---

### #8 `EmptyLatentImage` — 造一张纯噪声潜空间图

**作用**：生成采样器的"起点"——一张纯随机的潜空间图。整张最终图就是从这里被一步步去噪出来的。

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `width` | ← `#7` | 图像宽度（像素级）。注意：这个节点内部会把像素尺寸按 VAE 的压缩率折算成潜空间尺寸 |
| `height` | ← `#7` | 图像高度（像素级） |
| `batch_size` | `1` | 一次生成几张（同一套设置、不同噪声） |

**输出**：`LATENT`（纯噪声）。

---

## D 区 · 条件与采样（核心）

### #18 `TextEncodeQwenImage21` — 编码提示词

**作用**：把提示词交给文本编码器，产出**条件（conditioning）**。它同时管文生图和图像编辑两种场景。

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `clip` | ← `#4` | 文本编码器 |
| `prompt` | ← `#16` | 正向提示词（经过前面 PE 组的二选一） |
| `negative_prompt` | 空 | 负面提示词。**只有 CFG > 1 时才有意义**。Turbo 是 6 步无 CFG，所以留空是对的 |
| `resolution` | `1024` | 输出分辨率锚点。**主要给编辑任务用**：编辑时输出会按第一张参考图的宽高比缩放到约 `resolution × resolution`；设为 `0` 则让每张参考图保持自身尺寸。<br>纯文生图时保持默认 `1024` 即可 |
| `images` | 空 | 参考图槽位（可加 `image_1` 到 `image_16`）。提示词里用 `<image1>`、`<image2>` 引用它们。**文生图用不上，编辑才用** |
| `vae` | 空 | 可选。编辑模式下需要用它把参考图编码进潜空间 |

**输出**：`CONDITIONING`。

---

### #19 `BasicGuider`「BasicGuider (CFG off)」— 无 CFG 引导器

**作用**：把「模型」和「条件」打包成一个**引导器**，告诉采样器"去噪时往这个方向靠"。它属于**不带 CFG** 的版本，也就是只走正向提示，不算负向、不做放大。

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `model` | ← `#26` | 模型（已经过 LoRA 和缓存处理） |
| `conditioning` | ← `#18` | 条件（提示词编码结果） |

**为什么不用普通 KSampler 的 CFG**：Turbo 蒸馏时完全没训练 CFG，强行加会让画面崩坏。所以配套用 `BasicGuider`，负面提示词也就没有存在意义了。

**输出**：`GUIDER`。

---

### #20 `RandomNoise` — 随机种子

**作用**：产生随机噪声，作为去噪的"随机源头"。

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `noise_seed` | `42` | 随机种子。**相同种子 + 相同设置 = 完全相同的图**，这是可复现的关键。换个数字就换构图。ComfyUI 界面上还常带一个"生成后如何处理种子"的小控件（固定 / 递增 / 递减 / 随机），实际用的时候注意 |

**输出**：`NOISE`。

---

### #21 `KSamplerSelect` — 选采样器

**作用**：选定用哪种数学方法来"逐步去噪"。

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `sampler_name` | `euler` | 采样算法。本机列了几十个，常见的有：<br>• `euler`：一阶欧拉法，最基础。**Qwen-Image / Turbo 官方指定用它**<br>• `euler_ancestral`：带随机性的欧拉<br>• `dpmpp_2m` / `dpmpp_sde`：更精细的 DPM 系列，适合长步数<br>• `lcm`：专给 LCM 蒸馏模型用的<br>• `ddim` / `uni_pc` / `heun` 等：其他经典方法<br>**蒸馏模型必须用它训练时对应的采样器**（这里是 euler），换成别的通常直接崩 |

**输出**：`SAMPLER`。

---

### #22 `ViggleTurboSigmas` — 6 步噪声表（**改动高风险**）

**作用**：产出 Turbo 训练时用的那套 sigma 调度表，替代普通 KSampler 内置的调度曲线。这是第 1 层加速的另一半。

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `latent` | ← `#8` | 传起始潜空间图进来。它需要知道**图像分辨率**，因为 sigma 要做"按分辨率动态缩放"（同样一张表，大图小图的噪声节奏不同） |
| `nodes` | `1.0, 0.9375, 0.875, 0.75, 0.5, 0.25` | 6 步的原始 sigma 节点，逗号分隔的字符串 |

**改动规则（Viggle 官方，务必遵守）**：只能在高噪端加步数或减步数。

- 5 步：`1.0, 0.875, 0.75, 0.5, 0.25`
- 6 步（当前）：`1.0, 0.9375, 0.875, 0.75, 0.5, 0.25`
- 7 步：`1.0, 0.9583, 0.9167, 0.875, 0.75, 0.5, 0.25`
- 8 步（小字更清晰）：`1.0, 0.9375, 0.875, 0.75, 0.625, 0.5, 0.25, 0.125`

**四条低噪点 `0.875 / 0.75 / 0.5 / 0.25` 绝对不能动**。学生模型是朝着这几个点训练的，动了整张图会明显发糊（实测锐度从 0.020 掉到 0.014）。也别改成均匀分布或者试图加 CFG，对蒸馏模型没用。

**输出**：`SIGMAS`。

---

### #23 `SamplerCustomAdvanced` — 分离式采样器

**作用**：把噪声、引导器、采样器、sigma 表、起始 latent 五路数据组装起来，真正执行采样。它和普通 `KSampler` 的区别是**把各部件拆开单独接**——正是为了能插入自定义的 sigma 表。

| 参数 | 本工作流值 | 详解 |
|---|---|---|
| `noise` | ← `#20` | 噪声源 |
| `guider` | ← `#19` | 引导器 |
| `sampler` | ← `#21` | 采样算法 |
| `sigmas` | ← `#22` | 噪声调度表 |
| `latent_image` | ← `#8` | 起始潜空间图 |

**输出**：`LATENT`（去噪完成的潜空间图）。

# 第四部分：速查与禁区

## 4.1 想做什么，动哪个旋钮

| 想做的事 | 动哪里 |
|---|---|
| 换画幅 / 分辨率 | `#7` 的 `aspect_ratio` + `megapixels` |
| 换提示词 | `#6` 的 `value`（PE 关闭时） |
| 开 PE 自动改写 | `#9` 的 `value` 设为 `true`（需先装 PE 模型） |
| 再快一点 | `#22` 降到 5 步；或对比关掉 `#26` EasyCache |
| 小字更清楚 | `#22` 换成 8 步表 |
| 省显存（会更慢） | `#2` 换 int8 主模型；`#4` 换更小编码器 |
| 换构图 | `#20` 换种子 |

## 4.2 不要动的清单

| 项 | 原因 |
|---|---|
| `#3` 的 `strength` | 必须 1.0，这是 LoRA 的训练设定 |
| `#3` 换成普通 LoRA 加载器 | 合并会丢约 30% 更新量，画质下降 |
| `#21` 采样器 | 蒸馏模型只认 euler |
| `#22` 的 `0.875 / 0.75 / 0.5 / 0.25` | 四个低噪点一动就糊 |
| `#7` 的 `multiple` | 保持 32 的倍数，否则潜空间尺寸可能非整数 |
| `#5` 换 1.0 版 VAE | 2.1 的 VAE 是 64 通道，混用会解码崩坏 |

## 4.3 一句话记住整个流程

**模型 + 提示词编码 → 一路打包成"引导器"，另一路给出"起点噪声"和"多少步、每步多少噪声"，两者在采样器里汇合，反复去噪 6 次，最后解码成图存盘。** 三层加速分别砍在：起点步数（蒸馏）、途中步数（缓存）、权重体积（量化）。
