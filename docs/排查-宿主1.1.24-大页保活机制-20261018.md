## 0. 一句话结论

**保活机制本身没有变化——宿主依旧没有"切走不卸载"的口子。** 1.1.24 里 release 链路（`ui-sessions/release`）完整保留，承租 TTL 仍是 **720 分钟**，`keepAlive` / `stayMounted` / 常驻字段仍 **0 命中**。

**但真正的根因不是"卸载"，是"重建"**（见 §6，本次查透）：切会话触发 **layout scope restore**，宿主按服务端 profile 重建整份黑板布局，重建时用 `pruneSurfacesNotInPages` 把不在 pages 清单里的 surface 整页删除 → hui 的 iframe 随之销毁。

**只要 `plugin-page:comfyui-hana:workspace` 不在服务端返回的 `pages` 里，这个 surface 就被 `kB()` 连页带卡删掉；挂在它上的 iframe 必然销毁。**

### 6.2 为什么会被剪掉：`Yg()` 的过滤

保存 profile 时：

```js
function Yg(e){
  const t = Fx(e);
  return { pages: t.pages.filter(n => n.surfaceId).map(...) }   // ← 只存带 surfaceId 的页
}
```

**只有已经分配了 `surfaceId` 的页才会被写进 profile。** 若保存发生时 hui 页尚未拿到 `surfaceId`（例如那次保存来自另一个 scope、或页刚被剪过），它就不在清单里；下次 restore 就被剪。

### 6.3 pageId 本身是确定的（不是随机丢失）

```js
function sK({realization, pluginId, cardId, doc}){
  if (realization !== "page") return { pageId: null, ... };
  const o = dT(pluginId, cardId);          // → Nx → 固定 pageId
  return { pageId: o, cardAlreadyPresent: Bm(doc, o, pluginId, cardId) };
}
```

→ `plugin-page:comfyui-hana:workspace` 固定不变，**不是 id 漂移导致**。问题只在「恢复时的 pages 清单里有没有它」。

### 6.4 App 侧能做什么 `[判断]`

| 想法 | 可行性 |
|---|---|
| 让 App 自己声明常驻 | **不行**：宿主无此字段（§1.3） |
| 阻止 iframe 被卸载 | **不行**：卸载发生在 React 树重建，App 无法阻断 |
| 让 hui 页永远在 pages 清单里 | **半可行**：取决于宿主何时保存 profile，不由 App 控制 |
| 切会话前先确保布局已落盘 | **可尝试**：App 无法主动触发宿主保存 |
| 用独立原生窗 | 绕开，但用户已明确否决（不是大窗形态） |

**结论：App 侧没有直接口子。** 唯一的软目标是「降低布局被重建的频率」，这属于宿主行为，不是 App 能改的。

## 1. 代码侧：机制未变 `[代码]`

### 1.1 release 链路原样保留

`server bundle`（`1.1.24.../bundle/index.js`）：

```
POST /apps/:appId/ui-sessions/release
  → 校验 body 只允许 {token}
  → p2r({hanakoHome, appId, token}) 解出 leaseId
  → o.revoke(appId, leaseId)      // 主动作废承租
```

`renderer`（`ChatTranscript-Bj8TErej.js`）：

```js
function Ao(e){ if(!e||e.returned) return; e.returned=!0;
  const {owner:t, token:n} = e;
  fetch(..., /api/apps/${appId}/ui-sessions/release, { method:"POST", body: JSON.stringify({token:n}) })
  ...catch(()=> console.error("[use-plugin-surface-url] Static App UI cleanup failed; ..."))
}
```

→ 与 1.1.7 时的 `lo()` **逻辑一致**（变量名从 `lo` 变 `Ao`，行为不变）：**组件卸载即 release**。

### 1.2 承租 TTL 未变

| 常量 | 值 | 含义 |
|---|---|---|
| `jK` / `Y6` / `Ale` / `S2r` | `720 * 60 * 1e3` | **720 分钟 = 12 小时** |
| `I2r` | `60 * 1e3` | 60 秒（心跳/校验类） |

12 小时远大于实际使用时长，**不是过期导致掉线**。

### 1.3 仍然没有保活开关 `[代码]`

新版 renderer + server 全量检索：

| 关键字 | 命中 |
|---|---|
| `keepAlive` | **0** |
| `stayMounted` | **0** |
| `unmounted` | 0 |
| `idleReclaim` | 0 |
| `ui-sessions/release` | 1（ChatTranscript） |
| `appSurfaceSession` | 1（ChatTranscript）+ 1（error-bus） |

→ **宿主仍未向 App 开放任何"常驻/不卸载"能力。**

### 2.1 读法

- **跨小时的超长空档**（12159s / 22653s / 11799s）＝ 你离开电脑或关掉工作区，属正常。
- **17:12–17:32 的密集重建**（5 次，间隔 40–90s）＝ 我在改面板、反复刷新的时段。
- **20:55–21:21 的密集重建**（4 次）＝ 面板加载失败排查期间，你和我反复刷新工作区。
- **没有一次是"切到聊天页、什么都不做、然后掉"的干净对照。**

### 2.2 所以"现在又不保活了"要分开看

| 可能 | 证据 | 判断 |
|---|---|---|
| 宿主改了机制 | release 链路原样、TTL 未变、无保活字段 | **排除** |

| 浏览器节流 | 3 次变稀 | 次要，不影响存活 |
