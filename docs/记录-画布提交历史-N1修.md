## 一、问题

N1 加了「换工作流 → 刷新提交树 + 收起弹层」，两路触发：

- 主路径：canvas 元素上的 `litegraph:set-graph` 监听（`installHistoryGraphSwitchListener`）
- 兜底：`pollGraph` 内比对工作流名

缺陷：`litegraph:set-graph` **在任意 `setGraph` 时都触发**，事件本身**不代表「换了工作流」**：

1. **进/出子图**：`openSubgraph()` 也调 `setGraph` → 事件回调无条件执行 `historyOnWorkflowSwitch()` → **误关用户正开着的弹层**（真正的回归）。
2. **回跳装载**：`loadGraphData()` 也走 `setGraph` → 同样触发（回跳本就要关弹层，结果无害，但语义上不该走「换工作流」这条路径）。

根因：事件监听路径缺少「是否真换了工作流」的判断，与轮询兜底是**两套逻辑**（轮询有名字比对，事件没有）。

## 三、「统一判据」怎么落地

**单一定义**：`historyOnWorkflowSwitch()` 现在是**唯一的判据 + 动作入口**，两路（事件 / 轮询）都只调它，不再各自比对。

判据逻辑（L3805 起）：

```
取 name = currentWorkflowInfo().name（try/catch，取不到 → 保守 return false）
if (name === null)            → return false          // 取不到，不动
if (lastWorkflowName === null)→ lastWorkflowName=name; return false  // 基线未建立：只记不动
if (name === lastWorkflowName)→ return false          // 同名 → 不执行
lastWorkflowName = name                                // 确换了 → 更新基线
→ 执行【刷新树 + 收弹层】；return true
```

### 为什么「进子图」不再误关

进/出子图时页面**身份不变** —— `currentWorkflowInfo().name` 仍是同一个工作流名。`historyOnWorkflowSwitch()` 比对发现 `name === lastWorkflowName` → 立即 `return false`，**不执行**刷新/收弹层。弹层保持用户打开的状态。（`litegraph:set-graph` 照样触发，但入口拦截。）

### 为什么「回跳装载」不误判

回跳（`loadGraphData`）装进**当前页对象**，页身份与工作流名不变 → 同样命中 `name === lastWorkflowName` → 不执行。语义上回跳不再混入「换工作流」路径。（回跳后弹层收起由回跳自身逻辑负责，不依赖本入口。）

### 为什么不会「首次误关」

`setup()` 中、首轮 `pollGraph()` 之前先记一次基线（L4765）。此外入口内置兜底：若基线仍为 `null`（如 hello 失败未走到赋值），首次调用只 `return false` 并自记，不执行动作。两条都保证「初始工作流」不会被当成「换工作流」而误关弹层。

### 为何是「复用」而非「新造」

N1 的轮询内已有 `lastWorkflowName`（L112 模块级）。本次**就地提升复用**为两路共用基线，未新增第二个变量；轮询里的比对/更新一并收敛进统一入口，消除两套逻辑。
